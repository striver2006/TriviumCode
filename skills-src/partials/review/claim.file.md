### 0. 认领本阶段（写原稿之前）

原稿写在 `review --start` 之前，那一刻本阶段还没有运行留痕，护栏只能按**声明**判定这一阶段归谁写。
所以**写原稿之前**先认领；原稿已经写好了也补跑一次（同一声明幂等）：

```
TV topic claim --topic <主题> --stage {{STAGE}} --driver {{DRIVER}} --json
```

`<主题>` 取用户参数里的 `--topic`；没写时用原稿所在（或你打算写进）的主题目录名，即 `.reviews/<主题>/{{STAGE}}/` 里那一段。

- 本阶段已声明为你自己时它退 0、什么都不改，照常继续；
- **退 64 时原样转述并停止**：本阶段已由别家执笔，或阶段目录里已有别家后缀的文件。
  **不要删那些文件来换回认领**——那是刻意的限制，它们的去留请用户在终端处理；
- **退 2 时同样原样转述并停止**：审批正本 task.json 读不出，本次没有写入。恢复由用户在终端做，恢复后再重跑本步；
- 认领是**自声明**：它记下「这一阶段由谁执笔」，证明不了你就是那一家；窗口内的认领次数也不设上限（M10a 边界 ⑥）。

### 0.5. 准备并回读被审原稿（完成后才能解析）

**认领成功只声明作者，不会生成原稿。`topic resolve` 只定位已有文件，不负责起草。**
本步骤不能因认领成功而跳过；先核对项目的工件写入约定，再按以下分支完成：

- 用户已提供 `{{SUBJECT_FLAG}}` 或已有本主题原稿：用 Read 读取该原稿，保留原文；显式指定的路径继续透传，不另写替代件。
- 认领之后若原稿还没写：先用 Read 阅读任务材料与相关实现，再自行起草完整{{SUBJECT_NOUN}}。
  默认用 Write 落盘 `.reviews/<主题>/{{STAGE}}/<日期>-<主题>-<当轮 Driver>.md`。
  若项目明确约定了暂存后归档的传输方式，按该约定完成写入和归档，不能把暂存成功当成被审原稿已就绪。

**进入第 1 步前，用 Read 回读最终被审原稿，确认路径与正文；只有取得成功读取结果才能继续。**
缺少任务材料、写入/归档/回读失败时，报告具体缺口并停止；不创建空占位件，不用解析失败来代替本步骤，
不在失败后改用其它写入通道绕过限制。已有原稿不覆盖，尚未就绪时不启动评审。
