### AGY-01 · 阻断（blocker）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §4.2` |
| 类别 | correctness ｜ 层次 plan |

**问题**：缺失文件（ENOENT）控制流穿透导致误报为文件损坏：在伪代码中，readFileSync 捕获 ENOENT 后仅赋值 base = { ...DEFAULT_CONFIG }，未跳过后续解析逻辑，流程直接穿透至 JSON.parse(raw)；因 raw 为 undefined，JSON.parse(undefined) 必抛 SyntaxError，被外层捕获后抛出 Error('配置文件损坏: ...')，导致 R2「缺失回退默认值」完全失效。

**依据**：在 .reviews/配置加载重构/plan/2026-09-26-配置加载重构-glm.md 第 68-75 行伪代码中，第一段 try raw = readFileSync(...) catch: if e.code == 'ENOENT': base = { ...DEFAULT_CONFIG } 之后，无条件紧接着执行 try obj = JSON.parse(raw)。此时 raw 未赋值为 undefined，在 Node.js 中 JSON.parse(undefined) 必然抛出 SyntaxError 并被第 73 行捕获抛出文件损坏异常；对照 README.md 第 8 行 R2「配置文件缺失时回退到内置默认值，而不是抛错」的要求，该逻辑导致用例 1 无法通过。

**建议**：重构 loadConfig 的控制流分支：若捕获到 ENOENT，应明确短路跳过后续的文件内容解析（JSON.parse）和 fileObj 合并流程，直接进入环境变量覆盖及缓存写入；仅在文件实际读取成功时才执行 JSON 解析与对象合并。

### AGY-02 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §3.1` |
| 类别 | contract ｜ 层次 plan |
| 置信度 | high |

**问题**：环境变量类型转换基准依赖运行时未校验的 typeof base[k]，破坏契约并存在未定义行为：若配置文件中某键包含错误类型（如 port: "8080" 或 port: null）或包含非标量未知键（如嵌套对象），typeof base[k] 为 'string' 或 'object'。这会导致 APP_PORT 被当作 string 覆盖从而违反 AppConfig 的 port: number 契约；若为 'object'，计划中的 convert 未定义 object 转换分支，将导致运行时崩溃或未定义行为。

**依据**：查阅 src/config.ts 第 3-7 行，AppConfig 契约规定 port: number; debug: boolean; name: string；而 plan §3.1 声明「类型转换按合并后该键的实际类型（typeof）」，§2 明示「文件里 port 写成字符串不报错，APP_PORT 按 string 规则原样覆盖」，§4.2 伪码为 convert(v, typeof base[k])。当 JSON 文件类型异常或包含额外对象键时，typeof base[k] 无法反映配置契约期望类型，且无法处理 'object' 等类型。

**建议**：将类型转换的目标类型基准与 DEFAULT_CONFIG（或固定的 AppConfig schema 元数据）绑定，以契约原键类型为准进行转换，而不是被未校验的 JSON 脏数据或运行时对象类型带偏；同时遍历覆盖时建议以 DEFAULT_CONFIG 的合法键为准，防止文件中的未知键扩散至 env 解析。

### AGY-03 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §3.1` |
| 类别 | correctness ｜ 层次 plan |

**问题**：数字类型转换未防范纯空白字符串与负无穷大：plan 提出显式拒绝 ""，但在 JavaScript 中纯空白字符串（如 " "、"\t"）经 Number(v) 转换同样会得到 0 而非 NaN；此外拒绝规则仅列出 Infinity 未明确 -Infinity，可能导致空环境变量被静默转换为 0。

**依据**：在 .reviews/配置加载重构/plan/2026-09-26-配置加载重构-glm.md 第 38 行中，number 转换规则描述为「Number(v)，拒绝 NaN / Infinity / 空串（注意 Number("") === 0，须显式拒绝空串）」，对照 JavaScript 规范，Number(" ") 与 Number("\t\n") 均等于 0，仅判断 v === "" 无法拦截此类空白输入；对照 README.md R1 的类型转换要求，空输入转为 0 属于非预期行为。

**建议**：在数字转换校验中，改用 v.trim() === '' 拒绝所有空白字符，并采用 !Number.isFinite(n)（或显式同时排除 NaN、Infinity、-Infinity）确保数值在有效有限数范围内。

## 认为正确的部分

- 精准界定文件缺失：仅 ENOENT 回退默认配置，EACCES/EISDIR 等系统级读错误原样抛出（决策点 C），避免将权限或路径错误误掩盖为缺失。
- 文件损坏报错符合要求：在 JSON 语法错误或非纯对象时包装 Error，明确在错误信息中包含文件绝对路径并携带原始 cause，满足 R2 要求。
- 缓存与重试机制合理：采用 path.resolve 归一化路径作为缓存 Map 的键避免相对路径重复读盘；且仅缓存成功结果，损坏文件不进缓存（决策点 E），支持修复后重试。
- 只读机制彻底：通过 deepFreeze 递归冻结配置对象，返回类型为 Readonly<AppConfig>，兼顾运行时防御与编译期类型保护。
- 环境变量遍历方向合理：按配置顶层键反查 APP_<KEY>，天然避免了无序扫描整个 process.env 带来的未知变量干扰与大小写不确定性。
