- CODEX-03：§二区分仓库内调用点（grep 核实为零）与导出的潜在外部消费者（尾参可选，向后兼容）。
- CODEX-02、GLM-01：§三补测试落地决策：`src/greet.test.ts` + 内置 `node:test`，执行命令 `node --test src/greet.test.ts`，零新增依赖。

## 一、目标

给 `src/greet.ts` 的 `greet` 加一个可选的问候语参数，缺省仍是 `hello`。缺省路径的输出与现状逐字一致（现状：`hello ${name}`）。

## 二、做法

新签名：

```ts
export function greet(name: string, greeting: string = 'hello'): string {
  return `${greeting} ${name}`;
}
```

- **缺省问候语**：`greeting` 缺省值为 `'hello'`，不传时返回 `hello ${name}`，与改动前的返回值逐字相同。
- **调用方不受影响**：
  - 新参数追加在 `name` 之后的末位且可选，现有单参调用 `greet(name)` 在类型（仍只需一个 `string` 实参，返回类型仍为 `string`）与行为（返回值逐字不变）上都不变；
  - 仓库内调用点：`grep -rn greet`（排除 `.reviews/`、`.trivium/`）只命中 `src/greet.ts` 的定义行，当前**没有任何调用方**，所以不需要改调用方；
  - 外部消费者：`greet` 是公开导出，仓库外若有 import，由于新参数是末位可选参数，同样向后兼容，不需要改。
- 不改返回结构，不做别的重构。

## 三、测试

- 新增 `src/greet.test.ts`，用 Node 内置 `node:test` 与 `node:assert/strict`，从 `./greet.ts` 导入 `greet`；
- 两条断言：
  1. 缺省：`greet('world')` 严格等于 `'hello world'`（同时验证向后兼容）；
  2. 自定义：`greet('world', 'hi')` 严格等于 `'hi world'`；
- 执行命令：`node --test src/greet.test.ts`（本机 Node v25.2.1 默认剥离 TS 类型，不需要编译步骤）；
- 不引入 `package.json`、`tsconfig` 或任何 devDependency。
