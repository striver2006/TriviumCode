## 一、目标

给 `src/greet.ts` 的 `greet` 加一个可选的问候语参数 `greeting`，缺省仍是 `hello`。

缺省问候语的口径：

- 未传 `greeting`（即 `undefined`）时取 `'hello'`，输出与现状 `hello ${name}` 逐字一致；
- 显式传入任何字符串（含空串 `''`）都原样使用，不回退缺省值——不做额外的空串判断，保持改动最小。

## 二、做法

只改 `src/greet.ts` 一个文件，签名改为：

```ts
export function greet(name: string, greeting: string = 'hello'): string {
  return `${greeting} ${name}`;
}
```

- `greeting` 是第二个参数，位于必选参数 `name` 之后（TypeScript 也不允许可选参数排在必选参数之前）；
- 返回类型仍是 `string`；
- 不改任何调用方，不做其它重构。

## 三、测试

- 落点：新建 `src/greet.test.ts`；
- 运行器：Node 内置 `node:test` + `node:assert/strict`；本机 Node v25.2.1 原生剥离 TS 类型，可直接执行 `.ts`；
- **不引入**任何测试框架或依赖，**不新建** package.json / tsconfig.json；
- 导入写 `import { greet } from './greet.ts';`（Node 类型剥离要求显式扩展名）；
- 运行命令：`node --test src/greet.test.ts`，退出码 0 即通过。

断言两条：

1. 缺省：`greet('Bob')` 严格等于 `'hello Bob'`（同时充当既有行为的回归验证）；
2. 自定义：`greet('Bob', 'hi')` 严格等于 `'hi Bob'`。

## 四、调用方不受影响的依据

- **现状**：仓库内 `greet` 没有任何调用点，`grep -rn greet --include='*.ts' src` 只命中 `src/greet.ts` 里的定义行（实施后还会命中新建的测试文件）；
- **兼容机制**：即使将来或仓库外有调用方，既有的单参调用 `greet(name)` 仍合法——新参数追加在末尾且有缺省值，编译期签名兼容；运行期 `greeting` 取 `'hello'`，输出与改动前逐字一致；
- **可核对**：§三的断言 1 正是对单参调用旧行为的回归验证。
