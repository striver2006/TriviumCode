**依据**：在 src/limiter.ts:76 中，小幅回拨分支执行 else now = q.last()，直接改写了方法入参 now。随后第 86 行调用 this.reclaim(now, RECLAIM_PER_CALL, key)。在 reclaim 内部计算 cutoff = now - this.windowMs 时，基准被提高至当前 key 钳位后的未来时间点（即 q.last() - windowMs）。此时若 Map 中其他并发 key 的最近放行时间处于 [实际now - windowMs, q.last() - windowMs] 区间内，会被第 102 行误判为过期并被整 key 删除。该 key 在随后请求中会因重新初始化 Ring 而获得全新的完整配额，造成严重的窗口限流失效与静默超发。

**建议**：避免在 allow 内部直接覆盖入参 now；引入局部变量（如 effectiveNow 或 clampedNow）专门用于当前 key 的队列计算与 push，而将未被篡改的原始 now 传入 this.reclaim。

## 认为正确的部分

- 环形缓冲 Ring 的头尾下标运算（(head + len - 1) % cap 与 (head + len) % cap）逻辑严谨，容量与边界守卫齐备，消除了大 limit 下 Array.shift 的线性性能退化。
- 「删后重插 + 队头均摊回收」精确落实了计划裁决（revised-claude §3.1 与 AGY-03 裁决）的「活跃序」设计；以最后访问时间为序并在 now >= T + windowMs 后确保前序项均已过期，有效兼顾了 O(1) 均摊回收与防饥饿。
- 时钟回拨两档阈值边界（q.last() - now > windowMs 判定为故障并 clear 清空重计，<= windowMs 钳位至队尾）与计划裁决严格一致，精确落实了有界 fail-open 承诺。
- 保留 FixedWindowLimiter 作为 SlidingWindowLimiter 的 @deprecated 别名，平滑兼顾了对外契约兼容性与语义纠偏。
- 构造函数对 limit（正整数）与 windowMs（正数）的边界校验严密，拒绝了非整数、负数与 NaN 等异常输入。
