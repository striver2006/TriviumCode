### CODEX-01 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/limiter.ts:76-79（allow 的钳位分支 `else now = q.last();`）` |
| 类别 | correctness ｜ 层次 code |
| 置信度 | high |

**问题**：小幅回拨的「按队尾钳位」不只是把当前请求延后计数，它把整条队列的淘汰线都锚到了被钳低的 now 上：钳位本身不改已存时间戳，但一旦时钟随后恢复到真值，队内真实间隔远大于表观间隔的旧条目会一起提前过期。具体反例（limit=2, windowMs=1000）：allow(a,1000)=true、allow(a,1900)=true；回拨 allow(a,1500) 钳位到 1900 被拒（正确）；但随后 allow(a,2900) 时 cutoff=1900，1000 和 1900 两条同时出局，1900~2900 这 1000ms 真实窗口内放行了 2 个新请求，而 1900 处刚放行过——任意真实 windowMs 内可放行至多 2×limit。即「回拨 ≤ windowMs 不超发」只在回拨瞬间成立，承诺的长期上界依赖 now 不可被大幅扰动，头注释与测试用例名（'小幅回拨按队尾钳位，不超发'）都表述过强。

**依据**：实际运行推演 src/limiter.ts 的 allow 全路径：钳位分支只改局部 now，q 内容不变；下一大步前进时 `while (q.size > 0 && q.first() <= cutoff) q.shift();` 会把被旧 cutoff 保住的条目一次性清空。头注释仅笼统写了「假设被破坏时上界不成立」，未区分「前跳」与该回拨+恢复形态。

**建议**：方向二选一并保持一致：要么在文档里把钳位档的「不超发」限定为「本次调用不超发、长期上界需 now 与真实时间偏差远小于 windowMs」（该假设段落已有雏形，补上回拨+恢复这一形态）；要么在实现上只钳位「压入值」而淘汰线仍按原始 now 与队列自序处理。同时补一条「小幅回拨后紧跟 +windowMs 大步进」的用例，把选定语义钉死。

### CODEX-02 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/limiter.ts:88, 96-108（reclaim 的 `else break` 早停）与 allow 开头的删后重插` |
| 类别 | performance ｜ 层次 code |
| 置信度 | medium |

**问题**：均摊回收与 sweep 的「遇首个未过期 key 即停」依赖一个未声明的前提：Map 插入序 = 最后活跃时间戳的升序。正常时钟下成立，但回拨钳位会违反它——热 key 回拨后被重插到队尾，其存储时间戳却是陈旧的，可能小于身后一批 key 的时间戳。此后该 key 稳坐队头且长期「未过期」（热 key 每 windowMs 内总有请求），reclaim/sweep 每次在队头第一格就 break，其后所有闲置 key 永远得不到回收，Map 无界增长。这正是计划裁决 CODEX-07 暂缓的「key 基数型内存放大」的单机放大器版本：外部只需持续对某一热 key 注入回拨时间戳即可让回收停摆。

**依据**：读 src/limiter.ts 全文：allow 对所有请求（含被拒）都 `this.hits.delete(key); this.hits.set(key, q);`，钳位分支把存储时间戳降为 q.last()（可能远早于身后 key 的插入时刻）；reclaim 的 `else { break; }` 使扫描在首个未过期队头即终止。对照 .reviews/限流器重构/plan/2026-09-25-限流器重构-revised-claude.md 中 AGY-03/CODEX-07 的裁决，确认早停优化是本轮新采纳的机制，其前提未在计划中声明。

**建议**：给早停加兜底：例如记录「队头连续 N 次未过期则本轮跳过头部继续向后扫」，或 reclaim 对队头不满足时最多再看固定常数个 key 而非立即 break；至少在头注释里写明「早停假设 now 单调，时钟长期错乱时回收退化为仅 sweep 全量模式（须去掉 break）」，并把该退化模式作为可选参数暴露。

## 认为正确的部分

- 环形缓冲下标运算逐条验证正确：push 槽位 `(head+len)%cap` 在 len=cap-1 时恰落在 head 前一格且不覆写未出队数据；last 在满队列时 `(head+cap-1)%cap` 处理了 head 环绕；shift/push 均取模，len 永不超过 cap（push 前 `q.size < this.limit` 且 limit===cap），无负模、无越界读。
- 回拨两档阈值 `q.last() - now > windowMs` 判故障、否则钳位，边界归属（恰等于 windowMs 走钳位档）与计划裁决 CODEX-03/AGY-04 的「≤ windowMs 钳位 / > windowMs 故障」逐字一致；「最坏拒绝时长 ≤ windowMs」在钳位分支下成立（钳位后 cutoff=q.last()-windowMs，队尾永不被淘汰）。
- 「删后重插」实现正确：`delete(key)` 后 `set(key, q)` 把 key 移到插入序末尾，且复用同一 Ring 实例（q 已持有引用），Map 活跃序维护无误；拒绝路径同样重插，与 r2 §3.2「放行与拒绝都删后重插」一致。
- reclaim 在 for-of 迭代 Map 的同时 delete 当前/已访问条目，是 ECMAScript 规范保证安全的操作，无跳位、无重复访问；r1 被驳回的「空队列死分支」在此处 `q.size === 0` 仅作防御性兜底，可接受。
- 淘汰判据 `first() <= now - windowMs` 与文档声明的半开区间 (now-windowMs, now] 一致，'半开区间'用例（0/999/1000）钉住了边界；构造校验用 `!(windowMs > 0)` 顺带挡住 NaN，细节到位。
- 计划遗留的口径（sweep 缺省 Date.now()、只读 size getter、@deprecated 别名保一个版本、前跳不做特殊处理）都已如实落进代码。
