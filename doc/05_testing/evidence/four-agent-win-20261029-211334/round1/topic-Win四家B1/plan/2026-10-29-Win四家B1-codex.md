# sum 输入校验实施计划（原稿）

## 目标

为 `src/sum.cjs` 的 `sum(a, b)` 实现符合 `requirements.md` 的有限数值输入校验，并以测试锁定全部行为分支。

## 现状

- `src/sum.cjs`：仅 `return a + b;`，无任何校验。
- `test/sum.test.cjs`：仅覆盖两个正常值相加的正用例。
- 需求（requirements.md）：
  1. 只接收有限 number：两个入参都必须是 number 且为有限值（Number.isFinite）。
  2. 拒绝字符串、NaN、Infinity、-Infinity：抛出带说明的 TypeError。
  3. 允许负数与小数。
  4. 校验失败不得返回数值结果。

## 实施步骤

1. 在 `sum` 函数入口对 `a`、`b` 依次校验：使用 `typeof x !== "number" || !Number.isFinite(x)` 判定非法输入。
   - 该判定同时拒绝：字符串（typeof 非 number）、NaN（Number.isFinite(NaN) 为 false）、Infinity / -Infinity（Number.isFinite 为 false）。
   - Number.isFinite 不做类型强转（区别于全局 isFinite），对 `"1"` 这类可转数值的字符串也判定为非法，符合「只接收有限 number」。
2. 校验失败时抛出 `TypeError`，消息带说明，指明是哪个参数、收到的值与期望类型，例如：
   - `throw new TypeError(`sum: 参数 ${name} 必须是有限 number，收到 ${String(value)}（类型 ${typeof value}）`)`
   - 先校验 `a`、再校验 `b`，一次调用至多抛出一个 TypeError。
3. 校验通过后执行 `return a + b;`——正常路径（含负数、小数、大数）行为不变。
4. 校验失败路径不返回任何值（抛出即终止），满足「不得返回数值结果」。

## 测试策略

在 `test/sum.test.cjs` 中按分支补充用例（node:test + assert/strict），全部通过 `node --test test/sum.test.cjs` 运行：

- 正常值：`sum(1, 2) === 3`、`sum(10, 32) === 42`（保留现有用例）。
- 负数：`sum(-1, 2) === 1`、`sum(-1.5, -2.5) === -4`。
- 小数：`sum(0.1, 0.2)` 用 `assert.ok(Math.abs(r - 0.3) < 1e-9)` 或 `assert.equal(r.toFixed(1), "0.3")` 处理浮点误差。
- 字符串：`assert.throws(() => sum("1", 2), TypeError)`，消息含说明；再测 `sum(1, "2")`。
- NaN：`assert.throws(() => sum(NaN, 1), TypeError)`；再测第二个参数为 NaN。
- Infinity / -Infinity：`assert.throws(() => sum(Infinity, 1), TypeError)`、`assert.throws(() => sum(1, -Infinity), TypeError)`。
- 其他非 number 类型（加固）：`sum(null, 1)`、`sum(undefined, 1)`、`sum({}, 1)` 均抛 TypeError。
- 校验失败不返回值：对抛错分支用 `assert.throws` 包裹后，无返回值可断言——以「抛出且消息非空」间接锁定；另加一个对照用例确认合法输入仍返回 number 类型结果。

## 验收标准

- `node --test test/sum.test.cjs` 全部通过。
- 需求四分支（正常值／负数／小数／字符串／NaN／Infinity）均有对应测试。
- 业务实现仅改动 `src/sum.cjs` 的 `sum` 函数体；测试改动集中在 `test/sum.test.cjs`。

## 风险与备注

- 浮点小数断言使用容差或 toFixed，避免直接 `assert.equal(0.1 + 0.2, 0.3)` 造成的脆性。
- 不引入新依赖、不改变模块导出形态（仍为 `module.exports = { sum }`）。
