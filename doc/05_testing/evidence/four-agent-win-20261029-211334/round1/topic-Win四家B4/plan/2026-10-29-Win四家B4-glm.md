# sum 输入校验实施计划（Win四家B4）

## 1. 目标与范围

按 `requirements.md` 为 `src/sum.cjs` 的 `sum(a, b)` 增加输入校验：只接收有限 number，
拒绝字符串、NaN、Infinity、-Infinity（抛 TypeError），允许负数与小数。改动仅限
`src/sum.cjs` 与 `test/sum.test.cjs`，不引入依赖，不改模块导出形态。

## 2. 实施步骤

1. 在 `sum` 函数体入口增加参数校验函数 `assertFiniteNumber(value, name)`：
   - 判据 `typeof value === 'number' && Number.isFinite(value)`，同时满足才通过；
   - 不满足时抛 `TypeError`，消息含参数名（`a` / `b`）、实际类型与实际值；
   - `Number.isFinite` 已同时排除 NaN、Infinity、-Infinity，无需逐个特判；
   - 隐式拒绝字符串等其它类型（`typeof` 不匹配），符合需求第 2 条。
2. 对 `a`、`b` 依次调用校验后再执行 `return a + b`。
3. 校验失败路径不返回任何数值结果（直接抛出），符合需求第 4 条。

## 3. 测试策略

在 `test/sum.test.cjs` 追加用例，全部用 `node:test` + `node:assert/strict`：

- 正常值：正整数、负数（`-1.5 + 0.5 === -1`）、小数（`0.1 + 0.2` 用 `approximately` 或保留既有 equal 形态）；
- 拒绝字符串：`sum('1', 2)`、`sum(1, '2')` 均断言抛 `TypeError`（`assert.throws` 带 `/a/`、`/b/` 消息匹配）；
- 拒绝 NaN：`sum(NaN, 1)`、`sum(1, NaN)` 抛 `TypeError`；
- 拒绝 Infinity：`sum(Infinity, 1)`、`sum(-Infinity, 1)`、第二参数对称用例抛 `TypeError`；
- 隐式转换边界：`sum(true, 1)`、`sum(null, 1)`、`sum(undefined, 1)` 均非 number，抛 `TypeError`；
- 既有两条正常加法用例保持不变（回归基线）。

验证命令：`node --test test/sum.test.cjs`，全绿为准；语法检查 `node --check src/sum.cjs`。

## 4. 边界与风险

- 不改变 `module.exports = { sum }` 的导出形态；
- 不处理超过 Number.MAX_SAFE_INTEGER 的精度问题（需求未要求，浮点加法维持语言语义）；
- 错误消息为英文类型名 + 中文说明均可，本计划固定为含参数名的可读消息，便于测试断言；
- `BigInt` 同样不是 number，按同一判据拒绝（需求「只接收有限 number」的直译）。

## 5. 验收标准

1. 全部新增用例与既有用例通过 `node --test test/sum.test.cjs`；
2. `sum(1, 2) === 3` 等正常行为不变；
3. 六类非法输入（字符串 / NaN / Infinity / -Infinity / 布尔 / null-undefined）在任一参数位都抛 `TypeError`，且不返回数值。
