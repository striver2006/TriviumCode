### GLM-01 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/sum.cjs:4` |
| 类别 | correctness ｜ 层次 code |

**问题**：bigint 入参走 String(v) 分支，String(10n) 结果为 10（无类型标记），错误消息变成「sum: 参数 a 必须是有限 number，实际为 10」——回显值看起来恰是一个合法的有限数，与同一句话的拒绝理由自相矛盾。排查者拿到这条消息会误以为校验逻辑有 bug，而不是意识到传入的是 bigint。r2 计划 §5 只记录了「对 BigInt 走 String(v) 分支」，未讨论回显形态的歧义。

**依据**：src/sum.cjs:4 的 typeof v === 'bigint' 分支返回 String(v)；src/sum.cjs:15 的消息模板；test/sum.test.cjs:37-39 的 bigint 用例只断言 /^sum: 参数/ 前缀，断不出回显内容。String(10n) 恒等于 10 属 ECMAScript 语义，此判断为静态推读、未运行验证。

**建议**：bigint 分支的回显带上类型标记，让读者一眼看出不是 number：例如按 BigInt 字面量形态回显（10 加后缀 n）或写成 bigint: 10 一类带 typeof 前缀的形式，与其它非 number 类型的回显格式对齐。方向即可，不必大改。

### GLM-02 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/sum.cjs:6-7` |
| 类别 | security ｜ 层次 code |

**问题**：describeValue 把任意大小的入参完整序列化进异常消息，无长度上限：超大字符串或深嵌套对象会生成同量级的异常文本，随日志放大造成内存与日志膨胀；对象的字段值（可能含敏感数据）也被原样复制进异常与日志；JSON.stringify 返回 undefined 的形态（函数、symbol）还会经 String(v) 把函数源码全文带进消息。对一个定位为输入边界的校验函数，这是典型的无界回显面。

**依据**：src/sum.cjs:6 的 JSON.stringify(v) 与第 7 行的模板拼接均无截断；requirements.md 第 2 条只要求「带说明」，未要求完整回显值；r2 计划 §2.1 要点亦未涉及回显长度约束。

**建议**：对最终回显文本设一个较小的长度上限（截断加省略标记），既保住「带说明」的可读性，也封住无界回显。属加固项，非需求缺口。
