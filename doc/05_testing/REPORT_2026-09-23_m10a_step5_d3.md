### 1.2 认领出口文案（`src/trivium/driver-claim.ts` `claimRejectionMessage`）

`blocked-by-usage` 档的出口句，原文断言「会话内删不掉同样是刻意的」，理由是 Bash 守卫按角色后缀字面拦截。这是把启发式判据写成了确定性保证：D3 之前 Bash 侧不含 claude，`previous = claude` 那一格在会话内删得掉。这句也从来不是这条出口的真实理由。

**现文**（代码双审 r6 修订后）是四句：

1. 上列文件是以另一家的后缀写成的：可能是撤回前的旧声明留下的，
2. 也可能是尚无声明时写下、仍在使用的原稿。
3. 出口：请用户确认它们的去留后，在终端里处理再重试。
4. 不要在会话里删它们来换回认领——那正是这条限制要防的「会话自己翻转声明」。

`blocked-by-run` 档不动。

## 4. 没补的缺口

- **判据是启发式，不是确定性保证**：词边界字面匹配，不区分「写它」与「说它」。换一种写法让它认不出来，属于绕过判定，不是出口。强制力同样是单向的：终端里的命令不经过这个 Hook；codex / gemini 作 Driver 时，在它们自己的 CLI 里没有这个 Hook（L2）。
- **误拦面扩大已经发生**（r7 §3.2.1、R22）：命令文本里提到当轮 Driver 自己后缀的写形态命令，从此在会话内被拦，包括缺省 Driver 的 `-claude.md`。典型形态：
  - 克隆原稿；
  - 改名或删除旧稿；
  - commit message 带工件名；
  - 带重定向的 `--start`；
  - 焦点含写动词字面；
  - 恢复或清理带后缀文件；
  - **heredoc 正文同时出现写函数调用与带后缀的文件名**（r6 GLM-01）。判定刻意在未剥 heredoc 的原文上做，这是本仓实施中唯一真实被拦过的误报形态，D3 之后对 `-claude.md` 同样成立；
  - 归档之外沿用「日期-主题-角色」命名的文件（`doc/02_design/reference/` 与 evidence 下都有带 `-claude.md` 后缀的）用 Bash 改名或删除，也在射程内。

  出口：Write / Edit 落文件；`git commit -F <文件>`；恢复与清理在终端执行。`git add` 与只读提及不受影响（P1、P2 锁住）。
- **没有在真实会话里触发过**：用例都在夹具上直接调用 `hookPreBash`。本会话装完之后 Hook 已按 D3 判定，但没有专门构造一次「真实会话里被拦」的观测。真载体归 M10b。
- **D3 不改变提交锚**：提交锚按「位置 + 登记」判，与后缀无关。剩余边界两格仍在，段二登记为 EV-108。
- **`hooks.ts` 里与本步无关的失实注释没有改**，按 r2 §4.1 登记不改，段二报告汇总：
  - `resolveRoundDriver` 上方文档块写「代价是非缺省 Driver 仍写不出自己的原稿（已登记为已知边界）」，而 EV-72 已于第 1 步修掉这件事；
  - `hookPreWrite` 上方一处仍以 `criticRoleSuffixes(DEFAULT_DRIVER)` 作为当轮保护集的指针（r6 glm 在未覆盖范围里点到）。
- **变异 MD3b、MC1、MC2、MC4 的逐条归因是推断**；MD3a 已逐条核实。
- **文档尚未同步**：主设计、`.reviews/README.md`、根 `CLAUDE.md`、协议片段、PROTOCOL 里关于 Bash 侧后缀集与认领出口的口径，在段二统一改（r2 §3.0.5）。段二完成之前，这些文档写的仍是旧口径，读者应以代码为准。
