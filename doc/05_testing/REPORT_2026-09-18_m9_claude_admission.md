## 1. EV-42：逐文件 deny 形态 —— **正向结案**

### 1.1 三种条目形状，**判据不是同一个**

`enumerateDenyPaths`（`freeze.ts:346-347`）**无条件**往集合里加 `.trivium` 与
`expandHome(cfg.runtime.run_root)`，所以每一次真实运行的 `deny_paths` 都带着
后两种从未测过的形状——不是边缘情况。

| 形状 | 判据 | 结果 |
| :--- | :--- | :--- |
| 项目相对**文件** | 拦截两条腿（哨兵未泄漏 **且** 记入 `permission_denials`） | ✅ **成立** |
| 项目相对**目录** | 同上 | ✅ 成立 |
| 项目外**绝对路径** | **仅「规则语法被接受」** | ✅ 退 0、stderr 为空 |

**第三行的判据与前两行不同，不得并成一列读。** 初版我用了同一个判据，那是错的：
`--restricted` 本身就把文件工具限制在工作目录内，项目外的文件模型本来就读不到，
**「挡住了」无法区分是 deny 规则起作用还是 `--restricted` 起作用**——那是个
不可判定的实验设计。它能回答的是另一个问题，也正是计划双审 CODEX-05 真正担心的那个：
**CLI 会不会因为这种条目而拒绝整份 `--settings`**。答案是**不会**。

> 初版判据跑出来的 `两条腿都成立: false` 会让读者误以为「绝对路径 deny 失效」。
> 判据改准后重跑了一次（多花 3 次调用），**不让留痕里留一个会误导的行**。

### 1.2 落盘：`file_shape_verified: true`

结论由**探针第三臂**产出，不是手工回填——`probes/claude.ts:1067` 是
`probe.path_deny = await probeClaudePathDeny(bin, fx)` **整体赋值**，
任何手工写进 `config.local.yaml` 的值都会在下一次 `doctor` 时被覆盖回 `null`，
而 `peer_deny_applied` 读的正是这一格。回填的 `true` 会在某次 doctor 之后静默变回
false——**一次「我以为自己验过」的教科书形态**。

第三臂与既有 Grep 负对照臂**完全同构**（单独一次调用、同样两条腿、结论落自己那一格），
判据抽成纯函数 `judgeFileShape`。每次 `doctor` 因此多一次调用（约 +$0.008）——
这是刻意的取舍：合进主臂会让一次观测同时承载两个结论，把 `coverage_complete`
与 `file_shape_verified` 这刚拆开的两格又并回去。

**两个独立装置得到同一结论**：准入脚本（stdin 形态、自建夹具）与探针第三臂
（argv 形态、探针夹具）都判 `true`。

## 2. EV-43：stdin / argv 双臂形态复验 —— **零分叉**

| 格 | argv 臂 | stdin 臂 | 判定 |
| :--- | :--- | :--- | :--- |

**分叉的格：无。没测到的格：无。**

两臂复用同一份 `buildClaudeArgs` 产出，**唯一差别是 prompt 走 argv 末位还是走 stdin**——
这才是单变量对照。判据一律 import `probes/claude.js` 导出的 `judge*` 纯函数，
不在脚本里重写一份：脚本与探针的分歧只该来自输入，不该来自两份手写判据的措辞差异。

**这七格同时也是 2.1.276 上的版本复验**，且因为两臂在同一版本内对照，
「同结论」这个结论本身归因清晰。

### 2.1 两条边界，如实登记

1. **闭集是 8 格，本次双臂装置只覆盖了 7 格。** 第 8 格 `project_memory_blocked`
   （EV-44 新格）**没有进脚本的双臂 parity 装置**；它的 argv 形态**已有探针
   （`doctor`）单装置的实测**——探针的 `probeArgs` 把 prompt 放 argv 末位、
   `execProbe` 硬编码 `stdin: ''`，而对照臂同样显式给空 stdin，所以 §4 的落盘
   （`project_memory_blocked: true`）**本身就是一次 argv 形态、含对照臂的观测**。
   缺的是**同装置的双臂对照**，不是「argv 完全未知」。

   > 上一版这里写的是「只在 stdin 形态下测过，argv 形态未验」，**与本报告 §4
   > 自家的证据直接相抵**（代码双审 r1 GLM-05）。照那个措辞，后人会去补一个
   > 已经存在的观测，或误以为该格的 argv 行为完全未知。

2. **`denied_tool_in_trace` 那格的「同结论」强度低于其余六格**（代码双审 r1 GLM-02）：
   它的判据是**脚本内联**的，与探针落盘判据**问的不是同一个问题**——脚本那格测
   「模型发起过白名单外调用」，探针字段测「被拒的尝试留了痕」（按 `tool_use_id` 配对）。
   两臂之间仍是单变量对照（同一判据、只差 prompt 通道），所以**「同判据内两臂一致」成立**；
   但它**不是**与 §3.7 argv 基线（探针判词产出）的同口径比较。同源化已登记 EV-47。
3. **脚本夹具是非 git 仓库**（`mkdtemp`，与 M9 第 1 步报告 §2.2 的边界框一致），
   而探针的 `createFixture()` / `createMemoryFixture()` **是 git 仓库**
   （`initFixtureRepo`）。落进探针时条件变了，探针那一次的结论不能直接当成
   脚本那次的复现。

## 3. EV-44：`--restricted` 是否仍阻断项目记忆 —— **true**

| 臂 | 跑完了 | 工具调用数 | 看见记忆哨兵 |
| :--- | :--- | ---: | :--- |
| 受限臂（带 `--restricted`） | ✅ | **0** | ❌ 没看见 |
| 对照臂（去掉 `--restricted`，其余逐字相同） | ✅ | — | ✅ **看见了** |

⇒ `project_memory_blocked = true`。**零工具调用排除了「模型是去读文件才知道的」通道**。

### 3.1 `true` 臂为什么必须有对照

只跑受限臂的话，「CLI 在 headless 下压根不加载 `CLAUDE.md`（与旗标无关）」
会被记成「`--restricted` 挡住了」——**字段名就在撒谎**，而翻转条件
（厂商改掉该旗标语义）永远不会触发。与 `judgeVerboseBinding` 的
`positiveControlOk` 是同一条纪律。对照臂**按需跑**：受限臂已泄漏时不跑，省一次调用。

### 3.2 对 EV-44 裁定的后果

第 ⑤ 件（审查员身份片段）**对 claude 侧显式不做**的理由**在 2.1.276 上仍然成立**：
审查员读不到 `CLAUDE.md`，身份片段注进去会是**永远读不到的死件**。
身份声明只靠 BRIEF 首段（既有手法）。

**翻转条件已落成字段**：`ClaudeProbe.project_memory_blocked`，
**只有实测 `false` 的那天**本条结论作废。`null` 维持原裁定并记「待复测」——
`null` 是「没测到」，把没测到当证据正是本主题连修四轮的那个形状。
本格判据依赖模型配合作答，**`null` 将是常态**（同族的 `denied_tool_in_trace`
四次观测里三次落 `null`）。

## 4.2 EV-49：CLI 对含元字符的 deny 规则的实际方言（代码双审 r3 补测）

**触发时机**：EV-49 的条目逐字写着「**下一次跑准入脚本时**补含 `[` 与 `*` 的路径臂各一」。
r3 的 AGY-02（准入脚本没跟上 `buildDenySettings` 返回型重构）**必须重跑脚本才能验证修复**
——那个时刻就是本轮，所以一并测了。逗号与空格两臂是 r3 CODEX-05 追加的。

**装置**：`scripts/claude-admission-control.mjs` 的 `deny-dialect` 用例，CLI 2.1.276，
每臂一次真实调用。**这一格刻意绕过生产的语法门**：要测的正是「生产门拒绝生成的那种规则，
CLI 会怎么处理」，走 `buildDenySettings` 的话路径会被跳过、一条规则都不注入，实验就没有了。
规则用同一个 `shape` 手工包，其余（argv、执行、解析）仍走生产封装——这条偏差记在用例注释里。

| 臂 | 目录名 | 哨兵泄漏 | 进 `permission_denials` | 判定 |
| :--- | :--- | :--- | :--- | :--- |
| `[` | `t[3]` | **是** | 否 | ② 规则**匹配不到自身**，fail-open ⇒ **该挡** |
| `*` | `fix*` | 否 | 否 | ④ **判不出**（模型发起过调用，但两条腿都不成立） |
| `,` | `a,b` | 否 | **是** | ③ 规则**照常生效** ⇒ **该放行** |
| 空格 | `my key` | 否 | **是** | ③ 规则**照常生效** ⇒ **该放行** |

四臂均退 0、跑完、stderr 无抱怨，所以 EV-49 列的第一种可能（**CLI 拒整份 `--settings`**）
在这四种形状下**都不发生**。

### 4.2.1 结论推翻了我自己在同一轮里做的判断

r3 首版按审查意见把逗号、空格、反斜杠**一并挡了**，写的理由是
「三者都可达、匹配语义都未测，保守超集的代价只是可见的跳过」。实测之后这条理由**不成立**：

这个方言把路径**当字面量**处理，于是挡掉逗号与空格是**净损失**——
本可以被正常屏蔽的路径，规则被白白丢掉。空格那一类尤其吃亏：
它来自 `walkSensitive` 对 `sensitive_globs` 的文件系统派生（`docs/My Key.pem` 这种），
**是最不该丢规则的一类**。两者已放行。

**`*` 维持挡，但理由换了**：不是「fail-open」（没测出来），而是 r2 立的**过匹配**
——`fix*` 会扩成一批同前缀目录，超出 `deny_paths` 的字面集合，
可能连坐审查员合法读取的己方历史。那条理由独立成立，不依赖本次实测。

**反斜杠完全没排臂**，如实记为未测：它从主题名不可达（`validateTopic` 显式挡 `\`），
只能从 `walkSensitive` 来，保守维持挡。**没有拿逗号/空格的结论替它背书。**

剩余未结的两格（`*` 的三义性、反斜杠）已登记 **EV-51**。

### 4.2.2 `*` 那一格为什么判不出

观测是「哨兵未泄漏、没进 `permission_denials`、但模型确实发起过调用」。
三种可能现有判据区分不了：规则生效但未记名 / 模型读了别的东西 / Read 因别的原因失败。
**不把它写成「挡住了」**——那正是本主题连错四轮的那个形状（把「没测到」当证据）。
EV-51 给的修法是同时放一个同前缀的兄弟目录，看它有没有被连坐，
那同时回答了过匹配问题。

### 5.4 一次必须记账的方法失误：**第一批变异验证结果全部作废**

第一次跑变异矩阵时，我用 `basename` 给备份命名，而
`src/trivium/adapters/claude.ts` 与 `src/trivium/probes/claude.ts` **同名**——

而失败被 `>/dev/null 2>&1` 吞掉，**后续每一条变异跑的都是陈旧产物**。

于是那一批的 `fail 2` 证明的不是「变异被咬住」，而是「适配器文件坏了」。
**11 条结果全部作废。**

随后我建第二份备份时又犯了同形的一次：在"复现 M10 缺口"改过 `claude-trace.ts`
**之后**才建备份，**把一个变异版当成了干净基线**，于是恢复后两条用例持续红。

两次的共同结构与本主题连修四轮的那个形状一模一样：
**我为「我以为自己做了什么」建立了记录，而实际发生的是别的事。**

**可执行的对策**（不是「下次记得」）：

1. **变异脚本里构建失败必须中止并报**，不许 `>/dev/null 2>&1` 吞掉——
   重跑那一版就是这么改的，M10 的真结果因此才显出来。
2. **备份按全路径命名**（`src_trivium_adapters_claude.ts`），不用 `basename`。
   同名文件在本仓是常态（每家 CLI 在 `adapters/` 与 `probes/` 各有一份同名文件）。
3. **建基线之前先确认工作树干净**——`diff` 一次比事后追查便宜得多。
