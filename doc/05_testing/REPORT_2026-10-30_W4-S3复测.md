## 2. ISSUE-09②：环境路线逐级实测（候选一直接命中）

| 步骤 | 注入 | 结果 | 证据 |
| :-- | :-- | :-- | :-- |
| 对照 | 仅网关 env | stream-json 出现 `Git Bash wasn't found, so a SessionStart hook ran in PowerShell`（官方完整文案还建议对 PS 写的 hook 设 `"shell":"powershell"`——1.3.5 的命令形态本就两载体兼容） | 02 号 |

**结论②**：Claude 2.1.302 的探测函数会先读该环境变量（二进制内 12 处引用；basename 须为 `bash.exe`/`sh.exe` 且路径存在即采纳），进程级注入即生效。**无需重装 Git、无需目录联接**；日常交互式会话若要受益，由用户自行 `setx` 持久化即可（本次未做，属用户机器决策）。

## 3. ISSUE-09①：复核为误诊

- 二进制全文检索确认 claude 2.1.302 的 stream-json **不存在** `hook_started` 类事件——10-29 批次据「事件流无 PreToolUse hook_started」判「项目级 hooks 未注册」，判据本身不可观测。
- 同日主仓探针（02/04 号）里 SessionStart hook 实际执行、Stop hook 连续两次阻断收工并输出裁决缺口文案——hooks 在本机注册且阻断语义活着。
- **判别探针**（08 号，无闸门期）：headless 会话尝试新建 `.reviews/W4S3probe/plan/2026-10-30-probe-gemini.md`（伪造审查文件，hook 的无条件拒绝项）→ 被 `PreToolUse:Write hook error:` 实弹拦截，拒因含当轮 Driver 三级判定文案，文件未创建。
- 因此①不成立：10-29 canary 未被拦的完整解释就是③（sh 形态在 PowerShell 回退载体解析不到 sh、失败即放行），产品侧 1.3.5 已修。停点期「真实 Hook 事件」的可观测判据应取：**hook 拒因原文回现 + `permission_denials` 同 `tool_use_id` 关联 + 目标文件未变**，三者缺一不可（本报告与 cases.csv 按此口径留证）。

## 5. 顺带实测的两个环境事实（headless 会话侧，记入证据 meta）

1. **受限模式忽略用户 settings 的 env 段（证实既有机制，非新发现）**：01 号对照带 `--restricted` 时按官方语义不读 `~/.claude/settings.json` 的 env 块，网关凭据（`ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN`）直接报 `Not logged in`——与设计 §7.1「第三方网关」段一致；编排器经 `settings_env_source: user_settings` 做进程级注入补偿，本复测驱动器（`harness-headless-claude.js`）复刻的正是这条路。任何绕过编排器直起 `claude.exe` 的探针都要自带这层。
2. **`permissions.defaultMode: "plan"` 对 headless 同样生效**：不显式 `--permission-mode acceptEdits` 时模型自称 plan 模式、把业务写入改道成 plan 文件（06 号）——这是到达 hook 之前的客户端行为，测 Hook 必须显式覆盖，否则测不到目标路径。

## 6. 结论与遗留

- **W4-S3 达成**；ISSUE-09 三层全部收口：③产品侧（1.3.5 PowerShell 形态）、②环境侧（`CLAUDE_CODE_GIT_BASH_PATH` 进程级注入，05 号实测）、①误诊撤案（08 号判别探针）。
- 至此 2026-10-29 验收批次扩展批次的用例全部有结论，唯一未达成项消除。
- 遗留（非阻断）：claude 会话的「Git Bash wasn't found」提示在未注入变量的会话里仍会出现（纯警告，PS 形态 hook 在回退载体下阻断语义完好）；用户如需日常交互式会话也走 Git Bash 载体，可自行 `setx CLAUDE_CODE_GIT_BASH_PATH "D:\Program Files\Git\bin\bash.exe"` 持久化（可选配置说明已录入[使用手册](../07_manuals/使用手册.md) §9）。
- 判据修订建议（供后续验收任务书参考）：headless 停点负向的「真实 Hook 事件」应取可观测三证（hook 拒因原文回现 + `permission_denials` 同 `tool_use_id` + 目标文件未变），不再引用不存在的 `hook_started` 事件类型。
