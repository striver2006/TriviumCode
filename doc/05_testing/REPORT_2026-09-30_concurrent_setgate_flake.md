## 4. 偏离与如实登记

- **r2 §5.4 对改前树 U1c / U1d 的期望写错了**：r2 写「U1c / U1d / U1e 绿」，实际改前构建在 `ps` 取不到时先判 `pid_reused`、根本走不到终态与年龄判据，U1c / U1d 必红。`acceptance.mjs` 的期望按代码改正（改前与旧：U1c·d ✖），读数 18 / 18 是按改正后的期望算的。
- **旧树上 D2 第三条断言的红率比计划说的低**：r2 §5.4 写「预期大比例红」（依据探针满载 67～73 %），单进程空闲单跑实测 30 次红 6 次（r0）与 2 次（r1）——满载时持有者更慢、撞 EEXIST 后锁恰被释放更常见。结论不变（新断言对③有咬合力），只是比例按实测写。
- **`acceptance.mjs` r0 截错了失败块**：spec 报告器把失败详情放在「✖ failing tests:」汇总段之后，r0 在汇总段之前找，文案全空、红因归成「其他」；✔ / ✖ 与格判定不受影响。改后重跑为 r1（`acceptance-readout.json`），r0 留作 `acceptance-readout.r0.json`。
- **A2 背景全量第二遍红 1 条没截到用例名**：那时 `load-run.mjs` 只记失败计数；之后补了失败块截取，改后三组的背景全量两遍均 0 红。
- **`smoke-*.json`** 是探针早期冒烟（20～30 轮），分类函数当时只按单一原因标注（旧构建一轮同时有 unparsable 与 pid_reused 被标成③）；之后改为按原因组合标注，正式读数都在改后的分类下产生。
- **`mutation-names.mjs`** 原样拷自 `evidence/lock-reclaim-enoent-20260930/`，文件头注释仍写的是那个主题。
- **M3 的 desc 多写了「EV-158 相关格」**：那些用例在 `start-canonical.test.js`，不在本规格的期望套件里；实测红集见 §3.5。
- **Node 18 没有 `--test-timeout` 旗标**，`node18.txt` 不带该旗标跑（文件头已注明）。
- **Hook 误拦一次**：往 `lock.test.ts` 追加用例时用 heredoc，正文含状态文件名字面被拦；改用 Edit 工具追加，没有换写法绕判定。
