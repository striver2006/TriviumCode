## 3. 50% 线与是否上调预算/超时 —— 结论：**不上调**

r5 计划 §4.2 把「50% 这个数的依据」改成了「相对本臂实测典型值的倍数（1.5×）」。
拿到真实数据后发现这个表述本身有歧义，**如实记在这里，不掩盖**：

- **按字面读**（50% 线 = 1.5 × 中位成本 = 1.5 × $0.00876 ≈ $0.0131）：run1 的 $0.0249
  **超过**这条线——但 run1 并没有任何异常（照样一次命中 `true`/`ok`，事件数与另两次持平），
  超出只是模型输出长度带来的正常成本波动。按这个读法会把一次完全正常的成功运行标成
  "异常"，信号噪声比过高。
- **按常量注释的原意读**（探针常量注释「留一个数量级余量、兜异常不是精算」，`§4.2`
  原判定规则也是「实测成本或耗时超过**当前常量**（`--max-budget-usd 0.20` / `180s`）
  的 50%」）：50% 线是 **$0.10 / 90s**——检查的是"新臂的典型开销有没有把预算天花板的余量
  吃掉一半"，不是"这次比上次贵不贵"。三次实测（含最高的 run1）都远低于这条线
  （$0.0249 ≪ $0.10，10.855s ≪ 90s）。

**两种读法的操作结论一致**：当前 `PROBE_BUDGET_USD=0.20` / `PROBE_TIMEOUT_MS=180_000` 留有
充足余量（实测最高成本仅占预算的 12.4%，最长耗时仅占超时上限的 6%），**不需要上调**。
第二种读法更贴合常量本身「异常检测线，不是精算」的定位，也不会把正常波动误判为异常，
本报告采用它作为本次判定依据；r5 计划 §4.2 那句"50%线=1.5×典型值"的表述建议在下一次
计划性改动中改回"50%的现有常量"，避免以后按字面重跑这条判定时被 run1 这类正常波动
带偏。

**§4.2「上调的落点定为给 `execProbe`/`probeArgs` 加覆盖入参」维持代码双审第 1 轮的裁决**：
机制已建、按 CODEX-01≡AGY-01≡GLM-01 的裁决保持故意未接线——本次实测确认了"不接线"
是正确的（预算/超时都不需要上调），不是漏做。
