### 核出的两处文档与代码不符（用户拍板「文档按现状写，另立 BACKLOG」）

1. **EV-231「可粘贴配置样例」不存在**：主设计 12.1、PRD FR-27 / AC-20、QUICKSTART 文档头都写预检或 `doctor` 会给可粘贴的 provider 配置样例；代码里预检（`adapters/codex.ts` `availability()`）只点名该补的文件与 `[model_providers.〈家族〉]` 段，`doctor` 只列 profile 名单与哪些家族带得出凭据，`src/` 里没有任何样例输出。开工提示给 `.env.example` 的口径是「指向 doctor 样例」，照字面写不出来，停下来问过用户。
2. **EV-232 名单外的厂商 profile 退出码**：文档（USAGE、MANUAL、PROTOCOL、主设计 7.1 / 11.5 / 12.1）都写退 64；零配额实测预检退 **69**：

   ```
   preflight --stage plan --critics codex --profile-codex nonexist-xyz --skip-auth-check --json
   → 「只读能力可用」✗：本轮的 codex 厂商 profile「nonexist-xyz」在本机不存在。已探测到的：deepseek、glm、gpt、kimi、qwen。
   → exit_code 69
   ```

   原因是 `runPreflight` 里「只读能力可用」（`preflight.ts:1000`，退 69）排在「档位组合合法」（`:1021`，退 64）之前，而 M11 第 6 步起可用性检查也按解析出的厂商 profile 判；`review` 准备阶段顺序相反（`review.ts:809` 档位组合、`:869` 可用性），退 64。单测 `tier-resolve` F4 直接调 `checkTierCombos`，没覆盖整条预检的格序。原始输出见 `ev232-preflight-json.txt`（第三批重录，bundle 与第二批相同）。

### 剧本 9 与演进设计 §13.3 第 3 条的差异

§13.3 第 3 条原写闸门期改业务文件后「跑后 drift 留痕可见」。按现行实现，跑后漂移复算发生在审查收尾、闸门期之前，闸门期的改动不进 `snapshot.drift`，而由 `approve` 时的工作树改动摘要列出（基线 `snapshot.after_tree_hash`，EV-132 折中版）。剧本按现行实现给判据（9.4 看摘要、9.5 看 drift 仍为 false），另设可选对照 9.6（审查进行中改动才进 drift），差异写在剧本里。
