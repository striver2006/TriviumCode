# TriviumCode 稳定版部署手册

适用产品：1.2.9，macOS 与 Windows 原生。更新日期：2026-10-21。1.2.x 的网关注入、只读降级与 zcode 配置见发布包内《完整手册》增补篇或[设计说明书](../02_design/稳定版系统设计说明书.md) §7.1。本工具安装在用户目录、按项目启用，无服务器、数据库或常驻服务。

## 1. 部署前确认

| 条件 | 要求与检查 |
| --- | --- |
| 系统 | macOS（Apple Silicon 本机验证，Intel Mac/另一台 Mac 未测）或 Windows 10/11（硬前置 **Git for Windows**；进程身份/终止用系统 PowerShell 与 taskkill，无额外安装项）。Linux/WSL 未验收 |
| Node.js | 运行 ≥18，源码构建与测试用 ≥22；`node --version` |
| Git | ≥2.20；`git --version`；目标项目必须是 Git 仓库 |
| Agent | 安装需要的 Claude Code / Codex / Antigravity CLI / ZCode，并按厂商方法登录 |
| 网络与费用 | 安装包运行时无需下载 npm 依赖；真实审查和 doctor 模型探针需要供应商网络与配额 |
| 权限 | 可写自己的用户 skill 根、项目 `.trivium/` 和审查归档目录；无需 sudo |

安装包不含 Node、Git、VS Code、各家 Agent 程序、供应商 profile 或凭据。程序虽是 JS，并不代表平台无关：Linux 和 WSL 未进入支持范围，不能把复制成功当运行通过。Windows 支持自 1.1.0 起交付，边界与残余见 Bug 清单「Windows 移植残余」。

## 1a. Windows 部署要点（1.1.0 起）

- **硬前置**：Git for Windows（提供 Git 与 sh——verify 命令、Hook 守卫统一经其 sh 执行；Claude Code 在 Windows 上也以 Git Bash 执行 Hook）。无额外 PowerShell/工具安装项。
- **安装包**：`TriviumCode-<版本>-windows-x64.zip` 及同名 `.sha256`；快捷入口为 `一键安装.cmd` / `安装.cmd` / `安装前检查.cmd` / `卸载.cmd`（macOS 包的 `.command` 不适用于 Windows，反之亦然）。
- **一键安装（1.2.9 起）**：双击或终端运行包内 `一键安装.cmd`，依次完成 Git 前置检测 → 安装前检查 → 安装 → 装后版本核对 → `doctor --selftest` 14 步零配额自检（桩适配器，不调真实厂商）。任一步失败即停在对应输出上并按退出码收场（0 全过 / 1 前置缺失或读取面冲突 / 2 安装或版本核对失败 / 3 自检未全过）；检测到 `TRIVIUM_ASSET_ROOT` 时自动为安装器子进程剥离。分步手动路径见 §2.1–§2.3，保留作排查通道。
- **wrapper 双形态**：`trivium init` 在 `.trivium/bin/` 同时生成 `trivium`（sh 形态，Git Bash/Hook 用）与 `trivium.cmd`（cmd/PowerShell 用）；升级后每个项目重跑 init 刷新两者。
- **CLI 布局**：探针按 Windows 原生安装器布局查找（claude `%USERPROFILE%\.local\bin\claude.exe`、codex `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe`、agy `%LOCALAPPDATA%\agy\bin\agy.exe`、ZCode `<安装盘>\Program Files\ZCode\resources\glm\zcode.cjs`）；其它布局经 `config.local.yaml` 显式指路。
- **第三方网关（CC Switch，1.2.0 起）**：claude 与 codex 均无官方账号、走 CC Switch 时——codex 无需额外配置（鉴权在 `$CODEX_HOME`）；claude 须在 `.trivium/config.yaml` 的 `agents.claude` 段开 `settings_env_source: user_settings`，编排器会把 CC Switch 写在 `~/.claude/settings.json` env 段的网关配置经 `--settings` 内联带给每次调用（`--restricted` 忽略 settings 文件但仍认内联）。键值不落留痕；官方登录机器 env 段为空即自动无操作。模型档位须与本机 `trivium doctor --only codex` 实测目录对齐（如 qwen3.8-flash）。
- **codex 只读降级（Windows，1.2.1 起）**：codex CLI 在 Windows 上 `-s read-only` 不拦截写（上游缺口，Bug 清单 §3.1-8）。要在此前提下把 codex 用作审核者，在 `agents.codex` 段显式开 `readonly_enforcement: prompt-only`：预检以降级注记放行，补偿控制为提示语约束 + 事后轨迹/漂移核验（写入一旦检出该侧作废）。OS 级只读可用的平台（macOS/Linux）不要开启。
- **边界**：厂商 CLI 无跨进程优雅取消（取消由 worker 的 `cancel.requested` 标记 + taskkill 树杀兜底）；npm 的 `.cmd` 垫片装法支持但参数含 cmd 元字符不在面内；权限位语义降级。详见 Bug 清单 §3.1。

## 2. 从预构建安装包部署

发布包按平台出两种形态：macOS 为 `TriviumCode-<版本>-macos.tar.gz`，Windows 为 `TriviumCode-<版本>-windows-x64.zip`，各配同名 `.sha256`（当期入库条目见 [`releases/README.md`](../../releases/README.md)）。带 `-candidate` 的文件为提交前候选包，不应当成正式稳定包分发。以实际收到的文件名为准。

把包与 `.sha256` 复制到目标机（macOS 用终端，Windows 用 PowerShell；下例以 1.2.7 的实际包名为例）：

```sh
# macOS
shasum -a 256 -c TriviumCode-1.2.7-macos.tar.gz.sha256
tar -xzf TriviumCode-1.2.7-macos.tar.gz
cd TriviumCode-1.2.7-macos
node --version
git --version
```

```powershell
# Windows
Get-FileHash .\TriviumCode-1.2.7-windows-x64.zip -Algorithm SHA256   # 与 .sha256 文件内容比对
Expand-Archive .\TriviumCode-1.2.7-windows-x64.zip -DestinationPath .
cd .\TriviumCode-1.2.7-windows-x64
node --version
git --version
```

预期校验输出 `OK`。哈希只能核对传输与收到的校验文件是否一致，应从可信渠道取得安装包及校验文件。

包内关键文件：

| 文件 | 用途 |
| --- | --- |
| `dist/install.cjs` | 打包安装器 |
| `skills/dual-critic/scripts/trivium.cjs` | 打包编排器；依赖已内联 |
| `skills/` | 核心运行时资产与四家渲染入口 |
| `skills-src/carriers/` | 安装器读取的载体布局描述，必须保留 |
| `scripts/install-check.mjs` | 只读检查入口重名和历史残留 |
| `安装.command` / `安装前检查.command` / `卸载.command` | Mac 终端快捷入口，等同相应 Node 命令 |
| `安装.cmd` / `安装前检查.cmd` / `卸载.cmd` | Windows 终端快捷入口，等同相应 Node 命令 |
| `发布信息.json` / `文件校验.json` | 来源提交、构建指纹、版本和逐文件 SHA-256 |
| `第三方许可.txt` / `LICENSE` / `doc/` | 依赖许可、产品许可与手册 |

不需要 `npm install`，不需要在目标机编译。不要把运行时从包里单独抽成一个 CJS 后丢弃其他目录。

### 2.1 安装前检查

先退出正在执行的 TriviumCode 审查；不要在运行期间覆盖安装。通常使用默认路径，取消之前为源码调试设置的覆盖：

```sh
unset TRIVIUM_ASSET_ROOT
node scripts/install-check.mjs
```

退出 0 表示读取面未发现冲突；1 表示有同名入口或旧残留；2 表示产物缺失或检查出错。它不代替安装器的运行时身份与目录重叠检查，也不证明 CLI 已登录。

如果报告 `~/.agents/skills/dual-*` 等冲突，先确认是否是旧导入的本产品入口，再手动备份或迁走明确列出的路径。**不要删除整个 `~/.agents/skills`**，那里可能有其他工具。检查器和安装器不会代删。共享根中按内容认出的旧 `dual-critic` / `entry` 也会阻断安装；已改名的历史拷贝不保证检出。

### 2.2 执行安装

Windows 上推荐直接运行包内 `一键安装.cmd`（§1a，自动完成本节与 §2.1、§2.3 的全部步骤）。分步执行时：

```sh
node dist/install.cjs
```

默认对已存在家根的载体安装入口，未装的家跳过，运行时始终安装。指定部分目标：

```sh
node dist/install.cjs --targets codex
```

显式指定的目标家根不存在会失败，不会假装成功。默认目录如下：

| 内容 | 目标 |
| --- | --- |
| 共享运行时，必装 | `~/.claude/skills/dual-critic/`，即使不使用 Claude 主攻也安装 |
| Claude 7 份入口 | `~/.claude/skills/dual-*/` |
| Codex 7 份入口 | `$CODEX_HOME/skills/dual-*/`，未设时为 `~/.codex/skills/dual-*/` |
| ZCode 7 份入口 | `~/.zcode/skills/dual-*/` |
| Antigravity 7 份入口 | `~/.gemini/config/skills/dual-*/` |
| Antigravity 只读 Agent | `~/.gemini/config/agents/trivium-critic/agent.md`，其家根存在时安装 |

每家入口拍平，没有 `entry/` 嵌套子树；不向共读的 `~/.agents/skills` 安装。安装器同步自己的目录并裁剪源中已无的文件，不改各家全局登录或模型设置。运行时根非空但身份不符，或与本安装包目录重叠时拒装。

### 2.3 核对已安装程序

```sh
node ~/.claude/skills/dual-critic/scripts/trivium.cjs --version
node ~/.claude/skills/dual-critic/scripts/trivium.cjs doctor --selftest
```

版本应与所装稳定包 `发布信息.json` 的版本一致（不写死数字，随当期稳定包）；自检应为 14 步通过。自检使用桩，不调用真实厂商，不能证明登录、模型服务、实际客户端 Hook 或审查员只读能力。

## 3. 在一个新项目启用

切换到自己的 Git 项目根目录，不要在发布包目录里初始化：

```sh
cd /实际路径/你的项目
node ~/.claude/skills/dual-critic/scripts/trivium.cjs init --dry-run
node ~/.claude/skills/dual-critic/scripts/trivium.cjs init
./.trivium/bin/trivium --version
./.trivium/bin/trivium doctor --no-model-calls
```

`init` 生成/合并 `.trivium/config.yaml`、本机 wrapper、忽略规则、项目说明和登记的 Hook。支持重复执行，不覆盖用户现有 Hook。wrapper 内含 Node 绝对路径，所以目标机必须自己 init，不能照搬其他主机 `.trivium/bin/`。

共享项目策略进 Git；`config.local.yaml`、state、锁和 wrapper 不进 Git。不要复制旧主机的本机探针、认证缓存、运行目录或凭据副本。发布包不带本仓偏好的模型表，因此新项目可能与本仓选择不同。

## 4. 配置实际审核路线与验证命令

程序内置 Driver 为 Claude，默认审核者为 `gemini,glm,codex`。如果用 Codex 主攻，只选择已配置且不含 Codex 的审核者，例如 `--driver codex --critics gemini,glm`。只装一个入口不等于只需要那家审核 CLI；审核者集合决定预检所需的 CLI。

在 `.trivium/config.local.yaml` 写本机所需的非敏感覆盖，示例结构如下；CLI 入口、profile、模型名应按目标机事实填写。这个例子只演示选择，不能据此跳过探针：

```yaml
review:
  default_critics: [gemini, glm]
```

项目配置中的验证命令必须与你的项目一致；以下只适用于有相应 npm scripts 的项目：

```yaml
verify:
  build: ["npm run build"]
  test: ["npm test"]
```

不知道怎么选时先运行 `./.trivium/bin/trivium doctor --suggest-verify`，它只展示建议，不自动写配置、更不会替你决定执行任意命令。Node 运行环境可用与验证命令实际可执行是两件事。

然后只探测需要的真实审核者（会调用模型并消耗配额）：

```sh
./.trivium/bin/trivium doctor --only agy
./.trivium/bin/trivium doctor --only zcode
./.trivium/bin/trivium preflight --stage plan --driver codex --critics gemini,glm
```

`doctor --only` 用 CLI 名 `agy|zcode|codex|claude`；`--critics` 用 Agent id `gemini|glm|codex|claude`。使用厂商 profile 时需在该主机自行配置并探测实际组合；不要直接抄本仓 qwen/kimi/deepseek 等名称并假定存在。

`--no-model-calls` 只完成静态层，模型能力可能为空。预检 69 时按原因处理，不能自动跳过认证或改用别家冒充原路线通过。供应商服务、订阅或账号不具备时如实记未测。

## 5. 部署验收

按顺序核对并保存结果：版本 → 14 步桩自检 → init 及 wrapper → 静态探针 → 所选 CLI 真实探针 → 预检 → 一条正式 B/C/D 任务 → 裁决完整性 → 人工停点。最后一项的审核额度与人工批准应按实际任务安排。

Claude Code 的 Hook 需在真实客户端触发验收；ZCode 要在已信任桌面工作区核对尽力 Hook；Codex 和 Antigravity 按 L2 使用，不因目录里出现 Hook 文件就升级保护等级。

新主机尚未执行的项均记“未测”。本次交付时的验证结果见[发布检查报告](../05_testing/稳定版发布检查报告.md)。

## 6. 升级与回退

1. 保存原版本安装包、哈希、项目共享/本机配置备份，先用 `dual-status` 检查运行和闸门；不要覆盖运行中的程序。
2. 解压新包到新目录，检查 `.sha256`，执行安装前检查和安装。安装器会同步自己的运行时及入口。
3. 对每个已启用的项目重跑 `init`，刷新 wrapper 的本机 Node/运行时路径；重开相应 Agent 会话刷新 skill 列表。
4. 查版本，跑桩自检与实际需要的探针/预检。CLI 版本或路线变化不能直接复用旧组合准入证据。
5. 如需回退，用保留的旧包重装，再在每个项目 init；复核 schema 读兼容与旧配置。不能承诺旧程序读取新协议，因此回退前应有完整备份。

不要用 `TRIVIUM_ASSET_ROOT=<源码>/skills/dual-critic` 执行安装或卸载；那是调试资产覆盖，安装器会因源目标重叠拒绝。自定义运行时根属进阶部署，必须在安装、初始化、自检及后续调用中使用同一路径。

## 7. 卸载与保留数据

```sh
unset TRIVIUM_ASSET_ROOT
node dist/install.cjs --uninstall
```

卸载移除本产品的运行时、可认出的各家入口和 Agent 定义。不支持 `--uninstall --targets`。项目 `.reviews/`、`.trivium/` 和已合并的 Hook 不会自动删除；用户历史审计应先归档。

若彻底移除项目集成，应先检查本项目是否仍有开放运行，手动移除 TriviumCode Hook 条目和项目 `.trivium/`。**config 存在而 wrapper 消失时 Hook 按 fail-closed 阻断**，不能只删 wrapper；无 config 时守卫 no-op。各家配置中其他 Hook 必须保留。运行根是否含仍存活的 CLI 要先核对，不能直接整棵删除用户目录。

## 8. 常见故障

| 现象 | 检查及处理 |
| --- | --- |
| `node` 找不到 | 先安装 Node，再新开终端；GUI 仍失败则在该机重跑 init |
| CLI 版本不对 | wrapper 指向已安装副本，不是刚编译源码；重新安装并 init |
| 安装报重名/残留 | 逐路径检查与备份，迁走明确旧入口后再查，不自动强行覆盖 |
| 找不到 carriers 或 schema | 发布目录被拆散；重新解压完整安装包 |
| `69` | 阅读认证、CLI 版本、模型目录、profile 与只读能力错误；静态探测不足以通过 |
| `70` 或长期 `73` | 用 status/review --status 检查同一 run；不要启动重复审查 |
| `2` | 补齐裁决或由用户明确批准/拒绝/放弃；不要编辑 state 绕过 |
| `75` | 保存超时/失败原件，检查失败侧；不要把单侧结果称三审通过 |
| `.command` 被系统阻止 | 本版未签名/公证；核对来源和哈希后可在终端执行对应 Node 命令 |

更多运行期处置见[运维手册](./RUNBOOK_pipeline_ops.md)。Windows 原生移植和其他残余见[现存 Bug 与未完成工作清单](../08_project/现存Bug与未完成工作清单.md)。
