# TriviumCode 稳定版系统设计说明书

产品版本：1.3.0。核对日期：2026-10-24。本文按当前代码简述系统结构、数据和运行机制。1.3.0 起 macOS 与 Windows 为同一套代码，平台差异集中在 §7.1。

旧[总体与详细设计](./2026-09-10-Driver-DualCritic主攻双审流水线设计.md)、[LLD](./LLD_orchestrator.md)、演进设计及 ADR 全部保留，继续承载详细规则及历史决策；本说明书是发布版的实现导读，不建立第二套相冲突的规范。需求见[稳定版需求说明书](../01_requirements/稳定版需求说明书.md)。

## 1. 结构与边界

```text
用户与当轮 Driver
  └─ 四家载体的 7 个入口 skill（skills-src → 渲染产物）
       └─ 项目 wrapper .trivium/bin/trivium
            └─ Node CJS 编排器
                 ├─ 参数、主题、配置和预检
                 ├─ 冻结送审 → 后台 worker → 独立厂商 CLI
                 ├─ 轨迹解析与核验 → 延迟归档 → 逐条裁决闸门
                 └─ 人工审批 / 实际编译测试 / 复盘 / 清扫
```

编排器没有常驻网络服务或 Web UI，也不直接以聊天补全接口替代编程 Agent。`review --start` 派生后台工作进程，厂商 CLI 负责其模型服务连接。A 的跨阶段编排由入口 skill 指导 Driver 完成，单个 `review` 子命令只执行一次阶段审查。

## 3. 配置、路线与证据分离

加载优先级：内置默认 → 项目 `config.yaml` → 本机 `config.local.yaml` → 单次命令覆盖。`probe:` 由 doctor 保存，不能复制其他机器的结论冒充本机实测。某些段有整段替换语义，尤其是 `agents.<id>.tiers`；不是所有映射都逐键深合并。

`--profile` 是项目模型表；`--profile-<id>` 是厂商配置分层；`--tier-<id>` 是该侧 low/medium/high 档。`--native-<id>` 显式原生路线，同侧不能再给厂商 profile。切路线不会自动换模型；失败不悄悄切回别家。可用模型及 effort 枚举从探针读取。

每轮分别记录请求路线、配置声明及实际回读。Driver 模型仅取本轮声明；缺省、未知和无回读保留 unknown/null。模型族逐对比较，同族与未知只告警；不是“异构性必定成立”的证明。`model_override_applied` 缺席与 null 含义不同，不补齐成看似完整的证据。

`run.v3` 用于新审查，v1/v2 历史形状只读兼容；config.v2、review.v2（EV-247 起三档结论；历史 review.v1 只读兼容，判「是不是审查件」两版都认）、disposition.v1 与 verify 契约各自版本独立。产品 1.0.0 不代表把协议都升成 v1。Schema 先校形状，再经注册表校身份；当轮作者语义在 gate 校验。

## 5. 一次审查的执行链

1. 入口解析任务原文、焦点、阶段、选侧和模型；plan/bug 先 claim，再由 Driver 写自己的原稿。
2. preflight 核对环境、配置、探针、选定路线与认证。默认集合不自动去掉 Driver，冲突按参数错误拒绝。
3. 锁定主题，冻结 Git tree、diff、必读/禁读与请求路线；使用临时索引，不污染用户暂存区。
4. start 派生 worker 并返回 run_id/max_waits/bash_timeout_ms；wait 一次窗口未完退 73，继续同一 run。
5. 入选侧并发启动独立厂商 CLI。输出先留项目外，完成后再归档。轨迹按能力核验；作废类只重跑该侧一次，首次输出留在 `voided/`，其他侧不重跑。
6. 重新核对工作树漂移、禁读和写事件，解析 review；记录证据不足、失败、作废及降级，不能把进程 exit 0 等同有效审查。
7. archive 独占创建并自动抬升 rN；Driver 对每条意见写裁决，gate 对差集、role、共同 blocker、工件完整性等核对。
8. 计划与代码阶段按侧计票（EV-247）：审核者三档结论中不通过占半数及以上判不通过，否则修改后通过占半数及以上判修改后通过，否则通过占半数及以上判通过，都不到半数判修改后通过；失败、回退、作废的侧不计票。结论与轮次链（第几轮、最多几轮，缺省 3、上限 10）记入 run.json。gate 校验通过后按下一步分流：不通过且有余轮回 idle，由 Driver 改计划（每轮写完整新计划）或改代码后续轮；到上限仍不通过或无有效票立审批停点（命令 A 也停）。
9. B/C/D 在循环结束的那一轮到审批停点，用户明确决定后 approve 再次复核并记账；A 继续到实际 build/test。report 只读既有归档。

## 6. 状态与恢复

运行状态与闸门状态分别维护，取消运行、放弃闸门、拒绝审批是不同动作。状态转移受预期 run_id 约束，避免旧进程覆盖新一轮。审批前工作树摘要只告知，不替用户决定。

超时由 Node 控制。macOS 先 SIGTERM、宽限后 SIGKILL，按进程组发信号；Windows 的终止阶梯与进程身份按 §7.1 的原生模型实现（`taskkill /T` 软硬两步 + 取消标记文件），厂商 CLI 在 Windows 不承诺优雅收尾。PID 身份在 macOS 用规范化 `ps lstart` 核验，在 Windows 用 WMI CreationDate（UTC ISO）；无法确认存活/已退出时不猜测。CLI 记录在 macOS 按进程组（PGID）、在 Windows 按父链后代集合支持取消和遗留回收；派生到记录之间等窗口仍有边界。不要仅按 PID 手动杀进程或删状态文件“解锁”。

状态文件全局锁、主题运行锁及审批记账分别处理；增量计数写唯一文件后统计数量，不做并发读改写。凭据脱敏与到期整删分别有准入条件；只在回到对应项目会话或显式清扫时触发的部分不是后台定时任务。

## 7. 安全边界与平台设计

| 机制 | 保证及限制 |
| --- | --- |
| L1/L2 | Claude L1；ZCode L2 尽力 Hook；Codex/Antigravity L2。审批期 L2 业务写不靠 Hook 兜底 |
| 独立性 | 独立会话、延迟落盘、历史禁读与轨迹检测；不构造硬隔离镜像，不抵御恶意读取者 |
| 命令检测 | Shell 命令按已知文法识别；引用字符串、解释器、特殊重定向等仍有漏/误报，详见 Bug 清单 |
| 工件 | O_EXCL 防覆盖、hash/清单复核；不是操作系统级不可篡改存储 |
| 安装 | 检测共享读取面重名及历史残留，安装拒绝；doctor/preflight/start 仅提示，不自动移动用户文件 |
| 平台 | macOS：POSIX wrapper、BSD/macOS 工具及厂商布局。Windows：原生进程模型（§7.1）、Git for Windows 硬前置、`.cmd` 入口 wrapper。Linux/WSL 未验收 |

### 7.1 Windows 平台模型

**进程身份。** `util/platform.ts` 是平台差异的唯一落点之一：`enumerateProcesses()` 以一条 PowerShell（`Get-CimInstance Win32_Process`）取全量 `pid,ppid,CreationDate`，结果按 ~400 ms TTL 缓存（实测单查与全量枚举同价约 0.7–0.9 s，终止轮询不得每拍新起一个 PowerShell）。在飞枚举有单飞去重，`fresh` 请求（缓存命中但 pid 缺席时的强制重枚举，1.2.6）的搭车判据是**启程时刻**（1.2.8）：在飞那趟启程不早于本次请求 ⇒ 它拍的表对本请求已是新表，直接搭（两形态并发取值共享一趟是缺省时序）；启程更早的那趟可能拍在关注进程派生之前——等它落地后自起一趟。规范化启动时刻在 Windows 写 CreationDate 的 UTC ISO 形态（`yyyy-MM-ddTHH:mm:ss.ffffffZ`，显式格式化、与环境无关）；盘上字段名与 macOS 复用同一组，两形态互斥、读侧对**异平台形态**（跨平台共享 checkout 的场景）一律判 `unverifiable`、不按「不同一进程」处置（`isNativeCanonicalStartForm`，1.2.2）；macOS 的 `ps lstart` 形态逐字不变。枚举失败（超时/报错/解析为空）只回退**显式龄期内**（数秒）的缓存，超龄视同失败返回 null——无龄期的陈旧旧表是另一种猜（1.2.2）。

**组员判定。** macOS 的 `ps -axo pgid=,stat=` 在 Windows 无对应物。等价判据：以全量枚举建 `pid→ppid` 父链图，从记录的组长 pid 沿后代 BFS 计数仍在表的进程——覆盖原进程组语义（组长其后代即原组员），且覆盖 EV-163/168 记录过的孙辈盲区。组长退出后子进程的 PPID 残留仍指向它，与 POSIX 组号语义同样可判「组长已退、组员仍在」；枚举失败返回 null（`unverifiable`，不去猜）。

**终止阶梯。** `killProcessTree` 在 Windows 分派 `taskkill`：SIGTERM 位映射 `taskkill /PID <pid> /T`（WM_CLOSE，控制台进程常无效——如实保留），SIGKILL 位映射 `/T /F`。worker 活着时 detached 子进程父链完整，`taskkill /T` 连带清理；此为硬步兜底，不承诺厂商 CLI 自行收尾。

**worker 优雅取消。** Windows 跨进程发不出可捕获 SIGTERM（TerminateProcess 即强杀）。`run-files.ts` 登记 `cancel.requested` 运行目录文件：`--cancel` 在软步之前写标记；worker 的取消处理器主体抽为 `beginWorkerShutdown`，POSIX 仍由 SIGTERM 触发，Windows 另装 250 ms 轮询 watcher 读标记触发，随后走同一条 `shutdownTrackedTrees` 路径并按 143 退出。watcher 只认**不早于（安装时刻 − 15 s 回退量）**的标记：回退量覆盖 spawn→安装窗口（派生失败收尾、极快 `--cancel` 落在窗口内的标记不再被吞）与 FAT/exFAT 的 2 秒级 mtime 粒度；被判陈旧的标记留一条 worker 日志痕迹（1.2.2）。我方凭据抹除由 worker 代码执行，受此路径保护；错过优雅收尾而被硬杀时，凭据副本依赖运行根保留期整删兜底（残余见 Bug 清单 §3.1）。不依赖厂商 CLI 的优雅收尾。

**--start 补写与终态次序。** `--start` 派生 worker 后要补写身份（pid 与两种启动时刻，取值经进程表枚举、满载下可上秒级）并把 `phase` 置 `running`——而 worker 可能先于补写完成整轮（桩侧实测 ~1.3 s）。补写**只加身份字段，`phase` 已终态不再改回 running**（1.2.8 实测竞态修复）：否则刚完成的运行被 `--wait` 按「running + 进程已退」误判 `worker_lost（pid_gone）`，归档已是 success 仍整轮判败。

**路径域。** 项目相对路径的**匹配域与落盘域恒用 `/`**：win32 的 `path.relative` 产出反斜杠，`matchesAnyGlob` 匹配前先归一，禁读条目输出侧另由 `toDomainRel` 归一落盘形态。归一必须落在**匹配输入侧**——只归一输出救不了「什么进禁读集」的判定；带目录段的 glob（`**/*.pem`、`calls/**`）由此两平台同配，根级 `**/*-<id>.md` 不再依赖 `[^/]*` 吃掉反斜杠的侥幸成立（1.1.0 漏此侧归一，1.1.1 修复，见 Bug 清单 §5）。归一对真实路径输入（git 产出、`path.relative` 产物）两平台零变化；POSIX 文件名字面反斜杠属理论差异、不触发。链接语义：两平台**均不做**链接展开——与「不承诺抵御蓄意规避」的既有边界同族；POSIX 分支的 `/private` 前缀解析逐字保留、win32 无此概念。

**第三方网关（CC Switch 支撑，1.2.0）。** `--restricted` 按官方语义忽略 user/project/local settings 文件，而 CC Switch 把网关配置写在用户级 `~/.claude/settings.json` 的 env 段——受限模式一开即回落官方端点报「未登录」。通道取 claude 子进程的**环境变量**（1.3.2 起，EV-256；受限模式认进程环境变量，2026-10-24 win32 实测）：`agents.claude.settings_env_source: user_settings` 开启后，路线解析时读该 env 段（只收 `ANTHROPIC_`/`CLAUDE_` 前缀的非空字符串值），每次带模型调用的子进程经唯一注入函数 `claudeInvocationEnv` 拿环境补丁——**先**展开 `claudeRouteEnv` 的清除补丁（父进程 `ANTHROPIC_*` 等置空，隔离不变），**后**展开提取出的网关键，同名键网关值胜出；`invokeClaude`（审查调用、探活、目录臂）与探针 `routeInvocation`（各探针臂、记忆两臂、verbose 阴性对照）各调一次，`--version` / `--help` 不注入。`--settings` 只装 `permissions.deny`。1.2.0～1.3.1 曾经 `mergeSettingsEnv` 把网关键并进 `--settings` 内联载荷，键值因此出现在进程命令行里（Bug 清单 §3.1 第 14 条，已修）。安全边界：键值不进命令行，凭据类键值不落任何留痕——路线指纹只记 sha256，`invokeClaude` 与探针臂对 commandLine 与输出做**原串逐值替换** `<redacted-env>` 后再过模式脱敏。模型名键的值不进替换集（1.3.2 起，EV-257）：CC Switch 网关在 `system/init` 回报的模型名恰等于这些键的值，一并替换会把回读吞成占位符；豁免要同时过键名（`(ANTHROPIC|CLAUDE)_…MODEL[_NAME]`、不含凭据词、区分大小写）、值不命中模式脱敏、不与凭据同值、长得像模型名四道守卫（`gatewayScrubPlan`），否则照旧替换；回读侧另有独立兜底，`init.model` 带脱敏痕迹即记 null 与 `unverified`（`claudeModelReadback`）；剩下的暴露面是子进程环境块（同用户进程可读）；截断/折行/再编码形态的泄漏面不在原串替换射程内，与既有模式脱敏口径同一、登记为残余；官方登录机器上 env 段为空即自动无操作。codex 侧无此问题（鉴权在 `$CODEX_HOME`，与 settings 文件无关）。

**只读降级（prompt-only，1.2.1，Windows 线）。** codex CLI 在 Windows 上 `-s read-only` 不拦截 shell 写（上游缺口，Bug 清单 §3.1-8）。`agents.codex.readonly_enforcement: prompt-only` 是对该缺口的**显式取舍**：负对照失败时探针保留 `-s read-only` 旗标（该旗标本身让 CLI 在提示层面声明只读）并记 `readonly_enforced: false`（执法结论独立成字段，不塌缩进旗标空集），`availability()` 以降级注记放行、预检的「只读能力可用」一格带注记通过。补偿控制全开不动：BRIEF 既有只读措辞（写即失守、跑后复算检出整轮作废）+ 事后轨迹写事件核验 + 漂移复算——即防线从「事前阻止」换为「事后必查」，写入一旦检出该侧作废。缺省 `required` 行为逐字不变（fail-closed）；该配置不应在 OS 级只读可用的平台上开启。

**shell 与 wrapper。** `resolvePosixShell()` 在 Windows 定位 sh.exe：`where sh` → 由 `git --exec-path` 上溯 `<git-root>\usr\bin\sh.exe`（兼容 mingw64/ucrt64 布局）→ 常见安装路径，结果缓存；找不到时报「需要 Git for Windows」。verify 命令、verify 探针与 Hook 守卫统一经它取 sh；`trivium init` 在 Windows 同时写 `bin/trivium`（sh 形态，内容与 macOS 相同）与 `bin/trivium.cmd`（`@echo off` + node 绝对路径，CRLF），`checkWrapper` 按平台校验。

**探针与发布。** 四家探针的候选表按平台分派：Windows 补 `%USERPROFILE%\.local\bin\claude.exe`、`%LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe`、`%LOCALAPPDATA%\agy\bin\agy.exe`、`%ProgramFiles%`\`ZCode\resources\glm\zcode.cjs` 等实测布局，`which` 兜底换 `where`；隔离环境同步重定向 `USERPROFILE`（与 HOME 并设）。发布链按构建主机平台出包：Windows 为 `TriviumCode-x.y.z-windows-x64.zip` + `.cmd` 快捷入口，`发布信息.json` 记 `platform: 'windows'`；macOS 仍为 tar.gz + `.command`，形态不变。

**doctor 时限（EV-251）的 Windows 实现（1.3.0）。** 段内派生登记组时多记派生时刻；组长退出后按「父 pid 等于组号、创建不早于派生时刻」认本组孤儿后代，表里还有同号进程判复用、不发信号；结束时组长在就树杀组长，组长已退就逐个树杀孤儿直接子进程。信号只接得到 Ctrl+C 与 Ctrl+Break，跨进程 SIGTERM 即强杀，靠进程内计时器到点自收尾。临时目录台账加记启动时刻，pid 被复用的旧台账也能补删。给用户在终端执行的重跑命令是 `.\.trivium\bin\trivium.cmd …`。详见主设计 8.1 末段（v1.3.175）。

**归档登记路径（1.3.0）。** `run.json.artifacts[].path` 一律落 `/` 形态；早先在 Windows 上登记的反斜杠路径读取时归一成 `/`（盘上原件不改），同一份归档在两个平台上都能过提交锚的核对。

**如实边界。** 厂商 CLI 无跨进程优雅取消；身份判定吞吐低于 macOS（PowerShell 单查 ~0.7 s，靠枚举缓存缓解）；`.cmd` 垫片装法的 CLI 不在首选候选（原生 .exe 优先）；chmod 权限位在 NTFS 无对应语义（凭据副本的 0600 降级为只置只读位，靠运行根在用户目录下的隔离）；agy 的 pty 依赖在 Windows 以实测结论为准（管道不丢输出则免 pty，丢则试 Git for Windows 自带的 winpty，再不行如实报该侧不可用）。

## 8. 构建与发布

`scripts/build.mjs` 以 esbuild 内联 yaml/ajv 等依赖，分别产生 CLI 与安装器，target=node18、charset=utf8；测试逐文件转译为 Node 22 ESM。构建嵌入来源提交、作用面指纹、dirty 与时间。

`scripts/package-release.mjs` 从白名单按构建主机平台生成分发包（macOS 为 tar.gz + `.command` 快捷入口，Windows 为 zip + `.cmd` 快捷入口，Linux 拒绝）：运行时、四家入口、安装器必读的 `skills-src/carriers`、安装前检查、许可和文档。包内 `文件校验.json` 及包外 `.sha256` 可验证传输。发布元数据另存 CLI 哈希、`platform` 和打包时的 `source_snapshot`；`computed_at` 是来源复算时刻，二进制自身仍嵌入实际构建标识。正式包要求干净工作树并校验 CLI 版本与构建输入指纹；未提交内容只允许生成明确标注 candidate 的包。包不含 `.trivium`、`.reviews`、测试原始证据、源码、账号目录或 node_modules。产品本身不自更新。
