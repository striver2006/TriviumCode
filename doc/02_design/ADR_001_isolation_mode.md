# ADR-001: 审查员隔离模式采用就地审查（in-place），不构造冻结镜像树

> - **日期**：2026-09-11
> - **状态**：Accepted(通过)
> - **决策者**：Chen Zhenbo（项目负责人，评审意见 UR-03 / UR-06）；Claude Code 起草
> - **关联需求/问题**：PRD FR-07（审查工作目录与可读范围）、FR-10（背靠背隔离）、FR-15（审查员只读）、FR-16（送审自包含）；设计文档 AD-05、第 10 章；审核意见 RV-02

---

## 1. 上下文与问题陈述 (Context)

PRD FR-07 规定：审查 Agent 执行时的根目录为**所在项目根目录**，除另一个审查 Agent 生成的文件外可读取整个项目。FR-10 规定两位审查员互相不能看到对方输出。两条需求叠加产生一个工程问题：对方的审查文件会落在项目内的归档目录 `.reviews/`，如何在「cwd 就是项目根、全库可读」的前提下让审查员看不到它们。

设计 v1.0.0～v1.1.0 的做法是构造**冻结镜像树**（`mirror`）：用 `git archive` 把工作树解包到两份独立目录，构树时物理剔除对方的 `*-gemini.md` / `*-glm.md`，再 `chmod -R a-w`，审查员以镜像树为 cwd。审核意见 RV-02 指出这与 FR-07 字面冲突且代价未论证；v1.1.0 把 `in-place` 规格化为完整备选，默认值留待 M0 实测拍板。

2026-09-11 项目负责人明确要求：审核内容直接就地，不弄镜像；隔离靠访问项目根目录加提示语屏蔽对方输出。本 ADR 记录该决策及其机制性兜底。

---

## 2. 备选方案评估 (Considered Options)

- **方案 A：冻结镜像树（`mirror`）**
  - 优点：对方历史产出可被物理剔除，AC-04 机械成立；整树可 `chmod a-w`，只读有文件系统层保障；审查期间仓库漂移不影响本次结论。
  - 缺点 / 代价：镜像树不含 `.git`，审查员失去 `git log/blame/diff` 与追溯引入提交的能力；构树尊重 `.gitignore`，`node_modules/`、`.venv/` 等依赖缺席，需 `link_globs` 以符号链接带入并另做探针；每次运行两份拷贝，大仓库有时间与磁盘成本；与 PRD FR-07「根目录为所在项目根目录」字面不符，需回填 PRD；引入 `isolation.cost` 探针与 `_review/` 目录等额外概念。
- **方案 B：就地审查（`in-place`），仅靠提示语屏蔽**
  - 优点：与 FR-07 字面一致；`.git`、依赖、构建产物全部在场，能力无损；零拷贝、零构树时间；实现最简单。
  - 缺点 / 代价：「请不要读对方文件」可被模型忽略，泄漏不可检出；整树无法只读，审查员写入只能事后发现；审查期间开发者手改文件会造成结论与快照不一致。
- **方案 C：就地审查 + 三层屏蔽 + 漂移检测（本 ADR 采纳）**
  - 在方案 B 之上叠加：①本次对方结论延迟落盘且运行目录放在项目外（审查中在项目树内物理不存在，无需提示语）；②对方历史产出（同主题重跑）三层屏蔽——BRIEF 逐个列出禁读路径、探针证明厂商 CLI 支持路径级 deny 时自动注入、事后扫描工具轨迹命中即该侧作废重跑；③只读改为工具层禁写 + 前后 `tree_hash` / `git status` 指纹 + 轨迹写事件扫描；④送审前后复算快照，被审对象被改则整次作废，相关文件被改默认失败，无关文件警告并列出。
  - 优点：保留方案 B 的全部收益；泄漏与失守均可检出；轨迹核验零额外成本（轨迹本就为 AC-05 采集）。
  - 缺点 / 代价：历史产出的屏蔽是「事前提示 + 视厂商能力的 deny + 事后核验」，不是文件系统级事前阻断；需新增 `path_deny`、`scratch_paths` 两组探针；漂移只能检出不能阻止开发者手改。

---

## 3. 决策结果 (Decision Outcome)

我们决定采用 **方案 C：就地审查（`in-place`）为唯一隔离模式，配三层屏蔽与漂移检测**，原因如下：

1. 项目负责人明确裁决就地、不做镜像（UR-03），且该裁决与 PRD FR-07 字面完全一致，不再需要回填需求。
2. 需要屏蔽的对方产出经分析只有两类：**本次**结论可用延迟落盘 + 项目外运行目录做到物理不存在；**历史**产出（仅在同主题重跑时存在）泄露的是上一轮、已被 Driver 裁决过的意见，污染有限，用三层屏蔽把它降到可接受置信度，代价远低于镜像树。
3. 镜像树的核心代价（无 `.git`、依赖缺席）直接削弱审查深度，与 UR-01「结合整个项目评审」的要求相悖；就地模式让 `git log/blame`、依赖类型解析、只读命令全部可用。
4. 只读保障从「文件系统 + 工具层 + 指纹」退化为「工具层 + 指纹 + 轨迹」，但主仓库被写入仍可检出并中止（FR-15 / AC-08 不变）。

`mirror` 模式及其配套（`link_globs`、`exclude_globs`、`isolation.cost` 探针、`_review/` 目录、`cp -c` 复制）从设计中删除，不保留为配置项。

---

## 4. 后续影响与风险应对 (Consequences)

- **正面影响**：PRD FR-07 无需回填；`freeze` 模块从「构树」简化为「算哈希 + 生成清单」；审查员能力无损；无磁盘与构树开销；运行目录统一在 `~/.trivium/runs/`，项目内 `.trivium/` 只剩配置与状态。
- **负面影响 / 妥协点**：
  - 历史产出泄漏依赖提示语被遵守、厂商路径 deny 能力、事后轨迹核验三者叠加，无法做到事前物理阻断（设计 10.2「诚实边界」）。
  - 审查期间开发者手改文件会造成漂移，只能检出；Driver 自身在 `running` 期间由 Hook 禁写。
  - 两家 Agent 可能在项目根留下会话缓存等临时文件，需探针白名单，否则误判只读失守。
- **应对策略**：
  - `run.json.guard.peer_deny_applied` 逐侧记录路径 deny 是否生效；不可用时的降级策略列入设计 18.1 #12。
  - 轨迹核验命中 → 该侧作废重跑一次（BRIEF 追加更醒目禁读提示）→ 二次命中 `failed(peer_leak)`，strict 下整次中止。
  - 漂移策略可配置（`review.on_drift` / `on_drift_related`），默认无关文件 warn、相关文件 fail、被审对象 fail；命令输出与 `--start` 均提示「审查中请勿改动被审对象与相关文件」。
  - M0 探针新增 `agy.path_deny`、`zcode.path_deny`、`agy.scratch_paths`、`zcode.scratch_paths`；M3 验收 AC-04 / AC-08 / AC-17 按设计 15.3 更新后的方式验证。
  - 若后续实测显示历史产出泄漏率不可接受，重开本 ADR，备选是在同主题重跑时把对方历史文件临时移至项目外（仍不是镜像树），届时另立 ADR 评估。
