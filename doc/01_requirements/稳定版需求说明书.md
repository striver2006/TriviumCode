# TriviumCode 稳定版需求说明书

产品版本：1.3.0。核对日期：2026-10-24。本文是依据当前实现建立的发布基线，描述本版承诺；不把历史计划或厂商模型的偶然行为写成产品保证。1.1.0 在 1.0.0 基线上新增 Windows 原生支持；1.2.x 新增第三方网关（CC Switch）支撑与 codex 只读降级（Windows 线），行为承诺细节以[稳定版系统设计说明书](../02_design/稳定版系统设计说明书.md) §7.1 为准，其余承诺不变。1.3.0 起 macOS 与 Windows 为同一套代码：多轮评审循环与三档结论（EV-247）、预检失败自动校准（EV-251/252）与 Windows 原生支持两个平台都有，平台差异只在进程控制、路径与入口形态上分别实现。

旧[需求文档](./PRD_driver_dual_critic.md)与[原始需求](./原始需求.txt)保留，原 FR/AC 编号及验收边界继续有效。后续修改仍按既有主设计、协议与评审流程执行，本文不另设审批规则。

## 1. 目标与适用范围

面向在 macOS 与 Windows 上使用编程 Agent 的开发者，将起草、独立审查、逐条裁决、人工批准、编译测试与复盘组织为可核验的流程。确定性步骤由本地编排器执行；代码和裁决由当轮唯一 Driver 编写；审核者只读。

本版交付 Node.js CJS 编排器、安装器、四家载体入口、运行时资产和中文手册。运行不需要 npm 依赖目录。支持平台为 macOS 与 Windows 原生：Windows 以 Git for Windows 为硬前置（Git 本就是硬依赖，sh 语义、verify 命令与 Hook 守卫统一走其自带的 sh；另提供 `.cmd` 入口 wrapper），进程身份与终止用系统自带的 PowerShell/WMI 与 `taskkill` 实现。Linux、WSL 不在支持承诺内。Mac 跨架构兼容性及新主机验收情况见[发布检查报告](../05_testing/稳定版发布检查报告.md)。

## 2. 角色和流程

| 角色 | 本版行为 |
| --- | --- |
| 用户 | 决定任务范围，批准或拒绝 B/C/D 停点；管理厂商登录、模型服务和配额 |
| Driver | 可选 Claude Code、Codex、Antigravity、ZCode；唯一修改业务代码者；逐条裁决意见 |
| 审核者 | 从已启用的 Agent 中选 1～3 家，不能包含当轮 Driver；独立进程、只读审查 |
| 编排器 | 预检、送审冻结、调度、解析、归档、完整性核对、闸门、验证与状态恢复 |

产品内置 Driver 缺省为 Claude Code；内置审核集合为 Gemini/Antigravity、GLM/ZCode、Codex。本仓开发约定由 Codex 主攻、共享配置选择 Claude/Gemini/GLM，这是项目配置，不是产品缺省。默认集合不会自动剔除 Driver；换 Driver 应同时指定不含自己的审核者。

| 入口 | 需求 | 完成边界 |
| --- | --- | --- |
| A `dual-run` | 方案→多轮计划审查与修订→编码→多轮代码审查、应答与改码→真实编译测试 | 由 skill 驱动完整链路，不能用审查通过替代测试成功；评审循环到上限仍不通过时停下人工审核 |
| B `dual-review-plan` | 多轮审查已有计划，逐条修订并每轮输出完整新计划 | 循环结束后到人工审批停点，不自动编码 |
| C `dual-review-code` | 多轮审查已有代码差异，逐条应答并按接受项改码 | 循环结束后到人工审批停点（审批的是已改好的代码），不自动合入 |
| D `dual-review-bug` | 审查已有根因材料，形成修订结论 | 到人工审批停点，不自动修复 |
| 辅助 | `dual-status` / `dual-approve` / `dual-abandon` | 查询、明确人工决定、保留工件的放弃 |

## 4. 非功能需求与限制

- 运行依赖 Node.js ≥18、Git ≥2.20，开发及测试使用 Node.js ≥22。Windows 上硬前置为 Git for Windows（sh、verify 命令与 Hook 守卫的执行载体），并使用系统自带的 PowerShell（进程身份/终止）与 `taskkill`；无额外安装项。外部 CLI 版本、认证和模型可用性属于目标机事实，安装包不携带。
- 运行时与安装器分别打成零 npm 依赖 CJS；schema、提示词、镜头、Hook 及入口资产仍须随包分发，不能只复制 CLI 单文件。
- 审查在真实工作树中进行，非强沙箱。原始输出在项目树外；归档只追加、防覆盖并记录 hash。不能据此承诺抵御蓄意规避。
- Claude Code 为 L1；ZCode 为 L2（尽力 Hook）；Codex、Antigravity 为 L2。L2 不能保证审批期业务写入事前拦截，使用者必须遵守停点。
- 密钥扫描和脱敏是有限检测；不接管登录、不改全局模型配置、不把未知身份写成确定身份。运行副本的清扫受存活判定与保留策略限制。
- **第三方网关（1.2.0，Windows 线）**：claude 无官方账号、经 CC Switch 一类网关接入时，网关配置经 claude 子进程的环境变量注入（1.3.2 起，EV-256；1.2.0～1.3.1 经 `--settings` 内联载荷、键值会出现在进程命令行里），键值不进命令行、不落任何留痕（指纹仅 sha256、输出逐值脱敏；截断/折行形态的泄漏面与既有脱敏口径同残）。官方登录机器自动无操作。
- **codex 只读降级（1.2.1，Windows 线）**：上游 `-s read-only` 在 Windows 不拦截写时，可显式配置 `readonly_enforcement: prompt-only` 以「提示语约束 + 事后轨迹/漂移核验」放行（降级注记入留痕，写入检出该侧作废）；前提是探针旗标已落盘。OS 级只读可用的平台（macOS/Linux）不应开启。
- 超时、重试、严格/部分失败策略由配置控制。端到端耗时取决于最慢审核者与供应商，不承诺固定秒数或成功率。
- 输出 SHA-256、文件清单和源码来源；未提供 Apple 签名、公证或自带 Node 的独立 App。

## 5. 验收与已知边界

稳定发布检查包括类型检查、构建、全量自动化、包文件校验、隔离家目录安装/升级/卸载、28 份入口比对和 14 步桩自检，macOS 与 Windows 各自在本平台执行并记入[发布检查报告](../05_testing/稳定版发布检查报告.md)。Windows 原生支持按[现存 Bug 与未完成工作清单](../08_project/现存Bug与未完成工作清单.md) §3 的完成条件于 1.1.0 交付；厂商 CLI 在 Windows 无跨进程优雅取消等平台边界如实登记。真实厂商审查、真实客户端 Hook、新 Mac/新 Windows 主机和 Intel Mac 未在本次执行的项目均明确写“未测”。

M11/M12 已按各自报告及用户确认的边界收口，不等于所有历史 Bug 已清零。受限 Claude 组合的“工具面未注册”和“受控请求拒绝”不得代替真实模型写尝试；历史七组合通过也不迁移到新指纹。本版保留[现存 Bug 与未完成工作](../08_project/现存Bug与未完成工作清单.md)，不扩大历史证据的有效范围。
