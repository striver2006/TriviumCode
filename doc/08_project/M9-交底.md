## 4. 适配器怎么写：已经定好了，别再自己推

设计 **§11.1「旗标归属判据」** 与 **§3.7.1「M9 调用形态与旗标来源分工」**
已经把每一段 argv 的来源逐条钉死。两条最要紧的：

- **按 `adapters/codex.ts` 的纯透传形态写，不是按 zcode 写。** claude 的
  `readonly_flags` 装的是**可直接使用的 argv 片段**，与 codex 同族；zcode 那份是
  「候选串的接受记录」，才需要取旗标名、值另给全集常量（判据二）。
- **安全不变量一律从探针取，不得字面重建。** `--restricted` /
  `--strict-mcp-config` / `--tools` / `Read,Grep,Glob` 出现在 `adapters/` 里
  会被 `registry-parity` 第 6 条当场打红——**那是刻意的，不要去改测试**。
  漏掉 `--strict-mcp-config` 会让用户已连接的 MCP 写工具（发信、云盘创建与共享）
  进入审查会话工具面，那是能越出项目边界的失守面，且单次成本约 **24 倍**。

**演进设计 §7.2 的调用模板已作废**，照抄会当场失守——它缺两个安全不变量、
写 `--allowed-tools`（实测被接受的是 `--tools`）、`--json-schema` 传文件路径
（实测被拒，有报错样本）。该文正文自 v1.0.0 起冻结，**一律以主设计 §3.7.1 为准**。

**另有一条契约**：`adapters/` 不得 import `probes/`（`registry-parity` 第 5 条）。
探针的参数构造带着探针尺度的默认值（成本闸门按单次 $0.008 留余量、模型挑最便宜一档），
审查任务要读整份 BRIEF 与 diff，逐字复用会被 CLI 当场掐断。

## 6. 工作纪律

仓库根 `CLAUDE.md` 的双审流水线协议全部适用。特别注意：

- 实现可自主推进，但**提交前必须走完代码双审与审批，且两者都由用户发起**
  （四条 skill 标了 `disable-model-invocation`，你调不动，也不得自行跑 `trivium approve`）。
- **验证前必须 `npm run install:local`**——wrapper 指向全局副本，不装就验的是旧代码。
- Bash 侧 Hook 按字面拦：命令文本出现保护路径字样（编排器独占的那几个文件名、
  审查文档的角色后缀）且命令**像**写命令（`rm`/`cp`/`ln`/`install`/`chmod` 等词、
  重定向、heredoc）就会被拦。**出口是改用 Write / Edit 工具落文件、提交用
  `git commit -F <文件>`，不要绕判定。**
- 审查焦点措辞要避开那一串写动词字面。**`install` 尤其容易踩**——
  想提「`install:local` 那步」时很自然就写上了，换成「装到全局副本那步」。

## 附：EV-12 那两轮双审留下的一条方法论

M9 会大量涉及「同一份事实散落多处」的问题（探针结论、设计表格、适配层实现、
实测报告）。EV-12 结案时把一条教训写进了设计 §11.1 判据三，抄录于此：

> 落点清单**由 `grep` 生成，不手写**——但**锚点集本身也是手写清单**。
> 「改用 grep」只把记性从**落点**挪到了**措辞**。所以复跑时必须做一次
> **广撒网的差集自检**并轮换措辞；只跑列出的那几条锚点就宣布「清单由 grep 生成」，
> 与手写清单是同一种自欺。
>
> 这不是假想：EV-12 补第三锚点时第一版写「由/从探针结论**构造**」，
> 差集自检当场查出**那一轮自己改写出的 `README.md` 新文本仍然逃网**
> （实际措辞是「从探针结论**取**」）。**锚点第一次写对的概率不高，
> 差集自检才是那道真闸门。**

同族的还有一条，在 BACKLOG EV-39 里：**契约测试误伤时，正确处置是加具名豁免，
不是删黑名单条目。** 后者更省事，也更容易，而它削弱的正是守卫本身。
