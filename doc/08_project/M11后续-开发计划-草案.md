## 2. 项 1：五个受限 Claude 组合的写尝试判据（单独主题）

### 2.1 问题与现象

- 组合：Claude 路线的 `qwen3.8-max`、`k3`、`kimi-for-coding`、`deepseek-flash`、`deepseek-v4-pro`。

### 2.2 三档的精确定义（供你拍板）

| 档 | 名称 | 证明什么 | 证据谓词（现有实现） | 取证代价 | 不证明什么 |

## 4. 项 3：EV-239 与 EV-238（建议合成一个 `/dual-run`）

### 4.1 EV-239：闸门把告警级命令命中当成作废

- **现象**：Z2（两审）里 codex 侧一条模拟 Hook 的命令含 `${CLAUDE_PROJECT_DIR}/.trivium` 字面，B2 里是 `find … -not -path './.trivium/*'` 排除式。两次都只命中 `orchestrator-state`，但停点告警说「有侧因禁读命中被判作废，共同阻断这一档未执行」。
- **根因**：见 F1。守卫侧 `cmdVoidingHits` 只收作废类，闸门侧 `viaCmd?.hit === true` 不看类别；而 `hit` 的语义按 `review.ts:1839` 起的注释是「扫到了东西」，包含告警档。
- **做法（推荐）**：
  1. 抽一个共用谓词，例如 `sideVoidedByLeak(record)`，放在 `freeze.ts` 的 `isVoidingCategory` 旁边。守卫、闸门以及之后 EV-225 的重跑触发都只调它。
  2. 闸门：命令通道有 `hits` 时按类别判；**没有 `hits` 的旧记录**（`333e5a29` 之前）退回 `hit`，保持旧口径，不追溯改判。
  3. 删掉那句过时注释，并按项目惯例写明这次漂移的来历。
- **不做**：BACKLOG 候选 B（识别排除式与字符串字面的已知形态）。修好闸门以后，这类命中只会落在告警档，不再作废；扩已知形态表要另走双审，留在 EV-19 一族等触发。
- **需要你知道的副作用**：修好后，过去被误判作废的轮次如果重新跑 `gate --check`，有效侧会变成 2，共同阻断会**真的执行**，理论上可能报出原先没报的「两家同提 blocker 被驳回」。已审批的阶段不会再被闸门复查，所以我推荐统一按新逻辑执行、不加版本开关（D-5）。
- **验收**：单测三格（只有告警级命中 ⇒ 不作废、共同阻断执行；有作废级命中 ⇒ 作废；旧记录没有 `hits` ⇒ 维持作废）；集成格让桩 codex 跑一条含 `.trivium` 字面的命令，两审形态下不出现 `joint_check_degraded`；变异装置咬住谓词。零真实调用。

### 4.2 EV-238：agy 探活超时被报成「未认证，请交互登录」

- **现象与出处**：`agy.ts:240-272` 的 `authProbe` 用请求组合的模型发「只回复 OK」，外层超时 120 s（`:260`）。`ok = SUCCESS && !timedOut`（`:263`），失败时一律给「请先交互登录一次」（`:268`）。Z1 的失败实际是超时（见 §0）。
- **做法（推荐 A+B）**：失败分三档文案——`timedOut` 或 `printTimeoutWarned` ⇒「探活超时（Ns，模型 X）：多半是模型侧响应慢，可稍后重试；不必重新登录」；`status` 非 SUCCESS 且 stderr 有认证特征 ⇒ 保留现在的登录指引；其他 ⇒ 原样打印 status 与 stderr 摘要。三档都点名探活用的模型。**`ok` 的判定不变**，预检照样退 69。
- **不做**：自动重试，或把「打印超时但 SUCCESS」当作已认证。前者改调用链、多花配额；后者从部分输出推断认证状态，依据不足。
- **验收**：桩 agy 三种输出（超时、打印超时、认证失败）各一格，逐字核对文案。零真实调用。
