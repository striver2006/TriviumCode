## 三、修复后的决策表

以下针对带轮次链的计划审或代码审。每行的重试数是**每个受影响侧额外调用审核者的次数**，按默认瞬时预算 1、尚未被占用、无独立漂移失败或泄漏计算。表中“中止”统一表示 `failed/partial`，运行或终态 `--wait` 退出 75，无计票、无 `next_action`，run 的 gate 记 `failed`，本机槽回 `idle`，流程停在失败出口。不得靠补裁决把这次中止变为可审批轮。

| 场景 | 额外重试 | strict：计谁、运行与轮次 | 允许降级：计谁、运行与轮次 | gate / 人工后果 |
| --- | ---: | --- | --- | --- |
| 全部证据达标、均有有效结构化票 | 0 | 全部；0，`success/full`，按票型定论 | 同 strict | 先待逐条裁决，校验通过后按下述动作分流 |
| 一侧首次不足，重试达标并产出有效票 | 1，仅该侧 | 本侧只取重试票，其余各一票；0，`success/full`，按最终票型 | 同 strict | 正常分流，首次票不进 gate 或独立来源 |
| 一侧重试仍不足，其余有效票达到半数，例如 2/3 或 1/2 | 1，仅该侧 | 中止；其余侧可留痕，整轮不计票 | 仅合格侧；0，`success/partial`，原因点名该侧；按有效票三档定论，排除原因 `insufficient_evidence` | strict 无裁决推进；降级按动作分流。2/3 可查共同阻断，1/2 的共同阻断记未执行 |
| 多侧仍不足，尚有完成侧但有效票不到入选半数，例如只剩 1/3 | 各不足侧 1；健康侧 0 | 有证据失败即中止，整轮不计票 | 只计幸存的一票；0，`success/partial`，`undetermined / human_review` | 降级轮先待裁决；校验通过后连 A 也进入 `awaiting_approval`，共同阻断记 `skipped-insufficient-sides(1)` |
| 全部侧最终证据不足，没有可继续处置的侧 | 各 1 | 中止，零张计票 | 同样中止，零张计票 | 两种策略均无轮次结论或人工审批停点 |
| 执行证据达标，但整份解析回退使有效票不足（例：两侧都回退） | 0 次解析原因的模型重试 | 回退侧可裁决但不投票；例中 0，`success/full`，两侧排 `parse_fallback`，`undetermined / human_review` | 同 strict | 校验回退件的裁决后进入人工停点，独立来源不足；保留既有 L11 行为 |

`N` 为全部入选侧数，`n` 为有效结构化票数。运行允许完成后才执行 `n=0 或 2n<N → undetermined`。其余情况按达到半数的“不通过、修改后通过、通过”依序判；都未达半数取修改后通过。通过和修改后通过均为 `proceed`（校验通过后 A 回 idle，B/C 立人工停点）；不通过且未到上限为 `rerun`（校验后回 idle 续轮），到上限为 `human_review`。任一应裁决项未齐，gate 退 2，不推进。独立根因审 D 仍按本阶段的现行契约走停点，资格和共同阻断同样适用，不增设轮次链。[计票与动作](../../src/trivium/round-verdict.ts#L76)

## 四、最小实现与兼容

1. **把判定送回现有尝试循环。** 在 `guard.ts` 的尝试级回调多返回 `judgeSide` 已算出的证据结果、原因、项目读取数和生效下限。复用当前运行的根、请求、阈值和 capability。runner 对适配器失败、超时沿用原原因；对成功尝试先按 AC-25 处理泄漏，干净尝试才判证据。工具证据不足只重试本侧一次，用现有 `transientUsed` 和 `buildRetryHint`，给出观测计数与下限。预算为 0 或已耗尽直接收口；配置大于 1 时，单侧证据专属触发仍至多一次。一次尝试同时触发多项不足也只扣一次。泄漏独占现有的一次作废重跑，二次命中终结为 `peer_leak`；不重置瞬时额度。单侧总调用上界仍是 1 + `transient_max` + 实际用掉的至多一次作废重跑，预算为 1 时最多三次。
2. **保留适配器事实，在终判后统一决定侧资格。** 让 runner 将终次原始结果与证据失败原因一起交回，保留原始退出码。避免过早把原结果改为 `failed`，导致 `judgeRun` 跳过该侧、项目读取数被写成 0 或写事件/漂移归因丢失。按入选集合生成每侧一个判定结果，由 `decideMode`、选票装配、运行期共同阻断和归档读取共用。结果区分执行失败/超时、独立性作废、证据不足、整份回退和有效结构化件。证据耗尽时侧级为 `failed`，保留具体 `fail_reason`（例 `no_project_context`）、真实计数和下限，票级统一排 `insufficient_evidence`。通用失败侧的占位 `evidence_ok=false` 不能反向覆盖 timeout、鉴权或 `peer_leak` 的原因。尝试与终判不一致时以终判保守排除并记录，不另起一次模型调用。
3. **分别使用同一资格结果的三个后果。** 策略看“该侧可继续处置”，票看“提交了有资格的当前版结论”，共同阻断看“有资格的独立结构化来源”。保留证据合格的 `parse_fallback` 的执行完成资格，以及原文、F 编号裁决；其票和独立来源均排除。合格根中的逐条降级只影响该条意见的阻断资格，其编号仍须裁决。仅解析不合格时，维持 `executeRun` 的本地解析回退；gate 读旧原文的 `parseReview` 也只做本地解析。若同时缺证据，仅按证据预算处置。新规则下最终证据失败侧走已有 `.failed.json` 分支，保留原因和尝试次数；幸存侧的意见、附件哈希、`addresses` 与逐条裁决照现行契约检查。无需把这一侧的失败文本升级为正式意见。重试提示仍归档于 `.retry.md`，`critics.*.attempts` 保持现有作废重跑含义，避免报告误报作废。[失败归档](../../src/trivium/review.ts#L1849) · [解析与回退](../../src/trivium/review.ts#L1655) · [旧原文重解析](../../src/trivium/gate.ts#L1384)
4. **让 gate 跨进程读同一事实。** 建议终态新审查 run 在 v3 增加可选 `effective_failure_policy: strict | degrade`，记录此次执行实际采用的策略，也作为新资格语义的识别字段。另在 `round_verdict.excluded` 增加 `insufficient_evidence`。从正本的选侧、状态、证据、失败原因与既有泄漏记录还原相同资格；借助本地结构化件校验投票资格。带新字段的终态记录若把证据失败侧列为有效票，或计票/共同阻断人数与资格冲突，拒绝推进并报出侧与原因。新规则下因证据失败中止的 run 即使被显式指定 `--run-id` 且裁决齐备，`--check`、`--await-approval` 和审批复核也要拒绝；不可凭缺失的 `round_verdict` 回落到 entry 放行。共同阻断的运行期人数、`findJointRejectedBlockers`、`jointCheckState` 和审批前复核使用同一来源集合，少于两家写“未执行”及具体排除原因。
5. **历史按写入时的规则读。** v1 走原校验和内存迁移，v2 走原只读校验，缺新字段的旧 v3 按既有语义显示和复核。历史 `round_verdict`、`joint_checks` 和审批始终可读取；不在读盘或重新打开报告时重算、补写或产生追溯性审批。新记录必须由生产写出口和契约测试保证落入新分支；跳过、运行骨架与 verify 按各自原契约。历史回放中的“排除后”只用于对比。
