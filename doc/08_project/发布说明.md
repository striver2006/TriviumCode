# 发布说明

## 1.3.7（2026-11-23）· VS Code 驾驶舱与 Windows 稳定性收口

1.3.2 之后的首个正式安装包。其间内部版本 1.3.3～1.3.7 未单独出包，修复与改进随本版一并交付。新增的 VS Code 扩展（驾驶舱）是**独立交付物**，经 VS Code Marketplace 分发（`trivium-cockpit` 0.3.1），不在本安装包内。run / 审查文档契约沿 v3 口径，配置面变化随条目注明。

- **Windows worker 失联双根因修复（ISSUE-05a/05b，1.3.4）**：run_root 指进项目工作树内时，送审冻结与跑后复算的临时索引不再读 worker 心跳正原子替换的 `status.json`（Windows short read while indexing 致 worker 异常退出）；判 `pid_gone` 前重读一次 status，秒级运行的正常收尾不再被误判失联、`--wait` 不再把 success 覆盖成 failed。
- **Windows 逃 Job 派生与 Hook 去 sh 依赖（ISSUE-08/09，1.3.5）**：`--start` 经 WMI 中继派生 worker，不再随工具通道结束被收杀 Job 静默带走（12~15 s 静默死形态）；`--wait` 判 worker 确认已死时就地按记录结束本 run 的审查员 CLI（EV-157 收窄为「worker 仍活时不结束」）；Claude L1 Hook 在「找不到 Git Bash 回退 PowerShell」的机器上不再三层失效（命令重渲染为 `powershell -NoProfile -EncodedCommand`）。
- **writeAtomic 在 win32 上对改名覆盖做有界短重试（EV-260）**：rename 覆盖被并发写者或杀毒/索引服务短暂占用报 EPERM/EACCES/EBUSY 时按 [25,50,100,200,400] ms 指数退避有界重试（总睡眠 ≤775 ms），`--start` 不再偶发「内部错误：EPERM」退出；POSIX 分支逐字不变。
- **--wait 旧记录环境歧义护栏**：旧版写下、缺规范化启动时刻的 status 在异 TZ / 区域设置下比出「worker 已死」而 pid 上仍有活进程时不发信号（`lostWorkerReapHold`），如实播报；规范化记录比出的不符只可能是 PID 复用，照常结束。
- **证据不足审核侧的重试与计票修正（1.3.7）**：证据不足至多消耗一次共享瞬时重试额度，失败策略、计票与闸门统一核对逐侧资格；区分严格中止、降级翻票与转人工，历史运行的读取口径不变。
- **适配层与探针**：agy 1.5.2 读取工具改名适配（`view_file` → `read_file` 双名并计，1.5.1 未验证不承诺）；claude 失败取因优先取错误形态 result 的文本，第三方网关 stderr 常驻噪音不再把配额类失败误报成认证问题；认证探活负载降低（1.3.6）。
- **secrets 误报修复**：普通变量初始化的方法调用（如 `RecordingSessionGuard.acquire()`）不再被当长凭据误报。
- **任务书自足化与停点收录（1.3.3）**：任务书第 6 节输出契约不再引用资产根下 schema 绝对路径（agy 1.4.10 headless 对工作区外读取直接拒绝）；ZCode 0.17.0 停点收录。
- **接入范围收口（2026-10-29）**：Kimi Code / Qoder CN 候选接入终止，产品聚焦四家（Codex、Claude Code、ZCode/GLM、Antigravity/Gemini）；候选入口、专用探针与准入台账运行逻辑已移除，历史工件保留。
- **VS Code 驾驶舱扩展（独立交付，0.3.0 → 0.3.1）**：健康面板、装配与前置链、终端协同与运行监控（Phase 0+1）；审查意见结构化展示与运行历史（Phase 2）；裁决台与带外审批闭环（FR-8~FR-11，0.3.0）；审核者输出实时展示（终端关闭后可回看）与 GLM 主攻交互入口。安装与首次使用见扩展自带手册。
- **手册**：使用手册补齐驾驶舱实操并新增 13 页离线 PDF（`doc/07_manuals/使用手册.pdf`）。
- **发版登记（EV-263/264，均测试侧）**：Windows 全量两轮的红格定位为两族——`heartbeat-threshold-warning` 的 cancel 保守竞态被中继时延放大、`win-job-escape` 的「不在任何 Job」断言在 OS 26300 构建上过严（逃出收杀 Job 的修复语义经夹具复刻确认成立）；产品行为不改。读数与取证见[发布检查报告](../05_testing/发布检查报告.md) 1.3.7 一节。

正式包（本版先发 Windows `windows-x64.zip`，macOS `tar.gz` 在 Mac 上出包后补挂）与 `.sha256` 除作 Release 附件外，另按版本入库 `releases/1.3.7/`。

## 1.3.2（2026-10-27）· claude 首跑与第三方网关修复

1.3.1 之后的修复版，没有新功能；配置项、run / 审查文档 / 任务正本契约不变（`trace.json` 多一个诊断键，见下）。没有单独发 1.3.1 的安装包：Windows 开发机上装过一份不含 EV-254 修复、却同样标 1.3.1 的构建，为避免「同号不同码」直接发 1.3.2。

- **claude 升级或全新安装后首跑 doctor 不再误判（EV-254）**：此前 claude CLI 升级后、或盘上没有 claude 结论时，首次 `doctor` 必报「Claude 路线在探测期间发生变化」退 69，路线登记被删、只读旗标清空，要再跑一次才过。首跑引导改用配置副本，不再改写调用方配置。报告 `doc/05_testing/REPORT_2026-10-24_claude_first_run_route.md`。
- **网关凭据不再出现在进程命令行里（EV-256）**：开了 `agents.claude.settings_env_source: user_settings`（CC Switch 网关）时，1.2.0～1.3.1 把 `~/.claude/settings.json` env 段的键值并进 `--settings` 内联 JSON，本机能列进程命令行的进程都看得到。改为经 claude 子进程的环境变量注入，`--settings` 只装 deny 规则；未开启的机器零变化。Windows 真实网关验收通过。报告 `REPORT_2026-10-25_gateway_env_injection.md`。
- **网关机器上的生效模型回读不再被吞（EV-257、EV-258）**：输出的逐值脱敏原先把网关 env 的全部值都换成 `<redacted-env>`，模型名键的值也在内，`model_effective` 记成占位符却仍标 `envelope`。现在逐值替换只对凭据类键；模型名键的值要过四道守卫才不替换，凭据类键一处不放松；回读字段带脱敏痕迹时记 null 与 `unverified`。CC Switch 写进模型名键的上下文窗口后缀（如 `qwen3.8-max[1M]`）先剥掉末尾一个再判，单位大小写不敏感。`trace.json` 新增诊断字段 `modelReadback`（CLI 解析出的模型名、服务端回报的模型名、两者是否一致），只留痕、不进判定面。三项 Windows 真实网关验收均通过（EV-258 第一轮因大写后缀不通过，第二轮修好）。报告 `REPORT_2026-10-25_gateway_readback_model.md`、`REPORT_2026-10-26_gateway_model_suffix.md`、`REPORT_2026-10-26_gateway_model_suffix_case.md`。
- **手册收口**：Windows 终端（PowerShell / cmd）写法补全，预检失败自动校准写进使用手册。
- **已登记未修（EV-255）**：测试 `doctor-deadline` 的 I4 格在全量负载下偶发红（单跑 8 次 7 过），属测试侧时序问题，推测成因未实测证实，不涉及产品行为。

正式包（macOS `tar.gz`、Windows `zip`）与 `.sha256` 除作 Release 附件外，另按版本入库 `releases/1.3.2/`。升级注意见[部署手册](../06_deployment/部署手册.md) §6.2。

## 1.3.0（2026-10-24）· 双平台统一

## 版本变化

从产品 0.1.0 整理为首个 1.0.0 稳定发布基线。本版以现有实现为范围，不新增审核者、平台或放宽准入规则。旧设计文档的 v1.3.x、PRD 文档版本和运行协议版本各自独立，不改成产品版本。

- 保留 M0～M12 已实现能力：四家 Agent、动态选侧、不同载体 Driver、档位与路线、v3 证据、逐条裁决、作废侧重跑、共享读取面检查及 EV-245/246 修复。
- 新建中文需求、系统设计、部署、使用手册，更新首页与索引，保留旧规范和审计工件。
- 建立独立的现存 Bug 与未完成工作清单，区分历史遗留、已接受限制和未测项。
- 统一 package/lock/CLI 产品版本，修正安装前检查的 Node 18 路径定位兼容性；纠正卸载提示中“wrapper 缺失就 no-op”的错误说明，更新过时源码注释，不修改审查判定规则。
- 增加可复用发布命令、Mac 安装快捷入口、逐文件校验和 SHA-256、第三方许可与来源元数据；隔离解压安装测试覆盖安装/升级/卸载和 28 份入口。

## 发布与支持范围

正式 Tag 约定为 `v1.0.0`，版本分支名为 `1.0.0`。分支、Tag 应指向包含本版全部源码与文档的发布提交，不把旧 HEAD 打成新版本。保持原工作分支，不主动切换；提交前按全局 AGENTS.md 等待 Bob 确认。未请求推送，因此不自动推送远程。

正式分发命令：`npm run release`。输出 `dist/releases/TriviumCode-1.0.0-macos.tar.gz`、同名 `.sha256` 和解包目录。正式包要求干净工作树；提交前只生成带 `-candidate` 且元数据标为 candidate 的预览包。包中的 source_commit、source_dirty 和构建指纹是实际采样值，不凭标签名称猜测。

支持 macOS；目标机需有 Node、Git 和 Agent CLI/登录。Windows 原生支持列后续，Linux/WSL 未验收。包不带本机配置、探针或账号，不包含源码和历史测试原始证据；源码通过对应版本分支/Tag 获取。（本段为 1.0.0 时点口径。后续演进：Windows 原生已于 1.1.0 交付、1.2.x 为当前 Windows 线（zip 包 + `.cmd` 入口，见[部署手册](../06_deployment/部署手册.md) §1a/§2）；Linux/WSL 仍未验收。本说明不随各补丁版改写，当期状态以[现存 Bug 与未完成工作清单](./现存Bug与未完成工作清单.md)为准。）
