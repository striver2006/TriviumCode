参数：原生技能加载器在这份无参数占位符的正文末尾追加 `ARGUMENTS: <用户参数原文>`。
从该尾段取得本次参数；下文 `<参数>` 按转抄规约拼入命令。参数写法：`--topic <主题> [--stage plan|code|bug] [--reason <理由>]`

**只在用户显式调用本命令时执行。** 用户没有调用本命令时，不执行其中任何一步。
CLI 的 `-p` 模式把 `/skill:名字 …` 原样交给模型，由原生 `Skill` 工具加载；
原生加载和模型转抄是两步，不能把转抄结果当作客户端自动执行。

#### 参数转抄规约

- **来源**：用户随本命令给出的全部文本就是参数。逐字转抄：不增删、不改写、不翻译，也不「顺手」补全。
- **空参数**：用户什么都没写时，参数就是空的——`<参数>` 处什么都不放。**严禁自行编造**焦点、主题或任务目标；
  CLI 缺参时会退 64 并给出写法提示，原样转述给用户即可（FR-20「缺焦点拒绝启动」靠这一条保住）。
- **拼串**：旗标与取值原样照抄。取值含空格或 shell 特殊字符时整段放进**一个单引号参数**，
  里面的单引号写成 `'\''`，其余任何字符一律不转义；**不要改用双引号**（`$`、反引号会被 shell 展开）。
- **样例**：用户输入 `--topic 登录 重构 --reason 先合入再补文档` ⇒ `--topic '登录 重构' --reason '先合入再补文档'`

运行：

```
.trivium/bin/trivium abandon <参数>
```

把输出原样转述给用户。

不带 `--stage` 时放弃该主题下全部未关闭闸门，但**跳过 `running` 的那些**：
审查还在跑，闸门不能就地作废。要停掉进行中的审查，先 `.trivium/bin/trivium review --cancel <run_id>`，
再放弃。对 `running` 闸门显式指定 `--stage` 会退 2。
审批正本 task.json 读不出时也退 2，哪道闸门都不动；恢复由用户在终端做，恢复后再放弃。
放弃会解除业务写锁，但**已有工件一律保留**（PRD 第 10 章）——
放弃的是闸门，不是留痕。
