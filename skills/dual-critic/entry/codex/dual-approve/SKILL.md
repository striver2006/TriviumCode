参数：本载体**不替换**参数占位符。参数就是用户随本命令给出的全部文本（跟在命令名后面，或被载体标成「User request」的那一段）；
下文命令里写 `<参数>` 的地方，按下面的转抄规约把它拼进去。参数写法：`--topic <主题> --stage plan|code|bug [--reject --reason <理由>]`

**只在用户显式调用本命令时执行。** 本载体没有「禁止模型自行调用」的开关：你若是自己读到这份说明、
而用户并没有调用本命令，不要执行其中任何一步。

#### 参数转抄规约

- **来源**：用户随本命令给出的全部文本就是参数。逐字转抄：不增删、不改写、不翻译，也不「顺手」补全。
- **空参数**：用户什么都没写时，参数就是空的——`<参数>` 处什么都不放。**严禁自行编造**焦点、主题或任务目标；
  CLI 缺参时会退 64 并给出写法提示，原样转述给用户即可（FR-20「缺焦点拒绝启动」靠这一条保住）。
- **拼串**：旗标与取值原样照抄。取值含空格或 shell 特殊字符时整段放进**一个单引号参数**，
  里面的单引号写成 `'\''`，其余任何字符一律不转义；**不要改用双引号**（`$`、反引号会被 shell 展开）。
- **样例**：用户输入 `--topic 登录 重构 --reason 先合入再补文档` ⇒ `--topic '登录 重构' --reason '先合入再补文档'`

运行：

```
.trivium/bin/trivium approve <参数>
```

把输出原样转述给用户。

- 通过：`--topic <主题> --stage <阶段> [--reason <附言>]`。**`--stage` 必填**：一次放行哪一道闸门要说清楚。
- 拒绝：追加 `--reject --reason <理由>`。**拒绝必须给理由。** 拒绝与放弃可以省略 `--stage`。
- **用户在指令后写的自由文字是审批附言，传 `--reason '<原文>'`**（整段单引号包住），它会写进
  审批记录的 `reason` 字段。**不要**把它原样拼进命令当位置参数：`approve` 不接受多余的
  位置参数，会退 64 并列出被丢的内容——那不是 CLI 坏了，是附言没走对字段。
  `--reject` 不接受值：`--reject 理由` 同样退 64，理由一律走 `--reason`。

**只在用户明确要求时运行这条命令。** `approve` 不校验调用来源，你自己跑得通——
所以这道关靠的是你守规矩：审批是解除护栏的动作，发起权在用户手里。
审批记录会写进 `task.json.approvals`（含时间与会话来源）供事后对账。

两种结论都会解除业务写锁并保留全部工件。**拒绝之后流水线不会自动继续**——
你可以按用户意见改写归档内的修订件（改完重跑 `gate --check`），
但不得自动进入编码、改码或修复。改写用 Read / Write / Edit，重跑校验用
`.trivium/bin/trivium gate --stage <阶段> --topic <主题> --check`。
