**问题**：事件目录中 approval 见证事件的接受条件只有 approvalShape(event) 与 scopeDigest(event)===scopeDigest(a)，未像撤销分支那样比对 event.decision_id、topic、criterion_version 等身份字段。结果是 decision_id 不同的同 scope 批准事件可被当作当前被验批准对象的唯一见证（approved===1 通过），事件目录的历史记录与被验对象之间没有身份级对应，撤销后换 id 重建批准对象时虽仍因撤销事件 decision_id 不匹配而失败（fail-closed 保住），但合同声明的冲突/来源档在事件级没有闭合。

**依据**：实读 criteria-validation-core.mjs：第 38-48 行事件循环中 approval 分支仅形状加 scope 摘要，第 43 行撤销分支却要求 decision_id 与 criterion_version 一致；配套实读 criteria-consumer-v3.mjs（消费者会重算 scope，所有返回恒 production_consumer_enabled=false、diagnostic_only=true）与 test/unit/agent-access-criteria-v3.test.ts——其 conflict/duplicate 变异均为同 decision_id 的整对象克隆，未覆盖同 scope 异 decision_id 的见证混用场景。

**建议**：在 approval 事件分支比照撤销分支补齐 event.decision_id===a.decision_id（至少，建议连同 topic/criterion_version 或全文摘要），并在 criteria-v3 测试补一条同 scope 异 decision_id 批准事件不得充当唯一见证的负例；不改变 diagnostic-only 与关闭消费者的既有边界。
