### GLM-01 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/adapters/claude.ts:383-389` |
| 类别 | maintainability ｜ 层次 code |
| 置信度 | medium |

**问题**：projectClaudeDenyPaths在一份配置同时声明祖先与后代目录glob时（如a/**与a/b/c/d/e/**，且祖先名下存在余段不超过3的浅文件），后代根因under(d,parent)成立被排除出directories，而幸存的祖先根的covered()只覆盖余段不超过3段的路径，于是后代根下更深的禁读路径静默回退逐文件。方向保守不丢保护，但既有的深根压缩会因后来往配置加一个宽祖先glob而整体消失，settings字节数回涨并在启动前软线预检处被拒，因果相距很远；现有用例（claude-directory.test.ts首例的calls/**与calls/sub/**）只覆盖祖先能全覆盖的良性嵌套，未覆盖祖先盖不住后代深层文件的情形，注释与设计文档也未点明该交互。

**依据**：实读src/trivium/adapters/claude.ts:380-389：covered()要求余段split('/').length<=3且中间段ASCII；directories=roots.filter(d=>!roots.some(parent=>parent!==d&&under(d,parent)))；paths用covered(p,d.directory)过滤。test/unit/claude-directory.test.ts首个用例中calls/sub被排除但calls可全覆盖其下路径，未测宽祖先加深后代组合。当前.trivium/config.yaml的sensitive_globs仅含后缀类glob、无目录glob，生产行为暂不触发。

**建议**：在test/unit/claude-directory.test.ts补一个宽祖先glob与深后代glob共存的用例，钉住后代路径回退逐文件、directories只剩祖先根的投影结果与coveredCount；并在projectClaudeDenyPaths注释或设计10.1点明该交互，避免后续加宽glob时误判压缩失效原因。
