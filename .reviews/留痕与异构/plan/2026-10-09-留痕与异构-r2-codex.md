## 本轮细化的 v3 写契约与历史映射

v3 顶层新增必填 driver_declaration: {model:string|null,provider:string|null,source:'declared'|null} 与 family_comparisons: Comparison[]。每个 Comparison 必填 {left:string,right:string,status:'same-family'|'different-family'|'unknown',left_model:string|null,right_model:string|null,left_source:string|null,right_source:string|null,reason:string}；left/right 依注册表校身份，不能把 Agent 集复制到 Schema。running 骨架矩阵为空，终态比较 Driver 与入选各侧并覆盖审核者所有两两组合。

逐侧新增必填 access: {requested_mode:'native'|'profile'|'standard',profile:string|null,launcher_requested:string|null,launcher_effective:string|null,wrapper_sha256:string|null,configuration_sha256:string|null,provider_declared:string|null,provider_declared_source:string|null,provider_effective:string|null,provider_effective_source:string|null}。无启动证据时 launcher_effective=null；未走到版本探测时 cli_version 可null，实际 wrapper/config 指纹来自统一路由实现。模型和 effort 继续已有 requested/effective/source 字段，新 v3 effective 禁止 source=requested；Claude provider/effort 回读无证据即null。

v3 critics.<id>.heterogeneous 替换为三态字符串，与 Driver-vs-该侧 comparison.status 同值；override_reason 是该比较的依据与原因，同族/未知都有可见原因，不推测来自哪个默认档。前两个主题尚写v2时保持既有合法字段；全量改造交付统一新写v3。审查 front-matter 新增 access 和 family_comparisons，heterogeneous 变为三态，parse ECHOED_ORCHESTRATOR_KEYS 与 P9/P9′ 一起对账。

统一内存 RunMeta 兼容 v2/v3 的形状，sourceSchema 保留原始写契约；v1 经现有迁移补 Driver 与集合、仍标原始source=v1。旧逐侧 bool 保留原值，新比较矩阵在历史记录中视为null而非补算；新旧值通过类型和 sourceSchema 区分，消费侧禁止把 true 看成 different-family。旧 model_effective_source=requested 保留值并显示「旧版请求回填」，model_route 原样保留；历史读映射不回写新字段，不改被冻结工件。verify 独立分发保持原样。

## 目标与边界

执行用户批准的「Codex、Claude Code 双模式接入与异构判定修正」。前两个主题提供实际路由、探针指纹与逐组合认证；本主题实现诚实留痕和模型族三态比较。Agent 身份、归档命名、意见前缀及护栏沿注册表；供应商或模型都不改身份。同族、未知一律告警继续，不构成门禁，不自动换模型。提交、推送待用户确认，软件版本号由用户控制。

## 契约与迁移

1. 先将 v3 字段、来源和异构语义并入主设计，同步 PRD FR-17/AC-18 与协议。新写 `trivium.run.v3`，保留 v1/v2 原始 Schema 与冻结历史工件。读侧先根据 schema 用各自校验器验证原形状，再转统一内存形状；不得放宽旧 Schema 以强塞新字段，也不得将旧布尔值重新解释为新比较。
2. v3 路由证据记录请求模式/profile、实际入口、CLI 与包装器指纹；配置供应商与运行时回读供应商分别记录值/来源，请求和回读模型、effort 分开。没有运行证据的字段为 null，不以请求回填有效值。Claude 经 Qwen 启动仅能声明 Qwen，Claude provider/effort 无事件回读时 null。成功、失败、超时、取消均保留请求路线，未启动的实际入口字段不伪造。
3. `meta.ts`、`schemas.ts`、`archive.ts`、`gate.ts`、`hooks.ts`、`review.ts`、`run-protocol.ts`、worker 交接、`parse.ts`、`render.ts`、`report.ts` 的读写链路一并更新，明确 source_schema。verify 阶段继续自身 verify-run 契约，不误升级。Schema 只校形状，身份仍注册表校验，新增文件自动进入目录对账。
4. `--driver-model`、`--driver-provider` 为可选本轮会话声明。通过 resolve/preflight/review/worker 透传至运行元数据，来源固定为 declared。缺值退64，不从审核者配置或 Driver Agent vendor 推断主攻当前模型。声明与运行时回读清楚区分。
5. 集中维护保守模型族解析器（注册表的模型事实源或由注册表导出的函数）。已识别模型标识映射家族；通用别名 opus/sonnet/default、未知标识返回 unknown，不用 provider 名作族判据。支持版本后缀和provider命名空间，避免 gpt-oss 等开源族误等同 GPT 服务模型；供应商承载不同模型族必须正确分开。
6. 比较 Driver 声明模型与每个审核者有效回读模型，审核者之间两两比较，输出 same-family/different-family/unknown、参与方、判断来源与原因。Driver 信息缺失、别名未知、审核者未回读均 unknown，禁止 requested fallback。provider 仅作上下文，不构成异构证据。
7. 所有展示面和意见头部一致输出三态及理由；同族与未知都明确告警但继续。旧 v1/v2 heterogeneous 布尔显示为「旧版名义族判定」，保留原文，不捏造本轮 driver declaration。override_reason 文案不再依据 Driver 厂商名义族，历史原因不回改。收口 EV-107、EV-234 与相关 EV-230 文案。
