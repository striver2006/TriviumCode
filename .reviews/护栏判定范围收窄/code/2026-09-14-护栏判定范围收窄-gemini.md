### AGY-01 · 阻断（blocker）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/hooks.ts:517` |
| 类别 | security ｜ 层次 code |
| 置信度 | high |

**问题**：roleSuffixRuleBlocks 条件 (d) 存在严重漏洞：同段遇到包含脏字符的 token 时执行 continue 跳过，在白名单默认放行机制下，导致 --target-directory=.reviews/... 选项搬运、$DEST 变量及 $(...) 等搬运式伪造静默逃逸拦截。

**依据**：见 src/trivium/hooks.ts:501-523。第 517 行对非后缀 token 判定 if (DIRTY_TOKEN.test(t)) continue;，注释称「非后缀的脏 token 无法定位，不据此放行也不据此拦」。但该函数默认返回 false（放行），跳过检查即等同于举证全部通过并放行。这直接导致：1）cp --target-directory=.reviews/t/plan doc/x-gemini.md 或 install -t=.reviews/t/plan doc/x-gemini.md 因 token 含 = 而被 continue 跳过，且未按计划 §2.2 承诺提取 = 后的内嵌路径，直接放行；2）cp doc/x-gemini.md $DEST 或 $(echo .reviews/t/plan) 等变量/命令替换形式的目标因含 $、( 等同样被 continue 跳过并放行。test/unit/hooks.test.ts:410-415 的新增测试仅覆盖了纯位置参数形式，未覆盖选项型或脏 token 形态。

**建议**：在含角色后缀的段中，坚持修订计划 §2.2「宽介入、严放行、默认拦」原则。若存在无法证明安全（含脏字符且无法解析出确定安全路径）的 token，因无法举证必须 fail-closed 拦截；对包含 = 的选项（如 --target-directory=...、-t=...），必须切分提取 = 右侧的路径值传入 isInsideArchiveResolved 进行核验，严禁无条件 continue 跳过。

### AGY-02 · 阻断（blocker）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/hooks.ts:156-170` |
| 类别 | security ｜ 层次 code |
| 置信度 | high |

**问题**：resolveExisting 遇到指向归档内未创建文件的悬空软链（dangling symlink）时回溯到父目录，致使通过软链在归档内新建伪造审查件完全绕过 hookPreWrite 拦截。

**依据**：见 src/trivium/hooks.ts:112-170。当试图伪造新建一份尚未存在的审查文档时，若在 doc/ 下建立软链 doc/x-gemini.md 指向归档内待伪造的路径，因目标文件尚未创建，safeRealpath（内部调用 fsSync.realpathSync）抛出 ENOENT 并返回 null。resolveExisting 误判该文件不存在，逐级向上回溯到父目录 doc/，最终返回词法路径 /project/doc/x-gemini.md。isInside(root, ...) 判定在归档外，isForgedRoleFile 返回 false，hookPreWrite 放行写入。随后 Write 工具打开文件，内核自动沿软链在 .reviews/ 下新建出伪造文件。test/unit/hooks.test.ts:400 的软链测试因预先 writeFile 创建了真文件，未能覆盖目标尚不存在的场景。

**建议**：在 safeRealpath 或 resolveExisting 回溯过程中，不可仅凭 realpathSync 抛出 ENOENT 就断定路径不存在。应使用 fsSync.lstatSync 检查当前路径本身是否为符号链接；若是软链，必须用 fsSync.readlinkSync 取出目标并 resolve 规范化后判定其落点是否在归档根内。

### AGY-03 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/hooks.ts:447,487` |
| 类别 | correctness ｜ 层次 code |
| 置信度 | high |

**问题**：SEGMENT_SPLIT 以管道符 | 切分命令，导致流式处理（如 tar ... | tar -C .reviews/... 或 echo ... | xargs cp ...）将后缀与归档写入拆散至不同段而脱离条件 (d) 保护。

**依据**：见 src/trivium/hooks.ts:447 与 487-523。SEGMENT_SPLIT 将管道符 | 作为独立分段切分符，且 segHasSuffix 仅按单段独立计算。当执行 tar -C doc -cf - x-gemini.md | tar -C .reviews/t/plan -xf - 或 echo doc/x-gemini.md | xargs -I{} cp {} .reviews/t/plan/ 时，前段输出到管道，后段从管道读取并写入归档阶段目录。由于前段目的地不在归档内，而后段命令行中无角色后缀字面量（segHasSuffix = false），条件 (d) 在后段不触发；而后段的目标是阶段目录而非 _meta，规则 ② 亦不拦截，导致伪造件被流式搬运进归档。

**建议**：管道命令各部分处于同一执行流。若整条管道命令中任一段命中了 ROLE_SUFFIX_ANYWHERE，整条管道的下游消费段不得将数据输出到归档根内；或在管道两端共享上下文，禁止向归档根输出。

- 异常不外泄原则落实到位：safeRealpath 在内部消化 ENOENT 等异常并回退到词法比较，杜绝了异常穿透至 runHook 外层捕获导致静默放行（ALLOW）的问题。
