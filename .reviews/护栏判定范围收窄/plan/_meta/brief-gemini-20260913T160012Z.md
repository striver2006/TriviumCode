### 1.1 为什么收窄不会给伪造审查件开口子

伪造审查件的攻击目标是**骗过闸门**，而闸门的读取面是封闭的：

- `gate.loadRoundReviews` 只从 `metaDir(layout, stage)` 读 `_meta/review-<critic>-<runId>.json`；
- `gate.checkAdjudication` 只从 `listStageArtifacts(layout, stage)` 取工件，`layout.archiveRoot` 即归档根；
- `archive.ts` 是 `.reviews/` 的唯一写出口，`O_CREAT|O_EXCL` 防覆盖。

写在 `doc/` 下的 `x-glm.md` **不进入任何一条读取路径**，它对 gate 判定的影响是零。因此把判定收窄到归档内，不减少任何一条真实防线——这是本方案成立的核心论据，审查时请直接核对上述三处代码。

## 2. D-1：Write 侧收窄

```ts
// 现状
export function isForgedRoleFile(targetPath: string): boolean {
  return /-(?:gemini|glm)\.md$/.test(path.basename(targetPath));
}

// 改为
export function isForgedRoleFile(
  targetPath: string,
  projectRoot: string,
  archiveRoot: string,
): boolean {
  if (!ROLE_SUFFIX_RE.test(path.basename(targetPath))) return false;
  return isInsideArchiveResolved(targetPath, projectRoot, archiveRoot);
}
```

## 3. D-2：Bash 侧收窄——本计划的难点

Bash 侧规则 ① 与 Write 侧**不是同构的**，照搬会留缺口。

现状 ① 的价值恰恰在于「不依赖 cwd」：

```ts
if (/-(?:gemini|glm)\.md\b/.test(cmd)) return true;   // 扫整条命令文本，先于一切解析
```

而路径判定那一支（`hooks.ts:374`）在**推断不出目录时会跳过**：

```ts
if (cwd === null || /[$`]/.test(t)) continue;         // cd $VAR、命令替换 → 放弃路径判定
```

若把 ① 直接换成路径判定，`cd $VAR && rm x-glm.md`、`rm "$(f)-glm.md"` 这类就**两支都不命中**——从 fail-closed 退成 fail-open。CLAUDE.md 记的 RV-B1 教训正是这个形状：「豁免把 fail-closed 变成需要穷举危险形态的 fail-open，而 shell 的攻击面穷举不完」。本次方向虽然是收窄作用域而非加豁免，但一旦让「定位不出 ⇒ 放行」，性质就同构了。

**方案：分层判定，不确定即拦。**

```
对命令里的每个候选路径 token t：
  ├─ basename(t) 不匹配角色后缀        → 本条不管（交给既有的 ②③ 规则）
  ├─ 能定位（cwd 已知 且 t 不含 $ 或反引号）
  │     ├─ resolve 后在归档内           → 拦
  │     └─ resolve 后在归档外           → 放行（这就是本次要修的误锁）
  └─ 定位不出（cwd 为 null 或 t 含 $/反引号）
        → 拦（fail-closed 兜底，与现状等价）
```

要点：

1. **判定对象从「整条命令文本」变为「候选路径 token」**。这同时收掉一类误拦：commit message、脚本正文里**提到**文件名但不作为路径参数时不再命中。但 `candidatePathTokens` 会剥重定向符、跳过 `-` 开头的 token，因此 `git commit -m "改了 x-glm.md"` 里那串仍会被 `tokenize` 切成一个 token 并进入候选集——**误拦只是收窄，没有消除**，如实登记，不夸大成果。
2. **兜底分支保证 RV-B1 的五类负例全绿**：它们的目标路径都写在 `.reviews/t/plan/` 下，能定位的走路径判定命中，含 `$`/`<(` 的走兜底命中。这一条列为准入硬条件（D-5），实测为准。
3. 与 ②（`MENTIONS_OWNED`）的关系：`MENTIONS_OWNED` 不动。它管的是 `_meta` / `task.json` / `state.json` / `.trivium` 四个**路径组件**，本就不依赖 cwd，与角色后缀是两件事。

## 4. D-3：符号链接——收窄唯一真正放宽的一条路

`isInside`（`hooks.ts:633`）用 `path.relative` 做**纯字符串**比较，不解析符号链接。据此：

- 现状：`doc/evil.md` 是指向 `.reviews/t/plan/a-glm.md` 的软链 → basename 是 `evil.md`，**现状也放行**。所以 symlink 缺口不是本次引入的。
- 但收窄**改变了攻击成本**：改后攻击者可以直接建 `doc/x-glm.md` 软链指向归档内真审查件，路径判定按字符串认定它在 `doc/` 下 → 放行 → 写入实际落到归档内。现状这条会被 basename 规则挡住。

**处置**：新增的共用判定 `isInsideArchiveResolved` 在比较前对**父目录**做 `fs.realpath`（文件本身可能尚不存在，realpath 会失败），解析失败则退回字符串比较并**按在归档内处理**（fail-closed）。

两点如实说明：

- Write 侧的 `hookPreWrite` 已是 `async`，可以 `await realpath`；**Bash 侧 `bashTargetsProtected` 目前是同步函数**，要么改 async（调用链上 `hookPreBash` 本就是 async），要么用 `fs.realpathSync`。倾向后者：Hook 是短命进程，同步调用无并发收益损失，且改动面更小。请审查员评估这个取舍。
- realpath 会带来一次 `stat` 级 I/O。Hook 在每次 Write/Bash 前触发，需确认延迟可接受——预估单次 <1ms，但要实测而非假设。
