## 1. 问题与现状

### 1.1 EV-239：闸门对命令通道命中不看类别

作废判定在代码里有三个派生点，**只有闸门那一处不看类别**：

| 派生点 | 位置 | 口径 |
| :--- | :--- | :--- |
| 守卫侧级判定 | `guard.ts:396-427`（逐条命令分档）、`:480-487`（`peerArtifactRead` / `peerCommandHits`） | 只有作废类（`peer-artifact` / `peer-run-output`）命中才计入；告警档进 `notedCategories` |
| run.json 共同阻断运行期三态 | `review.ts:127` `jointCheckRunState`，读守卫的侧级判定 | 同上：只排作废类 |
| 闸门派生作废侧 | `gate.ts:1430-1437` `voidedSides` | 路径通道按类别（`VOIDING_DENY_CATEGORIES`）；**命令通道 `viaCmd?.hit === true` 即作废**，注释写「命令通道没有类别信息，命中即算」 |

- 注释出处：2026-09-17 `f2bc7635`（代码双审 r1 修复）。同主题 r2 `333e5a29` 随即给命令通道加了逐条带类的 `hits`（`review.ts:1834-1850`，类型 `types.ts:1655-1671`），闸门没有跟上。
- `hit` 的语义（`review.ts:1839` 起）是「命令通道扫到了东西」，包含告警档。所以只命中编排器状态目录（`orchestrator-state`，设计 §10.1.1 定为告警级，`types.ts:89`）的一侧，在守卫与 run.json 看来**有效**，在闸门看来**作废**。
- 后果：两审形态下有效侧只剩 1 家，`gate.ts:700-712` 报 `joint_check_degraded`，共同阻断这一档不执行；同一轮的 run.json `joint_check` 却记 `pending` / 有效 2 家——**同一次运行两份留痕互相矛盾**。实测：M11 第 12 步 Z2（两审，codex 侧一条模拟 Hook 的命令含编排器状态目录字面）出现了该告警；B2（三审，`find … -not -path` 排除式）里 codex 侧唯一一条命中就是 `category: orchestrator-state`（`doc/05_testing/evidence/m11-step12-20261012/b2-assessment.json`）。
- 旧记录的两种口径：路径通道没有 `hits` 时 `?? []`，按「无作废」处理；命令通道没有 `hits`（2026-09-17 之前的 run.json）时按 `hit` 作废。两者都**保持原样**。

### 1.2 EV-238：agy 探活超时被报成「请先交互登录」

- `adapters/agy.ts:240-272` `authProbe`：用请求组合的模型发「只回复 OK」，外层超时 120 s（`:260`）。
- `ok = parsed.status === 'SUCCESS' && !timedOut`（`:263`）；失败时一律给「探活失败（status=…）。请先交互登录一次」（`:268`），**不打印 `timedOut`，也不用 `:144` 已经算出的 `printTimeoutWarned`**。
- Z1 实测（`closeout-20261016-01/z1-preflight-69-01.json`）：status=SUCCESS 而 ok 为假，只能是外层超时；stderr 为 `[agy] print timeout after 1m40s with turn in progress; returning partial output`。同日 R0 无头读取通过、重试 30 s 即过，登录是正常的。
- 消费方：`preflight.ts:916` 取 `auth.detail` 作「Antigravity 已认证」一格的详情，失败即退 69。

## 2. 做法

### 2.1 EV-239：一个作废谓词，三处共用

在 `freeze.ts` 的 `isVoidingCategory`（`:166`）旁边新增两个导出：

```ts
/** 一组带类命中里有没有作废类 */
export function hitsVoid(hits: readonly { category: DenyCategory }[]): boolean;

/**
 * 一侧的两条泄漏通道记录是否判该侧作废（run.json `guard.peer_leak_via_path/command` 的形状）。
 * 路径通道：只看 hits，缺 hits 按无作废（旧口径）。
 * 命令通道：有 hits 按 hitsVoid(hits)；缺 hits 的旧记录退回 hit === true（旧口径）。
 */
export function leakRecordVoids(rec: {
  path?: { hits?: readonly { category: DenyCategory }[] };
  command?: { hit: boolean; hits?: readonly { category: DenyCategory }[] };
}): boolean;
```

- **守卫**：逐条命令的 `typed.some((c) => isVoidingCategory(c))`（`guard.ts:416`）改调 `hitsVoid`；`peerArtifactRead` 的计算口径不变（等价改写，不改行为）。
- **闸门**：`gate.ts:1430-1437` 的循环体改为 `leakRecordVoids({ path: viaPath 记录, command: viaCmd 记录 })`，删掉过时注释，按项目惯例写明这次漂移的来历（`f2bc7635` 写注释、`333e5a29` 加带类 `hits`、闸门没跟上）。
- **EV-225**（M12 批次 3）的重跑触发将调同一个 `leakRecordVoids` / `hitsVoid`，本批不接，只在注释里点名。
- `review.ts` 的 `peerLeakOf`（`:154`）是渲染层选「最重类别」，不是作废判定，本批不动。

### 2.2 旧记录与旧轮次（用户 D-5）

- 没有 `hits` 的命令通道旧记录照旧按 `hit` 作废，不追溯改判。
- 有 `hits` 的已归档轮次，若重新跑 `gate --check`，按新逻辑派生：之前被误判作废的一侧恢复有效，共同阻断会真的执行，理论上可能新报「两家同提 blocker 被驳回」。已审批的阶段不会再被闸门复查，所以统一按新逻辑、不加版本开关。这条写进主设计 §10.1.1 / 12.1 的变更说明。

### 2.3 EV-238：失败分三档文案，判定不变

把失败文案抽成纯函数 `describeAgyAuthFailure(out, model)`（放 `adapters/agy.ts`，导出供单测），`authProbe` 只在 `!ok` 时调它。三档按优先级判：

1. **认证档**：stdout 或 stderr 含未登录特征——取已存的原始样本 `Please sign in`（`REPORT_2026-09-24_m10b_driver_entry_probe.md:45`，空 HOME 下 `agy models` 的原话），匹配 `/please sign in/i`。文案：「探活失败：agy 提示未登录（模型 X，Ns）。请交互运行一次 `agy` 完成登录后重试」+ stderr 摘要。**优先于超时档**：未登录特征出现时，不论是否超时都报未登录。
2. **超时档**：`timedOut` 为真。文案：「探活超时（Ns，模型 X）：多半是模型侧响应慢，可稍后重试；近期没有登录过 agy 的话，也可能是在等交互登录，交互运行一次 `agy` 即可确认」+（`printTimeoutWarned` 时）「agy 自报 print timeout」+ stderr 摘要。后半句是给焦点第 3 条的兜底：真实未登录若表现为挂起直到超时，文案也不会把人引去「只管重试」。
3. **其他档**：以上都不是（status 非 SUCCESS、未超时、无未登录特征）。文案：「探活失败（status=…，模型 X，Ns）：原因未识别。若近期未登录过，请交互运行一次 `agy`；否则请看 stderr 摘要」+ stderr 摘要。

- 三档都点名探活所用的模型（`combination?.model ?? 探针模型首项 ?? '缺省'`）与耗时。
- `ok` 的判定、120 s 外层超时、退 69 都不变；不自动重试；不把「打印超时但有部分输出」当作已认证。
- **样本口径的已知局限**：仓库里只有 `agy models` 的未登录原话，没有 `agy -p` 的。本命令约定 Driver 不得自行调用 agy，所以本批不去取新样本；认证档的特征只用已存原话，取不到特征的未登录情形落到「其他档」，文案里仍给登录指引，不会误导成「只管重试」。若用户愿意在终端零配额跑一次空 HOME 的 `agy -p`，原话可补成夹具，另记。

## 4. 测试与验收

**单测**

- `leak-predicate.test.ts`：五个类别 × 两条通道 × 有无 `hits` 的全组合表：①`hitsVoid` 只对两类作废类为真；②`leakRecordVoids` 与「守卫口径」逐格一致——守卫口径直接用 `hitsVoid(路径 hits) || hitsVoid(命令 hits)` 表达；③旧形态（命令通道无 `hits`、`hit: true`）为真，路径通道无 `hits` 为假。
- `gate.test.ts` `loadRoundReviews` 一组：现有 ③（无 `hits` 的命令记录 ⇒ 作废）保留不改；新增 ⑤ 命令通道 `hits` 只有 `orchestrator-state` ⇒ `[]`；⑥ 命令通道 `hits` 含 `peer-artifact` ⇒ 作废；⑦ 同一条命令同时撞 `orchestrator-state` 与 `peer-run-output` ⇒ 作废（取最重档）。
- `agy-auth-failure.test.ts`：对构造的 `AgyInvokeOutcome` 逐档断言文案——超时（含 / 不含 `printTimeoutWarned`）、未登录原话（不超时、超时两种，后者必须落认证档）、其他；三档都含模型名与耗时；**Z1 原话**（status=SUCCESS、`timedOut: true`、stderr 为 print timeout 那一句）必须落超时档、文案里不出现「请先交互登录一次」。

**集成**（`fault-injection.test.ts`）

- 现有「AC-25 三审」与命令通道各格保持绿（作废类命中照旧作废）。
