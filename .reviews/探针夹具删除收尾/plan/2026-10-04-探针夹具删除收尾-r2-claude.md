## 2. 设计

### 2.1 夹具工厂（`fixture.ts`）

```ts
import { makeTempDir, tildeHome, tryRemoveTempDir } from '../util/fsx.js';

export interface Fixture {
  …（其余字段不变）
  /** 删夹具根：重试三次、失败不抛；删成功 null，删不掉返回提示（EV-199） */
  cleanup: () => Promise<string | null>;
}

/** 两个夹具的内容说明：记忆夹具里没有 .env，不能共用一句 */
const FIXTURE_CONTENTS = {
  main: '哨兵、虚构的对方审查件与假 .env',
  memory: '哨兵与项目记忆 CLAUDE.md',
} as const;

export function fixtureResidueText(kind: keyof typeof FIXTURE_CONTENTS, root: string, code: string): string {
  return (
    `⚠️ 探针夹具删除失败（${code}）：${tildeHome(root)} 仍在，` +
    `其中是探针写的夹具文件（${FIXTURE_CONTENTS[kind]}）与本次探测的临时文件，探针没有往里放真实凭据，请手工删除`
  );
}

async function removeFixtureRoot(kind, root): Promise<string | null> {
  const left = await tryRemoveTempDir(root, []);   // 没有凭据副本可查：不做现场查
  return left === null ? null : fixtureResidueText(kind, root, left.code);
}
```

两个工厂分别 `cleanup: () => removeFixtureRoot('main', root)` / `('memory', root)`。只删 `makeTempDir` 的返回值（2026-09-20 事故后的规矩，`tryRemoveTempDir` 文档块已写）。

**措辞与决策二原话的两处差异**（计划双审三侧均认可，收尾时向用户单独说明）：

- 原话「其中只有探针夹具文件（哨兵与假 .env）」——两处不成立：① 记忆夹具里没有 `.env`（§1 第 3 条），所以内容说明按工厂分开；② CLI 以夹具根为 cwd 运行，残留里还有它落的文件，「只有夹具文件」说过头（与 EV-200 代码双审 CODEX-02 ≡ GLM-01 同一关切），补「与本次探测的临时文件」。
- 原话「没有真实凭据」改为「探针没有往里放真实凭据」：夹具里的东西探针写得清楚，CLI 落的文件探针没有逐个看过；说「我们没放」是可核的事实，说「里面没有」是对 CLI 行为的断言。

### 2.3 codex 隔离探针（`probes/codex.ts`）

```ts
export interface CodexIsolationResult {
  isolation: ProbeIsolation;
  /** 临时目录删不掉时的提示；删成功为 null（EV-199，同 EV-198 旗标探针的 tempDirResidue） */
  tempDirResidue: string | null;
}

export function codexIsolationResidueText(dir: string, code: string): string {
  return (
    `⚠️ codex 隔离探针临时目录删除失败（${code}）：${tildeHome(dir)} 仍在，` +
    '其中只有探针写的 config.toml 与本次探测的临时文件，没有拷入凭据，请手工删除'
  );
}

/** 判定本体：原 try / catch（catch → 'shared'）原样搬进来，删除不在这里 */
async function judgeCodexIsolation(bin: string, dir: string): Promise<ProbeIsolation> { …原样… }

export async function probeCodexIsolation(bin: string): Promise<CodexIsolationResult> {
  const dir = await fs.mkdtemp(path.join(os.tmpdir(), 'trivium-codexhome-'));
  let isolation: ProbeIsolation = 'shared';
  let tempDirResidue: string | null = null;
  try {
    isolation = await judgeCodexIsolation(bin, dir);
  } finally {
    const left = await tryRemoveTempDir(dir, []);
    tempDirResidue = left === null ? null : codexIsolationResidueText(dir, left.code);
  }
  return { isolation, tempDirResidue };
}
```

`judgeCodexIsolation` 内保留原 catch → `'shared'`，判定本身不抛；finally 里不 return，万一将来判定改成会抛，异常照常上抛、不被删除收尾吞掉。

```ts

probe.isolation = iso.isolation;

```

### 2.4 五处接线怎么守（决策五待定项；r2 改，CODEX-01）

**主守法：假入口行为级用例（E 组），零配额。** r1 的「零配额跑不到 finally」与仓库事实相反（§1 第 8 条），撤回。

**通用摆锁法**：各家假入口不靠 cwd 找夹具，而是在被调到时扫 `$TMPDIR`（用例钉到本格私有根）下名字以 `trivium-probe-` / `trivium-codexhome-` 开头、还没有 `locked/` 的目录，在里面建 `locked/`、放文件 `f`、改 `0o500`。私有根里只有本格的目录，所以「扫到即本格夹具」；主夹具与记忆夹具先后存在（claude 主夹具 cleanup 之后才建记忆夹具），各自活着时被调到就各自上锁。由环境变量 `FAKE_LOCK` 开关；开了却一个也没锁到时假入口退 3、在 stderr 写原因，用例据此红，不静默通过。

- **E1** `probeClaude`（假入口照 `claude-structured-probe` 的装置写：`--version` 应答版本，`-p` 一律回通用成功事件流）：开锁时返回值 `notes` 里**恰有**一条主夹具提示、一条记忆夹具提示（各自逐字等于 `fixtureResidueText('main'|'memory', 路径, 'EACCES')`，路径由私有根重新列出），函数不抛、`probe` 照常返回。不开锁的对照格：`notes` 里没有任何「删除失败」字样，私有根下无残留。
- **E2** `probeAgy`（假入口：`--version`、`models` 应答，其余调用开锁后退 1）：开锁时 `notes` 恰有一条主夹具提示；对照格无提示、无残留。
- **E3** `probeZcode`（复用 `zcode-doctor-probe-home` 的 world 装置；具体走哪条早退分支在实现时按该装置的既有形态定，只要求夹具建成之后假入口至少被调一次）：开锁时 `notes` 恰有一条主夹具提示；对照格无提示、无残留。
- **E4** `probeCodex`（假入口：`--version` 应答；`debug models` 在 `CODEX_HOME` 指向隔离临时目录时退 1——对照翻转、判 `home_copy`——否则吐一份可解析的模型目录；`exec` 一类调用开锁后退 1；`CODEX_HOME` 钉到本格假家目录、里面放一份 `fake.config.toml`）：开锁时 `notes` 恰有一条主夹具提示与一条隔离探针提示（逐字等于 `codexIsolationResidueText`），`probe.isolation === 'home_copy'`（结论不因删不掉而改变，经 `probeCodex` 端到端）；对照格两种提示都没有、无残留。

**实现时的兜底规则**（如实承诺，不静默降级）：某一侧的假入口若因探针前置条件过多而无法在夹具活着时被调到，该侧退回 W1 的结构断言，并在测试文件头注释、报告「覆盖」一节与代码双审送审材料里写明是哪一侧、卡在哪一步——不在报告里把它写成行为级覆盖。

**补充守法：源码结构断言（W 组）**——便宜、不依赖假入口装置随探针演进而保持可用：

- **W1**（论域派生，CODEX-03）：读 `src/trivium/probes/` 下全部 `.ts`，取每一处 `.cleanup()` 调用，断言每一处都匹配 `const fixtureResidue = await <标识符>.cleanup();` 紧跟 `if (fixtureResidue) notes.push(fixtureResidue);`（中间只允许空白）；另断言全目录 `.cleanup()` 调用总数大于 0（防扫描写错而永绿），且每个文件里形态合格的调用数不少于该文件 `createFixture(` 与 `createMemoryFixture(` 调用数之和（建了几个夹具就要收几个）。不写死文件名与「5」。
- **W2**：`probes/codex.ts` 里 `probeCodexIsolation(bin)` 调用恰一处，且其后紧跟 `probe.isolation = iso.isolation;` 与 `if (iso.tempDirResidue) notes.push(iso.tempDirResidue);`。
- **W3**（论域内清零守卫，GLM-01、CODEX-02）：`src/trivium/probes`、`src/trivium/adapters` 两目录下全部 `.ts` 里，带 `recursive: true` 的 `fs.rm(` 调用数为 0。截取单次调用实参用**括号深度配平**（定位 `fs.rm(` 后按深度计数到配平的闭括号），不用单层正则。断言消息写明论域是「probes 与 adapters 两目录」，不说「全仓」。W3 自带两条自测：负例——源码串 `await fs.rm(path.join(a, b), { recursive: true, force: true });` 必须计为 1；正例——`codex-home.ts:177` 形态 `await fs.rm(path.join(codexHome, name), { force: true });` 必须计为 0。

### 2.5 单测（`test/unit/probe-fixture-cleanup.test.ts`，零配额）
