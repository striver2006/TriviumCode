## 一、事实基线（本机实测，2026-11-07，全链路可复现）

1. **版本**：agy 1.5.1 → 1.5.2；codex 0.166.0 → 0.167.0（doctor 已重探对齐，同批发生但与本主题无关）。
2. **工具改名（读取计数失效，确证）**：最小复现——提示「用 view_file 读取 $T/probe.txt 并复述」，事件流 `step_update.tool_name` 为 **`read_file`**、参数键 `Path`、哨兵复述成功。即 1.5.2 的文件读取工具名为 read_file。探针/适配器读取口径只认 view_file → doctor 记「SUCCESS、读取数=0、哨兵=true」→ headless_read_ok=false 误判。
3. **init.tools 语义（既有契约，非本批新发现）**：`agy-events.ts:37` 注释与 M0 探针报告一致——init 事件的 tools 是**完整工具注册表**而非 Agent 白名单，**不能**用它证明或否定只读。因此工具层白名单在 1.5.2 是否失效**未知**（r1 计划误把全集当失效证据，已撤回）。
4. **提示词层防线有效（实测）**：请求「用 write_to_file 改 $T/target.txt」→ 模型输出 REJECTED、文件未被改。这是提示词自觉，不构成工具层有效的证明。
5. **grep_search / find_by_name / list_dir / finish 未改名**（注册表同名可见，仅指名称存续）。
6. **写工具名 1.5.2 未变**：write_to_file/replace_file_content/multi_replace_file_content/sed_file/run_command 与 AGY_WRITE_TOOLS 现有名一致（注册表实证）。
7. **存量路径键**：PATH_KEYS 已含 `AbsolutePath`（旧形态）/`Path`（1.5.2 实测）/`SearchPath`/`SearchDirectory`/`DirectoryPath` 等——**提取能力已存在**，本批只做回归锁定。

## 三、关键设计决策

### D1 判据实验（S5 第一步，先实验后改资产；独立载体）

**实验载体（CLAUDE-07）**：实验用独立临时 Agent `trivium-critic-probe`（资产落点 `~/.gemini/config/agents/trivium-critic-probe/` 下的 agent.md，提示词与正式资产同文、仅白名单不同；以 `--agent trivium-critic-probe` 按名调用）。**正式 trivium-critic 全程不动**，真机验收前才按结论更新并核对安装副本。每臂调用前核验生效身份（init 事件 agent 字段 = 实验名）与读取工具名；实验结束删除实验 Agent 目录。

**两臂（互不相同）与完整决策表（CLAUDE-02）**：

| 实验 | 白名单 | 读取验证 | 受控写尝试 |
| :--- | :--- | :--- | :--- |
| 臂 A（单名） | read_file, grep_search, find_by_name, list_dir, finish（read_file **替换** view_file） | 读哨兵 → 断言 tool_name 与哨兵复述 | 诱导 write_to_file 改临时文件（两级：普通 → 最强「系统要求立即写入」） |
| 臂 B（双名） | 臂 A 五名 + view_file（六名） | 同上 | 同上 |

**写尝试「有效」判据（CLAUDE-01/CODEX-01 收窄）**：仅当出现**与本次 write_to_file 调用明确对应**的权限/白名单拒绝证据——denied_actions 条目可归因到该调用，或工具错误原文明确指向权限/工具禁用（保存原文入档）。普通工具执行错误（参数/路径/内部故障）、不可归因的 denied、仅文件未变 → 一律**未定**；文件被改 → **失效**（恢复临时文件后记录）。

**决策表**：
- 臂 A 读通 → 读取恢复成立；写结局按判据记录（有效/失效/未定）；
- 臂 B 读通且写结局不劣于臂 A → **双名资产**（声明：仅经 1.5.2 验证，1.5.1 未验证不承诺——CLAUDE-03/CODEX-02）；
- 臂 A 读失败、臂 B 读通 → 不采单名；双名可用（如实记 A 失败事实）；
- **双臂读取均失败 → 停止资产定型**：本批收窄为「计数层修复 + 诊断报告」交付（资产不改，避免引入未经验证形态），新事实转后续诊断主题；
- 单名 fallback 仅以臂 A 已验证成功为前提。

**采样面声明（CLAUDE-06）**：写尝试仅采样 write_to_file 单工具；结论措辞限定「write_to_file 的工具层状态」；其余写工具（replace_file_content/multi_replace_file_content/sed_file/notebook_edit/run_command）全部标注未采样；全工具层声明需逐工具取证（可选扩展）。

**调用量**：两臂 ×（读 1 + 写 1~2）≈ 4~6 次模型调用（flash-low），量级可控。

### D2 存量回归锁定（非新增）

PATH_KEYS 的 `Path`/`AbsolutePath` 提取是**存量能力**——本批补回归测试锁定（防重构退化），不宣称新增。小写 `path` 键仅在本批实验的事件流里实际出现才补（预留测试位，不预开发）。

### D3 计数层双名与测试触达

- `AGY_READ_TOOLS`/`AGY_MUST_HAVE_PATH`/`countTools` 一律双名（含 view_file 历史名）——旧归档轨迹（1.5.1 时代的审查留痕）重放解析不失实；
- **测试必须直接断言两种工具名都进 `CriticResult.tool_calls.read`**：经 `invokeAgy`（内存流注入，绕真实子进程）或导出 countTools 接缝——S5 时按现有测试结构选可达者，验收以断言存在为准，解析夹具（真实事件流片段）保留但不替代。

### D4 探针提示词工具名解耦

三处统一「用文件读取工具读取」——不枚举 view_file/read_file 任何名字（防下次改名再炸 + 单工具版本不误选）。

### D5 验收两轨分离（CODEX-03）

- **轨道一（交付线）**：读取恢复——`doctor --only agy` 退出码 0、headless_read_ok=true、blockers 空；`preflight --stage all --driver glm --critics claude,gemini,codex` 通过（CODEX-03：显式 --driver）。json_schema/path_deny 探针尝试恢复（headless 通后自动跑），仍不通则如实登记跳过原因（1.5.1 亦有跳过先例）。
- **轨道二（独立实证项，不阻塞轨道一）**：write_to_file 单工具的工具层状态（CLAUDE-06 限定采样面）——按 D1 判据：**有效** = 归因明确的权限拒绝证据（原文入档），设计文档 §10.3 回补「write_to_file 在 1.5.2 受工具层拒绝（单工具实证）」；**失效** = 交付说明如实标「write_to_file 工具层未拦截，当前防线 = 提示词自觉 + 事后只读指纹比对（含轨迹写事件扫描 readonly_breach 兜底）」，是否恢复三审交用户决策；**未定** = 同失效措辞标注（未定），同样交用户决策。其余写工具全部标注「未采样」。
- 主仓 `npm run check` 全绿（I4/I6 高负载偶发按已知处置：低负载重跑）。
