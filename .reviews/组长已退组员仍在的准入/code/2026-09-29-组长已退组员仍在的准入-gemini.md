### AGY-01 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `test/integration/gate-loop.test.ts:3306-3312` |
| 类别 | test-gap ｜ 层次 code |
| 置信度 | high |

**问题**：集成测试 K5 与 K6 在制造孤儿组时，直接对组长执行 killLeaderOnly(glmPgid)，未先等待 sleep 子进程派生完成（groupMemberCount >= 2）；随后紧跟 for (let i = 0; i < 40 && n === 0; i++) 循环等待 n > 0。已被 SIGKILL 的组长 sh 不可能在死后继续派生 sleep 子进程，若在极高负载下杀组长过早导致组员尚未诞生，该循环等待毫无意义且必然超时报错，存在偶发红（flaky）风险。

**依据**：查阅 test/unit/scrub-admission.test.ts:129-131（明确要求 untilMemberCount(g.pgid, (x) => x >= 2) 必须在 killLeaderOnly 前完成）与 test/integration/gate-loop.test.ts:3306-3312、:3356-3358。K5/K6 在 killLeaderOnly(glmPgid) 之前未做 groupMemberCount >= 2 的前置断言，且在杀掉组长后执行 for (let i = 0; i < 40 && n === 0; i++)。

**建议**：在 K5 和 K6 调用 killLeaderOnly(glmPgid) 前，增加对 groupMemberCount(glmPgid) >= 2 的前置轮询等待，确保子进程已在组内运行；同时移除杀组长之后等待 n === 0 变为 > 0 的无效重试循环。

### AGY-02 · 吹毛求疵（nit）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/run-protocol.ts:799` |
| 类别 | maintainability ｜ 层次 code |

**问题**：terminateRecordedCliGroups 的文档注释残留了旧版 EV-154 的自相矛盾表述：「isGone 对 alive 来源按组长判：组长服从 SIGTERM 而组员忽略时不升级（这一格 judge 会返回 orphaned，isGone 仍为假，继续升级……）」。句中「不升级」与括号内的「继续升级」直接矛盾。代码中 isGone 始终调用 judge(r)，在组长退出时会检查非僵尸成员数（返回 orphaned），使 isGone 为假并升级至 SIGKILL，不再是只按组长判。

**依据**：查阅 src/trivium/run-protocol.ts:799-802 与 :824-827，以及 test/unit/cli-group-record.test.ts:218-241（U15 变体测试明确断言组长退出后因成员仍在会升级 SIGKILL，不再停在 SIGTERM）。

**建议**：清理 :799 的自相矛盾表述，删去「按组长判……不升级」等旧版本残留，明确说明无论入判来源是 alive 还是 orphaned，只要组长已退且成员非僵尸计数 > 0 均返回 orphaned，并在宽限期内升级 SIGKILL 直至成员归零。
