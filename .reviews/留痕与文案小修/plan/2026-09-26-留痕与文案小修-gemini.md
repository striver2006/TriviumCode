**问题**：计划关于跑后漂移复算能力的现状依据与拟定新文案失实：将跑后漂移复算写成了「只比已跟踪文件」，并将该限定写入面向用户的入口资产与 QUICKSTART 文案中。实际上 `workTreeHash` 会将未被 `.gitignore` 忽略的所有未跟踪新增文件一并纳入比对，漂移复算完全能够检测到未跟踪文件。文案若断言「只比已跟踪文件」，不仅低估了系统的实际防御能力，而且会误导执笔者以为在审查期间新建未跟踪业务文件不会被漂移复算拦截。

**依据**：计划 §4.1 依据栏与 §4.3 D2（l2-notice.md）、D5（QUICKSTART）文案草案中均断言跑后漂移复算「只比已跟踪文件」。查阅 `src/trivium/util/git.ts` :50-66：`workTreeHash` 是在临时环境中通过 `git read-tree HEAD` 与 `git add -A -- .` 构建临时索引并 `write-tree`，代码注释明确注明「用临时索引计算当前工作树（含未跟踪文件）的 tree hash」；在 git 中 `git add -A` 会把未被 `.gitignore` 忽略的新增未跟踪文件同样加入索引。在 `src/trivium/freeze.ts` :528-536 中，`diffTrees` 比较前后 `treeHash` 能够检测到这些未跟踪的新增业务文件。经查，计划中的「只比已跟踪文件」系采信了 `src/trivium/gate.ts` :330 处的一句历史注释（「judgeDrift 是 git 树比对，只看已跟踪文件」），而该注释本身是不准确的描述（提交锚才只看已跟踪文件）。

**建议**：修正计划 §4.1 现状表、§4.3 D2 草案及 D5 QUICKSTART 修订项，删除「只比已跟踪文件」的错误描述，改写为「基于工作树比对（未被 .gitignore 忽略的文件均在比对范围内）」或直接使用「跑后漂移复算会发现（.gitignore 之外的文件）」；同时建议在实施时顺带更正 `src/trivium/gate.ts` :330 处的不准确注释。
