### CODEX-01 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `被审计划 §4.1 首行、§4.3 D2 草案第一条、§4.3 D5 第 1 项（QUICKSTART :320）` |
| 类别 | correctness ｜ 层次 plan |
| 置信度 | high |

**问题**：「跑后漂移复算……只比已跟踪文件」这一口径与实现相反：漂移复算的两侧哈希都是 workTreeHash()，它以 HEAD 填临时索引后 `git add -A` 再 write-tree，**未跟踪文件同样被算进来**，因此「审查进行中新建一个未跟踪业务文件」今天就是会被发现的。真正不在覆盖面上的应当写成：被 .gitignore 忽略的文件、编排器排除的归档根与 .trivium/、以及 probe 声明的 cli.scratch_paths。按现草案落地会把「能发现」写成「发现不了」（低估），同时把 ignored 文件这一真实盲区藏起来（误导），正是 EV-132 要消除的那类失实；而这句话要进 12 份渲染产物 + driver.snippet（再触发指纹追加与原位升级），改错的返工成本很高。

**依据**：读 src/trivium/util/git.ts:50-70（函数头注释逐字为「计算当前工作树（**含未跟踪文件**）的 tree hash」，实现是 read-tree HEAD → add -A → write-tree）；src/trivium/freeze.ts:432（快照基线同样用 workTreeHash）与 :518-542（judgeDrift 用 diffTrees(before.treeHash, afterTreeHash)，仅剔除 scratchGlobs 与归档根/.trivium）；src/trivium/review.ts:1083（收尾 afterTreeHash = await workTreeHash）；src/trivium/guard.ts:631 + src/trivium/config.ts:81（scratch_paths 缺省 []）。被误取的「只看已跟踪文件」出自 src/trivium/util/git.ts:314-330 的 deletedOrModifiedTracked，它的唯一调用点是 src/trivium/hooks.ts:1306-1319 的提交锚 checkArchiveIntegrity，与漂移复算不是同一条路径。另 grep doc/07_manuals/QUICKSTART.md 与 doc/04_development/GUIDE_env_setup.md 均无「已跟踪」字样，说明这句是本次新引入的表述。

**建议**：把这一档改成按实现写实的两面：能发现（改动/新建的未跟踪文件也算）、发现不了（.gitignore 忽略项、归档根与 .trivium/、probe scratch_paths），并在 §4.1 表里把「依据」从 freeze.ts 的哈希来源改成 util/git.ts 的 workTreeHash 那一处，避免实施时又照漂移函数反推出同一句错话。
