# 接入路由实施计划

日期：2026-10-09；Driver：codex；M11 第 12 步全量验收的前置任务之一。

## 目标与边界

执行用户批准的「Codex、Claude Code 双模式接入与异构判定修正」。本主题负责配置、档位与单次旗标解析，以及 Claude 的 cld 启动接线；探针认证和 run.v3 由另外两个主题负责。Agent 身份保持不变，供应商不成为新 Agent。软件版本号由用户控制，提交、推送待用户确认。未启动新的正式审查前不得改业务文件。

## 已核实事实

本机 Claude 2.1.295、Codex 0.162.0-alpha.17.2。cld 是用户 bash 包装脚本：支持 `--profile`、检查 `~/.claude/profiles/<name>.env`、source 后 exec 原生 Claude。`-p` 与打印模式有歧义，故编排器使用 `cld --profile <name> --print`。三个 profile 的默认模型分别是 qwen3.8-flash、kimi-for-coding、deepseek-flash；Qwen 的 Opus 映射为 qwen3.8-max。这些仅是启动配置声明，未证明服务端生效值。官方 Claude 当前不可用，保留实现和离线验证，真实验收标记待订阅恢复。

## 契约与实现

1. 先将接入契约并入主设计 §3.5、§11.1、§11.5、M11 章节；新 ADR 解释编程工具身份与接入方式分离。事实能力表测后回填，不伪称已经实现。同步协议、CLI 使用说明与 AGENTS。主设计仍是唯一规范。
2. `agents/registry.ts` 新增 profile 能力声明，Claude 与 Codex 声明支持；适配器 hook 与声明机器对账。其它模块按能力分支，不按具体 Agent id 或厂商字面分支。
3. `ClaudeCriticConfig` 增加 `profile?: string|null`、`bin?: string|null`、`profile_bin?: string|null`；档位的 profile 允许 null。config.v2 的判别联合与两段式身份校验保持。配置缺席或 null 走 native；档位字段缺席继承、null 清空。
4. `--profile-<id> <名称>` 用于 profile，新增 `--native-<id>` 布尔旗标。两者同侧冲突、缺值、不支持 profile 的侧均退 64。保留通用 `--profile` 的档位语义，避免混淆。接入优先级 CLI > 档位条目 > Agent 配置；模型和 effort 各自解析，切入口不暗改模型。
5. `tier-flags.ts`、`topic-args.ts`、`cli.ts`、`adapters/base.ts` 一起接线，显式 native 以 null 保留存在性，resolve 输出、preflight、review start、worker 重建均消费同一结果。已有模型来源、effort 来源、覆盖审计语义保留。
6. Claude 适配器保留原只读参数、stdin、MCP 隔离、禁读清单、输出 Schema、超时取消进程树清扫。路由对象包含 mode/profile/model/effort、实际执行路径、原生 CLI 与包装器指纹。profile 模式向 cld 传完整长旗标前缀；native 路线绝不隐式回退到 profile。
7. 子进程清理冲突 ANTHROPIC/CLAUDE 路由认证变量，再由显式路线加载；不改全局配置，不打印密钥或完整 profile。将 env/prefix 在全部 invoke 路径传入（正常、探活、探针）。日志对错误输出脱敏。
8. Claude 模型从 init 事件回读；provider、effort 没证据则 null。profile 配置仅声明来源。留痕字段在第三主题统一落 run.v3，不把配置供应商伪装成实际回读。

## 验证与完成条件

用现有 raw CLI fixture 扩展 null/继承/优先级、native/profile 冲突、能力声明对账、wrapper argv/stdin/env、模型切换独立性测试。起真实桩子进程证明 resolve → preflight → review → worker 到执行端，断言 stub 指纹。失败、超时、取消保留请求路线，凭据不进入输出。Antigravity、ZCode 回归。关键接线通过变异验证。

本主题完成后正式代码审查、逐条裁决、修复及 verify；完整项目串行两次 npm run check 与 14 步桩自检归总体验收。本机绝对路径只写本机配置，Qwen 模型与三审恢复须等第二主题真实准入；真实探针和验收共 48 次 CLI 启动上限，四批每批 12 次，审查另算每主题最多四轮。不能通过时如实记录未测或失败，不降判据，不自动换路线。
