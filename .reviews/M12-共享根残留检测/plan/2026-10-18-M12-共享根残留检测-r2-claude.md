## 1. 问题与现状（源码核实）

- 判定核心 `scanEntryCollisions`（`src/trivium/entry-collisions.ts:90-108`）对每个目标：先在**安装根顶层**按 `residueNames` 见名即判 `residue`（`:93-96`），再对每个入口名 × 每个读取根判 `foreign-entry` / `third-party`（`:97-105`）。共享根里的 `dual-critic` / `entry` 不在任何一条判据里。
- 安装器 `checkInstall`（`src/install.ts:269-287`）只对 `layout === 'entry'` 的家传 `RESIDUE_NAMES`（`:62`，`[path.basename(RUNTIME_SRC), ENTRY_SUBDIR]`），`readRoots` 是完整读取面（安装根 + 额外读取根）。
- 编排器侧 `sharedReadRootTargets`（`entry-collisions.ts:140-154`）给 doctor（`doctor.ts:585`）与 preflight（`preflight.ts:851`）构造目标，`readRoots` 只含额外读取根，`residueNames: []`（批次 5 计划 r2 T-3）。
- 运行时根身份行今天只在安装器里：`RUNTIME_IDENTITY`（`install.ts:128`）与 `isOurRuntime`（`:163-169`），用于 `runtime-foreign` 判定（`:159`）、缺省位置旧运行时提示（`:377`）与卸载（`:466`）。
- 10-16 的实例：Codex「从 Claude 导入」在 `~/.agents/skills/` 下留了一棵运行时根拷贝（`SKILL.md` 身份行为 `dual-critic`，含 `scripts/` 与 `schema/`，不含 `entry/`），当时安装器只读检查报出的 14 个问题全是同名入口，这棵拷贝一条没报（BACKLOG EV-240 行）。

## 2. 改动面

### 2.1 共享模块 `src/trivium/entry-collisions.ts`

- 类型：`EntryCollisionKind` 增加 `'shared-residue'`。
- 常量：`RUNTIME_ROOT_NAME = 'dual-critic'`、`RESIDUE_DIR_NAMES = [RUNTIME_ROOT_NAME, 'entry']`（D-7）。
- 新函数 `hasRuntimeIdentity(dir, runtimeName)`：`dir/SKILL.md` 以 `---\nname: ${runtimeName}\n` 开头（读不到即否）。**安装器的 `isOurRuntime` 改为调用它**（传 `path.basename(RUNTIME_SRC)`），`RUNTIME_IDENTITY` 常量随之删去；三处调用点（`:159`、`:377`、`:466`）不改。判据逐字不变，只是挪到共享模块，让「运行时身份行」只有一份实现。
- 新函数 `isResidueCopy(dir, entryNames = ENTRY_SKILL_NAMES)`（D-2，AGY-02）：①`hasRuntimeIdentity(dir, RUNTIME_ROOT_NAME)` 且 `dir/schema` 是目录；或 ②对 E ∈ {dir, dir/entry}：E 是目录时列一层子目录 c，对每个 n ∈ `entryNames` 查 `isOurEntry(E/c/n, n)`，任一为真即真。只读；`readdir` 失败（不存在、不是目录、无权限）一律当「否」，不抛。
- 新函数 `selfRuntimeRoot(argv1 = process.argv[1])`（GLM-02）：`argv1` 的文件名为 `trivium.cjs` 且父目录名为 `scripts` 时返回祖父目录，否则 `null`。测试进程里 `argv1` 是测试文件，恒为 `null`；单测经参数注入。
- 新函数 `realpathOr(p)`（AGY-03）：`fs.realpath(p)`，失败退回 `path.resolve(p)`。候选目录一定存在，可直接取真实路径；豁免路径不存在时不可能与存在的候选同一处，退回字面不影响结论。安装器的 `realOrResolved`（`install.ts:105`）不挪，`runtime-overlap` 判定不受影响。
- `EntryScanTarget` 增加两个**可选**字段（CODEX-01 / GLM-01 / AGY-01）：
  - `sharedResidueNames?: readonly string[]`：在额外读取根里按内容判 `shared-residue` 的候选名；缺省按 `[]` 处理，即不查。
  - `exemptPaths?: readonly string[]`：真实路径与其中任一的真实路径相同的候选目录不判（D-6）。
- `scanEntryCollisions` 每个目标的次序改为：①安装根残留（`:93-96`，**逐字不变**）→ ②**新**：对 `readRoots` 中 `r !== t.skillsRoot` 的每个根、`t.sharedResidueNames ?? []` 里的每个名字，候选存在、真实路径不在豁免里、`isResidueCopy(候选, t.names)` 为真 ⇒ 推 `{ kind: 'shared-residue' }` → ③同名入口（`:97-105`，**逐字不变**）。共享根没有候选、或目标不带新字段时，输出与今天逐项相同。
- `sharedReadRootTargets(agents, se, self = selfRuntimeRoot())`：每个目标加 `sharedResidueNames: RESIDUE_DIR_NAMES`、`exemptPaths: [resolveAssetRoot(undefined, se.env, se.home), self]`（`self` 为 `null` 时不放）；`residueNames` 仍为 `[]`。
- 短标签表加一项：`'shared-residue': '本产品运行时或入口子树的整棵拷贝（多半是别的工具导入时带进来的）'`；原三项逐字不变。
- 渲染（D-4）：
  - `describeSharedRootProblems`：按类别分两组。同名入口组非空时，**原标题行与逐行列表逐字照旧**；残留组非空时另起一段，标题「共享读取面里有 N 份本产品的历史拷贝（运行时根或入口子树，不随安装更新；带入口子树时会把别家的入口调出来）：」，逐行「`· 〈~ 路径〉  〈标签〉（〈各家显示名〉 会读到）`」；末尾出口句 `SHARED_ROOT_EXIT_HINT` 只出现一次。只有同名入口时，输出与今天逐字节相同。
  - `summarizeSharedRootProblems`：计数短语按组拼——只有同名入口「N 个同名入口」（今天的原文）；只有残留「M 份本产品的历史拷贝」；两者都有「N 个同名入口、M 份本产品的历史拷贝」；其余措辞不变，仍是一行。
  - 文案里不写小写 Agent id（`registry-parity` 的 grep 对账），会读到的家用注册表显示名。

本模块仍**不得 import `src/install.ts` 或 `src/entry-render.ts`**；`resolveAssetRoot` 来自 `src/trivium/asset-root.ts`，安装器已经引用它。

### 2.2 安装器 `src/install.ts`

- `checkInstall(selected, runtimeRoot?)`：新增可选第二参。每个目标加 `sharedResidueNames: RESIDUE_NAMES`（**所有目标都传**：新判定只看额外读取根，与 `layout` 无关；claude、gemini 没有额外读取根，传了也不查）、`exemptPaths: runtimeRoot ? [runtimeRoot] : []`。`residueNames` 那一行与注释逐字不变。安装器侧不加 `selfRuntimeRoot`：安装器从仓库的 `dist/install.cjs` 跑，不在运行时根里。
- `install()`（`:365`）调用时传 `plan.runtimeRoot`。
- `describeProblems` 的 `why` 加一项：`'shared-residue': '共享读取面里有本产品运行时根或入口子树的整棵拷贝（多半是别的工具导入时带进来的）：它不随安装更新，codex、zcode 都会读到；带入口子树时还会把别家的入口调出来'`。原六项与首尾两行逐字不变。
- 退出码：新类别与既有冲突走同一条 `InstallConflictError` 路径（退 1），一个文件都不写、不删。
- 同一个共享路径会按读到它的家各报一条（与今天 `foreign-entry` 在 codex、glm 各报一条同一口径）。
- `isOurRuntime` 改为调共享模块的 `hasRuntimeIdentity`（§2.1）。

### 2.3 `scripts/install-check.mjs`

- `checkInstall(plan.targets, plan.runtimeRoot)`：补传运行时根，豁免口径与真装一致。
- 标签仍从安装器产物取，新类别自动带出；无问题时的 ✓ 行、有问题时的行格式与退出码（0 / 1 / 2）都不变。

### 2.4 doctor / preflight

- 调用点（`doctor.ts:585`、`preflight.ts:851`）**不改**：新判定经 `sharedReadRootTargets` 进入，三处仍是同一份 `scanEntryCollisions`。
- doctor：仍只进 `warnings`、不进 `blockers`，退出码不变，与 `--only` 无关。
- preflight：仍是 `checkSharedReadRoots` 那一项，恒 `ok: true`、不带 `exitCode`；「本轮相关」仍是当轮 Driver ∪ 入选审核者里登记了额外读取根的家（批次 5 T-4），只扫这些家的额外读取根。只有残留、没有同名入口时也出这一项。
- 扫描家目录仍经 `entryScanEnv` 单一来源（注入口 → `TRIVIUM_ENTRY_SCAN_HOME` → `os.homedir()`）；豁免用的运行时根也按这份 `home` / `env` 求值，测试里不会读到真实家目录。

## 7. 不做与缺口

- 不删任何东西：安装器、`install:check`、doctor、preflight、卸载都只报不删。
- 安装根的 `residue` 不改成内容判据（D-5）。
- `review --start` 仍不跑这条检查（批次 5 T-5）。
- 共享根里**不叫** `dual-critic` / `entry`、但内容是本产品运行时的拷贝（被改名的拷贝）不判：要判就得遍历共享根的每个子目录、逐个读内容，扫描面与误判面都扩大；10-16 的实例与安装根历史残留都是原名。登记为缺口。
- 判据边界：别家 skill 若恰好同时满足「首键 `name: dual-critic` 且带 `schema/`」，或在 `entry/〈x〉/dual-*/` 下放了调用 `.trivium/bin/trivium` 的同名 skill，会被判为本产品残留——后者与 `isOurEntry` 已接受的边界相同（批次 5 代码双审 GLM-04）。
- 豁免边界（GLM-02 剩下的情形）：一份运行时既不是当前进程所在、扫描时也没设 `TRIVIUM_ASSET_ROOT` 指向它，却放在共享根里且仍在服役（例如经别的入口调用），doctor / preflight 会把它报成残留。只进告警、不阻断；安装器在安装场景内环境一致，不受影响。

## 8. 风险

- **误伤别家同名 skill**：两条内容判据都要求本产品特有的结构（身份行 + `schema/`，或调用 wrapper 的入口子树）；U1 ④⑤⑥、U5 ②、A-1 的「别家 `entry`」格守住。
- **安装根口径漂移**：新循环显式排除 `skillsRoot`，变异 ① 守住；既有用例一条不改。
- **豁免失灵导致活运行时被拒装或误报**：U2 ④、U3、U5 ③、A-1 / A-2 对应格守住；安装器与编排器用同一个 `resolveAssetRoot` 求值，编排器另加自身产物所在根。
- **安装器口径收紧**：今天能装上的机器，共享根里若有认定的残留，升级后会整次拒装——这正是任务目标要的行为；拒装文案点名路径，出口与同名入口相同（手工挪走后重装）。
