**问题**：SelftestResult.fixtureRoot 是双态字段但无注释：建夹具失败且删不掉时它是 mkdtemp 父目录本身（catch 分支 fixtureRoot 填 made.dir，S1 用例锁定这一形态），成功跑完时它是父目录下的 repo/ 子目录（finish 分支填 root）。紧邻的 runRoot 字段有注释说明''的含义，fixtureRoot 却没有；后来者很容易按字段名以为它恒指夹具仓库，在新增消费方（比如未来把失败时的保留路径拿去渲染或删除）时用错形态。

**依据**：src/trivium/selftest.ts:249-262 的 catch 分支 fixtureRoot 填 made.dir（父目录），而 :445-458 的 finish 分支填 root（base/repo）；test/unit/temp-index-cleanup.test.ts:258-262（S1）断言失败态 fixtureRoot 的 dirname 等于私有 TMPDIR 即父目录形态；:295（S5）断言成功态是 /t/trivium-selftest-abc/repo。

**建议**：给 fixtureRoot 补一行注释，写明两种形态各在什么分支出现（建夹具失败时为父目录或空串、成功后为父目录下的 repo），与 runRoot 的注释风格一致。

## 认为正确的部分

- 父目录结构（repo/ 与 runs/ 同在一个 mkdtemp 目录、收尾只删父目录）是对「删除只认 mkdtemp 返回值」规矩的正确解法：拼出来的兄弟目录不能删，改结构后父目录登记与删除都落在返回值上，两侧实现一致。
- makeFixture 的登记时序正确：FIXTURE_BASES.push 紧跟 mkdtemp 的 await、在 realpath 与一切可能抛出的写盘之前，FC4 以 topic 含 NUL 在 stageDir 写盘处注入建到一半失败并被变异 H5 咬住；退出钩子经 exitCleanupArmed 只挂一次。
- 退出挂点不选 node:test 的 after 的理由充分（helper 被 5 份验收脚本 import，普通脚本里 after 会起测试 harness 污染 stdout），保留变量 TRIVIUM_KEEP_FIXTURES 提供了排查逃生口且 FC2 验证提示形态。
- warnLine 用同步 writeSync(2) 且整体包 try/catch 永不抛，规避了 macOS 上 stderr 接管道时异步写在退出时刻丢行、以及异常穿出退出处理器改写退出码两个坑。
- FC 用例在子进程里跑 node --test 并摘除继承的 NODE_TEST_CONTEXT（否则子进程判为递归调用、跳过全部文件且退 0），这一坑被实测发现并写进注释与报告，避免了用例对空跑子进程断言的假绿。
- selftest 侧三个 return 分支的 runRoot 赋值形态一致（两个早退为空串、finish 为 runs），renderSelftest 保留支的同父判定不依赖调用时序（显式比对两个 dirname），S5 锁定同父、不同父、runRoot 为空三态。
- ST2 的摆锁从「第几个临时索引」改为按进程身份（PPID 链上找 review --worker）且 git 配置改走 GIT_CONFIG_GLOBAL 全局配置文件、锁落在父目录的工作树之外，注入不再依赖 --start 与 worker 的冻结顺序；该文件与 worktree-hash-cleanup 的过滤器脚本各自的前提断言（filter-ran 标记）都在。
- 8 处 -runs 拼接改为 fx.runRoot 且经产品 repoId 拼桶，gate-loop 的 precreateRunDirs 与 statusJsonOf 改收 Fixture 后仍与 CLI 用同一个 realpath 形态的 root 计算 repoId，桶名跨进程一致；测试无桶名字面断言。
- 报告与文档诚实：变异轮多留的 12 个 trivium-selftest- 目录如实披露并归因（M1/M2 各两轮）、存量三个前缀的处置交给用户、单测自建临时目录（EV-208）与 initFixtureRepo 不查退出码（EV-209）如实另登、计划双审为降级轮次（codex 缺席）的盲区写明。
