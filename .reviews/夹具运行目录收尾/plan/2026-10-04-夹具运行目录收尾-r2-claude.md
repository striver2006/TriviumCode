## 2. 设计

### 2.1 自检（`selftest.ts`）

```text
trivium-selftest-XXXXXX/      ← mkdtemp 返回值，made.dir，唯一删除目标
├── repo/                     ← 夹具仓库（fixtureRoot），git init 在这里
└── runs/                     ← 运行根（runRoot），buildFixture 预建
```

- `buildFixture(made, init)`：`raw = mkdtemp(...)`、`made.dir = raw`（不变）；`base = realpath(raw)`；`root = base/repo`、`runs = base/runs`，两者都 `mkdir`；配置写 `run_root: ${runs}`；返回 `{ root, runs }`。预建 `runs/` 是为了保留提示里给出的路径恒存在（第①步就失败时运行根可能还没被编排器建出来）。
- `SelftestResult` 新增 `runRoot: string`（没建出来时为 `''`）；`fixtureRoot` 语义不变（夹具仓库路径，现为 `base/repo`）；建夹具失败且删不掉时 `fixtureRoot` 仍给 `made.dir`（父目录，同 EV-204）。
- `finish` 与建夹具失败那一处**不变**：仍只删 `made.dir`——它现在就是父目录，夹具仓库与运行根一起走。
- **残留提示**（`selftestResidueText`，措辞覆盖两者，决策一）：
  `自检临时目录删除失败（<错误码>）：<路径> 仍在——自检只往里写了夹具仓库（含本次自检的审查留痕 .reviews/）与本次自检的运行目录（worker 日志、交接文件与状态文件），没有凭据，请手工删除`
  主语仍是「自检只往里写了…」（EV-204 口径：不断言目录全貌）；开头由「自检夹具目录」改为「自检临时目录」，因为删的不再只是夹具。
- **保留提示**（`renderSelftest` 的 `kept` 支）：第一行不变（`夹具保留在 <repo>`）、后两行不变，`runRoot` 非空时末尾补一行：
  `  本次自检的运行目录（worker 日志、交接文件与状态文件）在 <runs>；两者同在 <父目录> 下，排查完删这一个目录即可。`
  `<父目录>` 取 `path.dirname(runRoot)`，**只在它等于 `path.dirname(fixtureRoot)` 时**打「两者同在…」那半句，否则只打到 `<runs>`（AGY-03：不靠调用时序保证 dirname 恰好是父目录）。只用于显示，不作删除依据。
- 文件头注「跑完即删」、`buildFixture` 注释里「运行目录放到夹具旁边」两处按实改写。

### 2.2 `makeFixture`（`test/helpers/fixture.ts`）

```text
trivium-fx-XXXXXX/            ← mkdtemp 返回值，登记进 FIXTURE_BASES，进程退出时删
├── repo/                     ← fx.root
└── runs/                     ← fx.runRoot（不预建，保持与现状相同：由编排器按需建）
```

- `raw = mkdtemp(path.join(os.tmpdir(), 'trivium-fx-'))` 之后**立即**登记 `FIXTURE_BASES.push(raw)`（在任何可能抛出的写盘之前——建到一半抛出也会被收尾）；`base = realpath(raw)`；`root = base/repo`（`mkdir`）、`runRoot = base/runs`。
- `Fixture` 新增 `runRoot: string`；配置写 `run_root: ${runRoot}`；注释里 M20 那段按新结构改写。
- 不预建 `runs/`：现状下 `${root}-runs` 也是由编排器按需建的，`no-artifacts` 等用例对「运行根不存在」时 `listFiles` 返回空有依赖面，保持不变。
- **进程退出收尾**（模块级，首次 `makeFixture` 时挂一次 `process.on('exit', …)`）：
  1. 提示一律经 `warnLine(text)`：`try { fs.writeSync(2, text + '\n') } catch {}`——stderr 已关闭或管道破裂时最多丢一行，不让异常穿出退出处理器、不改退出码、不中断后面的删除（GLM-04）。
  2. 设了 `TRIVIUM_KEEP_FIXTURES=1`：不删，`warnLine` 打一行 `makeFixture：TRIVIUM_KEEP_FIXTURES=1，保留本进程的 N 个夹具目录：<路径>、<路径>…`。
  3. 否则逐个父目录各自包一层 try/catch：
     - 权限恢复 `unlockSync(dir)`：**进入每一层（含父目录自身）先 `chmodSync(dir, 0o700)`、再 `readdirSync(withFileTypes)`**，只对 `isDirectory()` 为真的条目递归（软链不跟随）；`chmod` 与 `readdir` 每一步单独 try/catch、一律吞掉（AGY-01 / AGY-02：它只是删除的准备，目录已不在或读不了都照样去删）；
     - `rmSync(dir, { recursive: true, force: true, maxRetries: 3 })`——`force` 吞 ENOENT，已被删掉的父目录不会被误报；抛出就 `warnLine` 一行 `makeFixture：夹具目录没删掉，请手工删除 <路径>（<错误码>）`，继续下一个。
  4. 防呆（R5）：条目 `basename` 不以 `trivium-fx-` 开头、或不是绝对路径时不删、`warnLine` 一行——清单只会由 `makeFixture` 写入，这一支正常不可达。
- 删除目标只来自 `mkdtemp` 的返回值本身（R1）；`chmod` 遍历不离开该目录。
- 被普通脚本（验收脚本）import 时同样在其进程退出时删——那些脚本都在结尾之前读完了夹具，退出后删不影响其读数；它们要排查时可设保留变量。
