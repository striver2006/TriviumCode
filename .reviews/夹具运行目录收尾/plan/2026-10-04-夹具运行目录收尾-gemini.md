### AGY-01 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `test/helpers/fixture.ts:70` |
| 类别 | correctness ｜ 层次 plan |

**问题**：收尾清理遍历在执行权限恢复与删除前未检查路径存在性，遇到目录已被提前移除时会抛出 ENOENT 并误报手工删除警告。

**依据**：plan §2.2 第 71 行规定收尾步骤为「先递归恢复权限（只对 Dirent.isDirectory() 为真的条目 chmodSync(0o700)，不跟随软链），再 rmSync(d, { recursive: true, force: true, maxRetries: 3 })；抛出就打一行 makeFixture：夹具目录没删掉，请手工删除 <路径>（<错误码>）」。在 test/helpers/fixture.ts 中，若某个用例或子进程已提前将该目录删除（或建目录异常抛出导致部分路径不存在），对不存在的路径 d 遍历子项或读取属性会在进入 rmSync 前直接触发 ENOENT，跳入 catch 块误报「夹具目录没删掉（ENOENT）」。

**建议**：在处理每个待清理路径 d 前增加 existsSync(d) 检查，或在捕获到 ENOENT 时直接放行视为已清理，避免不实报警。

### AGY-02 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `test/helpers/fixture.ts:71` |
| 类别 | correctness ｜ 层次 plan |
| 置信度 | high |

**问题**：递归恢复权限若仅从子项 Dirent 开始 chmod，父目录自身被赋只读权限时将无法读取子目录并提前阻断清理。

**依据**：plan §2.2 称「先递归恢复权限（只对 Dirent.isDirectory() 为真的条目 chmodSync(0o700)，不跟随软链）」。Dirent 仅代表子项条目。若夹具父目录 d（即 trivium-fx-XXXXXX）本身权限被外部用例修改为无执行/无读权限（如 0o500），递归恢复入口若直接对 d 调用 readdirSync 将提前抛出 EACCES 阻断遍历，导致子孙权限无法被恢复，进而使后续 rmSync 级联失败。类似模式在 test/unit/temp-index-cleanup.test.ts 与 test/integration/worktree-hash-cleanup.test.ts 的 unlockAll 中均显式先对目录自身执行 chmod 再 readdir。

**建议**：递归恢复权限函数应先对传入的当前目录自身尝试执行一次 chmodSync(dir, 0o700) 并忽略异常，确保具有读取子项权限后再遍历子目录。
