**问题**：FC4 的注入前提不成立：计划写「子进程 PATH 只给 node 所在目录（找不到 git，initFixtureRepo 抛出）；子进程退 1（用例失败）」。但 exec.ts 的 run() 对 spawn 失败（git 不在 PATH，ENOENT）走 child.on('error') → finish(null, null)，Promise 只 resolve（code:null）、从不 reject；git.ts 的 initFixtureRepo 是六条裸 await run(...)、从不检查退出码。因此 git 整个缺失时 makeFixture 不会抛出，而是静默返回一个没有 .git 的夹具——子进程会退 0 而非 1，FC4 的两条断言（退 1、用例失败）都不会发生，H5（登记挪到 initFixtureRepo 之后 → FC4 红）的锚点也随之落空。附带暴露：initFixtureRepo 对 git 失败完全不看退出码，这是既有代码的潜在静默降级面，与本计划无直接关系但值得一记。

**依据**：src/trivium/util/exec.ts:304-307（spawn error 也 resolve code:null，无 reject 路径）；src/trivium/util/git.ts:458-468（initFixtureRepo 六条 await run，无任何 code 检查）；test/helpers/fixture.ts:158（makeFixture 直调 initFixtureRepo，中间无别的可抛步骤）。此为源码推演，未运行验证。
