## 0. 结论速览

1. 新增模块 `src/trivium/tier-flags.ts` 承担三类旗标的**收集、键校验、取值校验、合并**，`cli.ts`（review / preflight）与 `topic-args.ts`（topic resolve）共用它——判定只有一份。
2. 命令行三值以「逐审核者的精确值」形态并入 `resolveTier` 的第四个参数；合并只此一份（`mergeCliOverrides`），**五处**消费同一组：`preflight.ts` 的 `checkModelSlugs` 与 `checkTierCombos`、`review.ts` 准备阶段的同两格、`review.ts` 路由点（`--tier-〈id〉` 选出的模型从这里进请求）、`run-protocol.ts` 的 `--start` 告警复查——前四个经两个校验函数内部合并，路由点用准备阶段算好的同一份合并结果（CODEX-02）。

## 2. 方案

### 2.1 新模块 `src/trivium/tier-flags.ts`

```ts
type FlagKind = 'tier' | 'effort' | 'profile';
export interface TierFlagValues { tier?: TierName; effort?: string; vendorProfile?: string }
export function tierFlagNames(): string[]   // tier-〈id〉 / effort-〈id〉 / profile-〈id〉，id 取 ALL_AGENT_IDS
export function collectTierFlags(get: (name: string) => string | undefined): Record<FlagKind, Record<string, string>>
export function assertTierFlags(cfg, driver, raw, picked): Partial<Record<CriticId, TierFlagValues>>
export function mergeCliOverrides(models, flags): Partial<Record<CriticId, TierOverrides>>
```

- **收集面 = 全部已登记 Agent**（写了但不可用的要落到明确报错上，不能被 `topic resolve` 当正文吞进焦点）；`profile-〈id〉` 同样按全部已登记收集。`get` 返回 `undefined` 表示没写，空串表示写了没给值（AGY-02）。
- **键校验**：三类旗标的键走与 `--model-〈id〉` **同一份判定**——把 `assertModelOverrideKeys` 的旗标前缀与「为它指定的 X」措辞参数化，既有 `--model-〈id〉` 报错文案逐字不变。
- **`--profile-〈id〉` 的额外一格**：键通过后，该侧适配器未实现 `vendorProfilesFor` ⇒ 退 64，「〈id〉 没有厂商 profile 概念；`--profile-〈id〉` 不是 `--profile 〈档位表名〉`」。钩子取 `realAdapters()`；源码不写 Agent id。
- **`--tier-〈id〉` 取值**：只收 `TIER_NAMES`——由 `adapters/base.ts` **导出**复用，本模块不自持字面量（GLM-03）；其余退 64 并列三档。
- **空值**：三类旗标写了但值为空串 ⇒ 退 64（与 `cli.ts` 的 `flagString` 缺值口径一致）。
- **`--effort-〈id〉` / `--profile-〈id〉` 取值**：这里只查非空；是否在原生枚举 / 本机名单里由 `checkTierCombos` 判。
- `critics.ts` 不引适配器表（避免反向依赖），参数化后的键判定仍住在 `critics.ts`；钩子那一格住在本模块。

### 2.2 三个入口

- `cli.ts` 的 review（`:620` 后）与 preflight（`:788` 后）：`collectTierFlags(name => 取值)`（写了没取到值由 `flagString` 先退 64）→ `assertTierFlags(...)`（在 `assertModelOverrideKeys` 之后）→ `reviewOpts.tierFlags` / `runPreflight({ tierFlags })`。help 两处补三行，措辞：「`--effort-〈id〉`、与 `agents.〈id〉.profile` 不同的 `--profile-〈id〉` 在 M11 第 6 步之前被预检的过渡闸拦下（思考等级与厂商 profile 尚未透传）；gemini 的 slug 已编码档位时思考等级本就不生效，只告警」（GLM-02）。
- `topic-args.ts`：`NAMED_FLAGS` 并入 `tierFlagNames()`；`resolveNamedFlags()` 随之扩大；收集时**按 `named[name] !== undefined` 判「写了」**，空串照传给 `assertTierFlags` 退 64（AGY-02）；输出三字段 `tiers` / `efforts` / `vendor_profiles`（逐入选侧，没写时 `{}`，恒存在）。

### 2.3 接到解析与校验（CODEX-02）

- `ReviewOptions`、`PreflightOptions` 增可选 `tierFlags?: Partial<Record<CriticId, TierFlagValues>>`（缺省 `{}`）。
- `checkModelSlugs` / `checkTierCombos` 增第五个可选参数 `tierFlags`（缺省 `{}`），**内部调 `mergeCliOverrides(overrides, tierFlags)`** 得到逐侧 `TierOverrides` 后交 `resolveTier`；既有调用与用例不动。
- 五处消费同一组：①`preflight.ts:1032` `checkModelSlugs`；②`preflight.ts:1034` `checkTierCombos`；③`review.ts:816/822` 同两格；④`review.ts:1145` 路由——准备阶段在校验之后算一次 `mergeCliOverrides(opts.modelOverrides, opts.tierFlags)`，路由点取它的 `[critic]`，不再内联展开；⑤`run-protocol.ts:491` `--start` 告警复查（经 `checkTierCombos`）。
- **过渡闸**：不改判据；文案里来源为命令行时点名旗标名（`--effort-〈id〉` / `--profile-〈id〉`）。
- **留痕空窗告警**（已定 ②）：`checkTierCombos` 对 `tierFlags[c].tier` 有值的侧追加告警「〈id〉：本轮档位名与来源尚未入档（M11 第 6 步起），事后只能从请求模型反推」；进预检与 `--start` 的 `warnings`。

### 2.4 交接文件与 `override_reason`

- 交接 `options` 增可选 `tierFlags`（新版读旧文件缺席即 `{}`）。
- `overrideReasonFor` 增一档：`modelOverrides[c]` 无值而 `tierFlags[c]?.tier` 有值 ⇒「用户经 `--tier-〈id〉 〈档〉` 选出了与当轮 Driver（…）同族的模型」。字段名、类型、出现条件都不变。
- 回滚方向的降级见 §5 第 4 条（CODEX-03）。

### 2.5 入口资产

- `src/entry-render.ts` 派生（论域同 `MODEL_HINT`：已启用审核者减本载体）：`TIER_HINT`、`EFFORT_HINT`（逐侧 `[--tier-〈id〉 〈档〉]` / `[--effort-〈id〉 〈值〉]`）、`TIER_FLAGS`、`EFFORT_FLAGS`（反引号列表）；厂商 profile 只对实现了 `vendorProfilesFor` 的侧派生：`VENDOR_PROFILE_HINT`（今天为 `[--profile-codex 〈名〉]`，codex 载体上为空串）与 **`VENDOR_PROFILE_CLAUSE`——含标点的完整分句或空串**，模板只放这个变量、不在模板里写括号或顿号（AGY-05）。`entry-render` 因此引入 `realAdapters()`；若审查认为不可接受，退路（由注册表 vendor 推导）违背已定 ③，届时停下问用户。
- 四份命令契约的 `argument-hint` 在 `{{MODEL_HINT}}` 后追加 `{{TIER_HINT}} {{EFFORT_HINT}} {{VENDOR_PROFILE_HINT}}`。
- `run.contract.md`：S0.5 字段说明加三字段；S0.6、S2、S6 三处写「非空时逐个传对应的 `--tier-〈id〉` / `--effort-〈id〉` 与厂商 profile 旗标」，并写明与 `models` 一样必须三处同一组；S6 那句「同 S2（…）」的括号枚举补三类旗标；「本命令收到的…要一并传下去」那段补三类旗标与丢失后果；过渡期限制照 §2.2 措辞。
- `partials/review/body.md`（B/C/D）：第 2 步预检与第 3 步 `--start` 两处同样补；`--start` 模板加三个槽位。
- 渲染产物 `npm run render` 同步；入口资产变了，提交后由用户重装。

## 5. 风险与遗留

1. **入口资产变了**：提交推送后同一条命令重建，再请用户重装四家目标；不装则会话里的 skill 仍是旧模板，新旗标不会被透传。
2. **本仓配置没有 tiers**：在本仓用 `--tier-〈id〉` 只会退 64；第 6 步计划定本仓档位形态时一并配。
3. **过渡期**（已定 ①）：`--effort-〈id〉` 与不等于 `agents.codex.profile` 的 `--profile-codex` 被过渡闸拦下退 64；gemini 的 slug 已编码档位时思考等级本就不生效，只告警（GLM-02）。用户可见面的每一处说明都照此写，不得写成已可用。
4. **跨版本回滚恢复**（CODEX-03）：交接文件读侧是断言不是校验，旧版本 worker 读新交接文件会静默忽略 `tierFlags`——用 `--tier-〈id〉` 起跑的运行若被旧版恢复，选档无声丢失、路由回落配置档位、`override_reason` 回到失实归因。不改 run.v2 的前提下无解，接受并写明（与既有 `handoffDriver` 的跨版本回落同形）；不可接受时唯一替代触及 run.v2，届时停下问用户。
5. **既有 `--model-〈id〉` 的空值丢失**（AGY-02 顺带）：登记 BACKLOG，本步不改。
6. **Hook 误拦**：提交说明写文件后 `git commit -F`；归档目录按目录名 `git add`。
