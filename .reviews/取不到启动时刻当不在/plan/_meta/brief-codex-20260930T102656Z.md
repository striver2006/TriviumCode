## 3. 修法

### D1 `RecordMatch` 加三态可选字段（`util/exec.ts`）

```ts
/** 与记录比对的三态结论（EV-175）：同一进程 / 不是同一进程（含已不在）/ 判不了（活着、记录有期望值、本次取不到启动时刻） */
export type RecordIdentity = 'same' | 'different' | 'unverifiable';

export interface RecordMatch {
  …（原五个字段不变）
  /** EV-175。可选只为兼容手工构造 RecordMatch 的调用方与单测；processMatchesRecord 总是给出 */
  identity?: RecordIdentity;
}
```

- 在 `processMatchesRecord` 的两个出口都填：`identity = sameProcess ? 'same' : alive && startedAt === null && expected !== null ? 'unverifiable' : 'different'`，抽成一个纯函数 `recordIdentityOf(m)`（导出，单测直接钉真值表）。
- **不变量**：`identity === 'same'` ⇔ `sameProcess`；原五个字段逐字不变——`judgeStale`、`workerGoneForCancel`、`classifyLostCancel`、`lostWorkerGone` 的输入与今天逐字相同，它们的行为因此不变（用户决策）。
- **不做「取不到后复检存活」**：`judgeCliGroup` 在取不到时会再 `kill(0)` 一次、确认不在就改判；这里若照做，就要改 `alive`，`judgeStale` 与 `lostWorkerGone` 的输入随之变——越出「sameProcess 含义不改、judgeStale 不改」。代价如实记：进程恰在 `kill(0)` 与 `ps` 之间退出时判 `unverifiable`（保守一侧），下一次判定即得 `different`。
- `processAlive` 的返回类型不动（hooks 与两处只看 `.alive` 的调用方不受影响）。
