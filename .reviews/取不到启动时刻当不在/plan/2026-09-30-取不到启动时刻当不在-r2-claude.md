## 3. 修法

### D1 `RecordMatch` 加三态可选字段（`util/exec.ts`）

```ts
/** 与记录比对的三态结论（EV-175）：同一进程 / 不是同一进程（含已不在）/ 判不了（活着、记录有期望值、本次取不到启动时刻） */
export type RecordIdentity = 'same' | 'different' | 'unverifiable';

export interface RecordMatch {
  …（原五个字段不变）
  /** EV-175。可选只为兼容手工构造 RecordMatch 的调用方与单测；processMatchesRecord 总是给出 */
  identity?: RecordIdentity;
}
```

- 导出纯函数 `recordIdentityOf(m)`：`sameProcess ? 'same' : alive && startedAt === null && expected !== null ? 'unverifiable' : 'different'`；`processMatchesRecord` 的**三个 `return`**（:613 legacy、:623 规范化且不在、:627 规范化且活着）都经同一个内部包装 `withIdentity(m)` 返回，不逐处手写（GLM-02）。
- **不变量**：`identity === 'same'` ⇔ `sameProcess`；原五个字段逐字不变——`judgeStale`、`workerGoneForCancel`、`classifyLostCancel`、`lostWorkerGone` 的输入与今天逐字相同，它们的行为因此不变（用户决策）。
- **消费方一律只在 `identity === 'unverifiable'` 时走新分支**，其余照今天的 `alive` / `sameProcess` 判（AGY-01）：`identity` 缺失（手工构造的 `RecordMatch`）即今天的行为，不会因可选字段缺失而放宽或收紧。
- **不做「取不到后复检存活」**：`judgeCliGroup` 在取不到时会再 `kill(0)` 一次、确认不在就改判；这里若照做，就要改 `alive`，`judgeStale` 与 `lostWorkerGone` 的输入随之变——越出「sameProcess 含义不改、judgeStale 不改」。代价如实记：进程恰在 `kill(0)` 与 `ps` 之间退出时判 `unverifiable`（保守一侧），下一次判定即得 `different`。
- `processAlive` 的返回类型不动（hooks 与两处只看 `.alive` 的调用方不受影响）。

### D2 `interpretStatus` 情形 A（`status.ts` :524）

改经 `processMatchesRecord(pid, { legacy: opts.fallbackPidStartedAt ?? null })`——没有 `canonical` 键即退回 `processAlive(pid, legacy)`，与今天逐字同一判据，多拿到 `identity`：`alive && sameProcess` 或 `identity === 'unverifiable'` ⇒ `inconclusive`（与活着同处置，用户决策）；否则 `pid_gone`。`fallbackPidStartedAt` 的文档块补一句：取不到时同活着处置。**生产行为不变**（§2 要点 1）。

### D3 `interpretStatus` 情形 C（`status.ts` :539～:541）

`identity === 'unverifiable'` 不判 `pid_gone`，**往下走心跳**：过期 ⇒ `worker_lost / heartbeat_stale`，新鲜 ⇒ `running`（用户决策）；其余格照今天（`!alive` 或 `!sameProcess` ⇒ `pid_gone`）。

连带（不另改代码，写进测试期望）：心跳新鲜时 `--wait` 继续退 73；过期时 `--wait` 走 heartbeat_stale 那条既有路径——写 failed + `lost.heartbeat_stale`，`goneForArchive` 经 D4 为假（run.json 不补收），抹凭据经 D4 不准入（报错正文多一行「凭据副本未抹：工作进程 N 仍在，但取不到……判不了……——留给会话启动清扫」），`cancelHint` 照常给出（「工作进程 N 仍在」是事实：`kill(0)` 成功）。之后若再 `--cancel`：`ps` 仍失败 ⇒ `classifyLostCancel` 判 `mismatch`，不发信号（§1.3）；恢复 ⇒ `alive` 格，按 EV-146 结束它。

### D4 `workerConfirmedGone`（`status.ts` :212～:214）

```ts

if (live.identity === 'unverifiable') {
```

### D5 `workerStillAlive`（`retention.ts` :99～:104）

显式正向判定（AGY-01）：`(a.alive && a.sameProcess) || a.identity === 'unverifiable'`——同一进程与判不了都当仍在（不整删、不抹，跨仓清扫计 `alive`）；`identity` 缺失即今天的 `alive && sameProcess`。守卫行（终态 / 没有 pid ⇒ false）不动——终态照删是 EV-163，不并入。文档块补一句。

- **手工出路**（CODEX-01 ≡ GLM-03）：工作进程被人在终端结束后 `kill(0)` 即失败、`identity` 为 `different`，下一次 `--cancel` 走既有的「已不存在，仅做状态与锁的清理」路径（:1801～:1806 → 挂载点 ③ → 收尾）。工作进程的命令行是 `review --worker 〈run_id〉`（:425～:427），能在终端认出。
- **退出码取 69（`EXIT.ENV`，经 `envError`）**，论证：
  - 70（`LOCKED`）：含义是「同主题已有运行持锁」，而 70 的正文正指向 `--cancel`——再用 70 就是让人从 `--cancel` 回到 `--cancel` 的闭环，且 70 文案不动（用户决策）；
  - 73（`STILL_RUNNING`）：只属于 `--wait`，skill 读到 73 会继续下一次 `--wait`；
  - 75（`STRICT_ABORT`）、64、65：语义不符；
  - 1（`FAIL`）：可用，但「一般失败」分不出「什么都没做、可以重试」与真正失败（如 `--wait` 判失联也是 1）；
  - **69（`ENV`）**：「环境或预检失败」——`ps` 派生失败、超时正是本机环境的故障，出路也是环境侧的（稍后重试、排查 `ps`，或上面的手工出路）；`cancelRun` 顶部已有抛受控错误的先例（:1693 `missingArtifact`）。
  - 69 + 重试在 `ps` **持续**故障下同样不会自己好（CODEX-01）；与 70 的区别是 69 的正文给了确定性的手工出路，不把人指回原处。
- 抛出后 CLI 顶层 `fail(message)`、以 69 退出（`cli.ts` :2002～:2004），stdout 为空；与既有「状态文件与交接文件都没有」那一格同一出口形态。
- 终态分支不受影响：`classifyLostCancel` 的 `mismatch` 格照旧；`none` 格下的 :1728 CLI 结束块经 D4 翻过来——判不了时不再结束活 worker 名下的 CLI（G-cancel-terminal）。

## 4. 残余与暂缓

- **R1（新登 EV-176，暂缓）**：主路径**已判同一进程、发过 SIGTERM 之后**，宽限期里 `ps` 转为失败 ⇒ `workerGoneForCancel` 判已退出、不升级 ⇒ 收尾经 D4 不抹、不补收 run.json（改后正确），但 status.json 仍写 cancelled、锁与闸门仍回收——工作进程若还没来得及响应 SIGTERM，就是一把活锁被释放。触发要「`ps` 在 5 s 宽限里由好转坏」且 worker 没在毫秒级响应 SIGTERM；修法要论证「退出未确认时锁留不留」，而今天 SIGKILL 之后 `killWaitMs: 0`、不等确认就回收锁是 EV-150 定的形态，动它会改变正常升级路径的语义，显著扩大范围，登记暂缓（用户决策「遇到没覆盖、会显著扩大范围的问题登暂缓」）。
- **R2（如实保留，不登）**：`--wait` 在心跳过期而判不了时仍把 status.json 写成 failed——与今天「心跳过期而进程还活着」同一语义（EV-146 那一格），用户决策即「过期判 heartbeat_stale」。
- **R3（如实保留，不登）**：D1 不做复检，进程恰在 `kill(0)` 与 `ps` 之间退出时判 `unverifiable`（§3 D1）。对 D6 的影响：那一刻 `--cancel` 退 69、什么都不动，重试即走 `different` 格。
- **R4（如实保留，不登；CODEX-01）**：`ps` **持续**取不到时，工具自己结束不了这一轮——`--cancel` 每次都退 69，出路只有 D6 正文写的手工结束。这是「判不了就不动」的直接代价，用户决策已选这一侧。
