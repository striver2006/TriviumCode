## 2. 改法

### 2.1 新增模块 `src/trivium/worktree-summary.ts`

只读，不抛错（内部任何失败都转成 `available: false`）：

```ts
export const SUMMARY_BUDGET_MS = 20_000;   // 摘要总预算（CODEX-02）
export const SUMMARY_JSON_LIMIT = 200;     // JSON 条数上限（CODEX-04）
export const SUMMARY_TEXT_LIMIT = 20;      // 人读条数上限

export interface WorkTreeSummary {
  available: boolean;
  /** 四种原因之一（§2.5），available 为 true 时为 null */
  reason: string | null;
  run_id: string;
  baseline: 'review_end';
  baseline_tree: string | null;
  current_tree: string | null;
  total: number;                                    // 排除后的变更总数
  truncated: boolean;                               // files 是否被 SUMMARY_JSON_LIMIT 截断
  files: Array<{ status: string; path: string }>;   // 按路径排序，最多 SUMMARY_JSON_LIMIT 条
  excluded_prefixes: string[];                      // diffExcludePrefixes 的结果
}
export async function summarizeWorkTree(i: {
  projectRoot: string; archiveRootRel: string; runId: string;
  afterTreeHash: string | undefined; budgetMs?: number;
}): Promise<WorkTreeSummary>;
export function renderWorkTreeSummary(s: WorkTreeSummary, opts: {
  exit: 'approval' | 'hold'; driver: string | null; topic: string; limit?: number;
}): string;
```

流程：
1. `afterTreeHash` 缺席 ⇒ `available: false`，原因 1。
2. `git cat-file -e <基线>^{tree}` ⇒ 不在 ⇒ 原因 2。
3. `workTreeHash` 取当前 tree；与基线相等 ⇒ `available: true`、`total: 0`。
4. 否则 `diff-tree -r --name-status --no-renames -z <基线> <当前>`，按 `diffExcludePrefixes(archiveRootRel)` 剔除归档根、`.trivium/`、`.git`，按路径排序。
5. 每一步的 git 超时取「总预算减已用」；任一步 `timedOut` ⇒ 原因 4；其余 git 失败 ⇒ 原因 3。

- 不剔 scratch 路径：基线取审查收尾时，审查员的 scratch 已在基线里；闸门期审查员不在跑。
- 只列文件名，不读内容；敏感文件（`review.sensitive_globs`）同样只出现名字。
- abandon 写法经 `entryCommandOf(opts.driver, 'dual-abandon')` 派生，与 `renderTamperedArtifacts` 同源（AGY-01）。

### 2.2 `util/git.ts`

- 内部 `git()` 加可选 `timeoutMs`，缺省仍为 120 s。
- `workTreeHash(cwd, opts?: { timeoutMs?: number })`：缺省行为逐字节不变，送审冻结与漂移复算的调用点不传；任一步 `timedOut` 时抛带 `timedOut: true` 标记的错误。
- 新增 `treeExists(cwd, tree, opts?)`：`cat-file -e <tree>^{tree}`，退 0 为 true、退 1 为 false，其它（含超时）抛错。
- 新增 `diffTreesNameStatus(cwd, a, b, opts?)`：**非零退出即抛**。解析协议（AGY-04）：`-z` 下输出为 `状态\0路径\0` 成对出现；按 `\0` 切分、丢弃末尾空段，段数为奇数即抛；`--no-renames` 保证不出现三段式。路径不加引号，不走 `unquoteGitPath`。
- **不改 `diffTrees`**：它是 `judgeDrift` 的依赖，改它的失败语义等于改漂移判定（§6.3 另登 BACKLOG）。

### 2.3 收尾落盘 `snapshot.after_tree_hash`

- `review.ts` :1339 写 `meta.snapshot.drift` 的同一处加 `meta.snapshot.after_tree_hash = afterTreeHash`。没走到复算的出口不写，字段缺席。
- `run.v2.json` 的 `snapshot.properties` 加 `after_tree_hash: { type: string, description: "审查收尾复算时的工作树 tree（与 tree_hash 同法）；只供审批时的工作树摘要作基线，不参与任何判定；缺席 = 本字段之前的旧留痕或运行未走到复算" }`，不进 `required`。

- 写入时点与 `drift` 相同，都在收尾时写（:1621 落盘）。之后 run.json 不再更新，S14 的不变量不受影响。

### 2.4 三个出口

| 出口 | 位置与顺序 | 人读 | JSON |
| :--- | :--- | :--- | :--- |
| `approve`（通过） | 复核循环全过（:1598）之后、落审批循环（:1602）之前：逐阶段算摘要并**先打印**，再 `recordApproval`（CODEX-03） | 是，`exit: 'approval'` | 追加 `worktree_summary: { <stage>: WorkTreeSummary }` |
| `gate --await-approval` | :1270 停点文案之后追加 | 是，`exit: 'hold'` | 追加 `worktree_summary` |
| `gate --check` 自动立停点（B/C/D） | :1444 停点文案之后追加 | 是，`exit: 'hold'` | 该分支 JSON 模式本就不输出停点，同样不加 |

- **approve 取「先打印、再落审批」**：摘要有总预算，被载体超时或 Ctrl-C 砍在摘要段时，审批还没记录、闸门仍在等待，重跑即可——这是良性的一边。先落审批再打印的话，砍在打印段时审批已记录、Driver 拿不到输出，可能向用户报「没批成」。
- **异常隔离**（AGY-03）：每个出口一个隔离块，覆盖 `readRunMeta` 以及摘要的计算与渲染。任何异常转成 `available: false`（原因 3）并 `warn` 一行；`recordApproval` 的调用、退出码、闸门迁移、JSON 的其余字段都不受影响。
- 摘要里的 run id 一律取自该出口复核所用的 run id（approve 为闸门项 `run_id`，与 `verified` 同值），取不到基线时也带上这个 id（CODEX-09）。
- 拒绝、放弃不打印。`--await-approval` 发现「本轮已有人工审批记录」（:1239）时不打印。
- `verifyRoundForApproval` 与 `gate.ts` 不改：摘要在复核通过**之后**另算，不进 `ok` 判定。

### 2.5 摘要文案

approve（`exit: 'approval'`），有改动：

```text
工作树改动摘要（只告知，不影响审批结论）：自审查收尾（run <run_id>）以来，3 个文件有变化
  M  NOTES.md
  A  src/new.ts
  D  src/old.ts
  （比对范围：未被 .gitignore 忽略的文件，不含 .reviews/ 与 .trivium/；闸门期提交过的改动同样列出）
  若这些改动不该发生：请自行 git diff 核对，必要时 <dual-abandon 写法> --topic <主题> 作废本轮后重跑。
```

- 停点（`exit: 'hold'`）：首句同为「（只告知，不影响审批结论）」，末句换成「审批时会再列出一次」。
- 超过 20 条：列前 20 条，再加一行「……另有 N 个，完整列表：」加照抄命令（CODEX-07）。命令由渲染按实际排除前缀生成：
  `git -c core.quotePath=false diff-tree -r --name-status <基线> <当前> -- . ':(exclude)<归档根>' ':(exclude).trivium'`。
  两个 tree 都在对象库里，照抄即可跑，结果与摘要同口径。
- 无改动：`工作树改动摘要：自审查收尾（run <run_id>）以来，未被 .gitignore 忽略的文件无改动（不含 .reviews/ 与 .trivium/）。`
- 不可用：`⚠️ 工作树改动摘要取不到：<原因>。这不影响审批；请自行 git status 核对。`

四种原因，逐字区分，都不与「无改动」同形：
1. 本轮没有审查收尾时的工作树基线，无法比对。（CODEX-05：不断言成因）
2. 基线对象已不在对象库（可能被 git 清理）。
3. git 调用失败：<stderr 首行或异常消息首行>。
4. 工作树摘要超时（超过 20 秒）。（CODEX-02）

### 3.1 单测（新文件 `test/unit/worktree-summary.test.ts`，每条用例用独立夹具目录）

1. 基线后无改动 ⇒ `available: true`、`total: 0`，渲染含「无改动」。
2. 修改 / 新建未跟踪 / 删除各一 ⇒ `M` / `A` / `D` 三行。
3. 被 `.gitignore` 忽略的文件改动 ⇒ 不出现；归档根、`.trivium/` 下改动 ⇒ 不出现。
4. **闸门期提交**：改文件后 `git commit` ⇒ 仍列出（钉住「不用 HEAD 相对」）。
5. 路径含空格、双引号、中文 ⇒ 原样（AGY-04 的成对解析）。
6. 21 条改动 ⇒ 人读 20 行 + 「另有 1 个」，照抄命令含两条 `:(exclude)`；205 条改动 ⇒ JSON `files` 200 条、`total: 205`、`truncated: true`。

8. 基线被清：**先造一个未跟踪文件再取基线**（使基线 tree 不可达，GLM-03），删掉该文件后 `git gc --prune=now` ⇒ `available: false`、原因 2，**不是「无改动」**。
9. 非 git 目录 ⇒ `available: false`、原因 3，不抛。
10. `diffTreesNameStatus` 对不存在的 tree 抛错（对照 `diffTrees` 返回 `[]`）；奇数段输出抛错。
11. 超时：`budgetMs: 1` ⇒ 原因 4（CODEX-02）。
12. 渲染两种出口：`approval` 末句含按 Driver 派生的 abandon 写法（codex 为 `$dual-abandon`），`hold` 末句为「审批时会再列出一次」（AGY-01）。
13. `workTreeHash` 不传 `timeoutMs` 时与改前同值（回归）。

## 6. 风险与边界

### 6.1 摘要不是判据

它不保证「闸门期没人改过」：
- 被忽略的文件看不见；
- 改了又改回的文件，tree 相同，不会列出；
- 基线可能被 git 清理而取不到，取不到时如实报，不会假称无改动；而闸门期提交得越多，越可能取不到——这个缺失不是随机的（CODEX-08），口径按 §3.5 实测写。

文案按这三条如实写，不说「未发现越界」。

### 6.2 `approve` 没有确认步骤

摘要在落审批之前打印，但同一条命令里人没有机会中止。出口是事后的：核对后 `abandon` 作废本轮（S15）。
「看了再批」在 L2 上的时点是停点那次打印（W4）。想要「审批前单独看」的只读入口，登进 §6.3，不在本主题做。

### 6.3 新登 BACKLOG（只登记，不做）

- `diffTrees` 失败时返回 `[]`，`judgeDrift` 因此会把「比不了」判成「无漂移」（S7）。改它等于改漂移判定，要单独走计划。
- 审批前单独看摘要的只读入口（`approve --dry-run` 或 `status` 带摘要），由用户定要不要。

## 7. 决策（已定）

**D1 基线** — **②**：收尾时把 `afterTreeHash` 落盘为 `snapshot.after_tree_hash`（run.v2 可选字段）。

- 摘要恰好是「审查收尾之后」的改动，覆盖裁决期与闸门期。
- **不算「改判定」**：没有任何判定读它；写入时点与 `drift` 相同，S14 的不变量不破；schema 只多一个可选字段，与 `snapshot.build`、`driver_guard_level` 同形（S13）。它算契约变更，6.7.1 与 PROTOCOL 登记。
