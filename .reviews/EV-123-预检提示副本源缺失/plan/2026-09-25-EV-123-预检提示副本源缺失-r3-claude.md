## 3. 改动

### 3.1 判侧与唯一出处

- `adapters/zcode.ts`：`export function zcodeOverrideSourcePath(): string`；`prepareZcodeHome` 的 `srcConfig` 缺省值、`authProbe.fingerprint()` 都改为调用它。
- `adapters/base.ts`：`CriticAdapter` 新增可选成员 `modelOverrideSource?(): string`。契约：文件不在 ⇒ 该侧拉起时不做模型覆盖；路径按运行编排器那个进程的 HOME 解析。zcodeAdapter 实现为 `() => zcodeOverrideSourcePath()`。
- 预检与 `startRun` 按「入选侧的适配器有没有这个成员」判侧，不写 Agent id 或 CLI 名字面量。

### 3.2 新检查与措辞

`checkModelOverrideSource(selected: readonly CriticId[], adapters: AdapterTable = realAdapters()): Promise<CheckResult[]>`：遍历 `selected`，对实现了 `modelOverrideSource` 的侧查文件在不在，不在的各出一项。`adapters` 参数是注入口（为可测性；只判存在、不读内容）。

```text
name:   `${label} 模型覆盖副本源`
ok:     true
warn:   true
detail: `⚠️ ${critic} 侧做模型覆盖要读的副本源 ${shown} 不在。该侧若在它缺位时拉起，就不做模型覆盖，` +
        `跑的是 ${cliName} 自己选的模型，不一定是请求的那个。要按请求的模型跑，先把副本源放回原处再发起；` +
        `已经发起的，跑完看 guard 有没有「本次没有做模型覆盖」告警（回读不到生效模型时它不出声）。`
```

- `label` / `critic` / `cliName` 一律经注册表取；
- `shown`：路径在 `os.homedir()` 之下时显示为 `~/…`，否则原样；
- 预检位置：④″，紧跟 C5，在探活之前。

### 3.3 警告这一级与转述通道

**口径**：通过项在说「本次有一部分没检查到 / 没按请求做到」时标 `warn`，由产出该项的代码置位，**不看文案**。

| 项 | 标 `warn` | 理由 |
| :--- | :--- | :--- |
| C5 运行期选模 | 是 | 本次该侧大概率跑不到请求的模型 |
| 版本漂移检查覆盖面 | 是 | 有 CLI 本次没比对版本 |
| 探活已跳过（`--skip-auth-check`） | 是 | 凭据本次没验 |
| 模型 slug 合法（`unverifiable` 或 `fellBack` 非空时） | 是 | 有侧没实际校验、或按基底目录校验 |
| 模型覆盖副本源（新检查） | 是 | 该侧可能不做覆盖 |
| 「X 可调用」的「入口在位（版本未校验）」 | 否 | 已由覆盖面项汇总念出，再标会重复 |
| 当轮 Driver | 否 | 信息，不是缺口 |
| 「该侧未实现探活」 | 否 | 四家真实适配器都实现 `authProbe`，只在桩模式可达 |

- `CheckResult` 加 `warn?: true`；`PreflightResult` 加 `warnings: { name: string; detail: string }[]`，由 `checks.filter(c => c.warn)` 得出，恒存在。`ok` 与退出码不受影响。
- 预检 `--json`：`checks[]` 单项在 `warn` 为真时带 `warn: true`；顶层 `warnings` 恒在。
- 预检人读：`warn` 项行首用 `⚠`；末行「✓ 预检通过」后追加「（含 N 条警告）」，无警告时与今天逐字相同。

**`--start` 复用**：
- 落点：`startRun` 内，FR-23 跳过分支**之后**、`ensureDir(rc.runDirBase)` / `writeHandoff` **之前**，以 `rc.sides`、`rc.adapters` 调 `checkModelOverrideSource`。
- `--start` 正常支：结果进 `StartOutcome.warnings`，JSON 恒带 `warnings`；人读分支在非空时逐条打印 `⚠ <detail>`。
- `finished_inline` 支：不计算，JSON 的 `warnings` 为 `[]`。
- 同步 `review --stage`：不提示（手工调试入口，skill 不走它；收尾 guard 仍在）。

**兜底分层与边界**：
1. 预检：最早，按缺省选侧，措辞为条件句；
2. `--start`：当轮选侧、拉起时点，**在派生之后**念出，用户可以立即 `--cancel`，拦不住拉起；
3. 收尾 `model_unenforced`：只在回读到生效模型、且与请求 modelId 不同时出声。

命令 B / C / D 下，文件缺失时同一条警告会在第 1 步与第 3 步各念一次。接受这个重复。

### 3.4 skill 的转述约定

- 预检步骤（三个 `dual-review-*` 第 1 步、dual-run S0）：在「失败则原样转述」之后补一句
  > 通过时若 `warnings` 非空，把每一条的 `detail` 原样念给用户，**然后继续**，不停下来等确认——警告不阻断，要不要处理由用户决定。
- 开场播报（三个 `dual-review-*` 第 3 步）：
  > `--start` 返回的 `warnings` 非空时，在开场播报里逐条原样念出 `detail`，并提醒：想中止就用 `TV review --cancel <run_id>`。
- dual-run：改写既有的继承句（:66-69），点名 `warnings`：「**开场播报（含 `warnings` 的逐条转述）与每次 `--wait` 后的进度播报，随委托一并继承**」。

## 4. 验证

### 4.1 用例

- **唯一出处**：HOME 钉到 mkdtemp、用完恢复。世界 A（不摆文件）⇒ 路径为 `<临时 HOME>/.zcode/cli/config.json`、`prepareZcodeHome` 不传 `srcConfig` 得 `source_missing`、fingerprint 为 null；世界 B（摆一份最小 `config.json`）⇒ 不是 `source_missing`、fingerprint 非 null。
- **`checkModelOverrideSource`**（注入假适配器）：无成员 ⇒ `[]`；文件不在 ⇒ 一项（`ok: true`、`warn: true`、以 `⚠️` 开头、含 `~/.zcode/cli/config.json`、不含临时 HOME 绝对路径、侧名取自注册表）；文件在 ⇒ `[]`；未入选 ⇒ `[]`；zcodeAdapter 实现了该成员且返回值等于 `zcodeOverrideSourcePath()`。
- **现有警告项**：C5、版本漂移覆盖面、探活已跳过、`checkModelSlugs`（`unverifiable` 非空的场景）各断言 `warn: true`。
- **口径断言**：在 `runPreflight` 的用例场景上统一检查：凡 `ok: true` 且 detail 任一行去缩进后以 ⚠️ 起头的项，必带 `warn: true`。
- **`runPreflight` 汇总**：文件级把 HOME 钉到 mkdtemp、默认摆好副本源；C5 与新检查各出一条 ⇒ `warnings` 恰两条、`ok: true`、`exitCode` 0；都不出 ⇒ `[]`。
- **人读输出**：`warn` 项行首为 `⚠`，末行含「含 N 条警告」；无警告时末行与今天逐字相同。
- **预检 `--json` 子进程**：`preflight … --skip-auth-check --json`，断言 `warnings` 键在、含「探活」那一条，`checks[]` 中对应项带 `warn: true`。
