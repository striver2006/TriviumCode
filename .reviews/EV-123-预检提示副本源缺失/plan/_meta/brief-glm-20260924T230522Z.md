- **(a) zcode 适配器导出 `zcodeOverrideSourcePath(): string`（推荐）**：返回 `path.join(os.homedir(), '.zcode/cli/config.json')`，C1 的缺省值、C2 的指纹、新检查三处都调它。

### 3.2 新检查（决策 D3：措辞）

`checkZcodeOverrideSource(cfg, selected): Promise<CheckResult | null>`：按入选侧经注册表取 CLI 名（同 C5，不写 `'glm'` 字面），只对 zcode 那一侧查 `zcodeOverrideSourcePath()` 是否存在；存在或未入选 ⇒ `null`（不出项）。
不在时：

```
name:   'ZCode 模型覆盖副本源'
ok:     true
warn:   true
detail: ⚠️ 副本源 ~/.zcode/cli/config.json 不在：若发起时仍不在，本轮 glm 侧不会做模型覆盖，
        CLI 跑的是它自己选的模型（EV-112 E2 实测为个人配置的默认模型），FR-06 / NFR-06 在该侧不成立；
        跑完 guard 会给「本次没有做模型覆盖」告警。要按请求的模型跑，先把副本源放回原处再发起。
```

- 路径**恒以 `~/` 形式展示**，不展示绝对路径：预检输出常被抄进 evidence 目录，不必带出用户名；
- 「若发起时仍不在」：预检与拉起之间文件可能被放回，预检只能说「若」，实际是否覆盖由收尾那条说；
- 位置：紧跟 C5 之后（④″），同样只在前面各项都通过时才跑；它不花配额，放在探活之前。

### 3.3 警告这一级（决策 D2：转述通道）

- **(a) 结构化标记 + JSON 汇总 + skill 约定（推荐）**：`CheckResult` 加 `warn?: true`；`PreflightResult` 加 `warnings: { name: string; detail: string }[]`（由 `checks` 过滤 `warn` 得出，不另存一份）；

## 5. 审查要点与你这一侧的镜头

被审对象是一份**还没实施的计划**。这决定了审查的重心与代码审完全不同：

- **现在指出比事后返工便宜几个量级。** 计划阶段最值得找的是「做了会发现方向不对」

- **不可逆决策优先。** 数据模型、对外契约、迁移与回滚路径、第三方依赖的引入——

- **计划没写的部分也是问题。** 需求里有、计划里没有的，属于遗漏；
  计划里含糊其辞（「适当处理」「必要时优化」）的，属于未决策。两者都要指出。
