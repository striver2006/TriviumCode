### 3.2 新检查与措辞（决策 D3）

`checkModelOverrideSource(selected: readonly CriticId[], adapters: AdapterTable = realAdapters()): Promise<CheckResult[]>`：遍历 `selected`，对实现了 `modelOverrideSource` 的侧查文件在不在，不在的各出一项（通常 0 或 1 项）。`adapters` 参数是注入口，函数文档注明「为可测性；本函数只判存在、不读内容」。

```text
name:   `${label} 模型覆盖副本源`
ok:     true
warn:   true
detail: `⚠️ ${critic} 侧做模型覆盖要读的副本源 ${shown} 不在。该侧若在它缺位时拉起，就不做模型覆盖，` +
        `跑的是 ${cliName} 自己选的模型，不一定是请求的那个。要按请求的模型跑，先把副本源放回原处再发起；` +
        `已经发起的，跑完看 guard 有没有「本次没有做模型覆盖」告警（回读不到生效模型时它不出声）。`
```

- `label` / `critic` / `cliName` 一律经注册表取，与 C5 同口径；
- `shown`：路径在 `os.homedir()` 之下时显示为 `~/…`，否则原样显示。预检输出常被抄进 evidence 目录，不必带出用户名；
- 措辞只陈述构造性事实：副本源不在 ⇒ `source_missing` 早退、编排器不注入模型 ⇒ CLI 自选（C1）。**不**断言「FR-06 / NFR-06 不成立」（个人默认模型与请求同 modelId 时跑的就是请求的那个），也**不**断言「跑完一定告警」（C14）。这两层背景与「EV-112 E2 实测为个人配置的默认模型」一并写进 RUNBOOK；
- 「该侧若在它缺位时拉起」对两个调用点都成立：预检时当轮可能压根没选该侧（C9），`--start` 时文件可能在派生之前就已放回；
- 位置：预检 ④″，紧跟 C5，同样只在前面各项都通过时才跑，在探活之前，不花配额。

### 3.3 警告这一级与转述通道（决策 D2 → (a) + (c′)）

**(a) 结构化标记 + 汇总**：
- `CheckResult` 加 `warn?: true`；`PreflightResult` 加 `warnings: { name: string; detail: string }[]`，由 `checks.filter(c => c.warn)` 得出，恒存在（无警告时为 `[]`）。`ok` 与退出码**不受影响**。
