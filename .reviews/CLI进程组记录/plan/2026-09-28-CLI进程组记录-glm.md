### GLM-01 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §4.4（terminateRecordedCliGroups 的 isGone）与 §7.2` |
| 类别 | correctness ｜ 层次 plan |

**问题**：结束链的 isGone 是组长判定（judgeCliGroup !== 'alive'）。若组长服从 SIGTERM 而组内其他成员忽略 SIGTERM，terminateProcessGroup 在 SIGTERM 后的宽限轮询会因组长已死而提前返回 { gone: true, escalated: false }——不升级 SIGKILL，播报按 gone 不打「未能确认退出」。存活并继续烧配额的组员被报告为已结束，与「按事实说」的既有播报纪律（exec.ts:517 注释、EV-150）相逆。计划 §3 矩阵 h 格与 §7.2 只写了「判定时组长已退出」与「判定-发信号窗口」两格，没有这条「终止中途组长先死、组员赖着」的子格；而 EV-154 的目标恰是结束烧配额的 CLI。worker 自己的处理器（shutdownTrackedTrees 按父进程句柄判）同形，即这是被沿承的盲点，但本主题把它引进了新的消费方与新的播报承诺。

**依据**：src/trivium/util/exec.ts:534-541——SIGTERM 后以 isGone 轮询，为真即返回、不升级；计划 §4.4 把 isGone 定义为 (await judgeCliGroup(r)) !== 'alive'（组长判定）。既有 U15/I2 的「忽略 SIGTERM」构造是 trap 打在组长 sh 上（src/trivium/adapters/stub.ts:304 `trap '' TERM; sleep…`），只覆盖组长忽略的形态。test/helpers/proc.ts:24 已有按 pgid 数组成员的同形判据可用。

**建议**：二选一，都不必改机制：把该子格如实写进 §7.2 与 MANUAL 的「仍需手工核对」清单（与 h 格同列）；或在 terminateRecordedCliGroups 收尾后按 ps 的 pgid 列数一次组成员、非零即 warn（一次 ps 的代价），并给 U15 补一个「组员忽略 SIGTERM」的变体用例。

### GLM-02 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §4.3（cliRecordsOf）与 §4.5（cliGroupsConfirmedGone）` |
| 类别 | correctness ｜ 层次 plan |

**问题**：cliRecordsOf 把「cli 键存在但形状不合法」（pgid 非整数/≤1/字符串、started_at 非字符串非 null）与「键缺席/null」同格处理为「没有记录」。取消侧这是保守方向（不发信号）；但清扫侧的后果是把「明明记了、只是读不懂」变成准入通过、可抹——与计划 §4.5 自述的 EV-20 既定口径（抹除不可逆，判不了就不抹）相逆。触发面窄（原子写已防撕裂；新写者恒写合法形状；剩下的是手改与未来版本改形状），但一旦发生是对不可逆动作的静默放行，且 deferred 计数里看不见它。

**依据**：计划 §4.3「只收 pgid 为 >1 的整数、started_at 为 string|null 的；其余（旧文件、手改坏的）当没有」及 U12 的分格；src/trivium/status.ts:95-103 readStatus 只做 JSON.parse + as 断言、字段层无校验（计划 T1 同一事实）；src/trivium/retention.ts:107-115 admitScrub 只在记录判 alive/unverifiable 时拦、记录被丢弃即直通。

**建议**：在清扫消费路径区分三态：键缺席或 null → 没有记录（照旧）；键存在而形状不合法 → 按 unverifiable 处理（判不可抹、计入 deferred）；合法 → 照判。U12 与 U14 各补一格「cli 键在而形状坏 → 清扫不抹」。
