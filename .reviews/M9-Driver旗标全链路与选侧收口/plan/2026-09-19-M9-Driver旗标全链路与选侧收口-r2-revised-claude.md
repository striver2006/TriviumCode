## 2. 实质修订

### 2.1 §6.7 取值链整段重做：不再从后缀反推 driver（AGY-01 / CODEX-01 / CODEX-02 / GLM-01）

**我的错在于用一个循环依赖去解另一个循环依赖。** `inferLatestRunId` 要 driver 才能跳过
Driver 产出，而 driver 又在留痕里——我的「先猜一次再复算」只是把循环包了一层，
在「裁决件尚未写出」这一格上第一趟就断了。

**新解法（codex 与 gemini 给的是同一条，采纳）**：**根本不从工件后缀反推**。
本轮 run 的运行元数据文件名**就是** run_id，而 run.v2 把 `driver` 与 `rerun_index` 列为**必填**。
`listRecordedRuns` 已经在这棵树上用过（`cli.ts:741`）。于是：

```
读该阶段的运行元数据 → 取最新一条 → 它权威地给出 driver 与 rerun_index
→ 再用这两个值去校验工件与裁决件
```

没有猜测、没有两遍、没有不动点、没有循环。GLM-01 的 2-循环与旧轮次终态**随之全部消失**，
不需要再定义「恰好两遍」「超限失败」这些补丁。

**仍要定义的两点**（GLM-01 的第 ③ 点）：运行元数据读不出来（缺失 / 损坏 / schema 不识）时，
以及该阶段一条运行元数据都没有时，各自的回落与文案。

**`cmdGate` 仍不加 `--driver` 旗标** —— 这条原则不变，而且新解法让它更站得住：
事实来源从「后缀反推」升成了「留痕直读」。

**覆盖点改为七处**（GLM-06）：`cli.ts` 的 731 / 759 / 762 / 775 / 801 / 866 / 876。

### 2.2 §6.9 判据落地写法改正：二值谓词，不搬 `classifyArtifact`（AGY-02 / GLM-02 / CODEX-04 / CODEX-07）

**换底方向三侧都认可，错的是落地写法。** 实读确认 `classifyArtifact`（`freeze.ts:212-248`）：

- **无 `export`**，是 freeze.ts 的模块私有函数；
- **三值** `peer-review | own-or-driver | indeterminate`；
- 为**禁读矩阵**设计，fail-closed（「判不出就禁」），其注释明写「fail-closed 只用在这里，**不外扩**」。

我写「复用」时没注意到最后那句——它自己就禁止了我打算做的事。

**改为**：在 `render.ts` 已有的 `parseFrontMatter` 之上写一个**二值**谓词，三处共用：

```
isReviewArtifact(abs): 解析失败 / 无 front-matter / 无 schema → false（不是审查件）
                       schema === 'trivium.review.v1' → true
```

这样：不引入 `topic.ts → freeze.ts` 的分层倒置；不把 fail-closed 语义带进选原稿语境；
**显式路径的判据明确为「只对 `schema === trivium.review.v1` 硬拒」**，
无 front-matter 的手写原稿一律放行——保住 R-1 自己留的显式逃生门。

**焦点一的边界问题有了确定答案**（glm 给的，我核了 `render.ts:394-403`）：
front-matter 缺失 / 损坏 / 非 UTF-8 / 空文件**四类形态全部坍缩为「无 schema」且不抛错**。
所以换底不引入崩溃型未知问题——**我担心的那个风险不存在，真正的口子在别处（极性与分层）**。

**残余风险如实收窄**（CODEX-07）：「front-matter 被剥掉的审查件」这一格，二值谓词判 false
（当原稿），比 r1 的登记判据弱。r1 判据在这一格是可靠的，只是不完备。
→ 「扛得住明天」收窄为「**对未损坏的留痕**扛得住」；残余风险登记 **EV-63**。

### 2.3 §4.2 匹配器三条约束重写（CODEX-05/06 + GLM-03/04 + AGY-03）
