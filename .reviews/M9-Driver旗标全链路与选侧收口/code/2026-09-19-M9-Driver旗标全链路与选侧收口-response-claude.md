## 2. 修改方案

### 2.1 闸门回落：区分「没有留痕」与「留痕全坏」（AGY-01 / CODEX-01 / GLM-02）

根因是 `latestRunMeta` 把两种情况压成同一个 `null`，而三条子命令又各自解读。

**改法**：让它把两者分开（返回体带上「扫到了几份」与「哪几份读不出来」），然后三条路径口径统一：

| 情况 | `--check` / `--await-approval` | `--check-artifacts` |
| :--- | :--- | :--- |
| 扫到 0 份 | 现状文案（请先跑一次双审） | 退回旧口径，但**打一条可见提示**说明 driver 与轮次是按缺省算的 |
| 扫到 N 份、全读不出 | **硬失败并点名**是哪几个 run_id、以及是哪一种成因 | 同样**硬失败**——静默按缺省 Driver 判工件齐备正是本函数要消灭的形态 |

同时把 `cli.ts` 与 `meta.ts` 两处互相矛盾的注释改准。

### 2.2 T-11：补非缺省 Driver 的闸门闭环（GLM-01 / AGY-02 / CODEX-05）

按 glm 给的最小形态，在 `gate-loop.test.ts` 现成骨架上加一条带桩用例（**桩配置显式点名 claude**，按 R-8）：

1. `makeFixture` 后落一份 `<日期>-<主题>-<SELECTABLE[0]>.md` 原稿
2. `--driver <SELECTABLE[0]> --critics claude` 跑完 plan 阶段
3. 裁决件未写出时 `gate --check` → 断言失败文案**点名 `-revised-<真Driver>.md`**，而不是「找不到运行元数据」
4. 补齐裁决件（front-matter 的 run_id 对上）后同命令退 0

**并同步收紧扫描判据**：`checkAdjudication` 那条从「实参块含 `driver`」改为「取值来自 `gateDriver`」，与 `checkStageArtifacts` 那条同款——否则 `driver: DEFAULT_DRIVER` 照样绿，我那条变异行也才真正立得住。

### 2.3 台账落盘（CODEX-03）

这是**我应该先做而没做的事**：把计划 §8 的记账真正写进 `BACKLOG.md`。新增 EV-58～EV-64，关闭 EV-53/EV-54（本步已实现），并把 §8 声称「关闭」的 EV-58 与真实编号对齐。本轮再新增 **EV-65**（两个同形函数抽共用实现）。
