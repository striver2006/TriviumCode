# E1 审查员 stdout 实时输出实施与验收计划

2026-11-20，Driver 为 Codex。开发基线为 feat/vscode-extension 的 589525fd4a6ee5034c29a680a3c52252adfefe32。核心 1.3.7、插件 0.3.0。范围采用 11 月 5 日插件计划 G3 和 §6.4 的 E1。验收对象是审核者自己的 stdout 从进程管道到真实驾驶舱的全程。

## 现状与改动位置

review.ts 为每侧建立运行目录下的 critic/out，runner.ts 的 runOneSide 管理 attempt、证据检查、作废搬迁及重试。四个适配器最终都通过 util/exec.ts 的 run 接收数据。setEncoding('utf8') 在任意管道分块间保留未完成的字符，BSD PTY 经 ptyOutputNormalizer 规整，appendOut 收集解析用的有限长度文本，close 或退出宽限到期才返回。onStdoutLine 不保留空行与换行符，不能用作逐字节传输。当前收集上限按 JS 字符串长度计算，本次保留解析器输入口径。

| 适配器 | 当前解析、落盘和脱敏顺序 |
|---|---|
| Codex | invokeCodex → stdout.jsonl → parseCodexEvents，另用既有结果文件、轨迹和证据流程。 |
| Claude | invokeClaude 在返回前调用 scrubGatewayEnv，按 gatewayScrubPlan 的替换表先抹非豁免 env 原值，再调用 redactSecrets，然后写 stdout.jsonl 并 parseClaudeEvents。保留模型名豁免与既有解析输入。 |
| GLM | invokeZcode 从包含前置告警的输出解析 envelope，run 写 stdout.json，继续沿用 rollout 的证据来源。 |
| Gemini | invokeAgy 在 PTY 或管道输入规整后调用 parseAgyStream，run 写 stdout.jsonl 与独立 trace。 |

runner 在每次尝试后运行 scrubSideDir，scrub.ts 对已存在的 stdout 和 trace 做通用扫描与必要的原子替换，凭据副本仍沿用各侧的清扫出口。把原始 data 直接送往界面或 out/ 会暴露先写后抹的窗口。E1 的展示字节须在写入前完成脱敏。正式预检使用项目 wrapper，当前它执行用户安装目录中的 trivium.cjs。安装态验收夹具需要单独指定刚构建的 bundle。

插件目前由 stateWatch 按仓库发现运行，attachRun 挂 RunWatch。statusWatch.ts 监听运行根，去抖后按末尾字节窗口重读 worker.log，终态经 review --status 复核再释放。cockpit.ts 的 onLog 触发 pushRuns，cockpitHtml.ts 的 renderRuns 重建卡片，logView 保留 details 的滚动位置，以 textContent 虚拟绘制可见行。切到 M3 只改变终端中继状态。这些路径能复用，逐批 stdout 不应触发全部卡片重建。Phase 4 的五万行样本直接向 Webview 注入消息，仅作滚动对照。

## 核心

1. 在 run 的 review 调用路径增设可选 stdout 接收器。仅四侧正式审查和指定的可控子进程桩传入，doctor、版本查询和非审查子进程维持现状。使用已解码、已做 PTY 规整的文本。解析器仍接收其现有边界的结果，不以展示日志作为判定输入。
2. 由适配器提供输出格式及必要的网关替换值，由共用写入器维护增量状态。针对跨块凭据保留仍可能构成命中的原始后缀，只向写队列提交已确定安全的前缀。先完成逐值替换，再按通用规则处理。以完成的记录和可证明安全的分隔符为切点，覆盖未闭合词、跨行赋值、PEM 起始行 / 头 / 正文 / 尾、字面转义换行和跨记录网关值。无足够上下文时保留到后续块或 EOF。安全后缀积累达到既有收集上限时记截断或暂缓并在界面提示。对照同一输入整段脱敏的结果做分割点穷举，不复制规则表。保留空行和最后的无换行内容。
3. 写入沿用 stdout.json 或 stdout.jsonl，采用每次尝试专属文件身份。每次尝试在派生前发布小型能力/状态记录（格式版本、尝试号、受支持的文件名、状态），文件和状态按已验证顺序发布。重试前把上次文件按 attempt 改名保留，处理 stashVoidedOutput 对整个 out 目录的搬迁。沿用最新 raw_stdout_path。只有已建立 E1 文件身份的内容可送 Webview。输出和状态文件权限 0600。输出只顺序写一次，成功封口等写队列 drain 再更新终态；run 结束时不重写全量。现有 trace 和审查归档、scrub 审计计数需回归核对。
4. 每侧按 32 KiB 或最多 100 ms 攒批，串行异步写，正确处理短写。256 KiB 高水位时暂停 child.stdout，降到 64 KiB 恢复，内存预算再计一次 Node 管道块和安全后缀。定时器、描述符及错误监听逐次释放。磁盘阻塞、永久错误、解析输入截断、超时、中止与强杀须有不同可观测结果。写失败停用该次展示、排空管道让原审查继续，记录最近可靠字节与原因（仅错误类别，无输出原文）。状态文件写不成时利用 worker.log 告警；缺少成功封口一律显示未确认完整。禁止以 E1 I/O 故障改票。

## 插件

1. 在已确认属于本工作区的 runDir 下按入选侧和 attempt 读取 E1 状态。仅接受确定的文件名、路径边界和常规文件，避免跟随符号链接越出运行目录。不得从 Webview 接受任意读取路径。记录字节 offset、文件身份与 UTF-8 解码残片；单读串行，按照实际 bytesRead 推进。重试、截断、轮转或读取落后超过显示窗口时重置到该侧可见尾部，提示窗口起点，正确处理起点跨 UTF-8 字符。
2. 复用 Webview postMessage 和虚拟行视图，增设按 workspace/run/topic/critic/attempt 区分的 stdout 增量消息。初始化和重新可见时发送有限尾部快照。批次包含序号/偏移，处理重复、丢失、乱序及新建上下文。限制在途消息数，合并积压消息或使用有限窗口重同步。各侧实际文字可见，能分别查看 worker.log 与原审查正文。隐藏面板停 stdout 监控和渲染，重新可见补读；终态确认、关闭面板、关闭窗口均清理。M1 关闭只切到 M3，不解绑运行。终态保留最后可见窗口并提供查看完整已脱敏文件的入口。
3. 新核心正在运行但尚无数据时显示「等待该侧输出」。旧核心/旧运行缺能力记录时显示「此运行未提供实时 stdout」，继续显示日志及归档。状态不可读、写入中断、取消、超时分别注明；隐藏期间结束的运行在回到面板时仍按原主题和运行号复核。UI 截尾与文件截断分别标注。

## 验收与证据

- 四套可控厂商替身走真实适配器与子进程管道，分批输出各自格式，记录发出唯一明文标记时间、磁盘可见时间、该侧实际 DOM 可见时间和子进程退出时间。每侧明确等待测试端读取磁盘并在安装态 Webview 确认标记可见才释放退出闩锁。独立断言 PID 存活与时间先后，超时清理。覆盖输入切在中文字符、行中、无末尾换行、敏感标记每一切点；在每次 append 和可见消息检验禁现完整标记，终态以预期脱敏数据的完整字节、顺序和哈希核对。
- 正常入口沿用 extension/test/e2e 的隔离仓、安装包、真实 Extension Host 和终端 Driver，两个仓各用新 user-data-dir、extensions-dir，共享运行根，互异主题及标记。至少一轮三侧并发，换 Driver 覆盖第四条路径。在第一批和第二批之间关闭 M1，M3 显示相同主题和 run_id 的新内容。终态检查归档意见、证据计数、指纹、裁决和闸门，人工审批停点留给 Bob。对旧核心搭配新插件、重试、作废搬迁、取消、超时、写失败、慢盘、隐藏/重开逐项实测。
- 桩性能、故障走 TRIVIUM_STUB_CRITIC 并断言 stub/0.0.0。四个生产适配器路径的可控 CLI 与桩模式分账。真实厂商通过正式编排器在隔离夹具运行，登记实际 CLI 版本、首次/末次 stdout 管道事件相对退出时间、是否只在收尾可见；计时仅保存时间和字节数。失败和未测如实登记，真实 CLI 不用于性能对照。记录加载的 runtime bundle 绝对路径及 SHA-256、VSIX 与包内实际安装的 extension bundle 哈希。

## 性能目标与判定（编码前冻结）

在同一台 Mac、同一 VS Code、同一 Node 和磁盘上交替运行基线与 E1。固定三侧、夹具、种子、输入字节和发送时序。稀疏组每侧 60 次 × 256 B、间隔 250 ms；高流量组每侧 512 次 × 16 KiB、间隔 20 ms。每组预热一轮并记录，正式各版本各跑五轮，基线采用 589525fd 核心及对应 VSIX。基线无现成大量输出桩时，在两份临时测量构建中使用相同的测试专用输出生成器，分别接入原有一次落盘与 E1 路径，保留测试补丁、两份核心指纹和输出规模核对，不以基线空载作分母。最终 E1 安装态再以交付 bundle 复核。硬闩锁的功能用例另跑，性能进程按既定时刻退出。

- 记录开始到审查终态的墙钟耗时、worker 和 Extension Host 各自 user+system CPU 秒与峰值 RSS、stdout 实写字节及状态元数据写入字节。macOS 进程统计按 PID 以统一短周期采样，短进程保留退出计量；必要时用相同的测试探针记录写调用成功字节，注明逻辑字节与系统物理 I/O 的区别。每个采样标记记录子进程产生、写完、宿主读到、postMessage 到达及实际可见 DOM 的时间，用同一机器时间基准，按最近秩计算每轮 P95，保留原始值、五轮中位数、缺失/被尾窗淘汰数量。基线没有 stdout 卡的延迟记为不可见，无数值。
- 两组各自以中位数判定，E1 总耗时 ≤ 基线 × 1.10 + 0.5 s；每个进程 CPU 秒 ≤ 基线 × 1.25 + 0.5 s，峰值 RSS ≤ 基线 + 32 MiB。成功轮 stdout 写入恰等于预期脱敏字节数，额外 E1 元数据写入 ≤ 每次尝试 16 KiB。三侧分别计算可见延迟，稀疏 P95 ≤ 750 ms、持续大量输出 P95 ≤ 1 s，计划采样标记缺失数 0。标记应在批内可视区域，采用跟随尾部与小批标记观测，全量输出另作字节对账。
- 另以相同负载测面板隐藏和恢复，隐藏时 E1 postMessage 与视图渲染均为 0，恢复后 1 s 内补到最新可见尾部。无活动运行时观察 60 s，E1 文件监听/定时器/读取/消息数为 0，跟基线各五轮比较 CPU、内存与写量。未达标按分段计时定位写盘、读盘、传输或渲染，保留失败轮、优化后同负载复跑；任何硬指标未达不宣称可默认开启。
