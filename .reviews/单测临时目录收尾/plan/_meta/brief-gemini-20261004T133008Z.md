## 2. 通用 helper：`test/helpers/scratch.ts`

```ts
export const KEEP_FIXTURES_ENV = 'TRIVIUM_KEEP_FIXTURES';
export interface ScratchOwner { owner: string; noun: string }   // 提示里的主语与名词
export async function scratchDir(prefix: string, who?: ScratchOwner): Promise<string>;
export function scratchDirSync(prefix: string, who?: ScratchOwner): string;
```

1. **调用面**：`fs.mkdtemp(path.join(os.tmpdir(), 'trivium-x-'))` → `scratchDir('trivium-x-')`，返回值与 `fs.mkdtemp` 完全相同（不 realpath——现有调用里有的自己 realpath，有的故意不），逐处机械替换、调用方其余代码不动。缺省主语 `scratchDir`、名词「测试临时目录」。
2. **前缀校验**：必须匹配 `^trivium-[A-Za-z0-9-]*$`，否则在 mkdtemp **之前**同步抛 `TypeError`——挡住 `../`、绝对路径、斜杠等让目录落到 `os.tmpdir()` 之外的写法，也让退出时的防呆有确定的名字可认。
3. **登记**：mkdtemp 一返回就 push `{ dir, parent: 调用时的 os.tmpdir(), prefix, owner, noun }`，同一个同步段里完成（`await` 之后没有别的 `await`）；首次登记时挂一次 `process.on('exit')`。登记早于调用方的任何写盘，「建到一半抛出」也会被收尾（EV-207 FC4 的语义）。
4. **退出时**（逐字沿用 EV-207 的三件：`warnLine`、`unlockTreeSync`、每条一个 try）：
   - 保留变量为 `1`：按主语分组（首次登记的先后），每组一行 `〈主语〉：TRIVIUM_KEEP_FIXTURES=1，保留本进程的 N 个〈名词〉：a、b`，不删。只有 `makeFixture` 一组时输出与 EV-207 逐字相同。
   - 否则逐条：**防呆**——`dir` 是绝对路径、`path.dirname(dir) === parent`、`basename` 以登记的前缀开头，三者不全满足就打 `〈主语〉：清单里有不像〈名词〉的条目，未删：〈路径〉` 并跳过（正常不可达；比 EV-207 的「basename 以 `trivium-fx-` 开头」多一条父目录核对，即「删除目标必须是 mkdtemp 在系统临时目录下直接返回的那一层」，对应 R1 / R5）；然后 `unlockTreeSync` → `rmSync(dir, { recursive: true, force: true, maxRetries: 3 })`；失败打 `〈主语〉：〈名词〉没删掉，请手工删除 〈路径〉（〈错误码〉）`、继续下一条。
5. **永不改退出码**：退出钩子里不抛（每条一个 try、`warnLine` 自身吞错），所以通过的测试文件不会因删不掉被判失败、失败的测试文件也不会被翻成通过。
6. **保留变量沿用 `TRIVIUM_KEEP_FIXTURES`**（决策一），文件头注释写明它管 `test/` 下全部经 helper 建的临时目录；`fixture.ts` 改为从 `scratch.ts` 再导出 `KEEP_FIXTURES_ENV`，FC 组的 import 不用改。
7. **`makeFixture` 的改动只有一行**：`const raw = await scratchDir('trivium-fx-', { owner: 'makeFixture', noun: '夹具目录' })`；`FIXTURE_BASES`、`exitCleanupArmed`、`warnLine`、`unlockTreeSync`、`removeFixtureBasesSync` 整体挪进 `scratch.ts`（改为通用清单），`fixture.ts` 不再 import `chmodSync` / `readdirSync` / `rmSync` / `writeSync`。

## 3. 守卫用例：`test/unit/scratch-guard.test.ts`
