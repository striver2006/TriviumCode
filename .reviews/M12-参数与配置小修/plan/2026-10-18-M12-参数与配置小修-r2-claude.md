## 0. 与上位计划文字相比多出的一处

上位计划 §5 与用户给的任务目标把 EV-228 的改动面写成 `topic-args.ts` 一处，并说「`cli.ts` 的 `flagString` 对同一情形退 64」。核源码后，**`cli.ts` 这条入口只有「后面紧跟另一个旗标 / 位于末尾」两种形态会退 64，`--model-〈id〉=`（显式写等号、值为空）同样被静默丢弃**：

- `cli.ts:425-434` `flagString`：值为 `true`（没取到值）时退 64；值为空串时返回 `null`。
- `cli.ts:397-404` `collectModelOverrides`：`if (v) out[id] = v;`——`null` 被跳过，模型覆盖消失，不退非零。
- 同文件 `cli.ts:411-414` 的 `tierFlagGetter` 对三类档位旗标已经把这个形态补上了（`flagString(...) ?? ''`，再由 `assertTierFlags` 按空串退 64）——`cli.ts` 里档位旗标与模型旗标对 `=` 空值的口径今天就不一致。

本计划**把这一格一并纳入**（§2.3），理由：任务目标的判据是「空值退 64，文案与档位旗标同源」，只修 `topic resolve` 一个入口、留下 `review` / `preflight` / `doctor` 的同一形态，正是 EV-53 那一族「收口一个入口、另一个原样丢参数」的形状。它同样是**行为变化**（原先静默丢弃的 `--model-〈id〉=` 改为退 64），与 EV-228 一并写进设计与说明。计划双审两侧均支持纳入；收口时向用户明示、请其追认。

## 1. 问题与现状（源码核实）

### 1.1 EV-228：`topic resolve` 下 `--model-〈id〉` 写了不给值被静默丢弃

- `topic-args.ts:111-171` `splitArguments`：取值旗标缺值（后面紧跟另一个**已知**旗标，或位于末尾）记空串 `''`；`--k=` 形态同样记 `''`。
- `topic-args.ts:638`：`const written = ALL_AGENT_IDS.filter((id) => named[\`model-${id}\`]);`——按真假过滤，`''` 判假被当成「没写」，**不报错、不退非零**，`models` 里没有这一侧，模型覆盖无声消失；之后命令 A 的 S0.6 / S2 / S6 照抄 resolve 输出，配置档位悄悄顶上。
- 同文件 `:647-657` 的三类档位旗标（M11 第 5 步）已按「键在不在」判：`collectTierFlags` 收 `undefined` 与 `''` 分开，`assertTierFlags`（`tier-flags.ts:106`）对 `''` 退 64：`--〈前缀〉-〈id〉 需要一个值，但没有给出。`
- 判定次序（档位旗标）：**先键**（`assertCriticFlagKeys`：该 id 是不是本轮入选审核者），**再空值**，再取值形状。

### 1.2 EV-228 关联：`cli.ts` 的 `=` 空值（见 §0）

- `review --start`（`cli.ts:666` 起）、`preflight`（`:842` 起）、`doctor`（`:815`）三处都经 `collectModelOverrides` 收集；`review` / `preflight` 之后 `assertModelOverrideKeys`（只判键），`doctor` 不判键。
- `--model-glm --focus x` / 末尾 `--model-glm`：`flagString` 退 64（文案「需要一个值，但它后面跟的是另一个旗标（或什么都没有）」）——**不变**。
- `--model-glm=`：静默丢弃——**本计划改**。

### 1.3 EV-227：`profiles.〈表〉.〈id〉.effort`（Agent 级）无读取点、与阶段格子里的 `effort` 同名不同层

- `types.ts:1132`：`ProfileEntry = Partial<Record<Stage, StageModel>> & { effort?: 'low' | 'medium' | 'high' }`——Agent 级 `effort` 是 v1 时代遗留（`config.v1.json` 的 `profiles.*.gemini|glm` 也收它）。
- 读取点：全仓 `src/` 对档位表只有一处按阶段的读取 `adapters/base.ts:2018`：`cfg.profiles[cfg.active_profile]?.[critic]?.[stage]`；`config.ts:600-601` 只看表名。**没有任何代码读 Agent 级 `effort`**。
- `config.v2.json:533-540`：`profiles` 的格子对象（`additionalProperties: false`）在 `plan/code/bug` 之外收一个 `effort`（`low/medium/high` 枚举），无 `deprecated`；`profiles` 描述（`:519`）末句写着「Agent 级 effort 键无读取点，见 BACKLOG」。
- M11 第 4 步之后阶段格子可写 `{model, effort}`（`$defs/stageModel`），阶段格子里的 `effort` 是思考等级、第 6 步起下传；Agent 级这个什么都不做。
- 废弃键表 `config.ts:444-463` `DEPRECATED_CONFIG_KEYS` 未收它；通配走查 `deprecatedConfigKeysIn`（`:467-483`）对 `'*'` 展开当层全部键、按键名排序，路径 `['profiles','*','*','effort']` 只命中**第三层**的 `effort`，阶段格子里的 `effort` 在第四层，**差一层、不会命中**。
- 本仓 `.trivium/config.yaml` 只有阶段格子里的 `{model, effort}`，没有 Agent 级 `effort`，本仓 doctor / preflight 不会因本批多出提示。

## 2. 方案

### 2.1 EV-228 主改动：`topic-args.ts` 按键存在判定

1. `:638` 改为按键存在收集：`ALL_AGENT_IDS.filter((id) => named[\`model-${id}\`] !== undefined)`。
2. 次序与档位旗标一致：**先** `assertModelOverrideKeys`（键判定，不变），**再**空值判定，空值退 64。
3. 赋值只在两步都通过之后（值必非空）。
4. 改 `:647-651` 那段注释里「既有 `--model-〈id〉` 的同一缺口另登记 BACKLOG，本步不改」一句。

### 2.2 文案同源：空值判定只此一份

在 `tier-flags.ts` 抽出一个导出函数（暂名 `assertFlagValuesGiven(prefix, raw)`，`prefix ∈ {'model','tier','effort','profile'}`，`raw: Record<string,string>`）：任一值为 `''` 即 `usageError(\`--${prefix}-${id} 需要一个值，但没有给出。\`)`。

- `assertTierFlags` 现有的空值循环（`tier-flags.ts:104-108`）改为对三类各调一次这个函数——**文案逐字不变**（现有 `tier-flags.test.ts:80-82` 与 `tier-flags-cli.test.ts` T2 照旧通过）。
- 模型旗标的空值判定调**同一个函数**、前缀 `model`。
- 遍历次序：按 `ALL_AGENT_IDS` 注册表序——多侧同时空值时报第一个，与档位旗标现状一致。

### 2.3 EV-228 关联：`cli.ts` 的 `=` 空值（§0）

1. `collectModelOverrides`：`args.flags.has(name)` 且 `flagString` 返回 `null`（即 `--model-x=`）时记 `''`，不再跳过；没写仍不出现；`true` 形态仍由 `flagString` 退 64（文案不变）。
2. `review --start` 与 `preflight`：在 `assertModelOverrideKeys` 之后调 `assertFlagValuesGiven('model', modelOverrides)`。
3. `doctor`：它不判键（现状），只在收集后调 `assertFlagValuesGiven('model', …)`；**不新增键判定**。
4. 空值在进入任何落盘前已退 64，下游拿到的值必非空，与今天相同。

### 2.4 EV-227：Agent 级 `effort` 进废弃键表

1. **`config.ts` `DEPRECATED_CONFIG_KEYS`**：表尾追加 `{ path: ['profiles', '*', '*', 'effort'] }`，注释写明：①两层 `'*'` 依次匹配档位表名与 Agent id；②**只命中 Agent 级那一层**，阶段格子里的 `effort` 在下一层、不会命中；③v1 配置迁移后带着它也会被提示（迁移不删内容）。
   - 文件头注释「路径里的 `'*'` 匹配 `agents` 下任一 Agent id」改准：`'*'` 匹配当层任一键。
   - 输出形态沿用：点分路径 `profiles.default.gemini.effort`，按表序、同条内按键名排序。提示正文 `deprecatedConfigNotice` 不改。
2. **`types.ts:1132`**：`ProfileEntry` 删去 `& { effort?: … }`，加注释（删除日期、EV 号、理由、「schema 仍接受它（标 deprecated），见 `DEPRECATED_CONFIG_KEYS`。不要加回来。」）。`tsc` 若报读取点，停下重核。
3. **`config.v2.json`**：
   - `profiles` 格子里 Agent 级 `effort` 加 `"deprecated": true` 与 `description`，**枚举不放宽**、不改 `additionalProperties`；
   - `profiles` 描述（`:519`）末句改为指向该属性的 deprecated 说明；
   - `$defs/stageModel` 里的 `effort` **不动**。
4. **默认值与 `init`**：默认配置的 `profiles` 本就不带 Agent 级 `effort`，无需删。
5. **不改的**：`config.v1.json`、`migrateConfigV1`、`resolveTier` 与适配器透传、`ATOMIC_CONFIG_NODES`、doctor / preflight 的提示通道本身。

### 2.5 不做的

- 不给 `--model-〈id〉` 加取值形状校验（如去空白）：档位旗标今天也不 trim，保持对称。
- 不给 `doctor` 补模型覆盖的键判定；报告里如实写这一残余不对称（`--model-codex X` 在 doctor 不判键）。
- 不改 `flagString` 的 `true` 形态文案（跨入口文案差异是两个解析器的既有差异，本批只保证**同一入口内**模型旗标与档位旗标逐字同源）。

## 3. 行为口径

### 3.1 `topic resolve`

| 输入形态 | 现状 | 改后 |
| :--- | :--- | :--- |
| 完全不写 `--model-〈id〉` | 退 0，`models: {}` | **逐值不变** |
| `--model-glm GLM-5.3`、`--model-glm=GLM-5.3` | 退 0，`models: {glm: 'GLM-5.3'}` | **逐值不变** |
| `--model-glm=`（写了不给值） | 退 0，`models: {}`（静默丢弃） | **退 64**：`--model-glm 需要一个值，但没有给出。` |
| `--model-glm --focus x`（紧跟另一个已知旗标） | 退 0，`models: {}` | **退 64**，同上文案 |
| 末尾 `… --model-glm` | 退 0，`models: {}` | **退 64**，同上文案 |
| `--model-claude`（Driver 自身）空值 | 退 0（被过滤） | **退 64，键判定的文案**（先键后值） |
| `--model-codex X`，但 codex 本轮没入选 | 退 64（键判定） | 不变 |

「紧跟另一个旗标」只对**已知**旗标成立：`--model-glm --不认识的东西` 照旧被当成值。

`critics` 字段、计划审与代码审两轮共用同一组的语义**不受影响**：`critics` 先于模型旗标解析，本改动不碰 `resolveCriticSelection`；改后唯一差别是原先「解析成功、覆盖丢弃」的输入改为在 S0.5 退 64、零工件。

### 3.2 `review --start` / `preflight` / `doctor`

| 输入形态 | 现状 | 改后 |
| :--- | :--- | :--- |
| 不写 / 正常写法 | 不变 | **逐值不变** |
| `--model-glm --x`、末尾 `--model-glm` | 退 64（`flagString`） | 不变（文案不变） |
| `--model-glm=` | 静默丢弃 | **退 64**，与 `--tier-glm=` 同文案 |

### 3.3 Agent 级 `effort`

| 配置 | 现状 | 改后 |
| :--- | :--- | :--- |
| 不写 | 无提示 | 不变 |
| `profiles.default.gemini.effort: high` | schema 通过、无提示、无效果 | schema 通过、**doctor / preflight 提示一条**、仍无效果 |
| 阶段格子 `{model: x, effort: high}` | 思考等级下传 | **不变、不提示** |
| 两者同在 | 阶段格子下传 | 阶段格子照常下传；只报 Agent 级那一条 |
| `profiles.default.gemini.effort: max` | schema 拒 | **仍拒** |

- **行为变化面**：原先能跑通、只是覆盖丢了的命令，改后在开跑前退 64、零工件。不影响任何不带空值的写法。
- **同一入口内同源、跨入口不同文案**：§2.5 已写明。
- **废弃键通配**：两层 `'*'` 展开所有表与所有键；表下写非 Agent id 的键会先被 schema 拒，走查只在合并结果上做，不可达。
- **删类型字段**：`tsc` 报读取点即停下重核。
