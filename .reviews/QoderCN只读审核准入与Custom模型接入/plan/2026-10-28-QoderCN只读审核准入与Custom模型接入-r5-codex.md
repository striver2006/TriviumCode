## 3. 有上限的执行层拒绝可观察性实验

先 Write、Edit、Bash，每工具独立 prompt、同目标状态与同模型绑定的两臂。正控制：Write 写新假文件；Edit 将已知文本变更；Bash 仅对夹具文件输出固定 canary。必须取得工具调用 ID、输入、同 ID 成功结果及夹具回读；权限 mode 或 allow 语法不明不算成功。候选臂恢复相同前置文件状态，仅更换为当前最小审核配置，要求真实工具调用/同 ID 失败与原生拒绝事件。工具未暴露或模型不调用单列，不能用它们证明拒绝。

每工具每臂最多 180 秒、最多 2 次；第 2 次只用于修正明确的参数/调用错误，保留第一次原件和重试理由，不改措辞诱导多次碰运气。Write/Edit/Bash 首阶段最多 12 次模型调用、36 分钟上限（不含生产探针的既有限额）；若全部候选臂无真实拒绝，则停止扩展执行入口，转为阻塞报告及可独立完成的安全验证，不无限重试。任何秘密命中、CLI/源/认证变化、清理失败立即停止后续原生模型派生，保留失败与租约，按已有安全回收流程处理。

先由实际 init.tools 清单确定其它工具。首阶段至少一项取得可观察执行层拒绝后，再覆盖 Agent/Task、MCP、网络及其它执行入口：无害子任务只读假文件；MCP 为本地只操作夹具的最小服务；网络仅 loopback 无敏感数据。每实际入口同样最多两臂各 2 次/180 秒，按实际清单一次覆盖后停止。无法构造真实正控制、未暴露、无调用或缺分发事件的必需项保持未测/阻塞。

permission-rule、permission-mode、tool-unavailable、unknown 分列；只有真实可配对的规则或分发拒绝才可成为对应执行层证据，不能混算 mode 或正常文件不变。保留原生 init、tool_use/result、permission_denied、result、退出码与信号；采集通过与准入通过分开。不得通过扩大候选工具面、替换生产 argv 或增加权限来制造绿色候选。

## 4. 随后安全矩阵及实现消费

Read/Grep/Glob 正常假文件正控制；同行、敏感、私有凭据假路径逐工具拒绝，覆盖相对/绝对、/var 与 /private/var、目录搜索、软链目标变化、运行中新建工件。每工具/路径变体最多同样两次/180 秒；空搜索结果不计拒绝，文件无变化不计成功隔离。记录调用实际目标与 canary 关联，软链变目标超出已验覆盖必须拒绝或重新验收。

配置叠加逐项用真实生效正控制验证共享技能、项目 Hook、插件、MCP、原生 user/project/local 配置；审核臂只未触发不可通过。先取得原生实际排除/拒绝格式，再实现验证器消费及脱敏原件回放/负例；没有观测格式继续走现有明确阻塞分支。不得先添加假设事件名或人为绿色数据。工具/路径/配置的子用例缺一格，该必需项仍阻塞，不能聚合掩盖。

运行期回退仅接受合法 init 之后真实发生；缺配置启动回退继续保留为 configuration-invalid，不能挪用。无法可控触发则未测。沿用生产 monitor 双通道首因粘滞、尾部扫描与 0 不覆盖失败。

原生生命周期依次自然成功/失败、启动失败、超时、取消、强杀、失联回收、整树退出、凭据清理，覆盖探针所有者和 worker 两类；必须回读 codec、主 CLI、辅助进程与脱组进程的身份/退出，不以主组空替代。复用 AbortSignal/TERM/KILL、lstart 身份与 credential lease；未知身份不杀、不删。每场景一次主试验、最多一次明确装置错误修正，单臂 180 秒，清理监督 30 秒上限；未退出保留租约并立即停止派生。Node 夹具仅补回归，不算原生证据。原始 code/signal、编排首因、清理结果分别保留，失败不被 CLI exit 0 或清理后成功覆盖。
