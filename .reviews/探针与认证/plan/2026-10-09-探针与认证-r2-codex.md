## 本轮细化的数据与预算接口

异构模型族判定交由「留痕与异构」，本主题输出 route 声明及回读来源，供应商值不能替代有效模型。指纹唯一实现位于适配层 Claude route 模块，doctor、availability、auth 与审查都调用它，不能抄第二份。

ClaudeProbe 新增 routes 字典，每项 {profile, fingerprint, probe}；fingerprint 是原生路径/底层版本/wrapper哈希/profile配置哈希组成的安全对象。native 与各非空 profile 分键；原单体字段仅作旧原生记录兼容，缺绑定指纹的旧结论不得作为新 profile 准入依据。probe.auth 原字段保留读取但不自动转换；新增 auth_routes: Record<组合哈希,{checked_at,cli_version,fingerprint,ok:true,combination}>，combination 保存 critic/mode/profile/model/effort 的非敏感值。旧 Agent 缓存不能证明新模型组合，首次重探。API factory 签名 authProbe(ctx,projectRoot,combination?)；四家真实适配器消费选定 model/effort/profile，桩和旧调用缺参有明确兼容，生产预检恒传解析组合。

Claude profiles 根可通过受控配置/测试注入口指定，缺省 ~/.claude/profiles；自动测试只读 scratchDir。实际包装器如仍固定 HOME，测试包装器必须消费同一个夹具根，生产不让元数据来自一目录而 cld 从另一目录加载。元数据只解析静态 export 的模型键和非敏感 provider 声明，不能 source。

doctor 缺省只探 Agent 配置选定的一条路线；显式 --profile-<id>/--native-<id> 可选择另一条。未探、失败、指纹过期分别显示，但均不能支持只读运行。--no-model-calls 不更新 paid probed_at；变更 fingerprint 时不能为旧 paid 结论换上新指纹。64 类解析/存在性检查先于69类环境检查，USAGE、PROTOCOL、MANUAL §5.4、RUNBOOK、CASE 剧本11、主设计11.5和测试同批改。

48 次是本次前置任务的真实能力探针/路线验收预算，三主题共用。正式审查与其审核侧预检另外登记，不占四批预算。事实核验的 --help/--version 独立标记；进入能力探针批次的这些启动同样记账，不把免费等同不计启动。每次实际 Agent 启动前原子认领唯一台账项，结果另外追加，不读改写计数；每批最多12个，四批最多48个，重试/失败/超时均计。台账位于 doc/05_testing/evidence/dual-mode-20261009/launches/，一个任务唯一根。

Claude 当前完整算法上界：version/help 2次、读取1、verbose负对照1、写负对照1、Schema1、路径deny三臂3、记忆两臂2，共11次；预算余下1次可验证 Qwen pro 模型，读取成功可作为同一组合认证证据，避免重复探活。每批不自动重试。Codex 先算实际探针调用数，再按 native/Qwen/Kimi/DeepSeek 顺序使用该批12次；预计超限或达到上限即停止真实调用、保留未测项，不减判据，不宣称七路线验收完成。实现和离线验证继续完成；任何增预算请求留待具体未完成清单可供用户审阅时提出。

## 目标与依赖

执行用户批准的「Codex、Claude Code 双模式接入与异构判定修正」。第一主题提供统一路由和包装器执行能力；本主题负责各路线只读探针、指纹与逐组合认证。第三主题统一记录 run.v3。Claude 官方当前不可用；原生离线测试保留，真实验收待订阅恢复。供应商不改变 Agent 身份。不改用户全局配置、版本号；提交推送待确认。

## 实现落点

1. 主设计先定探针契约与预检顺序，实测事实后回填。`types.ts`、`doctor.ts`、`probes/claude.ts` 扩展 native 与 profile 路线数据。每条结论以底层 CLI 版本、原生入口、包装器脚本哈希、对应配置哈希绑定；路线或任一指纹变化即失效，禁止挪用旧原生能力。保留历史探针读取，历史结论仅可用于同一可证明路线。
2. 安全提取 `~/.claude/profiles/*.env` 的文件名和非敏感模型映射，不执行配置内容来取元数据，不输出密钥或端点原文。只支持可辨认的静态 export；不能解析时明确告警，不猜。哈希在内存计算，密钥内容不进入日志、夹具、归档。配置模型映射是声明名单，不能冒充完整服务端目录；无法核实目录时告警，通过实际组合探活验可调用性。
3. 每条当前路线核实：读取、工具白名单、MCP 隔离、写入负对照、禁读检测、结构化输出、轨迹解析。复用现有 Claude 探针算法，不复用结论；全部探针子调用使用统一路由、所选模型和清理后的 env。doctor 无模型调用模式不得刷满 paid 能力的新鲜度。
4. `AuthProbe` 接受实际解析组合；Codex 与 Claude 探活按 Agent/mode/profile/model/effort 构造请求。preflight 先按阶段解析再去重；共享配置中不同阶段/档位必须验证本轮实际选用的组合（EV-229），单一模型结果不能覆盖另一组合。
5. 正缓存以组合与凭据/配置/包装器指纹隔离，TTL 保留，失败不缓存。缓存键采用规范化组合的哈希，不能存密钥或跨供应商复用。凭据指纹不得只用 mtime，刷新参数强制重测；清扫临时认证副本与 Codex HOME 沿用现有纪律。
6. preflight 与 prepareRun 的错误顺序统一：先检查参数、组合、显式不存在的 profile（64），再入口/只读能力/凭据/服务（69）。认证失败保留 stderr 的脱敏摘要、退出码与路线；不自动切换另一供应商。消除 EV-232。
7. CLI 版本取底层 Claude，包装器独立哈希。检查原生与 wrapper 可执行性、profile 存在性。全流程取消、超时、失败路径保持原生读保障、进程树终止、清扫与路线证据，不用 shell timeout，不复制全局设置或 MCP。

## 测试与真实启动预算

自动测试覆盖组合去重、三阶段不同模型、native 与 profile 缓存隔离、profile 文件或 wrapper 内容修改失效、指纹读取失败不缓存、异常64/69优先级一致、敏感值脱敏、真实桩子进程 argv/env、超时取消清扫。配置模型名单无法当权威目录；无完整目录的有效模型不被错误拒绝。旧探针不能静默放行新路线。Antigravity/ZCode 的已有探针和认证行为回归。
