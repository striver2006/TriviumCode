# 探针与认证实施计划

日期：2026-10-09；Driver：codex；M11 第 12 步全量验收的前置任务之二。

## 目标与依赖

执行用户批准的「Codex、Claude Code 双模式接入与异构判定修正」。第一主题提供统一路由和包装器执行能力；本主题负责各路线只读探针、指纹与逐组合认证。第三主题统一记录 run.v3。Claude 官方当前不可用；原生离线测试保留，真实验收待订阅恢复。供应商不改变 Agent 身份。不改用户全局配置、版本号；提交推送待确认。

## 实现落点

1. 主设计先定探针契约与预检顺序，实测事实后回填。`types.ts`、`doctor.ts`、`probes/claude.ts` 扩展 native 与 profile 路线数据。每条结论以底层 CLI 版本、原生入口、包装器脚本哈希、对应配置哈希绑定；路线或任一指纹变化即失效，禁止挪用旧原生能力。保留历史探针读取，历史结论仅可用于同一可证明路线。
2. 安全提取 `~/.claude/profiles/*.env` 的文件名和非敏感模型映射，不执行配置内容来取元数据，不输出密钥或端点原文。只支持可辨认的静态 export；不能解析时明确告警，不猜。哈希在内存计算，密钥内容不进入日志、夹具、归档。配置模型映射是声明名单，不能冒充完整服务端目录；无法核实目录时告警，通过实际组合探活验可调用性。
3. 每条当前路线核实：读取、工具白名单、MCP 隔离、写入负对照、禁读检测、结构化输出、轨迹解析。复用现有 Claude 探针算法，不复用结论；全部探针子调用使用统一路由、所选模型和清理后的 env。doctor 无模型调用模式不得刷满 paid 能力的新鲜度。
4. `AuthProbe` 接受实际解析组合；Codex 与 Claude 探活按 Agent/mode/profile/model/effort 构造请求。preflight 先按阶段解析再去重；共享配置中不同阶段/档位必须验证本轮实际选用的组合（EV-229），单一模型结果不能覆盖另一组合。
5. 正缓存以组合与凭据/配置/包装器指纹隔离，TTL 保留，失败不缓存。缓存键采用规范化组合的哈希，不能存密钥或跨供应商复用。凭据指纹不得只用 mtime，刷新参数强制重测；清扫临时认证副本与 Codex HOME 沿用现有纪律。
6. preflight 与 prepareRun 的错误顺序统一：先检查参数、组合、显式不存在的 profile（64），再入口/只读能力/凭据/服务（69）。认证失败保留 stderr 的脱敏摘要、退出码与路线；不自动切换另一供应商。消除 EV-232。
7. CLI 版本取底层 Claude，包装器独立哈希。检查原生与 wrapper 可执行性、profile 存在性。全流程取消、超时、失败路径保持原生读保障、进程树终止、清扫与路线证据，不用 shell timeout，不复制全局设置或 MCP。

## 测试与真实启动预算

自动测试覆盖组合去重、三阶段不同模型、native 与 profile 缓存隔离、profile 文件或 wrapper 内容修改失效、指纹读取失败不缓存、异常64/69优先级一致、敏感值脱敏、真实桩子进程 argv/env、超时取消清扫。配置模型名单无法当权威目录；无完整目录的有效模型不被错误拒绝。旧探针不能静默放行新路线。Antigravity/ZCode 的已有探针和认证行为回归。

真实探针及路线验收全项目最多 48 次 CLI 启动，必须逐次记录用途、请求组合、耗时、exit、指纹、能力结果；四批依次 Claude/Qwen、Claude/Kimi、Claude/DeepSeek、Codex native/Qwen/Kimi/DeepSeek，每批最多12次，到上限即停。--help/--version 事实核验与真实模型 CLI 启动分开记录，计数口径对所有路线相同，不将服务端请求数推断为CLI次数。探针算法先估计最大调用数，不能以降低判据压预算。真实验证不重复无必要请求，正式审查另按主题四轮封顶。

Qwen 准入通过后，共享配置 default/flash 使用 qwen3.8-flash，pro 使用 qwen3.8-max（必须实际探活）；不添加未验证 effort 默认值。本机填路径与 Qwen profile，移除临时两审 override，恢复共享三审。若准入未通过则保留现状、明确失败与未测项。

完成正式计划/代码审查、逐条裁决、verify 后，汇总报告登记 doc/05_testing/README；完整串行两次 npm run check、14/14 自检、构建重装与安装 hash 核对归最终验证。七条可用路线全部通过才宣称前置任务完成，随后另执行 M11 全量验收。
