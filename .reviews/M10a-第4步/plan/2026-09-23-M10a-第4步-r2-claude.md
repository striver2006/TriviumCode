### 2.2 判据怎么定

**上位设计的要求**：演进设计 §5「与 Driver 模型族不同；模型族**按生效模型判定，不按 Agent**」。

- **审核者一侧做得到**：按生效模型（`model_effective`，回读不到退回请求值）的模型名判族，与今天一致。
- **Driver 一侧做不到**：编排器不采集 Driver 的生效模型，只能按身份近似，这与「不按 Agent」有张力。
  近似取 r7 §5 的字面「当轮 Driver 的**厂商**」，并称之为**厂商名义族**：假定 Driver 跑的是其厂商的自家模型族。

**r2 修正（CODEX-04）：「模型族」在本仓有两种说法，本判据用的是哪一种。**
`config.ts` 把 `agents.codex.profile` 称为「家族」的唯一判定依据，默认 `qwen`。那个「家族」描述的是**审核者调用**（`codex -p <profile> exec`）连到哪家 provider，
不是 Driver 会话：用户自己起的 codex Driver 会话不经过这份配置。本判据用的是厂商名义族，**不等于**那种家族说法，两者冲突时按名义族判。
没有改用 `agents.codex.profile` 当 Driver 族，理由有两条：一是那等于拿审核者的配置去猜 Driver；二是只有 codex 一家有这个字段，用它就要按 id 分叉（纪律 7）。
代价要写明：**driver=codex 时**，审核者跑 qwen 会被判异构，审核者跑 `gpt-*` 会被判同族。这两类错判都进 EV-107。

```ts
// agents/registry.ts（新增，叶子模块，不引入依赖）
/**
 * 各厂商的**名义**模型族，按模型名判定（EV-62，M10a 第 4 步）。
 *
 * 唯一用途：`isHeterogeneous` 用它近似「当轮 Driver 的模型族」。
 * 编排器不采集 Driver 的生效模型，只能假定 Driver 跑的是其厂商的自家模型——
 * 这是**启发式**。本仓自己就有反例：codex 在本仓默认跑 qwen，Antigravity 提供 claude-* slug。
 * 它也**不是** `agents.codex.profile` 意义上的「家族」：那一个描述的是审核者调用连到哪家
 * provider，与 Driver 会话无关。与演进设计 §5「模型族按生效模型判定、不按 Agent」
 * 在 Driver 一侧有张力，根本解见 BACKLOG EV-107。
 *
 * 以 `Record<AgentVendor, …>` 声明：登记第五个厂商而不补这里，编译期就报错。
 */
export const VENDOR_MODEL_FAMILY: Readonly<Record<AgentVendor, RegExp>> = {
  anthropic: /claude/i,
  openai: /gpt/i,
  antigravity: /gemini/i,
  zcode: /glm/i,
};
```

```ts
// adapters/base.ts
/**
 * 审查模型是否与当轮 Driver 异构（FR-17 / AC-18；EV-62 起按当轮 Driver 判定）。
 *
 * 判据：模型名**不落在** Driver 厂商的名义模型族里，即判异构。两层都是启发式：
 * 模型族靠模型名判（`VENDOR_MODEL_FAMILY`），Driver 的模型族靠厂商近似。
 * 所以 `true` 的准确读法是「未检出同族」，不是「确认异构」。
 * 取不到模型名时判 `true`，与改动前一致。
 */
export function isHeterogeneous(model: string | null, driverVendor: AgentVendor): boolean {
  if (!model) return true;
  return !VENDOR_MODEL_FAMILY[driverVendor].test(model);
}
```

| Driver 厂商 | 审核者模型 | 改前 | 改后 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| anthropic | `claude-*` | false | false | 不变 |
| anthropic | 其他 | true | true | 不变 |
| 非 anthropic | `claude-*` | **false** | **true** | EV-62 原文的那一格。内置配置下可达：非 claude 的 Driver 可选 claude 审核者 |
| antigravity / zcode / openai | 本厂商名义族（`gemini-*` / `GLM-*` / `gpt-*`） | true | **false** | 新增检出。**r2 修正（CODEX-04）：内置配置下不可达，只对显式覆盖生效**（两档位 × 四家 Driver × 各三侧 × 三阶段，72 格实测零命中，codex 独立复跑一致） |
| 非 anthropic | 其他 | true | true | 不变 |

**误差方向**：`false` 只触发告警与 `override_reason`，不拦闸门。误报的代价是多一行告警，漏报的代价是把同源审查记成异构。两种误差本方案都有（§2.6）。

**考虑过、没采用的方案**：
- 「Driver 为 anthropic 时照旧，其余一律判异构」（r1 初稿）：对非 anthropic 的 Driver 放弃检出，误差全落在漏报一侧；
- 「driver=codex 时取 `agents.codex.profile` 当族」（CODEX-04 选项 a）：理由见上。
