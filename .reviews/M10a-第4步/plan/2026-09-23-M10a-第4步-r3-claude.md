### 2.2 判据怎么定

**上位设计**：演进设计 §5「与 Driver 模型族不同；模型族**按生效模型判定，不按 Agent**」。

- **审核者一侧**：按生效模型（`model_effective`，回读不到退回请求值）的模型名判族，与今天一致。
- **Driver 一侧**：编排器不采集 Driver 的生效模型，只能按身份近似，与「不按 Agent」有张力。
  近似取 r7 §5 的字面「当轮 Driver 的**厂商**」，称为**厂商名义族**：假定 Driver 跑的是其厂商的自家模型族。
- **它不是 `agents.codex.profile` 意义上的「家族」**：那一个描述审核者调用（`codex -p <profile> exec`）连到哪家 provider；Driver 会话由用户自己起，不经过这份配置。
  不取它当 Driver 族的理由有两条：一是那等于拿审核者的配置去猜 Driver；二是只有 codex 一家有这个字段，采用就要按 id 分叉（纪律 7）。

**r3 修正（GLM-01）：名义族的代价按可达性分写**，依据是本机探针的模型目录，不写成全称：

| 形态 | 结果 | 可达性 |
| :--- | :--- | :--- |
| driver=codex，gemini 审核者经 `--model-gemini gpt-oss-120b-medium` 显式覆盖 | 判同族（告警 + `override_reason`），而 codex Driver 实际多半跑 qwen | **可达**：agy 目录有该模型 |
| driver=claude 而 Claude Code 实际接的是别家模型，gemini 审核者经显式覆盖跑 `claude-*` | 判同族，实际可能异构 | **可达**：agy 目录有 `claude-*` |
| driver=codex，审核者跑 qwen | 判异构，实际可能同族 | **本机目录下不可达**：能跑 qwen 的只有 codex 审核者，而它在 driver=codex 时被排除；zcode 目录今天只有 GLM 系。zcode 目录出现 qwen 系之后才可达（它支持自定义 provider） |

```ts
// agents/registry.ts（新增，叶子模块，不引入依赖）
/**
 * 各厂商的**名义**模型族，按模型名判定（EV-62，M10a 第 4 步）。
 *
 * 唯一用途：`isHeterogeneous` 用它近似「当轮 Driver 的模型族」。
 * 编排器不采集 Driver 的生效模型，只能假定 Driver 跑的是其厂商的自家模型——
 * 这是**启发式**。本仓自己就有反例：codex 在本仓默认跑 qwen，Antigravity 提供 claude-* slug。
 * 它也**不是** `agents.codex.profile` 意义上的「家族」：那一个描述的是审核者调用连到哪家
 * provider，与 Driver 会话无关。与演进设计 §5「模型族按生效模型判定、不按 Agent」
 * 在 Driver 一侧有张力，根本解见 BACKLOG EV-107。
 *
 * 以 `Record<AgentVendor, …>` 声明：登记第五个厂商而不补这里，编译期就报错。
 */
export const VENDOR_MODEL_FAMILY: Readonly<Record<AgentVendor, RegExp>> = {
  anthropic: /claude/i,
  openai: /gpt/i,
  antigravity: /gemini/i,
  zcode: /glm/i,
};
```

```ts
// adapters/base.ts
/**
 * 审查模型是否与当轮 Driver 异构（FR-17 / AC-18；EV-62 起按当轮 Driver 判定）。
 *
 * 判据：模型名**不落在** Driver 厂商的名义模型族里，即判异构。两层都是启发式：
 * 模型族靠模型名判（`VENDOR_MODEL_FAMILY`），Driver 的模型族靠厂商近似。
 * 所以 `true` 的准确读法是「未检出同族」，不是「确认异构」。
 * 取不到模型名时判 `true`，与改动前一致。
 */
export function isHeterogeneous(model: string | null, driverVendor: AgentVendor): boolean {
  if (!model) return true;
  return !VENDOR_MODEL_FAMILY[driverVendor].test(model);
}
```

**行为对照**：

| Driver 厂商 | 审核者模型 | 改前 | 改后 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| anthropic | `claude-*` | false | false | 不变 |
| anthropic | 其他 | true | true | 不变 |
| 非 anthropic | `claude-*` | **false** | **true** | EV-62 原文那一格；内置配置下可达（非 claude 的 Driver 可选 claude 审核者） |
| antigravity / zcode / openai | 本厂商名义族 | true | **false** | 新增检出；内置配置下不可达，只对显式覆盖生效（72 格实测零命中） |
| 非 anthropic | 其他 | true | true | 不变 |

**误差方向**：`false` 只触发告警与 `override_reason`，不拦闸门。误报的代价是多一行告警，漏报的代价是把同源审查记成异构。

- 「非 anthropic 一律判异构」（r1 初稿）：误差全落在漏报一侧；
- 「driver=codex 时取 `agents.codex.profile`」（r1 CODEX-04 选项 a）：理由见上。
