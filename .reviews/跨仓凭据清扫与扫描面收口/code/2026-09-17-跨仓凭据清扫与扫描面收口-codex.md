**问题**：跨仓清扫对单个项目桶的 stat/readdir 失败静默 `continue`：该桶整棵不进论域，其中未抹的凭据副本不出现在 scrubbed/unknown/incomplete/scrubFailed 任何一格，命令照常报 ok:true 与「没有需要抹的凭据副本」。这与本补丁在 scrubRunDir 里刚修掉的『运行目录 readdir 失败静默 return {}、三个计数全不增长』是同一形状的缺口，只是挪到了桶这一级；并发整删（另一会话的 pruneRunDirs 删目录）时撞上也不报错。

**依据**：读了 src/trivium/retention.ts：桶循环 `try { if (!isDirectory) continue; entries = await readdir } catch { continue }`，catch 分支不向 out 记任何东西；同文件 scrubRunDir 的新注释明确写着「读不了运行目录 = 一侧都没抹……调用方的三个计数全不增长、该目录在待办里完全不出现」并为此加了 errors 上报（src/trivium/scrub.ts），而桶级没有等价处置。test/unit/retention.test.ts 的 scrubAllRunRoot 用例也没有桶读失败一格的断言。

**建议**：给 SweepResult 加一格（如 unreadable_buckets: string[]）或在现有 warnings 通道记账并渲染进人读输出，与会话启动待办的分档可见性口径对齐；补一条桶读失败仍上报的用例。
