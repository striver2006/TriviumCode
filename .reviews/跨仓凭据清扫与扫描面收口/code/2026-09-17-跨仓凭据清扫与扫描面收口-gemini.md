### AGY-01 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/retention.ts:569` |
| 类别 | contract ｜ 层次 code |
| 置信度 | high |

**问题**：scrubAllRunRoot 预演（--dry-run）与真跑在零侧运行（或仅 runDir 层未抹）目录上的统计与动作不一致。sideLayerPending 仅检查子目录中的 side 层哨兵；当目录无 side 目录时返回 false，导致该目录在预演中被计入 settled（终端展示为「侧层已收工（哨兵已记完成，真跑会跳过）」），但真跑分支并没有跳过，依然对该目录执行 applyScrub 并擦除 request.json，将其计入 scrubbed。

**依据**：阅读 src/trivium/retention.ts:569-573 及 578-591：sideLayerPending 实现仅遍历 runDir 下的 side 子目录，若无 side 则返回 false；此时 out.settled++ 且不会加入 out.eligible。然而在第 578 行 if (!opts.dryRun) 中，循环遍历的是 allRuns 中的所有 dir，对该 dir 调用 applyScrub(dir, ...)，applyScrub 会对 runDir/request.json 执行脱敏，若命中 secret 则推入 out.scrubbed。导致 --dry-run 报告无待处理项（settled 增加），而真跑却实际执行了脱敏并记入 scrubbed。

**建议**：在 sideLayerPending 中增加对 runDir 层（如 request.json 是否已被脱敏或超出大小限制等）的判定，或者统一 dryRun 与真跑的准入过滤，仅对判定为待清扫（eligible）的目录执行 applyScrub，避免预演显示跳过但真跑实际执行修改。
