**问题**：超长任务目标截断至 16000 字符时若直接使用字符串的 slice(0, 16000)，在目标文本包含 4 字节 Unicode 字符（如 emoji 或罕见字）时，恰好处于第 16000 个 code unit 位置的字符可能会被从代理对（surrogate pair）中间截断，产生孤立高代理字符（lone surrogate），可能在后续 JSON 序列化或作为进程参数传递时导致编码异常。

**依据**：查看被审文档 plan §2.3 以及 src/trivium/brief.ts。在 JavaScript 中 String.prototype.slice 按 UTF-16 code units 截断，若目标文本恰好在第 16000 处包含 astral code point，容易破坏 Unicode 代理对完整性。

**建议**：在实现 16000 字符截断时，建议考虑字符完整性（例如通过 Array.from(text).slice(0, 16000).join('')，或在截断后检查并规整未配对的代理字符）。
