## 3. 块二 · 审批链路

### 3.1 `gate.ts` 新增 `verifyRoundForApproval`

```ts
/** 两句判别文字：全仓唯一的纯文本，函数与测试共用（r3 修正，r2 CODEX-02 ≡ AGY-01 ≡ GLM-01） */
export const APPROVAL_CHECK_NO_RUN_ID = '推断不出 run_id 时不跳过复核';
export const APPROVAL_CHECK_META_UNREADABLE = '本轮运行元数据读不出，复核无从进行';

export async function verifyRoundForApproval(i: {
  cfg: Config; layout: ArchiveLayout; stage: Stage;
  runId: string | null;
  runIdPinned: boolean;          // 原样透传给 checkAdjudication（见第 3 步）
  runIdSource: string;
  recovery: { missingRunId: string; unreadableRunMeta: string };
}): Promise<{ ok: boolean; runId: string; result: GateCheckResult; tampered: TamperedArtifact[] }>
```

1. `if (!runId) throw new TriviumError(EXIT.MISSING_ARTIFACT, …)`。
   **注释从 `cli.ts:1134-1138` 原样带过来**，其中包括「`if (runId)` 那种写法等于留了个后门」一句。
   文案由 stage、`runIdSource`、`APPROVAL_CHECK_NO_RUN_ID`、`recovery.missingRunId` 拼成，**不引用 rerunIndex**。
2. `readRunMeta` 返回 null ⇒ `throw new TriviumError(EXIT.MISSING_ARTIFACT, …)`。
   文案由 run_id、stage、`APPROVAL_CHECK_META_UNREADABLE`、「不要删改这份运行元数据，它是提交锚」这句警示、`recovery.unreadableRunMeta` 拼成。
3. 执行 `loadRoundReviews` + `checkAdjudication`：driver 与 rerunIndex 取自 runMeta，
   **`runIdPinned` 原样透传**，它控制 `missing_disposition` 要不要提示「用 --run-id 指回更早轮次」（`gate.ts:132-142`）。
   其余参数（`degraded`、`voidedSides`、`readonlyBreach`、`runWarnings`、`expectedFallbackIds`、`missingSides`）与 `cli.ts:1155-1163` 的现有调用逐项相同。
4. `checkRecordedArtifacts(layout, [{ run_id, stage, artifacts: runMeta.artifacts }])`，**只核本轮**。
5. `ok = result.ok && tampered.length === 0`。

**判别文字的「唯一」按准确的口径写**：在本函数的各个抛错分支之间是唯一的；在全仓范围内是唯一的，靠的是落笔时 grep 结果为零，不是机制保证。

**篡改清单的渲染**：新写一个 `renderTamperedArtifacts(tampered)`，与函数放在一起，不改 `hooks.ts`（§5 偏差 3）。

### 3.2 两处调用

**`--await-approval`**：

```ts
verifyRoundForApproval({
  runId: latest?.run_id ?? null,
  runIdPinned: Boolean(pinnedId),
  runIdSource: pinnedId ? '--run-id' : '最新一次运行',
  recovery: {
    missingRunId: '用 --run-id <id> 显式指定，或先跑一次双审',
    unreadableRunMeta: '重跑一次该阶段双审',
  },
});
```

失败时渲染 `renderGateResult` 和篡改清单，`fail`，返回 `GATE_BLOCK`；通过时照旧透传 `preWarnings`。

**`cmdApproval`**（只在 `approved` 时走这一段）：
- 先对所有阶段做复核，全部通过后再逐一落审批。
- 每个阶段依次执行：`getGate` → `assertGateDecidable`（从 `recordApproval` 抽出的共用函数，**`recordApproval` 内保留原来的调用**）→ `verifyRoundForApproval`，参数为：
  - `runId: gate.run_id ?? null`
  - `runIdPinned: true`
  - `runIdSource: '本机闸门记录'`
  - `recovery`：**r3 修正（r2 CODEX-04）两个字段用同一段文案**，内容如下：
    > 本机闸门项没有指向一份可读的运行留痕：归档是正本，本机闸门是副本，两者已经分叉。
    > approve 不接受 `--run-id`；`--check` 与 `--await-approval` 不会改写属于别的运行的闸门项。
    > 出口：`/dual-abandon --topic <t> --stage <s> --reason '<说明分叉>'`，然后重跑该阶段双审。
    > 这会留下一条 run_id 为空（或为那个读不出的值）的放弃记录，请在 reason 里写明缘由。
- 复核不通过就退 2。`rejected` / `abandoned` 不复核。

### 3.3 `verifiedRunId` 绑定

`ApprovalInput.verifiedRunId`：`approved` 时如果它 `!== gate.run_id`，或者根本没传，就拒绝。
注释写明它只证明「调用方给出的 run_id 与闸门一致」，**不证明复核真的跑过**。
