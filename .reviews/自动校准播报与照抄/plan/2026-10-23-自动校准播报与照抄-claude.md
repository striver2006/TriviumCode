## 〇、要解决的问题

EV-251 的真实配额验收（`doc/05_testing/REPORT_2026-10-22_preflight_recalibrate.md` 第九节，时间线 `evidence/preflight-recalibrate-20261022/accept-20261023/timeline.txt`）里，编排器侧全部符合预期，但会话里的载体模型没照公共片段 `skills-src/partials/preflight/recalibrate.md` 做三件事：

1. **事前播报被跳过**：04:46:58 预检返回，04:47:01 直接拉起 doctor，其间无文本。片段第 8～9 行写的是「先发一行文本：「预检退 69……」」——要模型**自拟**一句话，模板夹在 `〈失败项名称〉`、`N`、`deadline_s` 三个待填槽之间，紧接着第 10～13 行是一大段执行细则。模型直奔执行。这一行是「不向用户确认」时用户唯一的事前知情点。
2. **事后播报推迟**：第二次预检通过后没有当即说「预检首次退 69，已自动校准后通过」，到收尾总结才提。片段第 15 行把它写成「照常往下走（`warnings` 照常念），并在同一条消息里说明」——「说明」排在「往下走」后面，又只要求「同一条消息」，没要求先说。
3. **擅自改写调用**：第二条 doctor 被改写成 `F=…/scratchpad/doctor-zcode.txt; .trivium/bin/trivium doctor --only zcode --deadline-s 900 --json > "$F" 2>&1; echo "EXIT=$?"; sed … | python3 …`（timeline 第 34、37 行），被 Hook 拦下两次后才改回照抄。**动机可还原**：`doctor --json` 输出带完整探针，单家就有 40 KB 上下（本次会话 agy 一家 41.6 KB），第一条的输出被载体截存进 `tool-results/` 文件，模型第二条就想「先存文件再挑字段」。片段第 10 行只说「逐个照抄，不改、不增删」，约束的是 `args` 数组的**项**，没说命令行**前后**不得添东西；也没说输出长怎么办、为什么不能重定向。

**本主题不改**：预检的检查项与判据、`recalibrate` / `eligible` 的判定、`invocations[*].args` 的内容、`deadline_s` 与 `bash_timeout_ms`、doctor 的任何行为与输出、Hook 的判据。

## 一、设计决定

### D1 · 播报句由编排器给出，skill 只照念（焦点：硬性步骤 vs 现成播报句）

两种取舍：

| | A · 只改措辞（硬性步骤） | B · 预检在 `recalibration` 里给现成句子 |
| :--- | :--- | :--- |
| 机制 | 片段里把播报写成带闸门的第一步：「在它出现之前不得发起 doctor」 | `recalibration` 多两个字段，句子已填好；片段只说「原样念这个字段」 |
| 模型要做的 | 读模板、从 `checks` 里挑失败项名、数 N、填 `deadline_s`，再发出 | 复制一个字符串 |
| 跳过的诱因 | 自拟是一个可省的「额外步骤」，且模板离 `invocations` 很远 | 句子就在工具结果里、紧挨 `invocations` 之前，读到调用清单之前先读到它 |
| 代价 | 零契约变更；但验收已证明「写清楚了」不够 | 预检 JSON 加两个键（加法，旧调用方忽略）；句子文案进 TS 源码，改文案要动代码与用例；PROTOCOL / 设计要登记 |
| 可断言性 | 只能断言片段里有这几个字 | 句子内容可单测（失败项名、N、秒数逐字核对）；片段只需断言引用了字段名与次序 |

**取 B，同时把 A 的结构改造一并做**（D2）：B 降低「做」的成本，A 的闸门措辞降低「跳」的概率，两者不冲突。不取 B 单独上——光有字段、片段仍把它埋在执行细则后面，等于把同一个问题换个字段名。

字段（只在 `eligible: true` 时出现；不 eligible 时缺席，保持现有 `{ eligible, why, invocations: [] }` 形状不变）：

- `announce_before`：`预检退 69，以下失败项可由 doctor 重新校准：〈各失败项 name，按 checks 次序以「、」连接〉；将依次在前台跑 〈invocations.length〉 次 doctor（每次至多 〈deadline_s〉 秒），会消耗少量配额。`——与现片段模板逐字同义，只是由代码填好槽位。
- `announce_after_pass`：`预检首次退 69，已自动校准后通过。`

**键序**：`eligible`、`why`、`announce_before`、`invocations`、`announce_after_pass`。`buildRecalibration` 按此次序构造对象，`cli.ts` 原样透传（JSON.stringify 保持插入次序），模型从上往下读时先撞上播报句、再看到调用清单。

**每条 doctor 之后那一行播报不改由编排器给**：验收里它每次都发了；且它要用 doctor 的结果（退出码、`blockers` 条数、`deadline.sections`），只能由 doctor 输出、而本主题不改 doctor 输出。

**放弃的两条路**：
- C · 预检自己拉起 doctor（如 `preflight --recalibrate`）：把播报与调用都收进编排器，模型无从跳过；但它改了预检的行为与时限模型（单条命令要撑过 N × 960 s，超出任何载体的工具上限），与「不改预检判据、doctor 行为与时限」冲突。
- D · Hook 强制「上一条消息含播报句才放行 doctor」：PreToolUse Hook 拿不到 assistant 的文本，且四家载体的 Hook 能力不一，做不成同一口径。

### D2 · 片段改写：先播报、后调用写成带闸门的硬性步骤（焦点：措辞放在哪）

改写 `skills-src/partials/preflight/recalibrate.md` 的「可校准」分支，原则：**每个必须发出的文本都写在它所约束的动作之前，并写明「在它出现之前不得做下一步」**；会被跳的句子不夹在长段落中部。

可校准分支改为四步（草案，措辞以实施为准，对账用例锚定加粗短语）：

1. **第一个动作是发文本，不是调用**：把 `recalibration.announce_before` **原样**作为一条文本发给用户。**在这句话出现在对话里之前，不得发起任何 doctor 调用。**（`announce_before` 键缺席——旧版编排器——时按格式「预检退 69，以下失败项可由 doctor 重新校准：〈失败项名称〉；将依次在前台跑 N 次 doctor（每次至多 `deadline_s` 秒），会消耗少量配额」自拟，同样先发后调。）
2. **逐条调用**：见 D3 的照抄规则；前台、`bash_timeout_ms`、不后台不拆两步、每条后一行播报、任何退出码都继续——这几句保留原意。
3. **重跑预检一次**：逐字相同的旗标、一次。
4. **结果一出来就定性**：
   - 通过：**你在这之后写的第一句话就是 `recalibration.announce_after_pass` 的原文**（取第一次预检 JSON 里的那个字段；第二次预检通过时没有 `recalibration`），然后才念 `warnings`、往下走。键缺席时说「预检首次退 69，已自动校准后通过」。
   - 仍失败：原样保留现有的停止与转述要求。

外层两处（`partials/review/body.md:75`、`commands/run.contract.md:82`）的「通过时若 `warnings` 非空……」紧跟在片段之后，次序天然是「定性句 → warnings」，不动。`run.contract.md` S0.6 后面「主题回显」「轮次上限」都要求同一条消息，也与「第一句是定性句」不冲突。

### D3 · 照抄约束写到「命令行前后不得添东西」并给出理由（焦点：怎么写才挡得住追加与改写）

光说「不改、不增删 args」挡不住验收里的形态——模型没动 `args` 的任何一项，动的是命令行的前后。改为：

- **命令文本恰好是** `.trivium/bin/trivium` 后接该条 `args` 各项（以空格连接，含空格或 shell 元字符的项加单引号），**前后不加任何东西**：不加重定向（`>`、`>>`、`2>&1`）、管道、`tee`、`;` / `&&` 后续命令、变量赋值或 `cd` 前缀。
- **说明理由**（模型对有理由的禁令遵循度更高，也让它不去「换写法」）：命令文本含 `.trivium`，Hook 见到重定向或写命令形态会整条拦下——加了也跑不成，只会多耗一轮。
- **给出它真正想要的东西的合法出口**：输出很长（单家数十 KB，含完整探针），载体可能把结果截存进文件；那是载体的事，照样不要改调用。读播报要的字段（退出码、`blockers`、`warnings`、`deadline`）时，**另起一次只读的读取**去读截存文件——读是允许的，改调用不允许。退出码以工具结果报告的为准。

这条规则对 `TV` 的其他调用（resolve、preflight、review）**不扩大**（备忘：别把断言的适用范围悄悄扩大）：只写在 `recalibration.invocations` 那一步，不改成全局纪律。外层模板与其余调用里已有的 `echo "EXIT=$?"` 等写法不受影响。

### D4 · 四家载体同一口径与对账用例的断言深度（焦点：对账能断言到什么程度）

**渲染口径**：片段不含任何 `{{…}}` 变量，经 `review/body.md`（三条 `/dual-review-*`）与 `run.contract.md`（`/dual-run`）引入后，四家载体的 16 份入口产物里这一节应**逐字节相同**。现有用例只逐条 `match` 若干短语，不核相同；本主题补上。（片段里的「Bash 工具超时」对 codex / gemini / glm 载体是字面借用——它们的工具不叫 Bash。现状如此、四家同一口径，本主题不改，登记在残余里。）

`test/contract/skill-recalibrate.test.ts` 改为：

- **逐份**：

## 三、风险与残余

- **模型遵循没有机械保证**：B + A 只降低跳过概率，不消灭；最后一道是真实会话验收。若验收仍跳，下一步可考虑的方向（不在本主题）：把播报句也放进人读输出 `renderPreflight`，或在 skill 里把「发播报」拆成独立的一轮回复。
- **另三家载体**的遵循情况未验，登记残余。
- **文案进源码**：以后改句子要同时改 TS、单测与手册；对账用例只锚字段名，不锚句子原文，避免片段与源码双写。
- **旧编排器 + 新 skill**：`install:local` 同时装两者，正常不会错配；错配时片段的「键缺席」回落句兜住。
