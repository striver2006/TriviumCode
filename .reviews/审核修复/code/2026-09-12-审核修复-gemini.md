### AGY-01 · 阻断（blocker）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/hooks.ts:261` |
| 类别 | security ｜ 层次 code |
| 置信度 | high |

**问题**：bashTargetsProtected 正则表达式因模板字符串未转义 \\s 蜕化为 [^s]*，导致含字母 's' 的主题归档独占文件（_meta/ 与 task.json）对 Bash 写入完全失防

**依据**：在 src/trivium/hooks.ts:261 中：new RegExp(`${archiveRel...}/[^\\s]*(?:/_meta/|/task\\.json)`)。由于模板字面量内未双重转义，`\\s` 被 JS 编译为普通字符 's'，导致生成的正则表达式实际为 `[^s]*`。任何名称含字母 's' 的主题（如 auth_service、session、user_status、skills 等），匹配在遇到字母 's' 时即刻截断，无法到达 `/_meta/`。在 review_done_awaiting_disposition 状态下，hookPreBash 完全依赖 bashTargetsProtected 拦截对 _meta 与 task.json 的写命令，由于正则失配，Driver 使用 sed -i 或 cat 重定向篡改审查结论（_meta/review-*.json）或 task.json 不会被拦截。

**建议**：将模板字面量中的 `[^\\s]*` 修正为双反斜杠转义 `[^\\\\s]*`，或改用结构化分词/路径组件规范化判断，避免手写正则歧义。

### AGY-02 · 阻断（blocker）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/cli.ts:680-686` |
| 类别 | contract ｜ 层次 code |

**问题**：gate --check 成功后无条件将闸门重置为 idle，使命令 B/C/D 的 awaiting_approval 闸门沦为非强制的自愿调用，可被 Driver 静默跳过

**依据**：在 src/trivium/cli.ts:680-686 中，gate --check 在裁决校验通过后，无条件执行 setGateChecked 将闸门重置为 'idle'。在命令 B/C/D（dual-review-plan/code/bug）的流水线定义中，停点恒为「等待人工审批」（awaiting_approval）。当前实现将置为 awaiting_approval 的逻辑拆分到了一个独立的命令步骤 `gate --await-approval` 中（cli.ts:596-606 及 skills/dual-review-code/SKILL.md 第 7 步）。由于 gate --check 已将闸门刷回 idle，如果 Driver 省略调用 --await-approval，所有的 Hook（hook-pre-write、hook-pre-bash、hook-stop、hook-pre-commit）均视闸门为 idle 并全部放行，Driver 可直接修改业务代码并提交收工，人工审批闸门被静默旁路；且此时若用户尝试执行 /dual-approve，src/trivium/approval.ts:52 会因状态为 idle 而报错拒绝。

**建议**：结合 run.json 中的 entry 标记或显式参数，当属于命令 B/C/D 时，gate --check 校验通过应直接原子迁移到 awaiting_approval 状态并输出停点指引，禁止中途落回 idle。

**问题**：bashTargetsProtected 缺乏对相对路径、全目录删除及 .trivium/bin 篡改的防御，攻击者破坏 wrapper 可使所有 Hook fail-open

**依据**：在 src/trivium/hooks.ts:258-264 的 bashTargetsProtected 中：仅包含以 archiveRel 为前缀的字符串正则和 `.trivium/(state.json|lock)`。若在子目录执行命令（如 `cd .reviews/topic/plan && rm -rf _meta` 或 `rm -rf _meta`），命令不含 .reviews 前缀即可绕过匹配。更严重的是，该判定未涵盖 `.trivium` 目录本身及 `.trivium/bin`，一旦执行 `rm -rf .trivium` 或 `chmod -x .trivium/bin/trivium`，.claude/settings.json 中的所有 Hook 守卫 `test -x "$W" || exit 0` 将全部因 wrapper 不可执行而永真 exit 0，整套闸门与防篡改体系被一次性解除。

**建议**：在 bashTargetsProtected 中增加对裸 `_meta`、`task.json`、`.trivium` 全目录及其 `bin` 子目录的保护，并在 `settings.json` 的 hook 脚本中对缺失 wrapper 行为进行审计或采取更安全的防御姿态。
