## 1. 问题与现状（源码核实）

### 1.1 EV-240：同名入口检测只在安装器里

- 检测在 `src/install.ts:276-303` `checkInstall`：对每个目标，`layout === 'entry'` 的家先在安装根顶层查 `RESIDUE_NAMES`（`dual-critic`、`entry`，`:56`，由 `ENTRY_OUT_DIR` 派生）判 `residue`；再对每个入口名、在完整读取面（安装根 + 额外读取根）逐个查同名目录：`isOurEntry`（`:258-266`，front-matter 名字对得上且正文含 wrapper 路径）为真且位于安装根 ⇒ 视为上一次安装、放行；否则判 `foreign-entry`（本产品的）或 `third-party`（别家的）。
- `isOurEntry` 还决定卸载的删除面（`:473`）。
- 报错文案在 `describeProblems`（`:311-328`），退出码由 `main()` 定（冲突 ⇒ `InstallConflictError` ⇒ 退 1）。
- 只读入口 `npm run install:check`（`scripts/install-check.mjs`）调安装器产物的 `planInstall` + `checkInstall`，自带一份三类短标签（`KIND`），退出码 0 / 1 / 2。
- 共享读取面由注册表给出：codex `entrySkillExtraReadRoots: ['.agents/skills']`（`registry.ts:345`）、zcode 同（`:390`）；claude、gemini 为空。求值在 `entrySkillRootOf`（`:547-561`），`home` 与 `env` 显式传入。
- doctor（`doctor.ts:515` `runDoctor`）、preflight（`preflight.ts:999` `runPreflight`）都不查。2026-10-13 Codex 的「从 Claude 导入」往 `~/.agents/skills` 拷进 7 个同名入口，是安装失败才发现的（BACKLOG EV-240）。
- 两个打包产物：`src/install.ts → dist/install.cjs`、`src/trivium/cli.ts → skills/dual-critic/scripts/trivium.cjs`（`scripts/build.mjs:89-100`）。安装器已经引用 `src/trivium/agents/registry.ts` 与 `asset-root.ts`，所以「共享模块放在 `src/trivium/` 下、两边都 import」是现成的形态。

### 1.2 EV-236：`request.json` 里同一份 diff 存了 N 遍

- code 阶段 `prepareRun` 只算一次补丁 `frozenDiffText`（`review.ts:900-917`），逐侧调用 `freeze` 时透传（`:1047`），`freeze` 原样放进返回的 `Snapshot.diffText`（`freeze.ts:505-537`）。
- `writeHandoff`（`run-protocol.ts:160-192`）把 `rc.snapshots` 整体写进 `request.json`，于是三侧各一份。10-11 那份 148.8 MB 的文件里 `snapshots` 占 145.4 MB（BACKLOG EV-236）。
- **各侧快照的 `diffText` 冻结之后没有读者**：全仓 `grep` 只有 `freeze.ts` 自己的赋值与 `input.diffText` 的读取；任务书用的是 `subjectSha256` / `subjectPath` / `treeHash`（`brief.ts:351-353`），审核者读的被审对象是归档里的 `_meta/changes-〈run_id〉.diff`（`review.ts:917-918` 的 `pendingDiff`，由 `--start` 落盘），漂移判定读 `subjectSha256` 与 `treeHash`（`freeze.ts:659-662`）。所以去重不改变任何送给审核者的字节。
- `rebuildContext`（`run-protocol.ts:215-300`）原样把 `h.snapshots` 交给 worker；作废重跑（批次 3）在 worker 内用同一份 `rc.snapshots`。`readHandoffIdentity`（`:1579-1586`）只读 `topic` / `stage`。清扫（`scrub.ts`）把 `request.json` 当文本整份扫，不解析结构。

## 2. EV-240 改动面

### 2.1 新共享模块 `src/trivium/entry-collisions.ts`

从 `install.ts` **搬出**（不是复制）下列内容，`install.ts` 改为 import：

- `isOurEntry(dir, name)`：逐字搬移，判据不变。
- 判定核心 `scanEntryCollisions(targets)`：入参每项为 `{ agent, skillsRoot, readRoots, names, residueNames }`，循环体与今天 `checkInstall` 的两段逐字相同（残留段改为遍历 `residueNames`，安装器对 `layout === 'entry'` 传 `RESIDUE_NAMES`、对 `top` 传空数组，等价于今天的 `if (t.layout === 'entry')`）。返回值形状即今天的 `InstallProblem` 子集（`kind` 只会是三类之一）。
- 三类短标签 `ENTRY_PROBLEM_LABELS`：与 `install-check.mjs` 今天的 `KIND` **逐字相同**；`install-check.mjs` 改为从安装器产物取这份表（`install.ts` 再导出），输出逐字不变。
- 运行时入口名单 `ENTRY_SKILL_NAMES`（T-1）。
- 共享读取面的目标构造 `sharedReadRootTargets(agents, home, env)`：对登记了额外读取根的每一家，`readRoots` 只取额外读取根（经 `entrySkillRootOf` 求值，与安装器同一个函数），`names` 取 `ENTRY_SKILL_NAMES`，`residueNames` 为空（T-3）。
- 渲染：`describeSharedRootProblems(problems)` 给 doctor 用的多行文本（按路径归并，列出会读到它的各家显示名与类别标签，末尾给出口）；`summarizeSharedRootProblems(problems)` 给 preflight 用的单行。两处文案只在这里出。

`install.ts` 保留：`checkInstall`（签名与导出不变，函数体改为把 `EntryTarget` 映射为扫描目标后调 `scanEntryCollisions`）、`InstallProblem`（类型不变，三类之外的 `missing-family` / `runtime-*` 仍只在安装器里产生）、`describeProblems` 与全部文案、`main()` 与退出码、`RESIDUE_NAMES` 的派生方式。

### 2.2 doctor

- 在环境段、紧挨已废弃配置键那条告警之后（`doctor.ts:563-568` 附近）调 `sharedReadRootTargets` + `scanEntryCollisions`，有问题就往 `warnings` 推一条（`describeSharedRootProblems` 的多行文本）。**只进 `warnings`，不进 `blockers`**：doctor 的退出码只看 `blockers`（`cli.ts:842`），所以不影响退出码；`--json` 的 `warnings` 字段随之带出。与 `--only` 无关（同废弃键那条：它说的是本机环境，哪一段都该看见）。
- 出口文案：「在 TriviumCode 仓库根跑 `npm run install:check` 只读核对，确认无用后手工挪走；安装器与 doctor 都不删这些路径」。路径按 `displayHomePath` 显示为 `~/…`（预检输出常被抄进证据，不带出用户名）。
- `DoctorOptions` 加可选注入口 `entryScanEnv?: { home; env }`，**只为可测性**，生产路径不传、取 `os.homedir()` 与 `process.env`（同 `probeBins` 的惯例）。
- 扫描本身任何异常都不让 doctor 失败：吞掉并推一条 warning「共享读取面检查没做成：〈原因〉」。

### 2.3 preflight

- 新检查项 `checkSharedReadRoots(selectedAgents, entryScanEnv)`，返回 `CheckResult | null`：相关家（T-4）的额外读取根里有问题时给 `{ name: '共享读取面同名入口', ok: true, warn: true, detail: '⚠️ …' }`，**恒 `ok: true`**，不带 `exitCode`；没问题、或相关家都没有额外读取根时返回 `null`（不出项）。
- 放在 ④⁗（已废弃配置键，`preflight.ts:1068-1072`）之后、⑥ 之前，与其它只告警项同样用 `checks.every(ok)` 门控。文案一行：哪个根、几个同名入口、本轮哪几家会读到，并点名「跑 doctor 看完整清单与出口」。
- `PreflightOptions` 加同一个可选注入口 `entryScanEnv`。相关家 = `opts.driver ?? DEFAULT_DRIVER` ∪ `selected`，按注册表的 `entrySkillExtraReadRoots` 过滤，不写 Agent id 字面量（`registry-parity` 纪律）。
- 扫描异常同样吞掉，退化为一条 warn 项，不改 `ok`。

### 2.4 两个产物同源的证明

- 新用例读两份产物：`dist/install.cjs` 与 `skills/dual-critic/scripts/trivium.cjs` 都含 esbuild 的模块标记 `// src/trivium/entry-collisions.ts`；`src/install.ts` 源码里不再有 `function isOurEntry` 与判定循环（扫源码断言）。
- 名单对账：`ENTRY_SKILL_NAMES` 等于契约 `name` 全集，等于 `planInstall` 对每家算出的 `sources` 名单（对账失败即红，提醒改了命令要同步常量）。

## 3. EV-236 A2 改动面

### 3.1 写侧（`run-protocol.ts` `writeHandoff`）

- 新增纯函数 `packSnapshots(snapshots)`：若各侧 `diffText` 都非空且逐字相同，返回 `{ snapshots: 各侧 diffText 置 null 的副本, frozen_diff: { sha256, text } }`；否则（plan / bug 阶段全为 `null`，或防御性地出现不一致）原样返回、不加 `frozen_diff`。**不改内存里的 `rc.snapshots`**（副本上置 null），`--start` 同进程后续逻辑看到的仍是原对象。
- `Handoff` 增加可选字段 `frozen_diff?: { sha256: string; text: string }`，schema 名不变（T-7）。

### 3.2 读侧（`rebuildContext`）

- 新增纯函数 `unpackSnapshots(h)`：没有 `frozen_diff` ⇒ 旧格式，原样返回（旧运行目录照常可读）。有 `frozen_diff` ⇒ 先核 `sha256(text) === frozen_diff.sha256`，再对每一侧核 `snapshot.diffText === null` 且 `snapshot.subjectSha256 === frozen_diff.sha256`，然后把 `diffText` 还原为同一份 `text`；任一核对不过 ⇒ `envError`（交接文件被改坏，拒绝执行）。这是**新增的拒绝**，只作用于新格式，没有放宽任何既有判据。
- 还原后的 `snapshots` 与去重前的内存对象逐字段相等（用例断言 `deepEqual`）。

### 3.3 不变的东西

- 任务书（`brief_text` 与 `_meta/brief-〈侧〉-〈run_id〉.md`）、被审对象 `_meta/changes-〈run_id〉.diff`、各侧 `subjectSha256`、`run.json` 的快照字段：都不经过 `diffText`，逐字节不变。
- 同步路径（`review --stage` 不派 worker）不写 `request.json`，不受影响。
- 清扫照旧整份扫 `request.json`；文件变小只会让「超过上限跳过脱敏」更少发生。
- 不碰 `denyPaths` 的逐侧重复（各侧内容不同，不是同一份数据），不碰 A1 / B。
