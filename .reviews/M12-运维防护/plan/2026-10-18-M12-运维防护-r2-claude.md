## 1. 问题与现状（源码核实）

### 1.1 EV-240：同名入口检测只在安装器里

- 检测在 `src/install.ts:276-303` `checkInstall`：对每个目标，`layout === 'entry'` 的家先在安装根顶层查 `RESIDUE_NAMES`（`dual-critic`、`entry`，`:56`，由 `ENTRY_OUT_DIR` 派生）判 `residue`；再对每个入口名、在完整读取面（安装根 + 额外读取根）逐个查同名目录：`isOurEntry`（`:258-266`）为真且位于安装根 ⇒ 视为上一次安装、放行；否则判 `foreign-entry`（本产品的）或 `third-party`（别家的）。
- `isOurEntry` 还决定卸载的删除面（`:473`）。
- 报错文案在 `describeProblems`（`:311-328`），退出码由 `main()` 定（冲突 ⇒ `InstallConflictError` ⇒ 退 1）。
- 只读入口 `npm run install:check`（`scripts/install-check.mjs`）调安装器产物的 `planInstall` + `checkInstall`，自带一份三类短标签（`KIND`），退出码 0 / 1 / 2。
- 共享读取面由注册表给出：codex `entrySkillExtraReadRoots: ['.agents/skills']`（`registry.ts:345`）、zcode 同（`:390`）；claude、gemini 为空。求值在 `entrySkillRootOf`（`:547-561`），`home` 与 `env` 显式传入；额外读取根只拼 `home`，`CODEX_HOME` 只影响家根与安装根。
- doctor（`doctor.ts:515` `runDoctor`）、preflight（`preflight.ts:999` `runPreflight`）都不查。
- 两个打包产物：`src/install.ts → dist/install.cjs`、`src/trivium/cli.ts → skills/dual-critic/scripts/trivium.cjs`（`scripts/build.mjs:89-100`，未开 minify，产物带 `// src/…` 模块注释）。安装器已引用 `src/trivium/agents/registry.ts` 与 `asset-root.ts`。

### 1.2 EV-236：`request.json` 里同一份 diff 存了 N 遍

- code 阶段 `prepareRun` 只算一次补丁 `frozenDiffText`（`review.ts:900-917`），逐侧调用 `freeze` 时透传（`:1047`），`freeze` 原样放进 `Snapshot.diffText`（`freeze.ts:505-537`），`subjectSha256 = sha256(diffText)`。
- `writeHandoff`（`run-protocol.ts:160-192`）把 `rc.snapshots` 整体写进 `request.json`，于是 N 侧各一份。
- **各侧快照的 `diffText` 冻结之后没有读者**：任务书用 `subjectSha256` / `subjectPath` / `treeHash`（`brief.ts:351-353`），审核者读归档里的 `_meta/changes-〈run_id〉.diff`（`--start` 落盘），漂移判定读 `subjectSha256` 与 `treeHash`（`freeze.ts:659-662`），`run.json` 只记 `subject_sha256` 等字段。
- 任务书第 3 段的节选来自 `excerptSubject`（`brief.ts:840`，缺省 400 行内返回全文），所以小 diff 时各侧 `brief_text` 里也各有一份补丁正文——那是送给审核者的内容，**不在本批去重范围**。
- `rebuildContext`（`run-protocol.ts:215-300`）原样把 `h.snapshots` 交给 worker；作废重跑（批次 3）在 worker 内用同一份 `rc.snapshots`。`readHandoffIdentity`（`:1579-1586`）只读 `topic` / `stage`。清扫把 `request.json` 当文本整份扫。

## 3. EV-236 A2 改动面

### 3.1 写侧（`run-protocol.ts` `writeHandoff`）

- 新增纯函数 `packSnapshots(snapshots)`：侧数 ≥ 1、首侧 `diffText` 为字符串、且各侧 `diffText` 逐字相同时，返回 `{ snapshots: 各侧 diffText 置 null 的副本, frozen_diff: { sha256, text } }`；否则（plan / bug 阶段全为 `null`、空快照、或防御性地出现不一致）原样返回、不加 `frozen_diff`（AGY-03）。**不改内存里的 `rc.snapshots`**。
- `Handoff` 增加可选字段 `frozen_diff?: { sha256: string; text: string }`，schema 名不变（T-7）。

### 3.2 读侧（`rebuildContext`）

新增纯函数 `unpackSnapshots(h)`，按序判：

1. 没有 `frozen_diff` 键：若有任一侧 `diffText === null` 而 `h.stage === 'code'` ⇒ `envError`（新格式丢了正文）；否则视为旧格式，原样返回（旧运行目录照常可读）。
2. 有 `frozen_diff` 而 `h.stage !== 'code'` ⇒ `envError`（AGY-02）。
3. `frozen_diff` 不是对象、`text` 或 `sha256` 不是字符串 ⇒ `envError`（AGY-02）。
4. `sha256(text) !== frozen_diff.sha256` ⇒ `envError`。
5. 每一侧：`snapshot.diffText !== null` 或 `snapshot.subjectSha256 !== frozen_diff.sha256` ⇒ `envError`。
6. 把各侧 `diffText` 还原为同一份 `text`。

以上拒绝都只作用于新格式（第 1 步的「code 阶段有 `null`」在旧格式里不会出现：旧版各侧都带正文），没有放宽任何既有判据。还原后的 `snapshots` 与去重前的内存对象逐字段相等。

### 3.3 不变的东西

- 任务书（`brief_text` 与 `_meta/brief-〈侧〉-〈run_id〉.md`）、被审对象 `_meta/changes-〈run_id〉.diff`、各侧 `subjectSha256`、`run.json` 的快照字段：都不经过 `diffText`，逐字节不变。
- 同步路径（`review --stage` 不派 worker）不写 `request.json`，不受影响。
- 清扫照旧整份扫 `request.json`。
- 不碰 `denyPaths` 的逐侧重复、不碰 `brief_text` 里的节选，不做 A1 / B。

## 8. 风险

- **隔离漏网**：U8 对账守住；新增直调或子进程跑 doctor / preflight 的用例不走隔离即红。
- **对账常量过时**：新增命令而忘改 `ENTRY_SKILL_NAMES`，U4 当场红。
- **旧版 worker 读新交接文件**（回滚场景）：各侧 `diffText` 为 `null`，旧版没有读者；`frozen_diff` 被忽略。
- **交接文件被手工改动**：新格式下多一道形态与 sha 核对，改坏会拒绝执行（旧格式不受这道核对）。
- **新环境变量被误用**：它只改变只读扫描的家目录，最坏结果是告警看错地方；安装器不读它。
