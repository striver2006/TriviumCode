### 0.2 失效路径（2026-10-26 Windows 验收第 1 步实测）

判读 `doc/05_testing/evidence/gateway-model-suffix-20261026/windows-readout.md`：CC Switch 写进 5 个生效模型名键（`ANTHROPIC_MODEL`、`ANTHROPIC_DEFAULT_{OPUS,SONNET,FABLE}_MODEL`、`CLAUDE_CODE_SUBAGENT_MODEL`）的后缀，码点逐个为 `U+005B U+0031 U+004D U+005D`，即大写 `[1M]`。同一次诊断确认 `dist/test` 已含第一轮新代码。片段剥不掉 `[1M]` ⇒ 剥后仍含方括号 ⇒ 守卫 ④ 判「不像模型名」⇒ 5 个键留在逐值替换集 ⇒ `init.model`（CLI 按这些键解析出的配置值，逐字等于键值）照旧被换成 `<redacted-env>`，回读兜底记 null + `unverified`。凭据类键照旧替换（这一面没问题）。

### 0.3 第一轮「只认小写」的依据为什么不成立

第一轮计划 r2 §2.1 的原话：「**只认小写 k / m**：Claude Code 文档与 CC Switch 实测写的都是 `[1m]`；大写不认是 fail-closed」。两半分开看：

- **「Claude Code 文档写 `[1m]`」**：成立，但它只说明 Claude Code 自己的示例用小写，说明不了第三方工具写进 settings.json 的是什么。
- **「CC Switch 实测写的是 `[1m]`」**：**不成立**。这句话的出处是 EV-257 Windows 判读（`evidence/gateway-readback-model-20261025/windows-readout.md`）里写的 `qwen3.8-max[1m]`——而那次逐键诊断对未豁免的模型名键只打印「形状」（字母一律换 `a`、数字换 `9`），读数是 `aaaa9.9-aaa[9a]`。形状**抹掉了大小写**，`[9a]` 既可以是 `[1m]` 也可以是 `[1M]`。判读把形状还原成了小写的具体值，计划又把这个还原值当成「实测」，据此定了判据，并把 `[1M]` 写成反例锁进单测 S11、access-modes 新格与变异 M5a。真实值从未逐字核过。

旁证（推断，未逐字核，只用来说明与本次读数相容）：EV-257 判读里 `result.modelUsage` 的键被替换、而 `canonicalModel` 记作小写 `[1m]` 且未被替换——若那份判读照录了原文大小写，可解释为键逐字等于配置值（大写，被替换），`canonicalModel` 是 CLI 归一化后的小写形态（不等于任何键值，没被替换）。

### 0.4 验收清单为什么没先逐字核后缀大小写

第一轮 Windows 验收清单（`evidence/gateway-model-suffix-20261026/windows-acceptance.md`）第 1 步沿用 EV-257 的诊断口径：未豁免的模型名键只打印形状（为了不把可能是凭据的值打出来），已豁免的才打印原值。期望表直接写了「值列为 `qwen3.8-max[1m]`」——期望值本身来自上面那次形状还原，清单里**没有任何一步**在定判据之前单独核后缀的真实字符。而形状变换恰好把唯一要紧的那一位（单位的大小写）抹平了，于是失败时第 1 步也只能读出「守卫 4 `N`」，要追加一段码点诊断才定位到大小写。

这次的对策落在两处：①第 1 步诊断直接对每个模型名键打印末尾方括号段的码点（不打印方括号之前的部分，见 §6.2）；②期望表里的具体值只写「从第 1 步码点读数来」，不再从任何形状读数推。已记入流水线已知坑清单（「别从形状推真实值再据此定判据」）。

## 二、改法

### 2.1 片段改为显式字符类，不用 `i` 旗标

```ts
const CONTEXT_WINDOW_SUFFIX_PATTERN = String.raw`\[[1-9][0-9]{0,3}[kKmM]\]`;
```

为什么写成显式字符类 `[kKmM]`，而不是给正则加 `i` 旗标：

1. **片段被嵌进整行正则**。`PROFILE_MODEL_LINE` 由键名、`export`、引号与片段拼成；若靠 `i` 旗标放宽，就得给整行正则加 `i`——键名部分 `ANTHROPIC_(?:MODEL|DEFAULT_[A-Z_]+_MODEL|SMALL_FAST_MODEL)` 随之大小写不敏感，`export anthropic_model=…` 这种 shell 里根本是另一个变量的行也会被收。这是在键名判据上的放宽，超出本题范围。显式字符类把放宽限定在单位那一个字符位上，片段仍是唯一真相源、不带旗标、各使用点照旧自管锚定（第一轮计划三审 AGY-01 ≡ GLM-01 定的口径不变）。
2. **只认 4 个 ASCII 码点**。`i` 旗标若与 `u` 旗标同用，Unicode 大小写折叠会把开尔文符号 `K`（U+212A）折成 `k`；显式字符类没有这层折叠。本题只要放行 CC Switch 实际写出的 ASCII 大写，不扩到任何非 ASCII 字符。
3. **语义一眼可读**：数字位与锚定不受影响，审查与变异都只盯一个字符类。

`stripContextWindowSuffix`、`looksLikeModelName`、`PROFILE_MODEL_VALUE`、`claudeModelConsistency` 的代码一行不改，随片段生效。

### 2.2 注释与说明

- `claude-route.ts:71-75` 片段的文档块：「加小写 k 或 m」改为「加 k / K / m / M（单位大小写不敏感，EV-258 第二轮：CC Switch 写的是大写 `[1M]`，Windows 码点实测）」；「大写、多位、其它单位一律不认」改为「多位、0 开头、其它单位字母或字符一律不认」；补一句为什么用显式字符类不用 `i` 旗标（§2.1 第 1、2 条的一句话版）。
- `looksLikeModelName` 文档块（`:91-92`）与 `claude-trace.ts` 一致性函数文档块里的举例只写了 `[1m]`，补「或 `[1M]`」。
- `PROFILE_MODEL_VALUE` 的单行注释不动（它写的是「同一片段派生」，仍成立）。

### 2.3 影响面

- **未开 `settings_env_source` 的机器**：`settingsEnv` 为 `{}`，`scrubGatewayEnv` 只过模式脱敏，根本不走守卫 ④——scrub 输出逐字不变（§6.1 对拍的 off 五情形逐项核）。
- **开了、但模型名键不带大写后缀**：守卫 ④ 判定结果与第一轮相同（小写形态、无后缀形态的判定不变），替换集不变。
- **开了、模型名键带合法大写后缀**：该键（及同值的模型名键）由「替换」变为「豁免」——这正是要修的。挂同值的非模型名键仍让该值进替换集（守卫 ③ 不变）。
- **profile 元数据**：`export ANTHROPIC_MODEL="qwen3.8-max[1M]"` 一类行由「不收」变为「收」，消费面只有 doctor 的「配置声明模型」注记。
- **一致性留痕**：`init.model` 为 `x[1M]`、回报为 `x` 时由 false 变为 true（只进 `trace.json` 的 `modelReadback`，不进判定面）。

| :--- | :--- | :--- | :--- |
