# 驾驶舱 GLM 主攻交互入口实施计划

基线为 feat/vscode-extension 的 456c2f0f，核心 1.3.7、插件 0.3.0。Codex 主攻。交付覆盖 macOS 的 M1 点火、同会话续话与 M3 接续。

## 现状与落点

驾驶舱 handleIgnite 校验前置链冻结的表单、主题并认领，由 carrierOf 取 GLM 的 cliKey=zcode。从 loadProbe 取 cli.zcode.entrypoint，按固定 shellCommand 从 version_probe.runner 或项目 wrapper 取绝对 Node，assembleEntryCommand 组装 /skill dual-run 加正文和已解析旗标。TerminalRelay.ensureSession 以 agent、topic、entry 复用终端，脚本模式把脚本作为唯一 shellArgs，设置 cwd、provider 路径与 auto 模式独占日志目录。injectText 延迟、分段粘贴与回车后返回终端存活状态。ZcodeTurns 从独立目录跟踪主 session 的轮次，relay 用 pending 串行等待轮末。关闭处理切 M3，运行卡继续由原有 watcher 维护。当前 direct 分支跳过日志目录和环境。

Phase 4 记录桌面 CLI 0.17.3 补齐 provider 路径后仍缺 @zcode/tui。独立启动器 3.18.2 的 bin/zcode.mjs 经 Node 24.14.0 启动内置 0.17.1；旧报告在夹具探针中换过入口，本次保留实际桌面探针并从驾驶舱选择。后台 src/trivium/adapters/zcode.ts 从 cfg.probe.cli.zcode 得到 entrypoint、实测 readonly_flags，向 invokeZcode 传 entry 和 ctx.nodePath。实现只在扩展进程读取新设置。

## 点火规则

1. 在 package.json 贡献工作区可用的 trivium.launch.glmInteractivePath 和 trivium.launch.glmNodePath，默认空。前者接受本地文件的绝对路径（独立可执行 zcode 或 JS 入口），后者可选，仅脚本解释器。按当前根 URI 读取设置。路径按文件处理，允许空格，不解析命令行。显式配置缺失、相对、目录、不可读或需执行却不可执行均就地报错，显示设置名和修复示例，结束此次点火。解释器须可执行的绝对 Node；显式错误不回落。
2. 未配交互入口先按 Extension Host 的 PATH 顺序找 zcode，忽略空或相对目录，跟随符号链接识别 JS 启动器。再检查常见 macOS 安装位置（用户 .local/bin、Homebrew 前缀等），不执行 shell 初始化。GUI 找不到登录 shell 里的自定义安装时，手册引导在自己的终端用 command -v zcode 和 command -v node 将结果填成绝对路径。没有自动候选时用原探针入口，包括原已验收的独立脚本、夹具或可执行文件。只在识别出桌面包的既有脚本布局且确认缺对应 TUI 依赖时拦截并指向独立发行版和设置；保留可用旧脚本。应以实际发行布局验证依赖判别，不推测未知安装的运行结果。
3. 扩展端解析出启动来源、入口、模式与实际解释器。直接可执行时绝对路径作 shellPath、无业务 argv；JS 脚本用绝对 Node 作 shellPath、脚本绝对路径为独立 argv。优先显式 Node，再兼容原探针绝对 runner、wrapper 中的绝对 Node；检查文件权限。直接包装程序的内部解释器以真实进程树采样。保留旧探针脚本的 provider 路径传递；独立发行版优先使用自身配置。核实本机发行启动器对 provider 与 Node 的实际继承。
4. GLM 的独立会话日志按 waitForZcodeTurn 在分支前分配，在两种启动形态都传 ZCODE_LOG_DIR。保留 separateEnter、显式发送模式与同一队列；复用时展示原会话的实际启动信息。入口缺失或解析失败给修复动作，创建异常或进程提前关闭报告启动失败；存活并注入只提示已向该终端送入文字。运行号由现有监控回读。关闭后保留原主题和运行关联。其他 Driver 继续原启动路径与终端参数。

## 回归与交付

- 解析器单测用临时目录覆盖两类显式入口、自动查找和优先级、GUI PATH 缺失、空格和符号链接、无效显式路径、旧探针、桌面包缺依赖及可用旧脚本。真实 Extension Host 中由可控子进程记录 cwd、argv、独占日志环境，验证脚本和直接可执行两支及复用。增加断言防止干扰其他 Driver。后台对照在隔离仓设置不同交互路径，读取实际审核命令、模型、证据及原探针版本。
- 扩展中文手册给出两套可复制配置、GUI 与终端路径核对、桌面缺依赖和原生登录/选模提示。根 npm run check，扩展 npm run check，npm run package -- --out 指向新名字，安装态 TRIVIUM_TEST_VSIX 指向该文件执行 npm run e2e。保留既有三个 0.3.0 包并比对哈希。
- 在新建隔离工作区、独立 VS Code 用户数据和扩展目录安装最终 VSIX，检查包与安装文件哈希。沿用 runM1 的真实 Webview 与终端操作，但为本场景选择入口 A，保留后台探针原值，在隔离设置指向实测独立发行版和解释器。观察窗口中交给 Bob 完成原生信任、登录、选模、逐次权限或人工审批。采集终端进程路径、解释器、启动器与组件版本、SHA-256，核开场文本、/skill dual-run、主题和实际 run_id。记录初始与两次续话不同的输入、可验证的答案、唯一提交、session/turn ID，分别在模型忙和空闲时各点一次，同一主题关终端后核 M3 和原编号。夹具中用无业务写入的任务和有界审核侧，桩侧明确标注。
- 再用另一 Driver 的隔离正式审查运行真实 GLM，保留与主攻设置不同的原探针。核实际 command_line 中的脚本、只读参数、CLI 版本、模型回读、证据及归档，排除桩指纹。报告只摘非敏感字段。命令 A 的计划审、逐条裁决、代码审与 verify 照常走完，人工停点交 Bob。以安装态、续话、M3 和后台对照齐备为 Goal 完成条件。
