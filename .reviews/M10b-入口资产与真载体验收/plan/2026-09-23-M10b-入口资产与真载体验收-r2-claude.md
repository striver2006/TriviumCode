破坏 claude 侧的字节兼容（源自 r1 AGY-06）。`dual-critic` 本就在同步面内。

> **备选**：若 §2.4 的嵌套枚举实测发现**某家会递归枚举**，则改扁平命名
> （如 `skills/dual-critic/entry-<agent>-dual-<cmd>/`）或另择落点，**并在 §3.2.2 的内容映射里排除它**。

### 3.2 安装多目标与运行时根

#### 3.2.1 运行时／资产根是必装目标

运行时与机读资产（`dual-critic` 的 `scripts/trivium.cjs`、`schema/`、`prompts/`、`hooks/`、`lenses.yaml`）
今天绑死在 claude 根上（`init.ts:45-46`、`review.ts:397-401`，wrapper 写死绝对路径）。
配合「目标家根不存在 ⇒ 跳过不失败」，只用 ZCode / Codex / agy 的机器上运行时没落盘
⇒ wrapper 指向不存在的文件，四条命令一家都跑不了（源自 r1 CODEX-01）。

- **运行时／资产根是必装目标**，不随注册表派生、不参与「根不存在即跳过」。
- **落点写死为常量**：**`TRIVIUM_ASSET_ROOT ?? ~/.claude/skills/dual-critic`，维持现值不变。**
  > **「同源派生」指三处代码从这一个常量取值**（`writeWrapper` / `assetRootDefault` /
  > `resolveAssetRoot`），**不是**「按机器上目标家派生」——后者会让运行时根随装机形态出现多取值，
  > 恰恰重建要消灭的形态（源自 r2 GLM-02）。
- 「装了入口资产却没有运行时」判为**安装失败**（响亮报错）。

##### 跨产品副作用与回滚成本（**源自 r5 CODEX-09**）

在非 Claude 机器上无条件创建 `~/.claude/skills/dual-critic`，两条后果必须登记：

1. 用户**日后装上 Claude Code 时，这份副本会被当作已安装的 skill 静默生效**——
   而它从没被那台机器同意过。
2. 「运行时根只在四家目标全部卸载时才移除」在这类机器上**永不触发**（claude 目标压根没参与），
   卸载面留下一个**不属于任何目标的孤儿目录**。

**处置**：
- 创建时**打印一行**「运行时资产落在 `<路径>`（Claude Code 若日后安装会把它当已装 skill）」，
  并进 QUICKSTART / MANUAL；
- **卸载改按「运行时根自身的目标归属」判移除条件**，不绑在 claude 目标的在场与否上；
- §7 新增风险行登记这条跨产品副作用与其回滚成本（原 D9 的「回退零成本」只算了代码改动，
  没算已扩散到用户机器上的足迹）。

## 7. 量级与风险

### 7.1 双审轮次

按 r5 codex 实测口径（本仓 26 主题 / 66 轮 code 双审，均值 **2.5**、中位 **2**）估：

| 环节 | 轮次 | 备注 |
| :--- | :--- | :--- |
| 本计划自身（plan 档） | 1～3 | 本稿是 r1 |
| 第 1 步 准入实测 | **0** | 零行为改动；但**12～16 次真实调用 + P-2 阻塞点重试上不封顶** |
| 第 2 步 渲染 + 安装多目标 | 2～3 | diff 体量最大的一步 |
| 第 3 步 Hook 多目标 | 1～2 | 条件步，不通过时只落文档 |
| 小主题 EV-82 | ≥2 | 重开待修 + T2 复验 |
| 第 4 步 验收 | **3 轮命令 B**（单列，不计入阈值） | **glm 轮是人机串行的交互会话，墙钟不可按调用时长估** |
| 第 5 步 回溯 | 0～1 | 改 8 类文档 + 12 份资产，是「改语义只改一半落点」的高发位置 |
| **小计（阈值论域，不含验收轮）** | **6～11 轮** | |

**墙钟**：每轮不止子进程时长——原 M10 r3 实测总耗时 2571s 而三侧自身合计 1479s
（约 1100s 收尾开销）；r4 那轮更是 codex 脚本级超时 25m0s 导致**整轮作废重跑**。
加上第 1 步的不可控重试与第 4 步的人机串行，**M10b 量级为 3～5 周**。

### 7.2 触发口径

- **每轮双审收尾时**核对累计轮次与累计墙钟，往 `doc/08_project/M10b-轮次台账.md` 追加一行
  （run_id、轮次、墙钟日），起点写死为本稿落笔日。
- **阈值**：累计轮次 > **15 轮**（上限 11 的 1.36 倍）或累计墙钟 > **6 周**
  ⇒ 按纪律 1 回补估算并向用户报告。
  > **阈值与上限留裕量**：原 M10 r4 曾把阈值设成与修正值上限相等，正常进度就会触发，
  > 「超阈值就报告」会被训练成噪声。

### 7.3 风险

- **R-b【最高】zcode 真载体不可用**：`zcode` 不在 PATH（编排器走应用包内 `zcode.cjs`），
  而真载体是 ZCode 的**交互会话**。**按 P-2，这是硬阻塞，不是可登记的降级。**
  它是本里程碑唯一「可能根本做不到」的一格。
- **R-h 阻塞点的暴露时点**：§2.3 的真载体格验的只是**一条只读 CLI 调用**，
  故「**preflight 层的可执行性在第 1 步暴露；全链载体风险仍在 §3.4 薄冒烟与第 4 步检验**」。
  §3.4 就是为压缩这段暴露延迟而设。
- **R-g glm 侧的环境风险**：桌面端会改写 `~/.zcode/v2/provider_config.json`
  （切 provider 家族时抹掉 `defaultModelSelection`、把自定义 provider `enabled` 翻 false，
  CLI 随即 `Model creation failed`）——撞上时先看 RUNBOOK 那行，**不是**编排器的锅（EV-87）。
- **R-i 联合校验在解析回退时不生效，且它是波动的**：原 M10 五轮里 r1 / r3 失效、r2 / r5 生效。
  **不能指望它自然解除。** §2.7 已安排一次诊断。
  后续轮次若再遇两侧以上回退，**驳回 blocker 时须按具名行号写实理由**。
- **R-l【新增】运行时根的跨产品副作用**（§3.2.1）：在非 Claude 机器上创建 `~/.claude/skills/dual-critic`，
  日后装 Claude Code 会被当已装 skill 静默生效；卸载条件永不触发留孤儿目录。
  **回滚成本含已扩散到用户机器上的足迹，不只是代码改动。**
- **R-m【新增】入口资产同名 × 共享读取面**（§3.2.2）：四家入口资产同名，
  而 `~/.agents/skills` 是 codex 与 zcode 共享根。本稿已把它钉为禁装，
  但**若第 1 步实测发现某家只读得到那个根**，这条决策要重议——届时选项只剩「改承载面命名」。
- **R-e L2 Driver 的残余风险**：入口资产预批准了 `Bash(.trivium/bin/trivium:*)`，
  L2 Driver 可自写裁决件再自跑 `approve`，复核只保「裁决齐备」不保「审批来自人」。
  `approval.ts:16-33` 已有诚实表述，§6.2 的 RUNBOOK 行搬运它，与 R18 **并列**登记。
- **R-f selftest 不覆盖非缺省 Driver**：`selftest.ts` 零处 `driver`，证明力只到 claude 侧。

## 8. 验证方式

- 每步：`npm run typecheck && npm run build && npm test` 全绿。
- **前置钩子**（§5.1，可执行步骤，失败退非零并停止）：第 4 步开工前核 EV-82 的 **T1 三条成分**。
- **每轮双审收尾**（§7.2）：往轮次台账追加一行。
- **安装验证分两层**：
  - **沙箱安装**（每步前置）：注入临时 home，四目标逐一覆盖，不碰开发者真实的家目录；
  - **开发机真实安装**（`npm run install:local`）：只在需要用 wrapper 验证全局副本时做，**不是每步前置**。
- **多目标验证要真跑一台「只有另一家」的机器形态**（§3.2.1），确认运行时根仍被装上。
- 变异验证：第 2 步（渲染产物与源不同步 ⇒ `entry-render-parity` 红；
  运行时根参与「跳过」⇒ 只装一家的形态红）、第 3 步（`effectiveGuardLevel` 去掉「配置在场」输入 ⇒
  「探针 true 但配置不在场」用例红）各至少一条红。
- `trivium doctor --selftest` 全绿。
- **变异验证前先确认 `dist/test` 真被重编**（`node scripts/build.mjs --tests-only`）。
