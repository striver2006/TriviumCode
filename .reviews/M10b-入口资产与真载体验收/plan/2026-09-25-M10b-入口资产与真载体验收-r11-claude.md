## 1. D-4：缺省审核者集合减去当轮 Driver（用户 2026-09-25 拍板 (a)；追加到 r5 §5.3）

### 1.1 问题

r5 §5.3 让命令 A 接受 `--driver`，但没有看选侧：codex、gemini、glm 三家都在缺省审核者集合里（注册表 `defaultSelected`），
任何一家当 Driver 时，`resolveCriticSelection` 走缺省集合就撞上「含当轮 Driver」而退 64。
命令 B / C / D 可以显式传 `--critics` 绕开；**命令 A 不收 `--critics`**（M7b 第 5 步 GLM-02 的既有边界），没有出口。
第 2 步渲染给另三家的命令 A 入口，在缺省配置下因此必然跑不通。

### 1.2 三个选项与拍板

| 选项 | 做法 | 结论 |
| :--- | :--- | :--- |
| **(a)** | 选侧来自**缺省集合**时减去当轮 Driver；显式 `--critics` / `--only` 含 Driver 仍退 64 | **选定** |
| (b) | 命令 A 接受 `--critics` | 不选：GLM-02「一次跑两轮，选哪几侧语义不清」的理由仍成立 |
| (c) | 不改，登记为已知边界 | 不选：会交付一个三家都跑不通的入口 |

### 1.3 为什么 (a) 的行为变化是安全的

- 这条路径改前**恒退 64**，放行它不改变任何今天能跑通的流程；
- claude 当 Driver 时缺省集合里本就没有 claude（`defaultSelected: false`），**J3 兼容轮不受影响**；
- 第 4 步 glm 轮走命令 B、显式 `--critics`（r5 §7.1），不受影响；
- 只减缺省、不减显式：用户亲手写下含 Driver 的集合是明确的自审意图，照旧退 64，不静默去掉；
- 减完为空（缺省集合只有 Driver 一家）落到既有的「空集合」报错，不回落全集。

代价：非 claude Driver 走命令 A 时是两审而不是三审；开场播报的 `models` 如实列出入选侧。

### 1.4 落点与验证

- `critics.ts` 的 `resolveCriticSelection` 缺省分支（唯一判定处，`topic resolve`、`preflight`、`review --start` 都经它）；
- 用例：`critics.test.ts` 三条（减去不退 64、显式仍退 64、减完为空退 64）；`topic-args.test.ts` 命令 A 用例改为在**缺省配置**下断言放开后的真实路径；
- 变异：`mutation-spec-2.json` 两条（退回不减、显式也静默减）均咬住；
- 断言旧语义的两处测试注释已追加更正（`topic-args.test.ts`、`stub-agent-kit.test.ts`）；
- 第 5 步回溯追加：设计文档里选侧规则那一节写明「缺省集合先减去当轮 Driver」，QUICKSTART 的命令 A 说明写明两审。

## 2. 更正 r10 §2.4.2 第二段（事实断言被推翻）

**原文**：「含角色后缀字样的那一组，在装有 TriviumCode Bash Hook 的载体上会被已知误拦拦下：这是预期，照实记录为『被拦』」。

**实测**（往返用例 `test/integration/args-transcription-roundtrip.test.ts`，第 2 步报告 §1.5）：

| 焦点内容 | Hook 判定 |
| :--- | :--- |
| 写动词字面 + 角色后缀字样 | 拦 |
| 只有写动词字面 | **同样拦**：`TV` 本身含 `.trivium`，已满足「提到保护对象」那一半 |
| 只有角色后缀字样 | **不拦**：缺 `writeLike` 前置门 |

**替换为**：焦点或任务目标里**含写动词字面**时，经 `TV` 发出的命令会被已知误拦拦下，与有无角色后缀字样无关；只含角色后缀字样不拦。
这是预期，照实记录为「被拦」，不算失败，也不为它开豁免（RV-B1）。入口资产的误拦提示已按此写。

**怎么漏的**：r10 落笔时把 Bash 侧判据记成了「写动词 ∧ 角色后缀」，漏了「保护对象」的另外几项字面（`.trivium` 等），而 `TV` 的路径本身就含其中一项。
