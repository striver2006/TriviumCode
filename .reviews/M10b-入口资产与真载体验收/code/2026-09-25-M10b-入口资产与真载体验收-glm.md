### GLM-02 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/install.ts:155（syncDir 的 fs.copyFile）` |
| 类别 | correctness ｜ 层次 code |
| 置信度 | low |

**问题**：TRIVIUM_ASSET_ROOT 指向 <repo>/skills/dual-critic（同上，文档推荐的调试用法）时，安装路径 syncDir 的源与目标是同一目录，会对该目录下每个文件执行 fs.copyFile(s, d)（s 与 d 同一路径）。libuv 的 uv_fs_copyfile 以 O_TRUNC 打开目标：若所用 Node/libuv 版本无 same-file 防护，源文件被截断为空；防护是否存在随版本而异（审查侧禁止写命令，无法实测）。与 GLM-01 同一根因：运行时根取值完全信任环境变量指向。

**依据**：src/install.ts:139-158（syncDir 对每个文件项 copyFile，无 src===dst 判断）；src/trivium/asset-root.ts:22-31；对 libuv copyfile 语义的离线查证结论（O_TRUNC 截断因果链确定，same-file 防护存在性与版本不确定）。

**建议**：syncDir 里加同路径短路（resolve 后 src===dst 即跳过拷贝），或 install 检测到 runtimeRoot 与安装源同路径时直接报「无需安装」。修前用一个临时文件实测本机 Node 的同文件 copyFile 行为并把结论记进报告。
