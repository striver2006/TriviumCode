## 0. 范围

### 0.1 本主题做什么

`probes/claude.ts` 的 `json_schema_ok` 那一臂，与 `scripts/claude-admission-control.mjs`
的第 ③ 段，都在用**手写的迷你 schema** 判「`--json-schema` 能不能强制结构化输出」。

本主题把这两处改喂**真实契约**，并让「CLI 拒绝了这份 schema」这件事**在字段上可见**。

- **不改 `stripMetaSchemaRef` / `readSchemaJson` 的行为**，只复用。

> 而 `adapters/agy.ts:288` 生产送真实契约路径）。今天无活触发器，登记见 §6。

## 3. 方案

### 3.1 探针结构化臂改喂真实契约（经适配层同一份变换）

把 `probes/claude.ts:1208` 那段自造 schema 换成 `readSchemaJson(<契约路径>)`。

- **探针臂**：`probeArgs` 不剥头，调用点这一次 `stripMetaSchemaRef` 是这条臂**唯一**剥壳点。
  绕开它会撞回拒绝形态，而那个形态会记成 `null`——**修复动作本身伪装成"没测到"**。
- **脚本臂**：经 `buildClaudeArgs` 出口已剥一次，改用 `readSchemaJson` 后剥两次，**幂等、不去掉**。

### 3.2 喂哪一份副本？——本稿唯一的不可逆决策

**取 A（生产同源）。三轮双审、八侧次独立同意。** B 会造出「探针绿而生产读另一份」，
C 回答的是副本漂移（另一论域）。「CI / 干净检出常态未测」不成立：本仓无 CI 面、
探针臂明写不进 `npm test`；A 下未安装与生产不可用同因同果；干净检出有环境变量通道。
残余只剩「干净检出 + 未装 + 不设环境变量的 doctor 场景」。

#### 3.2.1 TTL 按成因拆，**不按字段废新鲜**

按字段废新鲜**没有落点**（新鲜度是段级，现状表第 15 行），且未安装机器会死循环。

| 成因 | 处置 |
| :--- | :--- |
| **资产根未安装** | spawn 前可判的确定事实，每轮 doctor **免 API 复核存在性**；**不废整段新鲜**。可见性靠 notes 指路句，**不进 warnings**（§3.7） |
| **模型行为类 null**（缺键 / 不可 parse） | 保留 TTL，可见性交给 §3.7 |
| **撞闸 null**（超时 / 预算） | 不与 TTL 合并；处置见 §4.2 |
| **其余未测形态** —— 环境／CLI 层失败：拿不到退出码、正对照不成立、两头皆空、跑到一半失败、零退出但未跑完 | **保留 TTL，可见性同 §3.7。** 这一行是 r4 补的：r3 宣称「按成因拆三档」是完整划分，而 §3.4.1 产出的 null 成因远不止三类——**不写出来就是让实现者替计划做决定**（r4 CODEX-03 ≡ GLM-05） |

#### 3.2.2 资产根怎么进探针

| 半 | 内容 |
| :--- | :--- |
| **归属** | 解析规则提成一处并导出，**落 `config.ts`**——`probes/claude.ts:41` 今天已 import 它，现成先例、不新开方向。`review.ts` 与 `init.ts` 改引它。合并**无行为变化**（同一条 `override ?? env ?? homedir` 链）。**契约相对路径一并纳入（r5 补，CODEX-08）**：`review.ts:497` 今天是唯一运行期路径拼接点（`path.join(assetRoot, 'schema/review.v1.json')`），只把资产根做共用出口、不把这半句也定死，改完后探针与脚本仍要各自拼一次，等于把「同一事实两份实现」从资产根搬到相对路径。新增导出函数（如 `resolveReviewSchemaPath(assetRoot)`）与资产根解析一起落 `config.ts`，探针与脚本都改调它 |
| **取值** | 由 **doctor 解析后注入** `probeClaude(opts)`，`opts` 增可选 `assetRoot?: string` |

**为什么取值要注入——两条独立成立的理由**：

1. **准入脚本经 dist 动态 import `probes/claude.js`**（`claude-admission-control.mjs:93-108`），
   让 probes 依赖编排层会把整条编排链拖进它的 import 图；
2. 避免第三份资产根规则副本。

> r2 稿在这里引用了一条**不存在**的红灯（`registry-parity` 只扫 `adapters/ 不得 import probes/`，
> 硬编码扫描目录在 `:1106`）。**这一稿不引用它**；该方向的契约由 §5 用例 6 真正补出来。

**注入口同时是 §5 用例 1／2 的测试缝。** 用例经参数注入，**不改 `process.env`**。

### 3.3 提示词与 `requiredKey` 随契约改

提示词改为对夹具文件做一次**最小审查**并允许 `findings` 留空数组（`review.v1.json:22`）；
`requiredKey` 由 `first_line` 改为 **`summary`**。

> **判据函数要改什么**：`requiredKey` 的比较逻辑不变，但**三态出口与输入面必改**——
> 签名要收 `timedOut` / 退出码 / stderr / `trace.eventCount` / 正对照，
> 两条 false 出口（catch 与 `typeof` 失败）要改落 null。

**这一格证到什么、证不到什么：**

1. **证到**：CLI 接受**剥壳后的**全局资产根契约文件，并按它交付了可解析的结果。
2. **证不到「完全合规」**：判据只查「能 parse 且某键是 string」。
3. **证不到「全程强制」**：方言不认的键可能被静默忽略，**这一格可以保持绿而强制面已收窄**。

**可归因性（r4 新增，CODEX-09）**：落盘里今天**没有任何字段记录被喂的是哪一份 schema**。
叠加模型行为类 null 保留 7 天 TTL、以及副本可能过期——**「这一格是绿的」无法归因到哪一份副本**，
陈旧副本上的绿会安静地绿满一个 TTL，**而那正是本主题要买的保证**。
落点：notes（或字段旁）带上被喂 schema 的**路径 + 内容指纹**，成本是一次哈希。

### 3.4 判据：三态，`false` 严格收紧

#### 3.4.1 前置门与映射

**前置门（任一成立即 `null`，照 `judgeVerboseBinding` 门序，现状表第 17 行）**：

1. `timedOut`；
2. 拿不到退出码（`typeof exitCode !== 'number'`）；
3. **正对照不成立**——同轮**读探针**（另一条只读臂）的 `completed !== true`。

**「跑完」的操作定义（r4 补，GLM-01 ≡ AGY-02）**：
**`completed` ＝ result 事件在场且非 error**（`claude-trace.ts:74-87`）。
r3 稿的行 4～6 前置「跑完」而没定义它，于是有一整格无归属。
**下面表格里的 `completed` 是结构化臂自己这次调用的 trace 结论**，与前置门 3 读的
「读探针」完成状态是两个不同信号，不要混为一谈（r5 补，避免行文歧义）。

**行序即互斥性（r5 改，CODEX-04 ≡ GLM-02）**：`completed` 与退出码彼此独立
（`claude-trace.ts:161-168`：`completed` 只读 `result` 事件的 `is_error`/`subtype`，
不读退出码），故「非零退出 + `completed === true`」是真实可能形态。r4 表的行 3
（「非零退出但已吐出事件⇒null」）未限定 `completed !== true`，会与末行（`true`）同时
命中、给出矛盾结论。**收紧行 3 的前件为 `completed !== true`**，让前四行与后三行以
`completed` 是否为 `true` 严格二分，不留给实现者判次序。

| 输入 | 结论 | 理由 |
| :--- | :--- | :--- |
| 非零退出 + `eventCount === 0` + stderr 非空 | `false` | CLI 干净拒绝——**唯一**允许落 false 的形态 |
| 非零退出 + `eventCount === 0` + stderr 也空 | `null` | 两头皆空的静默失败，先例第四道门 |
| 非零退出 + `completed !== true` 且已吐出事件（r5 补 `completed !== true` 前件，堵住与末行的重叠，CODEX-04≡GLM-02） | `null` | 「跑到一半才失败，记未测，不猜」 |
| `completed !== true` 且不落上述三行（含零退出但未跑完、预算掐断、`max_turns`、`result` 为错误 subtype 等——r5 把原「或非拒绝形态」这一未定义措辞改成穷举式定义，GLM-02） | `null`，note「未跑完（撞闸或未获模型答复），需重测」（r5 补正面内容，原稿只负向写了不附「模型未合规」，GLM-02） | r4 补的兜底行。对一次模型根本没交付任何东西的运行，「跑通但模型未合规」是失实归因 |
| `completed` 且输出不可 `JSON.parse` | `null` + note「跑通但模型未合规，需重测」 | §3.4.3 |
| `completed` 且缺 `requiredKey` 或其非 string | `null` + 同一条 note | 同上 |
| `completed` 且 `summary` 为 string | `true` | — |

> 照先例末尾再加一条**显式兜底**：以上都不匹配 ⇒ `null`。
> 先例有这一条（`:707-711`），r3 表没有。

#### 3.4.2 判据形态写死：**行为特征，不做文案匹配**

沿用 `judgeVerboseBinding` 的口径，**不**把 `no schema with key or ref` 写进判据——
厂商改一句话文案匹配就静默失效，**且失效方向是放松**。
退出码也不能单独判别（`adapters/claude.ts:919-922`）。

#### 3.4.3 为什么「不可 parse」与「缺键」都落 null

这一格**第一次依赖模型配合度**：探针档位是 haiku，而 M9 留痕显示**连 sonnet 都调了 5 次
`StructuredOutput`、前 4 次被 CLI 打回**。这两条出口在现判据里**都返回 `false`**，
叠加 §2.2 的降级扳机与 7 天 TTL，**一次模型抖动会把生产的结构化输出关掉一周**。

### 3.5 准入脚本第 ③ 段同改

- 改调同一个 `readSchemaJson`，提示词与 `requiredKey` 与 §3.3 一致；
- **按 §3.3 的新签名把五个输入全部接进判据调用**：`timedOut` / `exitCode` / `stderr` /
  `trace.eventCount` / 读探针的 `completed`（正对照）。
  > r3 稿只点名了 `stderr` 与 `exitCode` 两个（r4 GLM-02）。漏接不是风格问题：
  > **没有 `eventCount` 判不了行 1～3 的分格，没有正对照判不了门 3**——
  > 脚本臂要么塞占位值、要么退回旧行为，**两种都让"两个身位再次分叉"，
  > 恰是本节自己要防的**。同脚本 ⑦ 段的 `judgeVerboseBinding` 五输入全传，照抄那个形态。
- **契约路径来源定死：脚本经同一个共用解析出口取资产根**（含环境变量通道）。
  不定死会让 B 选项从后门溜回来。
- **脚本接线的落点（r5 补，AGY-02 ≡ GLM-05）**：`loadProd()`
  （`claude-admission-control.mjs:93-108`）今天只动态导入 `adapters/claude.js`、
  `adapters/claude-trace.js`、`probes/claude.js`、`util/exec.js`，**未含 `config.js`**——
  需新增该动态导入才能拿到共用解析出口（§3.2.2）。

- **求值点**：条件在 `probeClaude` **返回处**求值——doctor 对 claude 段无新鲜度短路、

- **本轮结果的载体（r5 补，CODEX-03）**：`probeClaude` 的返回值新增一个**仅描述本轮**的
  结构化臂结果三态字段（例如 `structuredArmRan: 'not-attempted' | 'uninstalled' | 'ran'`，
  作为返回对象的属性、不落进持久化的 `ClaudeProbe`，仿 zcode `flagsIndeterminate` 是返回值
  字段而非落盘字段的先例，见现状表第 22 行）。doctor **只读这个字段**判断「结构化臂本轮是否

  时间戳不可用，不能反过来支持「早退轮不触发」这个结论，本次改正引用。

  > **实现阶段改注（代码双审 GLM-05，Driver 裁决：接受合并）**：落地时把这里的三态
  > （`not-attempted`/`uninstalled`/`ran`）与 `judgeJsonSchema` 的四个 cause 合并成了
  > 一个六值联合 `StructuredArmCause`（`'carried-over'` 覆盖 `!bin` 与 `skipModelCalls`
  > 两条早退，其余四值即 `JsonSchemaCause`），而不是分立成两个字段。核实无信息丢失：

  > `claudeSeverity` 的 `!probe.entrypoint` 分支独立报 blocker，与这个字段无关），
  > 成因区分仍留在 `notes` 的两条不同文案里。合并后的唯一事实来源见
  > `probes/claude.ts` 的 `StructuredArmCause` 类型定义。

- **成因区分由探针侧给机读落点**，照 zcode 段 `flagsIndeterminate` 先例（现状表第 22 行）——
  doctor 只做映射，不拿 null 反推成因。

- **成因 → 文案映射（r5 补，GLM-03）**：覆盖面内两类成因各自独立文案，仿 zcode
  `flagsZeroExit`/`flagsIndeterminate` 两条不同文案的先例：
  - 干净拒绝（`false`）：「CLI 拒绝了本仓契约文件，已降级为提示词约定」；
  - 结构化臂真跑过但撞闸/未跑完（§3.4.1 兜底行那一类）：「本轮探测未跑完（撞闸或未获
    模型答复），非模型不合规」；
  - 结构化臂真跑过但不可 parse/缺键（§3.4.1 后两行那一类）：「模型未按契约给出合规输出，
    需重测」。
  **兜底行那一类不得复用「模型未合规」字样**——这正是 §3.4.1 刚在 note 侧修掉的失实归因，
  不能在 warning 侧复发。

- **覆盖面**：`false`（干净拒绝）+「**结构化臂真跑过且落 null**」（即上面三类文案覆盖的
  全部 null 成因）。

- **「资产根未安装」这一档不进 warnings**——可见性归 notes 指路句（§3.2.1）。
  **第三条独立理由（r5 补，GLM-03）**：未安装是 spawn 前**可判的确定性环境事实**
  （§3.2.1），不是「跑了才知道」的运行时不确定性，与另外两类成因性质不同——混进 warnings

**不进 `preflight` 失败面**：适配层已有降级路径，不必升成准入硬阻断。

### 4.1 拒绝形态 —— **零 API 成本，本地复跑**

> （r4 CODEX-06 ≡ GLM-08）。已删。

### 4.2 真实契约下模型能否出合法对象 —— **唯一的有成本件**

**必录产出**：该臂的单次实测成本与耗时。

**撞闸的处理逻辑已定死**：`completed !== true ⇒ null + note`（§3.4.1 的兜底行，r5 改准
note 正面内容见 §3.4.1），**不随参数变**。

**实测只用于校验余量**，**预登记判定规则**：

> 实测成本或耗时超过当前常量（`--max-budget-usd 0.20` / 180s）的 **50%** 时，
> **先上调该臂的预算与超时**；上调后仍撞闸，才接受「撞闸 ⇒ null + note」作为稳态。
> **上调要带上限，且要求两次以上实测**——单样本超阈可能只是抖动（§3.4.3 引的 M9 留痕
> 显示这一格方差很大）。**上调目标给具体值**，不写「上调」了事。

**第二档预登记（r5 补，CODEX-06）**：实测若落在**模型层不合规**（`completed` 可达但
不可 `JSON.parse` 或缺 `requiredKey`，§3.4.1 后两行），处置为——记为残余，该格长期 `null`
**不阻塞** M10a 第 2 步的开工判据；允许**一次**换档（如临时升到更强模型）或改提示词的
重测，重测仍不合规则维持 `null` 并写入 §6 残余表，不再无限重测。**不为它预留升级路径**——
探针档位是否长期用 haiku 是另一个决策，不在本轮变更。

**50% 这个数的依据（r5 改，CODEX-07）**：原依据（探针常量注释「典型单次约 $0.008」）
出自**旧臂**（迷你 schema、回一行字），本主题要量的是**新臂**（读夹具 + 出真实契约对象）
的典型成本，两者不保证相同——**改为相对本臂实测典型值的倍数**：先做两次以上实测取
典型值，50% 线 ＝ 该典型值的 1.5 倍，取值时机在完成两次以上实测**之后**，功能定位不变
（仍是异常检测线，不是精算）。**脚本臂不同吃这一档**（`claude-admission-control.mjs:74-78`
有自己独立的 `BUDGET_USD`/`TIMEOUT_MS`/`CASE_MAX_CALLS` 与调用次数硬刹车 §12，撞线即整个
准入流程失败停机）——脚本臂受硬上限保护、风险与探针臂的「静默降级」不同源，两者成本
常量独立管理不算「两个身位分叉」（那条口径约束的是 schema 来源与判据逻辑，不约束成本
常量）。

**上调的落点（r4 补，CODEX-04 ≡ AGY-04）**：`PROBE_BUDGET_USD` 与 `PROBE_TIMEOUT_MS`
是**模块常量**，`probeArgs` 与 `execProbe` 都不收按臂覆盖（现状表第 16 行）。
照 r3 字面做只能抬模块常量，**等于把只读负对照臂、路径 deny 臂、读探针臂的上限一并抬高——
一次未经讨论的全局配额上调，方向与 §3.2.1 相反**。
**落点定为给 `execProbe` / `probeArgs` 加覆盖入参**。
**谁传（r5 补，CODEX-05）**：覆盖值由结构化臂的调用点显式传入，两个函数本身**不为它设
默认值**——`probeArgs` 是导出函数（`test/unit/claude-events.test.ts:483,509` 直接调用），
不写死这条会让其它调用点无意间共享覆盖值，等于本条要避免的「全局配额上调」换个位置
重演。测试面见 §5 用例 8 与变异 11（r5 新增，CODEX-05 ≡ GLM-04）。
