## 0. 一句话结论

**23 条全部接受，无一驳回。方案主轴（生产同源、经适配层同一份变换、双处同改）三侧独立判为正确，
§3.2 取 A 三侧独立同意**——但本稿有**两处事实错误**和**一处接不通的接线**，任一都足以让落地即返工。

最重的一条我自己把危害写反了方向：我写「`json_schema_ok` 没有任何消费方，一次准入失败完全无声」，
而实际是 **`false` 会让 claude 与 agy 两侧生产都静默放弃 `--json-schema`**（`adapters/claude.ts:810`、
`agy.ts:288`）。**不是无声，是换了个更差的行为**。这个错误直接推翻了我 §3.4 的设计方向：
我本打算把 `false` 的成因面**扩大**，而那等于扩大一条会关掉生产结构化输出的降级路径。

## 2. 需要展开的三条

### 2.1 我把危害写反了方向，而它连带推翻了 §3.4 的设计方向（判 CODEX-01 ≡ GLM-01 → CODEX-02）

原稿 §2.2 的推理链是：拒绝 ⇒ null ⇒ null 不报警 ⇒ **无消费方** ⇒ 完全无声。
于是 §3.4 的设计动机是「把 `false` 的成因面**扩大**，让失败可见」。

实际链路是：`false` ⇒ **两侧生产都不传 `--json-schema`** ⇒ 降级为提示词约定 + 宽松解析。
`false` 不是一个"报警值"，它是**一个扳机**。

**方向因此反转**：`false` 要**收紧**到只由「CLI 明确拒绝」触发，而不是扩大。
CODEX-02 指出的第三条出口（模型没交 `summary`）如果落 `false`，
配上探针用的是 haiku 而生产是 sonnet、连 sonnet 都被 CLI 打回过 4 次形态，
再配上 TTL 7 天——**一次模型抖动会把 claude 生产的结构化输出关掉一周**。

这是本轮三侧意见里咬合最紧的一串：CODEX-01 给事实、CODEX-02 给后果、CODEX-09 与 CODEX-04 给时效面。
我起草时把 `json_schema_ok` 当成一个纯诊断字段，**没去查它有没有消费方就断言"没有"**。

### 2.2 资产根的落地形态：三侧给了三个不同的落点，我取其中两个的组合（判 CODEX-03 ≡ AGY-01 ≡ AGY-04 ≡ GLM-05）

| 侧 | 建议 | 我的取舍 |
| :--- | :--- | :--- |
| codex | 解析规则提成一处共用出口（`review.ts` export 或搬 util）+ `probeClaude` 增注入口 | **归属**部分采纳 |
| gemini | 提到 `config.ts` 或 `adapters/claude.ts` 并导出，三方共同引用 | **归属**采纳（低层模块，避开分层红线） |
| glm | 由 doctor 解析后把路径注入 `probeClaude`，不让 probes 反向 import 编排层 | **取值路径**采纳 |

三条不冲突，是同一问题的两半：**解析规则要有单一归属**（今天有两份：`review.ts:396` 与 `init.ts:45`），
**取值要靠注入**（否则 probes → review.ts 的反向依赖会踩 `registry-parity` 的分层契约，AGY-01 指出这会当场红）。

我核过两份规则同形（`override ?? env ?? homedir` 与 `env ?? homedir`），**合并无行为变化**，
所以这是一次纯粹的去重，不引入风险。

### 2.3 判据形态由「候选未定」变成「照本仓既有纪律写死」（判 GLM-04 + CODEX-05）

原稿 §3.4 我列了三个候选（stderr 文本匹配 / 退出码 / 结构化错误事件）并说「先测再定」。
GLM-04 指出本仓对同形问题**已有定论**：`judgeVerboseBinding` 用行为特征而非文案，
并写明理由——厂商改一句话文案匹配就静默失效，**且失效方向是放松**。

CODEX-05 补上另一半：退出码不足以单独判别（预算掐断的 result 也可能退 0）。
两条拼起来，判据形态已经不必等实测就能定死。这也让 §4.1 从"决定判据"降级为"补两个数据点"。

## 4. 方法记账

**本轮我犯的是一个比"读窄论域"更基本的错**（上一主题刚记过那条）：
**我对一个字段断言"它没有消费方"，却没有去 grep 它**。

`grep -rn 'json_schema_ok' src/` 是一条一秒钟的命令，它会直接吐出 `adapters/claude.ts:810`
与 `agy.ts:288` 两个消费点。我没跑它，而是从"doctor 里没看到"推出了"没有任何消费方"——
**从一个局部观察推出了全局断言**。三侧里有两侧独立跑了这条 grep 并当场打脸。

更糟的是这个错**不是孤立的失实，它决定了方案方向**：因为以为没人消费，
我把 `false` 当成无害的诊断值、打算扩大它；查清之后方向要反转成收紧。
**一条没核的事实断言，带偏了整个 §3.4。**

固化做法：**计划稿里凡出现「没有 X」「唯一的 X」「从未 X」这类全称否定断言，
落笔前必须附上穷举方式**（grep 命令 / 目录范围），并把那条命令写进稿子供审查员复跑。
这与上一主题固化的「落点论域要穷举」是同一条规则在**断言侧**的应用：
那条防的是改漏，这条防的是说错。

r2 稿的 §1 现状表将逐行补上「这一行怎么穷举的」。
