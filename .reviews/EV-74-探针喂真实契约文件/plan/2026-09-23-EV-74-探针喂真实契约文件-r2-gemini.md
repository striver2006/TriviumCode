### AGY-01 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §3.2` |
| 类别 | contract ｜ 层次 plan |
| 置信度 | high |

**问题**：§3.2 对未安装落 null 的 TTL 处置写为「json_schema_ok === null 时该段不判新鲜（或强制重探该侧）」，会导致在未全局安装资产且未配环境变量的开发环境下，claude 探针陷入永久过期（stale）的死循环。preflight 会每次报过期并要求运行 doctor，而每次 doctor 重探后因无资产依然落 null，导致结论永远无法被系统认作新鲜，且每次 doctor 都会重复消耗配额。

**依据**：src/trivium/config.ts:825-827 的 cliProbeIsFresh 与 :841-843 的 staleCliProbes 是基于 probed_at 时间戳对整个 CLI 探针做统一新鲜度判定的；probes/claude.ts:943-952 亦明确 probed_at 的语义是「这一键探到过」。若将单个字段的 null 状态作为该段不新鲜的判据，且在选项 A 下未安装属于合法且常态的残余，未安装机器将无法通过任何 preflight 检查。

**建议**：撤销「json_schema_ok === null 时整段不判新鲜」的规则。保留 probed_at 的正常刷新，将未安装资产的可见性完全交给 doctor 的报告提示（如在 doctor 输出中明确定位该 note，或引导配置 TRIVIUM_ASSET_ROOT），不得破坏 cliProbeIsFresh 的通用时间戳契约。

### AGY-02 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §3.4.1` |
| 类别 | correctness ｜ 层次 plan |
| 置信度 | high |

**问题**：§3.4.1 判据表格将落 false 的条件定义为「非零退出 + 零 result 事件 + stderr 非空」，这与它声称对齐的既有先例 judgeVerboseBinding 存在关键信号结构偏差：先例要求的是整个 stdout 零事件（emitted === 0），而本稿写成了「零 result 事件」。如果 CLI 在运行时已经输出了部分事件（如 system/init 或 tool_use），随后因网络断开、OOM 或外部中断非零退出，此时同样无 result 事件且 stderr 有错误输出，按本稿规则会被误判为 false，直接在生产层关掉结构化输出 7 天。

**依据**：src/trivium/probes/claude.ts:704-710 的 judgeVerboseBinding 明确断言 o.exitCode !== 0 && emitted === 0（由 parseClaudeEvents 解析出的 eventCount === 0），并在注释中明文定性「非零退出却吐了事件多半是跑到一半才失败，记未测，不猜」；而 adapters/claude-trace.ts:161-168 的 result 事件处理只在正常结束时存在。M9 第 1 跑拒绝形态（exitCode: 1, duration: 0.7s, 零 API 调用）在参数解析期即失败，根本不会输出任何事件。

**建议**：严格对齐先例信号结构，将判据明确改为「非零退出 + eventCount === 0（整个输出零事件）+ stderr 非空 ⇒ false」；有前序事件但无 result 事件的非零退出一律归入 null（记未测，不猜）。
