## 0. 范围

### 0.1 本主题做什么

`probes/claude.ts` 的 `json_schema_ok` 那一臂，与 `scripts/claude-admission-control.mjs`
的第 ③ 段，都在用**手写的迷你 schema** 判「`--json-schema` 能不能强制结构化输出」。
真实审查请求送的是 `skills/dual-critic/schema/review.v1.json`。两者形状差得远，
而正是这个差把 M9 第 6 步验收的第 1 跑整跑打掉（零 API 调用即拒）。

本主题把这两处改喂**真实契约**，并让「CLI 拒绝了这份 schema」这件事**在字段上可见**。

### 0.2 本主题不做什么

- **不改 `review.v1.json` 本身**。它的方言约束由契约用例 A31 守着，不在本主题论域。
- **不改 `stripMetaSchemaRef` / `readSchemaJson` 的行为**。它们是 M9 第 6 步已落地的
  既有件，本主题只是**复用**（见 §1 证据行）。
- **不动 agy / zcode 两侧**。它们传文件路径且接受 2020-12，与本条无关。

### 0.3 为什么现在做

它是 M10a 第 2 步的开工前置（计划 §6.1 的钩子核 BACKLOG 状态列），
且 BACKLOG 登记的触发条件之一就是「下一次动 `probes/claude.ts`，或 M10 前」。

## 2. 问题与危害

### 2.1 准入三步的 `true` 答非所问

M6 探针、M9 第 1 步、第 3 步复验，三处都记下 `json_schema_ok: true`。这三个 `true`
**都是真的**，但答的是「这个旗标收不收内联 JSON」这个**形态**问题，
不是「它收不收本仓的契约文件」。于是准入全绿而第一次真实审查零 API 调用即拒。

这正是 EV-42 那一类「形状实测」要防的：**探针夹具与真实请求之间的差异**。

### 2.2 拒绝形态会落 null，而 null 不报警——三重静默

这条是 BACKLOG 明写的，我核过链路，成立：

1. CLI 拒绝 schema ⇒ **零 result 事件** ⇒ `trace.completed === false`；
2. `judgeJsonSchema` 见 `!completed` ⇒ 返回 **`null`**（"没测到"），**不是 `false`**；
3. 三态纪律里 null 不报警；
4. 而 `json_schema_ok` **今天没有任何 doctor 消费方**。

四层叠起来，一次真实的准入失败会**完全无声**。所以本主题若只把 schema 换掉、
不动可见性，下一次契约文件改动引入不兼容关键字时，症状与 EV-74 一模一样。

### 2.3 两份自造 schema 是同一个病的两个身位

探针与准入脚本各造一份，谁都不是生产送的那份。改一处不改另一处，
准入脚本会继续给出"答非所问的 true"。

## 3. 方案

### 3.1 探针结构化臂改喂真实契约（经适配层同一份变换）

把 `:1208` 那段自造 schema 换成 `readSchemaJson(<契约路径>)`。

**为什么必须经它而不是自己 `readFile`**：`stripMetaSchemaRef` 是这条链路上
唯一处理 2020-12 头的地方；绕开它会当场撞回第 1 跑的拒绝形态，而按 §2.2
那个形态会记成 `null`——**修复动作本身会伪装成"没测到"**。

### 3.2 喂哪一份副本？——本稿唯一的不可逆决策

| 选项 | 含义 | 代价 |
| :--- | :--- | :--- |
| **A 生产同源** | 走 `resolveAssetRoot()`，读 `~/.claude/skills/dual-critic/schema/review.v1.json` | 依赖安装状态；干净检出 / CI 上文件可能不存在 |
| B 仓内副本 | 像 `parse.ts` 那样绑 `skills/dual-critic/schema/review.v1.json` | **探针绿而生产红**——全局副本过期时照样漏，EV-74 在上一层原样复发 |
| C 两份都喂 | 各判一次，不一致则报 | 两次 API 调用，成本翻倍 |

**取 A。** 理由：本主题的全部意义就是「让探针问的问题等于生产问的问题」，
而生产问的是全局副本。B 保住了可复跑性却把病搬了个家——
它恰好是本主题要治的那个形状（夹具与真实请求不同源）。

**A 的代价要显式处理，不能靠运气**：文件不存在时**落 `null` 并在 `notes` 里
写明「未安装资产，本格未测」**，不得回落仓内副本——回落就是偷偷变成 B。

> 这条决策我标成**不可逆**是因为：一旦按 B 落地并跑绿一次，后面很难再有人
> 愿意回头把它改成"可能因未安装而落 null"的形态。请审查员重点看 §3.2，
> 特别是「A 在 CI / 干净检出下会不会把探针变成常态未测」——
> 如果那是常态，A 的收益就被抵消了，我需要被告知。

### 3.3 提示词与 `requiredKey` 随契约改

真实契约要求 `schema / verdict / summary / findings` 四个顶层键、
`additionalProperties: false`，`findings[]` 每项 9 个必填键。
现有提示词「读 X，回答它的第一行内容」在这份契约下**无法构造出合法对象**。

改法：提示词改为对夹具文件做一次**最小审查**并明确允许 `findings` 留空数组
（契约自身写明「空数组合法」，`review.v1.json:21`）；`requiredKey` 由
`first_line` 改为 **`summary`**（顶层必填且为 string，与 `judgeJsonSchema`
现有的 `typeof === 'string'` 判据相容，不必改判据函数）。

> **一处要说清的限度**：`judgeJsonSchema` 只查「能 parse 且某键是 string」，
> **不做 schema 校验**。所以改喂真实契约后，这一格证的是
> **「CLI 接受这份契约并按它出了可解析的结果」**，仍不是「输出完全合规」。
> 本主题不扩到全量校验（那要引 ajv 进探针，成本与论域都另说），
> 但**这句限度要写进 notes 与设计 §3.7**，不能让下一个人再把它读大。

### 3.4 让"CLI 拒绝了 schema"在字段上可见

这是 §2.2 的对治，也是本主题比 BACKLOG 字面描述**多做的一件**。

- `execProbe` 透传 `stderr` 与退出码（`RunResult` 本来就有，只是被丢了）；
- 结构化臂在 `completed === false` 时，用拒绝特征（实测文本见 §4.1）
  区分**"CLI 拒绝了这份 schema"**与**"调用没跑完"**：前者判 `false`，后者仍 `null`。

**判据形态待定，取决于实测**：是靠 stderr 文本匹配、还是靠退出码、
还是 CLI 有结构化的错误事件。§4.1 先测再定，**不在本稿里写死**。

> 为什么不直接"`!completed` 一律判 false"：那会把超时、崩溃、网络失败
> 全算成"确认不支持"，方向是 fail-green 的反面但同样失真，
> 且违背本仓三态纪律里「没测到」与「确认没有」不得合流的既有口径。

### 3.5 准入脚本第 ③ 段同改

改为调同一个 `readSchemaJson`，提示词与 `requiredKey` 与 §3.3 一致。
它已经 `import` 了探针模块（`mod.probe.judgeJsonSchema`），复用路径是通的。

### 3.6 设计 §3.7 口径改准

`:390` 那行今天写的是「这格只证形态，不证契约文件……探针改喂真实文件登记 EV-74」。
结案后改为：证的是「CLI 接受**全局资产根的**契约文件并据它出了可解析结果」，
并把 §3.3 那条限度（不做全量校验）与 §3.2 的未安装落 null 一并写进去。

### 3.7 要不要给 `json_schema_ok` 加消费方？——请审查员裁定

§2.2 的第 4 层是「无 doctor 消费方」。不补这一层，即便判据从 null 改成 false，
**也没有任何地方会因此报警**。

- **纳入的理由**：不补则 §3.4 的可见性只到字段，到不了人。
- **不纳入的理由**：`doctor` / `preflight` 的失败面属准入门槛，
  加一格会改变对外行为，论域比本主题大。

我的倾向是**纳入但只做最轻的一档**：`doctor` 输出里把 `false` 显示为告警行，
**不进 `preflight` 失败面**（不改闸门行为）。请三侧独立判这个取舍。

## 4. 先实测、后定稿的两件

本仓纪律：取值靠实测的必须留探针结论，不能只活在计划稿里。

### 4.1 拒绝形态的可观测面（决定 §3.4 的判据）

**判别法**：与"正常但超时"的对照跑比，看哪个信号能把两者分开。

喂剥过头的真实契约 + §3.3 的最小审查提示词，看 `result` 能否 parse、
`summary` 是否为 string、`findings` 是否被接受为空数组。

> 两件都要落进 `doc/05_testing/evidence/ev74-*/`，连同命令原文、CLI 版本与基线指纹。
> **两件都要真实 API 调用，有成本**（M9 验收单跑约 $1.2～1.6，本组两跑规模小得多，
