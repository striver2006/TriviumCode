## 2. 问题与危害

### 2.1 准入三步的 `true` 答非所问

三处 `json_schema_ok: true` **都是真的**，但答的是「这个旗标收不收内联 JSON」这个
**形态**问题，不是「它收不收本仓的契约文件」。于是准入全绿而第一次真实审查零 API 调用即拒。

### 2.2 `false` 不是报警值，是**降级扳机**

| 层 | 事实 |
| :--- | :--- |
| 拒绝 ⇒ null | CLI 拒绝 ⇒ 零事件 ⇒ `completed === false` ⇒ `judgeJsonSchema` 返回 `null` |
| null 不报警 | 三态纪律里 null 不报警；doctor 侧确无该字段分支（现状表第 12 行） |
| **`false` 改生产行为** | `adapters/claude.ts:810`：`false` ⇒ **本次不传 `--json-schema`**，降级为提示词约定 + 宽松解析并记 degradation；`agy.ts:288` 同形 |

准确表述：**doctor / preflight 无告警面，但适配层有降级消费方。**
不是"完全无声"，是**换了个更差的行为**。

> 这个事实在 `types.ts:658` 的 JSDoc 里白纸黑字写着
> （「**消费方**：……为 false 时降级为提示词约定 + 宽松解析」）。
> r1 稿断言"没有任何消费方"，**在类型注释里就已被否证**。

### 2.3 两份自造 schema 是同一个病的两个身位

改一处不改另一处，准入脚本会继续给出"答非所问的 true"。

## 3. 方案

### 3.1 探针结构化臂改喂真实契约（经适配层同一份变换）

把 `probes/claude.ts:1208` 那段自造 schema 换成 `readSchemaJson(<契约路径>)`。

**两臂的剥壳位置不同源，理由要分述**：

- **探针臂**：`probeArgs`（`:164`）原样透传、**不剥头**，所以调用点这一次
  `stripMetaSchemaRef` 是这条臂**唯一**的剥壳点。绕开它会撞回第 1 跑的拒绝形态，
  而按 §2.2 那个形态记成 `null`——**修复动作本身伪装成"没测到"**。
- **脚本臂**：经 `buildClaudeArgs` 出口已剥一次。改用 `readSchemaJson` 后剥两次，
  **幂等、无害、不去掉**。

### 3.2 喂哪一份副本？——本稿唯一的不可逆决策

| 选项 | 含义 | 代价 |
| :--- | :--- | :--- |
| **A 生产同源** | 走统一解析出口，读全局资产根下的契约 | 依赖安装状态（见下方三条修正） |
| B 仓内副本 | 编译期绑仓内文件 | **探针绿而生产红**——本条在上一层原样复发 |
| C 两份都喂 | 各判一次，不一致则报 | 两次调用；它回答的是"副本漂移"，另一论域（§6） |

**取 A。两轮双审、五侧次独立同意。** 「CI / 干净检出常态未测」的担心**不成立**：

1. **本仓没有 CI 面**（仓库根无 `.github/`），探针臂明写**不进 `npm test``。
   A/B/C 在 CI 下同样不跑——**CI 半句对 A 并不额外成立**。
2. **A 下「未安装」与「生产不可用」同因同果**：生产走同一个
   `readSchemaJson(req.schema_path)`，读不到会降级并记 degradation。
   不存在「探针 null 而生产绿」的反向失真；**反倒是 B 会造出「探针绿、生产读另一份」**。
3. **干净检出有现成通道**：解析链先读 `TRIVIUM_ASSET_ROOT`。

真正的残余只剩**「干净检出 + 未装 + 不设环境变量的 doctor 场景」**。

#### 3.2.1 A 的代价处置：TTL 按成因拆开，**不按字段废新鲜**

r2 稿写「`json_schema_ok === null` 时该段不判新鲜（或强制重探该侧）」，**这条错在两处**：

- **粒度不存在**：新鲜度是**每 CLI 一个 `probed_at`**（现状表第 15 行），没有字段级。
  按字段废新鲜 = 每次 doctor **重跑 claude 全模型段**（读、负对照、写、路径 deny 全套烧配额），
  且会**连坐其余各字段**——它们本轮明明重验过。
- **未安装那一档会死循环**：未安装机器上该字段**永远**是 null，于是
  preflight 永远报过期 ⇒ 要求跑 doctor ⇒ 重探后仍 null ⇒ 永远不新鲜，**且每轮烧配额**。

**定稿：按成因拆三档，删掉「（或）」那个两可。**

| 成因 | 处置 |
| :--- | :--- |
| **资产根未安装** | spawn 前可判的确定事实，每轮 doctor **免 API 复核存在性**即可；**不废整段新鲜**。可见性靠 notes 的指路句 |
| **模型行为类 null**（缺键 / 不可 parse） | **保留 TTL**，可见性交给 §3.7 的 warnings 通道 |
| **撞闸 null**（超时 / 预算） | **不与 TTL 合并**；处置见 §4.2 |

> 「别让它成为每 7 天安静失败一次的格」这句，
> 要连同「**别让它成为每轮 doctor 重复烧钱的格**」一起成立。

#### 3.2.2 资产根怎么进探针

按现状接不通（现状表第 7、8 行）：未导出、`probeClaude` 无入参、`test/` 下无用例引用。
照字面做最省事的结果是在 `probes/` 再拼一份 homedir 字面量＝**第三份事实源**，
并让 `TRIVIUM_ASSET_ROOT` 静默失效。

**改动分两半，两半都要做**：

| 半 | 内容 |
| :--- | :--- |
| **归属** | 把解析规则提成一处并导出，**落 `config.ts`**——`probes/claude.ts:41` 今天就已 import 它，是现成先例、不新开依赖方向。`review.ts` 与 `init.ts` 都改引它。合并**无行为变化**：`override ?? env ?? homedir` 与 `env ?? homedir` 是同一条链 |
| **取值** | 由 **doctor 解析后注入** `probeClaude(opts)`，`opts` 增可选 `assetRoot?: string`，缺省走统一回落链 |

**为什么取值要注入而不是让 `probes/` import 编排层——理由换成两条独立成立的**：

1. **准入脚本经 dist 动态 import `probes/claude.js`**（`claude-admission-control.mjs:93-108`），
   让 probes 依赖编排层会把整条编排链拖进它的 import 图；
2. 避免第三份资产根规则副本。

> **r2 稿在这里引用了一个不存在的红灯**（「`registry-parity.test.ts` 守着分层契约、
> 会当场红」）。实际它只扫 `adapters/ 不得 import probes/` 一个方向
> （`:1091`，扫描目录硬编码 `src/trivium/adapters`），而 `probes/claude.ts:41`
> 今天就已 import `../config.js`。**这一稿不引用它。**
> 若认为 probes → 编排这个方向该守，**补一条真正守它的契约**（见 §5 用例 6），
> 而不是靠记性——AGENTS.md 纪律 12 要的就是这个。

**注入口同时是 §5 用例 1／2 的测试缝。** 用例经**参数注入**临时路径，**不改 `process.env`**
（环境变量是给人用的开发通道，拿它做测试会引入全局状态污染与并发冲突）。

### 3.3 提示词与 `requiredKey` 随契约改

真实契约要求四个顶层键、`additionalProperties: false`。现有提示词「读 X，回答第一行」
在这份契约下**无法构造出合法对象**。

改法：提示词改为对夹具文件做一次**最小审查**并明确允许 `findings` 留空数组
（`review.v1.json:22`）；`requiredKey` 由 `first_line` 改为 **`summary`**
（顶层必填、`type: string` + `minLength: 1`）。

> **判据函数要改什么——r2 稿这句写错了。**

### 3.4 判据：三态，`false` 严格收紧

`false` 是**生产降级扳机**（§2.2），扩大它等于扩大一条会关掉结构化输出的路径。

#### 3.4.1 三态映射

**前置门（任一成立即 `null`，照 `judgeVerboseBinding` 的门序，现状表第 17 行）**：

1. `timedOut`；
2. 拿不到退出码（`typeof exitCode !== 'number'`）；
3. **正对照不成立**——同轮读探针的 `completed !== true`。
   > 这道门 r2 稿只写成了散注、没进判据。配额掐断、CLI 崩溃、外部终止会产出与
   > 干净拒绝**相同的三个条件**，正对照是它们唯一的归因来源；
   > 先例注释写明"负对照那次非零退出**无从归因**，记未测"。

**过门之后：**

| 输入 | 结论 | 理由 |
| :--- | :--- | :--- |
| 非零退出 + **`eventCount === 0`**（整个 stdout 零事件）+ stderr 非空 | **`false`** | CLI 干净拒绝了这份 schema——**唯一**允许落 false 的形态 |
| 非零退出 + `eventCount === 0` + **stderr 也空** | `null` | 两头皆空的静默失败，先例的第四道门 |
| 非零退出但**已吐出事件** | `null` | 「跑到一半才失败，记未测，不猜」 |
| 跑完、未拒绝、**输出不可 `JSON.parse`** | **`null`** + note「跑通但模型未合规，需重测」 | 见 §3.4.3 |
| 跑完、未拒绝、**缺 `requiredKey` 或其非 string** | **`null`** + 同一条 note | 同上 |
| 跑完、`summary` 为 string | `true` | — |

> **r2 稿在这里把先例的信号口径写松了一档**：写的是「零 **result** 事件」，
> 而先例用的是 **`emitted === 0`（`trace.eventCount`，整个输出）**。
> 两者不等价——CLI 吐出 `system/init` 后才断网/OOM/被中断，同样"无 result 事件"
> 且 stderr 有内容，按 r2 的写法会落 `false`、直接关掉生产结构化输出。

#### 3.4.2 判据形态写死：**行为特征，不做文案匹配**

本仓已有定论：`judgeVerboseBinding` 用非零退出 + 零事件 + stderr 有内容（**布尔**），
并写明「不去匹配字串」的理由——**厂商改一句话文案匹配就静默失效，且失效方向是放松**。
本稿沿用，**不**把 `no schema with key or ref` 写进判据。

退出码也不能单独判别：`adapters/claude.ts:919-922` 写着
「错误路径的 result（预算掐断、max_turns）也可能退 0」。

**实现前提**：`execProbe` 透传 `stderr` 与退出码（现状表第 10 行）。

#### 3.4.3 为什么「不可 parse」与「缺键」都落 null

改喂真契约后，这一格**第一次依赖模型配合度**：
