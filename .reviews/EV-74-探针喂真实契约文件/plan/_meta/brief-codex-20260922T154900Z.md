## 2. 问题与危害

### 2.1 准入三步的 `true` 答非所问

M6 探针、M9 第 1 步、第 3 步复验三处都记 `json_schema_ok: true`。这三个 `true`
**都是真的**，但答的是「这个旗标收不收内联 JSON」这个**形态**问题，
不是「它收不收本仓的契约文件」。于是准入全绿而第一次真实审查零 API 调用即拒。

### 2.2 `false` 不是报警值，是**降级扳机**——r1 稿在这里写反了方向

r1 稿写的是「没有任何消费方 ⇒ 一次准入失败完全无声」。**后半句失实**（现状表第 11 行）。
真实链路分两条：

| 层 | 事实 |
| :--- | :--- |
| 拒绝 ⇒ null | CLI 拒绝 ⇒ 零 result 事件 ⇒ `completed === false` ⇒ `judgeJsonSchema` 返回 `null` |
| null 不报警 | 三态纪律里 null 不报警；**doctor 侧确无该字段分支**（现状表第 12 行，这半句 r1 稿是对的） |
| **`false` 改生产行为** | `adapters/claude.ts:810`：`false` ⇒ **本次不传 `--json-schema`**，降级为提示词约定 + 宽松解析并记 degradation；`agy.ts:288` 同形 |

所以准确表述是：**doctor / preflight 无告警面，但适配层有降级消费方。**
不是"完全无声"，是**换了个更差的行为，且只有事后读 degradations 才知道**。

**这个更正反转了 §3.4 的设计方向**：`false` 的成因面要**收紧**而不是扩大——
理由见 §3.4。

### 2.3 两份自造 schema 是同一个病的两个身位

探针与准入脚本各造一份，谁都不是生产送的那份。改一处不改另一处，
准入脚本会继续给出"答非所问的 true"。

## 3. 方案

### 3.1 探针结构化臂改喂真实契约（经适配层同一份变换）

把 `probes/claude.ts:1208` 那段自造 schema 换成 `readSchemaJson(<契约路径>)`。

**为什么必须经它——理由要按臂分述**（r1 CODEX-07）：

- **探针臂**：`probeArgs`（`:164`）原样透传 `opts.jsonSchema`、**不剥头**，
  所以调用点这一次 `stripMetaSchemaRef` 是这条臂**唯一**的剥壳点。绕开它会当场撞回
  第 1 跑的拒绝形态，而按 §2.2 那个形态会记成 `null`——**修复动作本身伪装成"没测到"**。
- **脚本臂**：经 `buildClaudeArgs` 出口已剥一次。改用 `readSchemaJson` 后会剥两次，
  **幂等、无害、不去掉**（`adapters/claude.ts:126-130` 注释明言该出口就是给绕过
  `readSchemaJson` 的调用方兜底）。

### 3.2 喂哪一份副本？——本稿唯一的不可逆决策

| 选项 | 含义 | 代价 |
| :--- | :--- | :--- |
| **A 生产同源** | 走统一解析出口，读 `~/.claude/skills/dual-critic/schema/review.v1.json` | 依赖安装状态（但见下方三条修正） |
| B 仓内副本 | 像 `parse.ts` 那样编译期绑仓内文件 | **探针绿而生产红**——EV-74 在上一层原样复发 |
| C 两份都喂 | 各判一次，不一致则报 | 两次调用；且它回答的是"副本漂移"，是另一论域（§6 已登记） |

**取 A。三侧独立同意。** r1 稿担心的「CI / 干净检出常态未测」**经三侧核查不成立**，
三条理由写进本稿留痕（r1 CODEX-04 ≡ GLM-02）：

1. **本仓没有 CI 面**（仓库根无 `.github/`），且探针臂要真实 CLI + 配额、
   明写**不进 `npm test`**（`claude-admission-control.mjs:9-12`）。这一格从来不是
   「人人机器上都会跑」的格，A/B/C 在 CI 下同样不跑——**CI 半句对 A 并不额外成立**。
2. **A 下「未安装」与「生产不可用」同因同果**：生产走的正是同一个
   `readSchemaJson(req.schema_path)`，读不到会降级并记 degradation
   （`adapters/claude.ts:815-818`）。所以不存在「探针 null 而生产绿」的反向失真；
   **反倒是 B 会造出「探针绿、生产读另一份」**。
3. **干净检出有现成通道**：解析链先读 `TRIVIUM_ASSET_ROOT`，
   所以不安装也能把这一格测起来（`AGENTS.md` 已记载该开发通道）。

真正的残余只剩**「干净检出 + 未装 + 不设环境变量的 doctor 场景」**这一窄条。

**A 的代价要显式处理，三条都不能靠运气**：

- **落 null 且 notes 必须指路**（r1 GLM-02）。r1 稿的文案只写「未安装资产，本格未测」，
  把读者停在问题上。改为写明可用环境变量指向工作树来测这一格——
  **不指路会让"常态未测"的担忧自证**。
- **禁止回落仓内副本**。回落就是偷偷变成 B。
- **TTL 要处置**（r1 CODEX-04 ≡ CODEX-09）：`probe_ttl_days: 7` 按键时间戳判新鲜，
  未安装落 null 后该段会被记成新鲜，**null 最多安静挂 7 天**，而 notes 只有
  主动跑 doctor 的人看得见。落点：`json_schema_ok === null` 时该段**不判新鲜**
  （或强制重探该侧）。

### 3.2.1 资产根怎么进探针（r1 稿缺这一节，三侧独立命中）

r1 稿说「走 `resolveAssetRoot()`」，但**按现状接不通**（现状表第 7、8 行）：
它未导出、`probeClaude` 无入参、全仓无测试 import 过它。
照字面做最省事的结果是在 `probes/` 里再拼一份 homedir 字面量＝**第三份事实源**，
并让 `TRIVIUM_ASSET_ROOT` 这条既有通道静默失效。

**改动分两半，两半都要做**：

| 半 | 内容 | 为什么 |
| :--- | :--- | :--- |
| **归属** | 把解析规则提成**一处低层共用出口**并导出；`review.ts` 与 `init.ts` 都改引它 | 今天有两份同形规则（现状表第 7 行）。合并**无行为变化**：`override ?? env ?? homedir` 与 `env ?? homedir` 是同一条链，后者只是没有 override 参数 |
| **取值** | 由 **doctor 解析后注入** `probeClaude(opts)`，与 `configuredBin` 同型；`opts` 增可选 `assetRoot?: string`，缺省走统一回落链 | **不能让 `probes/` 反向 import 编排层**：会新开 probes → 编排的依赖方向，`registry-parity.test.ts` 守着分层契约、会当场红；准入脚本经 dist 引探针模块时还会把整条编排链拖进 import 图 |

**这个注入口同时就是 §5 用例 1／2 的测试缝**（r1 GLM-05 ≡ CODEX-06）。
用例经**参数注入**临时路径，**不改 `process.env`**——环境变量是给人用的开发通道，
不是测试通道，拿它做测试会引入全局状态污染与并发冲突（r1 AGY-04）。

### 3.3 提示词与 `requiredKey` 随契约改

真实契约要求四个顶层键、`additionalProperties: false`，`findings[]` 每项 9 个必填键。
现有提示词「读 X，回答它的第一行内容」在这份契约下**无法构造出合法对象**。

改法：提示词改为对夹具文件做一次**最小审查**并明确允许 `findings` 留空数组
（契约自身写明「空数组合法」，`review.v1.json:22`）；`requiredKey` 由 `first_line`
改为 **`summary`**（顶层必填、`type: string` + `minLength: 1`，与 `judgeJsonSchema`
现有 `typeof === 'string'` 判据相容，**不必改判据函数**）。

**这一格证到什么、证不到什么（三段式，r1 CODEX-08 ≡ GLM-07）：**

1. **证到**：CLI 接受**剥壳后的**全局资产根契约文件，并按它交付了可解析的结果。
   这比 r1 稿说的强——M9 留痕显示 CLI 会**打回形态不对的交付**，
   所以一次 `true` 同时证明「CLI 的方言接受了这份剥壳件」。
2. **证不到「完全合规」**：`judgeJsonSchema` 只查「能 parse 且某键是 string」，不做 schema 校验。
3. **证不到「全程强制」**，这是 r1 稿漏掉的一头：CLI 按自家方言校验，
   **方言不认的键可能被静默忽略**。契约将来引入这类键时，
   **这一格可以保持绿而强制面已收窄**——症状与第 2 条那个缺口**不同源**。
   2020-12 独有键由 A31 守（**单向黑名单**），draft-07 独有与跨方言语义变化的键
   不在其论域，改契约时人工核。

**「CLI 方言校验」与「本仓 ajv 的 2020-12 校验」不互推**，这句要进设计口径。

### 3.4 判据：三态，且 `false` 要**收紧**

**方向相对 r1 稿反转**。r1 稿想扩大 `false` 让失败可见；查清 §2.2 后，
`false` 是**生产降级的扳机**，扩大它等于扩大一条会关掉结构化输出的路径。

#### 3.4.1 三态映射

| 输入 | 结论 | 理由 |
| :--- | :--- | :--- |
| 非零退出 + 零 result 事件 + stderr 非空 | **`false`** | CLI 干净拒绝了这份 schema——**唯一**允许落 false 的形态 |
| 超时 / 拿不到退出码 / 两头皆空（非零退出但 stderr 也空） | `null` | 没测到。「两头皆空」这一档是 `judgeVerboseBinding` 已有的第四道门：非零退出 + 零事件还有配额掐断、CLI 崩溃、外部终止等成因 |
| 跑完了、CLI 没拒绝、**但输出缺 `requiredKey`** | **`null`** + note「跑通但模型未合规，需重测」 | 见 §3.4.3 |

正对照取**同轮读探针**的 `completed`（免费，同一轮本来就跑）。

#### 3.4.2 判据形态写死：**行为特征，不做文案匹配**（r1 GLM-04）

本仓对同形问题已有定论：`judgeVerboseBinding`（`probes/claude.ts:694-712`）用
**非零退出 + 零事件 + stderr 有内容（布尔）**，并写明「不去匹配字串」的理由——
**厂商改一句话文案匹配就静默失效，且失效方向是放松**（`path_deny` 中文自由文本
反解是前车之鉴）。本稿沿用同一形态，**不**把 `no schema with key or ref` 写进判据。

退出码也不能单独判别：`adapters/claude.ts:919-922` 自己写着
「错误路径的 result（预算掐断、max_turns）也可能退 0」。

**实现前提**：`execProbe` 透传 `stderr` 与退出码（`RunResult` 本就有，只是被丢了，
现状表第 10 行）。

#### 3.4.3 为什么「缺键」落 null 而不是 false

这是本轮双审挖出的最深一条（r1 CODEX-02）。改喂真契约后，这一格**第一次依赖模型配合度**：

- 迷你 schema 时代只需模型回一行文本；真契约时代要求交出含 `schema` const、
  `verdict` 四值枚举的四键对象；
- 探针档位是 **haiku**（现状表第 16 行），而 M9 留痕显示**连生产档位 sonnet
  都调了 5 次 `StructuredOutput`、前 4 次形态不对被 CLI 打回**；
- 若「模型没交出 `summary`」落 `false`，叠加 §2.2 的降级扳机与 §3.2 的 7 天 TTL，
  **一次模型抖动会把 claude 生产的结构化输出关掉一周**。

本仓对这一族早有明文纪律：准入脚本写着
「**凡结论依赖模型行为的格，一律按没测到 ⇒ null 记，判为分叉前必须先重测**」
（`claude-admission-control.mjs:420-428`），`judgeReadonlyBreach` 的三态也是为同一毛病补的。

### 3.5 准入脚本第 ③ 段同改

- 改调同一个 `readSchemaJson`，提示词与 `requiredKey` 与 §3.3 一致；
- **把 `structured.stderr` 与 `structured.exitCode` 一并传给判据函数**（r1 AGY-02）。
  `callOnce` 已经返回 `{raw, stderr, exitCode, timedOut, trace, completed}`，
  而 `:460-462` 只传了三个字段。**不透传就会让脚本臂遇到拒绝形态依然误落 null——
  两个身位再次分叉，而那正是 §2.3 要治的病。**

### 3.6 设计 §3.7 口径改准

结案后改为 §3.3 的三段式，并写进 §3.2 的「未安装落 null + 指路」与 §3.4 的
「`false` 只由 CLI 明确拒绝触发」。

### 3.7 `json_schema_ok` 的可见面：纳入最轻一档

r1 稿把这一节写成「请审查员裁定」，且「不纳入的理由」建立在一个**错误前提**上
（以为加消费方才会改变对外行为）。实际是**对外行为早就被改了**（§2.2），
真正要讨论的是**要不要让人看见**。

**定：`doctor` 输出里把 `false` 显示为告警行，不进 `preflight` 失败面。**

理由以适配层「降级不阻断」的既有口径为锚（r1 GLM-01）：

- 适配层已有优雅降级路径，所以不必把它升成准入硬阻断；
- 而 doctor 告警的边际价值很具体——**在烧掉一次真实审查之前可见**，
  而不是 r1 稿说的「否则完全无声」。

## 4. 先实测、后定稿的一件（r1 稿写成两件、且成本写大了一倍）

### 4.1 拒绝形态的两个数据点 —— **零 API 成本，本地复跑**

r1 稿把这件算成一次烧钱调用，还额外安排了一次「正常但超时」的对照跑。**两处都错**
（r1 CODEX-05 ≡ GLM-03 ≡ AGY-05）：

既有留痕唯一没记的是**退出码数值与 stdout 事件条数**，那才是本次复跑的增量，近乎免费。

> 两件**不能合并**（输入不同：不剥头 vs 剥头 + 新提示词），但「合并省成本」的动机

### 4.2 真实契约下模型能否出合法对象 —— **唯一的有成本件**

喂剥过头的真实契约 + §3.3 的最小审查提示词，看 `result` 能否 parse、
`summary` 是否为 string、`findings` 是否被接受为空数组。

**必录产出（r1 CODEX-09）**：该臂的**单次实测成本与耗时**。
理由是 r1 稿只核算了一次性验证成本，**没核算改完之后的稳态成本**——
这一格每次 doctor TTL 到期都会跑，而 `--max-budget-usd 0.20` 与 180s 超时
是按「读文件回显第一行」定的（M6 基线约 $0.017）。

⇒ 回到本主题要治的静默未测，且被 TTL 记成新鲜。二选一：上调该臂预算/超时，
或接受「撞闸 ⇒ null + note 提示重跑」并与 §3.2 的 TTL 处置合并。
