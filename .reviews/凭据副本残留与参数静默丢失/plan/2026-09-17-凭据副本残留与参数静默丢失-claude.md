# 凭据副本残留与参数静默丢失：三条「跑通了、但结果不是你以为的」

## 0. 这一批为什么放在一起

三条都是同一个形态：**命令退 0，留痕正常，实际发生的事与用户以为的不一样。**
它们和 skill 反复警告的 `--base` / `--critics` 漏传是同一族缺口。

| 编号 | 用户以为 | 实际发生 | 谁在 30 天里承担后果 |
| :-- | :-- | :-- | :-- |
| EV-20 | 审查跑完，凭据只在 `~/.codex` | 明文 bearer token 与 `auth.json` 的副本躺在 `~/.trivium/runs/<run>/codex/codexhome/`，直到 `retention.run_dir_days` 到期；J9 的扫描器从不看那里 | 任何打开运行目录排障的人（2026-09-16 我就是这么把 token 打进终端的） |
| EV-24 | 审批附言进了留痕 | 附言成了位置参数，被 `parseArgs` 收进 `sub[]` 后无人读取；`reason` 仍是 `null` | 事后对账的人 |
| EV-18 | `--topic X` 指定了主题 | 焦点正文里一个裸 `"` 让 `tokenize` 进入引号态，此后所有空白失效，`--topic X` 被粘进同一 token 落进 `rest`，主题回落推断 | 审查跑在错误主题下；报错（若有）指向推断结果而非真因 |

三条的修法互不依赖，放一起是因为它们**共享同一条验收判据**：修完之后，这三种输入要么按用户的本意生效，要么**响亮失败**（退 64、说清原因与正确写法）。不允许第三种结局。

## 1. 来源与证据

- 条目原文：`doc/08_project/BACKLOG.md` 第 112 行（EV-18）、117 行（EV-20）、121 行（EV-24）。
- 代码基线：HEAD `bed986b`，工作树干净。
- 复核方法：三条我都重读了源码定位（下文行号以该 HEAD 为准），没有靠 BACKLOG 的描述转述。
- 与 BACKLOG 描述有出入的两处，先更正：
  1. EV-20 说「`scanSecrets` 只挂在 `archive.ts`」——**实现在 `secrets.ts:132`**，是纯字符串函数；`archive.ts` 是它仅有的三个调用方（`:154` / `:199` / `:218`）。缺口的准确表述是「没有任何调用方把运行目录的文件喂给它」，不是它自身论域写死。
  2. EV-18 说「`--` 之后的内容被拼成一整串再重新分词」——准确落点是 **`cli.ts:68` 的 `argv.slice(i+1).join(' ')`** 先丢掉 argv 边界，再由 `topic-args.ts:143` 的 `tokenize` 重新切。两跳，第一跳才是根因：shell 已经切好的边界被主动扔掉了。

## 2. 三条的具体内容与修法

### 2.1 EV-20 · 凭据副本随运行结束抹除，且运行目录进入扫描面

**现状（`adapters/codex-home.ts:186-247`）**：`prepareCodexHome()` 往 `<run>/codex/codexhome/` 写四类东西——裁剪后的 `config.toml` 与 `<profile>.config.toml`（保留整个 `[model_providers.*]` 段，明文 `experimental_bearer_token` 就在这里）、`~/` 路径指向的目录文件（`models-*.json`，非敏感）、原样拷入的 `auth.json`、以及末尾追加的信任记录。权限 0600 已做。**跑后没有任何消费方读这些副本**：跑后唯一被回读的是 codex 自己写的 `sessions/`（`codex-trace.ts:206`，取生效模型）。

**现状（生命周期）**：`codex.ts:492` 准备副本 → `:504` 拉起 → 四个出口（拉起异常 `:517`、超时 `:527`、无最终回复 `:547`、成功 `:596`），**没有一个出口清理副本**。探活路径 `codex.ts:288-312` 用 mkdtemp 且 `finally` 里删掉——那条路已经做对了，真实审查这条没有。`retention.ts:69` 到期整目录删，粒度只有「整删」一档。重试（`runner.ts:113-150`）会用同一个 `out_dir` 再调一次 `run()`，即再准备一次副本。

**修法：三处挂载 + 一份哨兵 + 一次后验扫描。**

| 层 | 落点 | 做什么 |
| :-- | :-- | :-- |
| 抹除函数 | `adapters/codex-home.ts` 新增 `scrubCodexHome(codexHome)` | 删除凭据载体（D-1 定形态）；随后对 `codexhome/` 下 **`sessions/` 以外**的每个普通文件跑 `scanSecrets`（D-2 定范围），命中即删该文件；写哨兵 `codexhome/scrubbed.json`（时间、删了什么、扫了几个文件、命中几处、失败原因）。**幂等**：哨兵在且 `ok: true` 即跳过 |
| 主挂载 | `adapters/codex.ts` 的 `run()` | 从 `prepareCodexHome` 成功起，把后续全部逻辑包进 `try { … } finally { await scrub }`——覆盖成功、超时、无最终回复、拉起异常四个出口。重试会重新准备副本，不受影响。抹除失败：`warn` + 哨兵记 `ok: false`，**不改变该侧审查结果**（结果已经产出，配额已经烧掉；但失败要看得见、要被下面的清扫重试） |
| 取消路径 | `run-protocol.ts:686` `cancelRun` | 确认工作进程组已死之后，对该运行目录调一次清扫（下一行）。`--cancel` 是 SIGKILL 的唯一入口，`finally` 在这条路上跑不到 |
| 清扫兜底 | `retention.ts` `pruneRunDirs` | 对「终态或 worker 已死」但**尚未到期**的运行目录，逐侧调适配器的抹除；已到期的照旧整删。这条覆盖崩溃、断电、`kill -9` |
| 适配器契约 | `adapters/base.ts` `CriticAdapter` 新增**可选** `scrubRunDir?(runDir): Promise<ScrubOutcome \| null>` | 「哪一侧在运行目录里放了凭据副本」是该侧的知识，不住在 `retention.ts` 里（纪律 10：Agent 差异只在注册表与适配器）。codex 实现它；agy / zcode / 桩不实现 = 「没得抹」，清扫如实跳过 |
| 调用接线 | `hooks.ts:1037` 会话启动钩子 | `pruneRunDirs` 多接一个 `adapters` 入参（`realAdapters()`），人读输出多一行「已抹除 N 个运行目录的凭据副本」 |

**为什么不删整个 `codexhome/`**：`sessions/` 是跑后唯一被回读的东西（生效模型来源），也是排查 codex 超时的依据；`adapters/base.ts:838-842` 「项目外写入不算失守」的论证也建立在 codex 每次都往那里写之上。整删会让这些证据随凭据一起消失。

**为什么不加配置开关**：EV-30 刚查出七个零消费方的配置项。抹除是安全底线，不该有「关掉」的档位；要调试凭据问题去看 `~/.codex` 本体。

### 2.2 EV-24 · 多余位置参数一律退 64，审批附言走 `--reason`

**现状（`cli.ts:58-92`）**：`parseArgs` 把不以 `--` 开头的 token 收进 `positional`，`sub = positional.slice(1)`。全文件只有 `cmdTopic`（`:557`，要求 `sub[0] === 'resolve'`）和 `cmdGate`（`:608`，取 `sub[0]` 作 hook 名）读过 `sub`，**其余九条命令一律不读**，多余的位置参数就此消失。`cmdApproval`（`:963-1023`）的 `--reason` 已经存在（`:1016`）且对通过与拒绝都记录——EV-24 说的「审批附言那是另一个字段」，**字段已经有了**，缺的是「用错了要报错」和「skill 要教对」。

**同族的第二个坑，一并修**：`parseArgs:83` 的「下一个 token 不以 `--` 开头就当值」对布尔旗标同样适用。`approve --reject 理由文字` 会让 `reject` 拿到字符串值，`:972` 的 `=== true` 判假，**拒绝静默变通过**；`--json 附言` 会静默关掉 JSON 模式。`cli.ts` 里以 `=== true` 判定的布尔旗标共 16 个：`allow-single` `await-approval` `check-artifacts` `dry-run` `help` `json` `keep-fixture` `no-model-calls` `quiet` `refresh-auth` `reject` `selftest` `skip-auth-check` `start` `suggest-verify` `version`。

**修法：**

| 落点 | 做什么 |
| :-- | :-- |
| `cli.ts` `parseArgs` | 新增 `BOOLEAN_FLAGS` 常量（上面 16 个）；这些旗标**永不吞下一个 token**，后面的非旗标 token 落回 `positional`——于是被下面的判据接住 |
| `cli.ts` `main()` 分发前 | 新增位置参数上限表：`topic: 1`、`gate: 1`，其余 0。超出即 `usageError`，报错体列出多余的 token 原文，并按命令给写法提示：`approve` / `abandon` → 「审批附言请写 `--reason <文本>`，含空格时整段加引号，它会写进审批记录的 reason 字段」；`topic` → 「原始参数请放在 `--` 之后」；其余 → 附 USAGE |
| `cli.ts` USAGE `:190-191` | `approve` 行补 `[--reason <附言>]`，与拒绝的 `--reason` 区分说明 |
| `cli.ts:749-751` 停点话术 | 「通过」那行补 `[--reason <附言>]`，让用户在停点处就看见附言的正确写法 |
| 对账测试（新） | `test/contract/` 加一条：扫描 `cli.ts` 全部 `flags.get('x') === true` 判据，断言 x ⊆ `BOOLEAN_FLAGS`——防止下次新增布尔旗标时忘记登记，又回到静默吞值 |
| `skills/dual-approve/SKILL.md` | 明写：用户在指令后写的自由文字是审批附言，传 `--reason '<原文>'`，**不要**原样拼进 `$ARGUMENTS`；命令退 64 提示「多余的位置参数」时就是这个原因 |

**为什么放在分发层而不是各命令入口**：十一条命令里只有两条合法地读 `sub`，逐条加判据等于写九遍同一句话，且下一条新命令必然漏。上限表是一处声明，缺省为 0 是 fail-closed。

### 2.3 EV-18 · `topic resolve` 按 argv 逐个读取，不再重新分词

**现状**：`cli.ts:68` 把 `--` 之后的 argv 用空格拼回字符串，`topic-args.ts:143-168` 的 `tokenize` 再按引号与空白重切。`tokenize` 遇到 `"` 或 `'` 无条件进入引号态并丢弃该字符，引号态内所有空白失效，收尾时未闭合的引号态**静默当作已闭合**。于是正文里一个裸引号就把其后的 `--topic X` 粘进同一 token，`splitArguments:89` 把整坨扔进 `rest`，`:353-372` 见 `topic` 为空即回落推断。**`review --start` 不受影响**（`cli.ts:333-384` 直接读 argv）——BACKLOG 记的绕法正是利用这一点。

四条 review skill（`dual-review-plan/code/bug:42-57`、`dual-run:46-47`）教的「给正文补字面双引号」是给 `tokenize` 准备的：字面引号穿过 shell 到达 `tokenize`，被它当成分组符。这套指引对「正文本身含引号」这一族**必然失效**，而且**它本身就在改动 FR-20 承诺逐字送达的文本**——只是 `tokenize` 又把它剥掉了，两个错误恰好抵消。

**修法：删掉第二跳，也就不需要第一跳的补救。**

| 落点 | 做什么 |
| :-- | :-- |
| `cli.ts` `ParsedArgs.trailing` | 类型改为 `string[]`：`--` 之后的 argv **原样保留数组**，不再 `join(' ')` |
| `cli.ts` `cmdTopic` | `rawArgs` 直接取 `args.trailing`；**删除 `--args` 传法**（D-3）——它是「整串再切」的另一个入口，全仓只有 `cli.ts` 自己提到它，skill 与测试零使用；USAGE `:159` 与 `:561-565` 注释同步 |
| `topic-args.ts` `splitArguments` | 入参改为 `string[]`；**删除 `tokenize`**。旗标识别、贪婪取值、白名单外的 `--xxx` 原样进正文，这些语义**一字不改**——变的只是「token 从哪来」：从 shell 来，不再自己猜 |
| `topic-args.ts` 响亮失败（D-4） | 切分完成后，若 `named.topic` 未给、而某个 `rest` token 内部含 `--topic` 旗标字样（`/(^\|\s)--topic(=\|\s\|$)/`），退 64：「检测到 `--topic` 字样但它被包进了同一个 shell 参数里，未被识别为旗标。要指定主题，把 `--topic <主题>` 放在引号之外；若它只是焦点正文的一部分，请同时显式传 `--topic` 以消歧。」——这是 BACKLOG 要求的「给了却没识别就响亮失败」的落点，只针对 `--topic`：它决定审查落在哪个目录，误判代价最高 |
| `topic-args.ts:366-371`、`exit-codes.ts:59-67` | 两处提示文案里「把整段用双引号包起来重传」改为「把整段正文作为**一个** shell 参数传（单引号包住），旗标放在引号之外」 |
| 四条 skill 的第 2 步 | 删掉「补字面双引号」与「为什么 shell 的引号不管用」两块，换成一段：`--` 之后按 shell 参数逐个解析，把用户正文整段放进一个 shell 参数（单引号包住；正文含单引号时改用双引号并转义 `$`、反引号、`\`、`"`），旗标放在引号外；正文里的 `--xxx`、引号、反斜杠原样进入焦点，**不需要也不应该再补字面引号**。示例行 `:48` 改为 `-- '重点核实 --plan-file 透传说明是否准确' --topic X` 的形态 |
| `test/unit/topic-args.test.ts` | 37 个用例的入参由字符串改为数组（**不写按空白切分的 helper**，那等于把 `tokenize` 搬进测试）。`:42`「引号内的空格被保留」改名为「单个 argv token 内的空格原样保留」；`:267-277` 边界契约注释里「靠字面引号保护」改为「靠 shell 引号把正文包成一个参数」——契约本身（argv 里裸露的已知旗标就是真旗标）**不变**，`:280` / `:301` 两条照常绿 |

**为什么不是「修 `tokenize`」（BACKLOG 的方向②）**：修它能解决裸引号，解决不了成对引号恰好包住 `--topic X` 的形态，也解决不了字面引号污染 FR-20 文本。根因是重新分词这件事本身；shell 已经做过一次、做得比我们好。

## 3. 需要你拍板的决策

### D-1 · EV-20 抹除的形态

| 选项 | 行为 | 代价 |
| :-- | :-- | :-- |
| **A · 删除三份凭据载体（推荐）** | `config.toml`、`<profile>.config.toml`、`auth.json` 整份删除；`sessions/`、`models-*.json`、`fakehome/` 保留 | 跑后看不到那次运行用的 `base_url`——但 `trace.json` 的 `isolation` 段已记 `strippedKeys` / `copiedFiles`，`run.json` 记模型与 profile，provider host 由 `doctor` 从本体读；跑后**没有任何代码消费这三份副本**（已 grep 核实） |
| B · 脱敏保留结构 | toml 里 `experimental_bearer_token` / `api_key` 行的值改为 `<redacted>`，`auth.json` 删除 | 要维护一份「哪些键是凭据」的黑名单，漏一个键就是静默残留——这正是 `KEEP_TOP_KEYS` 选白名单而不选黑名单的同一个理由（`codex-home.ts:32-40`）；后验扫描能兜住 `looksReal` 判得出的，兜不住低熵 token |

BACKLOG 写的是「抹掉凭据、保留其余结构」。我读它的本意是保 `sessions/`，不是保 toml 骨架——骨架在跑后没有读者。推荐 A。

### D-2 · 后验扫描的范围

| 选项 | 说明 |
| :-- | :-- |
| **A · `codexhome/` 下 `sessions/` 以外的全部普通文件（推荐）** | 覆盖 `models-*.json` 副本、`fakehome/` 里 codex 可能写的缓存、以及任何本轮没想到的东西；命中即删。`sessions/` 排除：它是 codex 的会话记录，含送审包全文，`looksReal` 对被审代码里的测试夹具密钥有误报可能，删了就丢排障证据 |
| B · 连 `sessions/` 一起扫，命中行就地脱敏 | 覆盖「模型在沙箱里读了自己的 config 并把 token 写进会话」这一威胁。要改 JSONL 的行内内容，实现面与误报面都大一圈 |

推荐 A，并把 B 对应的威胁**登记为新条目 EV-32**（模型自读凭据进会话记录），本轮不做。

### D-3 · 删除 `topic resolve --args`

`--args <值>` 与 `--args=<值>` 是 `cli.ts:563` 注释里承认「有歧义」的传法，skill 从 v1.2.3 起改用 `--` 终止符，全仓无其他调用。保留它就得保留一个字符串切分器。推荐**删除**，USAGE 与 PROTOCOL 同步；如果你知道有外部脚本在用它，改为 B：保留但走「不再分词、整串即正文」的语义并在 USAGE 标注废弃。

### D-4 · `--topic` 字样被包进正文时：退 64 还是只提示

推荐**退 64**（理由见 2.3 表）。代价：焦点正文谈论 `--topic` 且用户没显式给主题时会被拦一次，出口是显式传 `--topic`。若你觉得代价大，改为 B：只在 `notes` 里提示，`topic_inferred` 照旧为 true——但那就回到「靠 Driver 回显、靠用户看见」的老路，BACKLOG 明确要求的是响亮失败。
