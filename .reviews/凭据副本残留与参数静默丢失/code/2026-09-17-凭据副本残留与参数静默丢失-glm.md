### GLM-01 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/adapters/zcode.ts:435（配合 src/trivium/scrub.ts:60 的 ORCHESTRATOR_LOG_FILES）` |
| 类别 | security ｜ 层次 code |
| 置信度 | high |

**问题**：zcode 适配器把模型 I/O 原文（rollout：完整请求/响应与工具结果，含送审包全文）逐字拷贝到 `<侧>/out/rollout.jsonl`。抹除的三层都够不到它：载体删除与后验扫描只作用于 home/ 与 codexhome/，就地脱敏只认 stdout.jsonl / stdout.json / trace.json 三份。于是同一份内容出现两种命运——home/.zcode/cli/rollout/model-io-*.jsonl 的原件命中密钥形态即删，out/ 里的副本既不删也不脱敏，随运行目录保留 30 天。若模型 I/O 中出现过凭据（审查员读了含真实密钥的上下文文件、或经 Grep 之类的绕过通道读到自己的配置副本——探针记录里白纸黑字写过该通道），这份副本就是漏网通道。scrub.ts 文件头给「out/ 其余不碰」的理由是「审查结果，归档时已过 assertNoSecrets」，对 rollout.jsonl 不成立：它不进归档、只活在运行目录。跑后没有任何代码回读它，脱敏不破坏任何功能。

**依据**：src/trivium/adapters/zcode.ts:427-435（读 home 下 rollout 后 copyFile 进 req.out_dir/rollout.jsonl）；src/trivium/scrub.ts:60（清单只有三份）、:160-181（redactLogs 只遍历清单）、:33（「out/ 其余不碰」的归档侧理由）；grep 全部适配器确认只有 zcode 往 out/ 写第四份原始日志（agy.ts:274-275、codex.ts:496-497 只写 stdout+trace）；test/unit/credential-scrub.test.ts 明确断言「out/ 里只脱敏三份日志」，即该缺口被当成交付物锁住了。

**建议**：把 rollout.jsonl 并进 ORCHESTRATOR_LOG_FILES（就地脱敏、保 JSON 结构，与 stdout 同款）；并考虑按 v1.3.14 对 run-files 的教训把这份清单从适配器的 out_dir 写入点派生或加反向对账用例——手抄清单已经漏了第一份，这正是本项目记过的「手抄白名单第三次同形」。

### GLM-03 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/adapters/zcode.ts:179（scanAndRemoveSecrets(homeDir) 无 exclude）` |
| 类别 | correctness ｜ 层次 code |
| 置信度 | medium |

**问题**：codex 侧把 sessions/ 排除在「命中即删」外的两条理由——含送审包全文、对被审代码里的测试夹具密钥有误报面、删了丢排障证据——逐条适用于 zcode 的 home/，但 zcode 的扫描没有任何豁免。实测（本次运行 glm 侧沙箱 HOME 的目录树）：home/.zcode/cli/ 下躺着 rollout/model-io-sess_*.jsonl（模型 I/O 全文）、log/zcode-*.jsonl、db/db.sqlite(-wal/-shm) 与整棵 plugins/cache（含 node_modules 数千文件）。这些文件过同一套规则，而 anthropic-key、jwt、slack-token 等规则没有 confirm 熵闸：被审项目的测试夹具里若有一个字面量假密钥（本仓库自己都要靠运行时拼接来规避），它随模型 I/O 进 rollout/log 后即命中 → 原始排障证据被删。rollout 正是 zcode 侧工具参数与生效模型的回读来源（zcode.ts 文件头自述），事后复算（EV-26 式）靠它。同一次运行里同一份内容的 out/ 副本却被刻意保留（GLM-01），系统对同一内容同时执行「删」与「留」两种策略。附带代价：每次尝试的 finally 都全量扫 plugins/node_modules 数千个小文件。

**依据**：本次运行 glm/home 的 Glob 列表实证 rollout/log/db/plugins 实存；src/trivium/adapters/zcode.ts:179（无 exclude 调 scanAndRemoveSecrets）；被审补丁中 codex-home.ts 的 KEEP_AFTER_RUN=['sessions'] 与 src/trivium/scrub.ts:95-96 的豁免理由自述；src/trivium/secrets.ts:71-99（anthropic-key/jwt 等规则无 confirm，删除面不设熵闸）。

**建议**：与 EV-32 对称处理：对 home/.zcode/cli 的 rollout/ 与 log/ 改走就地脱敏（跑后无回读方，脱敏不破坏功能；db 二进制直接跳过），或把 zcode 侧的误报面登记为新 EV；plugins/cache 可直接排除——编排器与事后排障都不需要它，还能省掉每次尝试的数千文件扫描。
