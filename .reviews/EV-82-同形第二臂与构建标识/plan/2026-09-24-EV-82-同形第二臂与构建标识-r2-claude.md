## 2. 改动一：构建标识（**r2 重写**：CODEX-01、CODEX-07、CODEX-08、AGY-01、AGY-05、GLM-03）

**目的**：让「安装副本就是当前工作树构建的」有机器证据，T2 假阴性时先核它。

**作用面**：「影响安装产物内容的路径集」= `src/`、`scripts/`、`skills/`、`package.json`、`package-lock.json`、`tsconfig.json`。
`test/`、`doc/` 不进安装产物，故排除；生成物 `skills/dual-critic/scripts/trivium.cjs` 已被 `.gitignore` 覆盖，不引入噪声。

**写入**（`scripts/build.mjs`，主包构建时经 esbuild `define` 注入一个常量）：

| 字段 | 取法 |
| :--- | :--- |
| `repo_root_commit` | `git rev-list --max-parents=0 HEAD`，多根时取字典序第一个。作**仓库身份**用 |
| `git_head` | `git rev-parse HEAD` |
| `dirty` | `git status --porcelain -- <作用面>` 非空 |
| `inputs_sha256` | 对 `workTreeHash` 得到的 tree，逐个取 `<tree>:<作用面路径>` 的对象 id（不存在记 `absent`），按路径排序拼接后取 sha256 |
| `built_at` | ISO 时间 |

取不到 git（例如 M10b r5 §7.3.2.1 用 `git archive` 导出的基线树）时整个常量注入 `null`，**不报错**。测试构建（`--tests-only`）注入固定测试值。

**读出**：`meta.ts` 组装 `snapshot` 时加可选字段 `build`（上表或 `null`）。`run.v2.json` 的 `snapshot` 增可选属性 `build`，不进 required。

**比对**（`review.ts` 收尾段，注入点在 `writeRunMeta` **之前**，与「本轮原稿不在保护集」那条同位，AGY-05）：

- **本仓模式判定**：被审项目的根提交哈希 = `build.repo_root_commit` ⇒ 被审项目就是编排器本仓。
- **非本仓模式**：`snapshot.build` 只作**自述指纹**记录，**不比、不告警**（CODEX-01：外部项目里 HEAD 恒不等，告警会常亮）。
- **本仓模式**下四条文案各自独立：

  | 条件 | 文案 |
  | :--- | :--- |
  | `build === null` | 构建标识缺失（取不到 git 的构建） |
  | `build.dirty === true` | 构建时工作树有未提交改动 |
  | 收尾时用同一作用面**重算**的 `inputs_sha256` ≠ `build.inputs_sha256`（CODEX-08） | 安装副本不是当前工作树构建的 |
  | `build.git_head ≠ snapshot.git_head` | 安装副本与仓库 HEAD 不同版 |

  `build === null` 那条在非本仓模式下也不出（无从判定是否本仓）。

- 告警进 `meta.gate.warnings` 并打到收尾 stderr；**只告警、不阻断、不改 `evidence_ok`**。
- **doctor**：显示当前编排器的构建标识一行，并注明本仓模式是否成立。

**对上位 r5 的影响**（CODEX-01）：r5 §3.3.2 与 §11 的 T2 断言「安装副本构建标识 = `snapshot.git_head` 且非 dirty」只在本仓模式下有意义。
T2 本来就在本仓做，判据成立；但措辞要限定为「本仓模式下」。按 r5 §14「事实断言被推翻」的口径，在 EV-82 小主题收口报告里追加更正，**不回改 r5**。

> **不做**：不校验安装副本内容（M10b r5 §6.2 登记的内容层边界，不在这里补）。

## 3. 改动二：同形第二臂（EV-94 ②；r5 §3.3.3 T1 ②(a) 的实现）（**r2 重写**）

**目的**：在**配置读取层**，用与审查臂**同形**的副本再判一次；与白名单臂并排比较，区分副本形态差异（H2）与「配置层之后」的回落。

### 3.1 `prepareZcodeHome` 增一个可选参数（AGY-03）

`prepareZcodeHome(runDir, model, { srcConfig?, transformCopy? })`：`transformCopy(cfg)` 在 `writeFile` **之前**作用于副本对象。
**不传时行为与今天逐字相同**（审查臂不传），用例锁住「不传即与今天同一份输出」。
这样凭据在写盘前就被替换，没有「先写真实凭据、再覆写」的窗口。

### 3.2 新函数 `probeModelOverrideFullCopy(entry, node, cwd, { cliConfigPath?, model?, timeoutMs?, readonlyArgs? })`

1. **门控**：与白名单臂同一门控（副本源在场才介入）。
2. **请求模型**（CODEX-10）：参数 `model` 缺省取 `pickNonFirstModel`（与白名单臂同口径，非首位）；可显式传入，诊断实验传 `GLM-5.3-Flash`。
3. **造副本**：`makeTempDir` 建临时根（清理只认这个返回值，R1），调 `prepareZcodeHome(<临时根>, <请求模型>, { srcConfig: cliConfigPath, transformCopy: <凭据替换> })`。
   **与审查臂同一个构造函数**，不另写准备逻辑。
4. **早退**（CODEX-02）：`prep.homeDir === null` 或 `prep.route !== 'config_copy'` ⇒ **不拉起**，返回 `override: null` 与 why。
   绝不以真实 HOME 拉起。
5. **凭据替换规则**（CODEX-04、CODEX-05、GLM-05）：对**整份副本递归遍历**（含嵌套对象与数组，不限于 `options`），满足下列任一条的字符串值换成哨兵常量：
   - 键名匹配凭据形态（`apiKey`、`token`、`secret`、`password`、`authorization`、`cookie` 等，大小写不敏感，按子串匹配）；
   - 位于任一 `headers` 对象之下；
   - **形态兜底**：`redactSecrets(value).count > 0`，不论键名。

   其余值**原样保留**，所有键**一律保留**（顶层与 provider 白名单外的键正是 H2 的嫌疑面，动了就测不到）。
   替换了哪些**键路径**（只记路径，不记值）进 notes 与报告。哨兵沿用计算属性键写法，避开 `fixture-credentials` 扫描器。
6. **环境**（GLM-04）：`zcodeProviderEnv(entry, …, { omitPersonal: true })` + 清 `ZCODE_CREDENTIAL_ENV_KEYS` + `HOME` 指向副本 HOME；带只读参数。
   即**与白名单探针臂同形**。与审查臂的已知偏差：审查臂不清那两个凭据键。为此对这两个键加宿主预置检测（照 `PROVIDER_CONFIG` 变量检测的先例），预置时进 notes，判读表各格列为备择成因。
7. **判定**（GLM-07）：从 `probeModelOverride` 抽出一个纯函数，只返回**三态判据与观测值**（`override` / `observed`），两臂都调它（用例断言是同一引用）；**成因文案由各臂自带**。
   同形臂 `global` 的文案并列「键形态差异（H2）」与「凭据替换破坏导入」两种成因。
8. **清理**：`finally` 里 `fs.rm(<临时根>, { recursive: true, force: true })`；不调 `scrubZcodeHome`（R2）。

### 3.3 凭据面（GLM-05）

键名判据加形态兜底仍是**黑名单**性质，漏判的凭据会原样进副本。
缓解措施：`makeTempDir`（0700）、副本 0600、写盘前替换、一次拉起、`finally` 整删。残余面是 SIGKILL 先于 `finally`。
这与审查臂整份拷贝的残余面同形，**是缓解，不是消除**。

### 3.4 机读落盘与展示（AGY-04、CODEX-06）

- `ProbeSection` 的 zcode 段增 `model_override_full_copy`，**只存三态枚举**，与 `model_override` 同构；requested / observed / why / 替换键路径一律进 notes。
- 沿用「**null 不覆盖**上一轮结论」。
- **运行期消费方**：doctor 的两臂不一致告警（EV-94 ② 触发器），**只在两臂都是本轮产出且都非 null 时**触发；「本轮是否产出」记在 notes。
- doctor 两臂并排一格，写明「本臂只判配置读取层」。

## 4. 实验与判读（**r2 重写**：CODEX-03、CODEX-10、CODEX-11、AGY-02、GLM-01、GLM-02、GLM-06）

改动合入后 `npm run build` 与 `npm run install:local`（各单独一条），跑一次 `.trivium/bin/trivium doctor`（刷新两臂），

**配额前提**（CODEX-11）：「零配额」成立的前提是副本里凭据全被换成哨兵、provider 不是免密端点。本机副本源唯一 provider `bigmodel-coding-plan` 需要密钥。
最坏成本：每次 doctor 多一次 headless 拉起，超时上限与兄弟臂同为 30s，超时记 null、不重试。

**判读前提**：
1. **请求值一致**（CODEX-10）：白名单臂请求值、同形臂请求值、诊断实跑请求值（`GLM-5.3-Flash`）三者并排登记。不相等时，各格结论降级为「在臂请求的那个模型上成立」。

3. **环境**：09-22 入口文件替换，环境漂移不可排除（诊断 r3 §2），各格结论照加注。

**判定次序**（AGY-02）：先判任一臂为 null（未判定），再按两臂三态组合查表。

| 白名单臂 | 同形臂 | 读出什么 | 下一步 |

  - 流程：用可控的假入口脚本（按参数在副本 HOME 下写出或不写 `v2/provider_config.json`）覆盖 `config_copy` / `global` / 超时 / 未识别四种停止形态（AGY-06）；

- **隔离腿取证函数**：只读键名；合成个人配置里含凭据值时，函数输出不含任何值（断言）。
