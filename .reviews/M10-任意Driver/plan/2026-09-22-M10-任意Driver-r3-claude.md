## 3. 第 2 步：EV-72 主题级 Driver 落盘（schema 变更）

### 3.1 问题

plan / bug 原稿在 `review --start` 之前由 Driver 写出，那一刻该阶段零留痕，`resolveRoundDriver`
回落缺省 Driver，非缺省 Driver 的 `-<id>.md` 原稿被判伪造件退 2。EV-68 刻意接受该边界。

### 3.2 方案（**r3 全节重写**）

> **r2 的错误**（CODEX-02 / AGY-02）：r2 把交叉校验限定在「零留痕窗口」以保住演进设计 647 行的
> 「跨阶段换 Driver 允许」，但 **code 阶段初态必然是该阶段零留痕**——窗口限定不但没放开跨阶段换 Driver，
> 反而**精确覆盖了它发生的那一刻**。且 claim 的「已存在且不同 ⇒ 退 64」与 `resolveRoundDriver`
> 第 2 级按**主题**取值这两处 r2 完全没动，死锁只是从缺省 Driver 场景挪到了跨阶段场景。
> **本稿采纳 CODEX-02 的选项 ②：主题级 driver 改为按阶段记录，第 2 级按阶段取值。**

#### 3.2.1 落盘形态：按阶段，不按主题

`TaskMeta` **additive** 加可选字段：

```
drivers?: { [stage: 'plan'|'code'|'bug']: { driver: AgentId; claimed_at: string; claimed_by: string } }
```

- **不是**主题级单值。理由：它要与 `resolveRoundDriver` 第 1 级「该**阶段**最新 `run.json.driver`」同构；
  主题级单值与第 1 级的论域不一致，正是 r2 死锁的根源。
- schema 仍 `trivium.task.v1`：既有文件缺该字段 = 「未声明」，与 `run.v2.driver_enabled` 的
  「缺失即无从得知」同构。

#### 3.2.2 `topic claim` 子命令

`trivium topic claim --topic <主题> --stage <阶段> --driver <id> [--json]`：

- 由**编排器**创建 `task.json`（不存在则 `emptyTask`），写入 `drivers[<阶段>]`。
- **该阶段**已声明且 driver 相同 ⇒ 幂等退 0；**该阶段**已声明且不同 ⇒ 退 64
  （提示「该阶段已由 <X> 认领；换 Driver 请新开主题，或在**新阶段**认领」）。
- **别的阶段**声明了别的 driver ⇒ **正常放行**（这正是跨阶段换 Driver 的合法形态）。
- **`--stage` 必填**：不默认，避免「认领了哪一道」含糊。
- **不提供覆盖旗标**：同阶段覆盖会让该字段成为第二个「沿用前一条的值」的槽位（EV-68 否掉
  `GateEntry.driver` 的理由逐字适用）。**该结论在按阶段拆分后仍成立**，且不再锁死合法场景。

#### 3.2.3 三级判定与交叉校验

`resolveRoundDriver` 改三级：
1. **该阶段**最新 `run.json.driver`（现有行为不动，留痕损坏仍硬失败）；
2. **`task.json.drivers[<该阶段>].driver`**（按阶段，不按主题）；
3. `DEFAULT_DRIVER`。拦截文案分别注明来源。

**交叉校验**：`topic resolve` 与 `review --start` 校验 `--driver` 与**同阶段**的声明／留痕是否一致——
- 该阶段有留痕 ⇒ 与**最新留痕**比对，不符则报错且**指向留痕**；
- 该阶段零留痕但有声明 ⇒ 与声明比对；
- 该阶段零留痕且无声明 ⇒ 不校验（首次认领的正常入口）。

`topic resolve` **保持纯只读**（USAGE 明写「不创建任何目录」，不改这条承诺）。

#### 3.2.4 自声明边界与第二事实源

- **自声明**（r1 CODEX-03）：claim 之后，「当轮 Driver」第一次由**被保护方自己声明**，
  而它直接决定 Write/Edit 侧的保护集（全集减当轮 Driver）。本仓先例是
  `ApprovalRecord.session_id`（`meta.ts:43-57`：「谁解的闸是整条链子上最该留痕的事件」）。
  故 `drivers[<阶段>]` 必带 **`claimed_by`**（session 来源），在 `--json` 与预检输出可见。
  计划显式写明：**它是 Driver 自声明，权威等级低于 run 留痕**。
- **第二事实源**（r1 CODEX-04）：`drivers[<阶段>]` 与 `runs[].driver` 是两份取值。
  **不变量**：`runs[].driver` 由编排器在 `review --start` 追加、是**留痕**；
  `drivers[<阶段>]` 由 claim 写入、是**声明**。二者不一致时**以同阶段 `runs[]` 最新一条为准**
  并在 `preflight` 提示（不报错——跨阶段换 Driver 合法）。
  `run-files-parity` / `registry-parity` 增这两个键关系的盯防点。

#### 3.2.5 入口资产接线

入口资产（第 5 步渲染）在「解析主题」步之后、写原稿之前插一步
`TV topic claim --stage <本阶段> --driver <自家 id>`；claude 载体也加——
它是缺省 Driver，claim 的效果只是留痕，行为不变（J3）。

### 3.3 测试

  - **沙箱安装**（每步前置）：注入临时 home，四目标逐一覆盖，不碰开发者真实的 `~/.codex` / `~/.zcode` / `~/.gemini`；
  - **开发机真实安装**（`npm run install:local`）：只在需要用 wrapper 验证全局副本时做，**不是每步前置**。
- **多目标验证要真跑一台「只有另一家」的机器形态**（D9），确认运行时根仍被装上。
- 变异验证：第 2 步（第 2 级退回按主题取值 / 整个忽略）、第 3 步（去掉任一条判据 / 去掉 4.1.1 的登记）、
  第 4 步（approve 跳过复核 / 跳过 sha256 抽核 / `if (runId)` 写法）各至少一条红，记入应答件。
- `trivium doctor --selftest` 全绿（缺省 Driver 路径不退化）。
- 第 7 步报告含每轮命令、退出码、留痕路径与 sha256。
- **变异验证前先确认 `dist/test` 真被重编**（`node scripts/build.mjs --tests-only`；`npm run build` 不含测试树）——
  EV-82 r3 前两轮变异循环因此空跑过。
