## 7. 量级与风险

### 7.1 双审轮次

**计数论域**：代码双审轮次，**含**本计划自身已耗与后续。按 r5 codex 实测口径
（本仓 26 个主题 / 66 轮 code 双审，均值 **2.5**、中位 **2**，M8 那主题 12 轮）估：

| 环节 | 轮次 |
| :--- | :--- |
| 本计划自身（plan 档，已耗 r1～r5 共 **5 轮**；r6 起算 **1～2 轮**） | 6～7 |
| 第 1 步 EV-72 | 2～3 |
| 第 2 步 EV-55（**安全关键面，最易超一轮**） | 2～3 |
| 第 3 步 翻开关 + approve 复核 | 2～3 |
| 第 4 步 登记清理 | 1～2 |
| 前置小主题 EV-74 / EV-79（EV-79 状态是「todo · **待双审**」，修法本身还要过双审） | 2～3 |
| **合计** | **15～21 轮** |

> 「各步一轮」是**无先例支撑的乐观假设**——主设计 M9 行自证单步多轮是常态
> （第 5 步三轮代码双审 + 接线判据重写五版；第 6 步前置 EV-68 又是一轮独立计划双审）。
> 本表按 2～2.5 轮/步给区间，不再假设一轮。

**墙钟**：每轮不止子进程时长。r3 实测总耗时 2571s、三侧自身合计 1479s ⇒ 约 **1100s 收尾开销**；
r4 那轮 codex 更是脚本级超时 25m0s 导致**整轮作废重跑**。按每轮 30～45 分钟墙钟 + Driver 修订与
人工审批的人在环，**M10a 量级为 2～3 周**。

### 7.2 触发口径（可执行）

- **每轮双审收尾时**核对累计轮次与累计墙钟，写进 §8。
- **阈值**：累计轮次 > **28 轮**（合计上限 21 的 1.33 倍），或累计墙钟 > **4 周**
  ⇒ 按纪律 1 回补估算并向用户报告。

  > 正常进度就会触发，「超阈值就报告」会被训练成噪声——这个失效机制
  > 本仓在别处说过（「提示会常态化到无人再看」）。

  （run_id、轮次、墙钟日），**起点写死为本稿落笔日（`9d9cf94` 之后）**。

### 7.3 风险

- **R-a 安全关键面重写的退化风险**：第 2 步把判据从「位置 ∧ 后缀正则」重写为「位置 ∧ 两个排除项」，
  **两个排除项都必须配正例 + 变异**（§3.3）。r4 给 `changes.diff` 配了、给 `running` 没配——
  **同一个动作只做一半**正是这类重写最易无声丢失的形态。
- **R-c 误拦面扩大**：六种形态见 §3.2.1，出口已判据式写进三处（§3.2.2）。
  **如实登记**：提交锚只挂 Claude Bash matcher，终端直接提交完全绕过——强制力单向，
  不假装它是机械边界。
- **R-e L2 Driver 的残余风险**：闸门期可改业务文件，事后暴露。
  本稿把「审批前裁决完整 + 工件哈希一致」守死（§4.3 / §4.4）。
  **并补**：L2 Driver 可自写裁决件再自跑 `approve`，复核只保「裁决齐备」不保「审批来自人」——
  `approval.ts:16-33` 已有诚实表述，§6.2 的 RUNBOOK 行搬运它。
- **R-i 联合校验在解析回退时不生效，且它是波动的**：r1 两侧回退 ⇒ 失效；r2 两侧结构化 ⇒ 生效；
  r3 再次失效（而那轮有两个 blocker）；r5 gemini + glm 结构化 ⇒ 生效。
  **不能指望它自然解除。** M10a 还要跑 15～21 轮双审，闸门在已知会波动的能力面上运行。
  **处置**：把解析回退的**诊断**（定位根因、评估可修复性，非修复本身）安排进第 1 步的双审后
  顺带采集一次形态，给「是否里程碑内修复」一个数据依据；**修复本身不在 M10a 范围内**。
- **R-j 3.1.1 的登记会改变 claude 侧 `artifacts[]` 内容**（**仅 plan / bug 轮**）。
  M10a 不含兼容验收（J3 在 M10b），但**该变化要在 §6.2 的 README 行登记**，
  并**移交 M10b 作为 J3 白名单的一项**：`path` = 该轮被审原稿的归档相对路径
  （取自 `input.subjectPath`）、`sha256` = 冻结时的 `subject_sha256`、
  **条目位置 = `metaArtifacts` 末尾（brief 之后）**；**code 轮无此新增条目**。

## 5. 审查要点与你这一侧的镜头

被审对象是一份**还没实施的计划**。这决定了审查的重心与代码审完全不同：
