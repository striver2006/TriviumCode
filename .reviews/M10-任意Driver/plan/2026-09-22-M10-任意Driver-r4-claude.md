## 3. 第 2 步：EV-72 按阶段 Driver 落盘（schema 变更）

### 3.1 问题

plan / bug 原稿在 `review --start` 之前由 Driver 写出，那一刻该阶段零留痕，`resolveRoundDriver`
回落缺省 Driver，非缺省 Driver 的 `-<id>.md` 原稿被判伪造件退 2。

### 3.2 方案

#### 3.2.1 落盘形态：按阶段，不按主题

`TaskMeta` **additive** 加可选字段：

```
drivers?: { [stage: 'plan'|'code'|'bug']: { driver: AgentId; claimed_at: string; claimed_by: string } }
```

**不是**主题级单值——它要与 `resolveRoundDriver` 第 1 级「该**阶段**最新 `run.json.driver`」同构；
主题级单值会精确覆盖跨阶段换 Driver 发生的那一刻（r2 CODEX-02 / AGY-02）。
schema 仍 `trivium.task.v1`：缺该字段 = 「未声明」。

#### 3.2.2 `topic claim` 子命令

`trivium topic claim --topic <主题> --stage <阶段> --driver <id> [--json]`，**四个分支**：

| # | 条件 | 行为 |
| :--- | :--- | :--- |
| 1 | 该阶段已声明且 driver **相同** | 幂等退 0 |
| 2 | 该阶段已声明且 driver **不同** | 退 64（「该阶段已由 <X> 认领；换 Driver 请新开主题，或在**新阶段**认领」） |
| 3 | **该阶段已有 run 留痕且与 `--driver` 不同** | **退 64 并指向留痕**（r3 新增，见下） |
| 4 | 别的阶段声明／留痕了别的 driver | **正常放行**——这正是跨阶段换 Driver 的合法形态 |

> **r3 修正（AGY-02 / CODEX-03 / GLM-04，三侧命中）**：r3 只有分支 1/2/4，
> **不核该阶段已有的 run 留痕**。codex 给出的死锁序列：不带 claim 的 `review --start`
> 落了 code 阶段留痕（CLI 手工路径、第 5 步之前的过渡形态）⇒ 之后 `claim --stage code --driver <别家>`
> 因无既有声明而**成功** ⇒「声明 ≠ 留痕」死锁：新 Driver 被 §3.2.3 拒绝，原 Driver 被声明方向卡住，
> 而无覆盖旗标、`task.json` 对 Write/Edit 独占（`hooks.ts:477-481`），
> **用户唯一出路是绕过护栏手改文件**。分支 3 与 §3.2.3 的交叉校验同向、fail fast。

- **`--stage` 必填**：不默认，避免「认领了哪一道」含糊。
- **不提供覆盖旗标**：同阶段覆盖会让该字段成为第二个「沿用前一条的值」的槽位（EV-68 的理由）。
  该结论在按阶段拆分后**仍成立**，且不再锁死合法场景。

#### 3.2.3 三级判定与交叉校验

`resolveRoundDriver` 改三级：
1. **该阶段**最新 `run.json.driver`（现有行为不动，留痕损坏仍硬失败）；
2. **`task.json.drivers[<该阶段>].driver`**；
3. `DEFAULT_DRIVER`。拦截文案分别注明来源。

**交叉校验**（`topic resolve` 与 `review --start`）：
- 该阶段有留痕 ⇒ 与**最新留痕**比对，不符则报错且**指向留痕**；
- 该阶段零留痕但有声明 ⇒ 与声明比对；
- 该阶段零留痕且无声明 ⇒ 不校验（首次认领的正常入口）。

`topic resolve` **保持纯只读**（USAGE 明写「不创建任何目录」）。

#### 3.2.4 自声明边界与两份取值的不变量

- **自声明**：claim 之后「当轮 Driver」第一次由**被保护方自己声明**，而它直接决定 Write/Edit 侧的保护集。
  先例是 `ApprovalRecord.session_id`（`meta.ts:43-57`）。故必带 **`claimed_by`**，在 `--json` 与预检可见。
  **它是 Driver 自声明，权威等级低于 run 留痕。**
- **不变量**：`runs[].driver` 是**留痕**，`drivers[<阶段>]` 是**声明**。
  **同阶段二者不一致没有合法来源**（只可能来自手改或历史遗留）⇒ **预检报错**，指向留痕。

  > **r3 修正（CODEX-03）**：r3 写的是「不一致时以留痕为准并在 preflight **提示**（不报错——
  > 跨阶段换 Driver 合法）」。那句括号理由是从 r2 的**主题级**方案原样搬来的，
  > **按阶段拆分后就失效了**：`drivers[stage]` 与 `runs[stage]` 的不一致根本不可能是跨阶段造成的。
  > glm 另指出「不变量自己制造了自己要永远提示的状态，preflight 提示会常态化到无人再看」——
  > 故改为**报错**，并由分支 3 从入口堵住主要成因。
- `run-files-parity` / `registry-parity` 增这两个键关系的盯防点。

#### 3.2.5 入口资产接线

入口资产（第 5 步渲染）在「解析主题」步之后、写原稿之前插一步
`TV topic claim --stage <本阶段> --driver <自家 id>`；claude 载体也加——行为不变（J3）。
