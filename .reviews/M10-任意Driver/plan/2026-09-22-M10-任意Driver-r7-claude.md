## 2. 第 1 步：EV-72 按阶段 Driver 落盘

### 2.1 问题

plan / bug 原稿在 `review --start` 之前由 Driver 写出，那一刻该阶段零留痕，`resolveRoundDriver`
回落缺省 Driver，非缺省 Driver 的 `-<id>.md` 原稿被判伪造件退 2。

### 2.2 落盘形态：按阶段，且声明史追加不覆盖

`TaskMeta` **additive** 加可选字段：

```
drivers?: {
  [stage: 'plan'|'code'|'bug']: {
    driver: AgentId;
    claimed_at: string;
    claimed_by: string;
    history?: { driver: AgentId; claimed_at: string; claimed_by: string; revoked_at: string }[];
  }
}
```

**不是主题级单值**——它要与 `resolveRoundDriver` 第 1 级「该**阶段**最新 `run.json.driver`」同构；
主题级单值会精确覆盖跨阶段换 Driver 发生的那一刻（r2 双审两侧命中）。
schema 仍 `trivium.task.v1`：缺该字段 = 「未声明」。

> **`history[]` 是 r6 修正（GLM-04）**：`drivers[<阶段>]` 是单值、改写即覆盖，
> 而 r6 的分支 3 只写「留日志」未指载体——若日志只是命令行输出，**撤回史不落任何持久面**。
> 而 `claimed_by` 正是 §2.4 自声明边界的控制点，其先例 `ApprovalRecord.session_id`
> （`meta.ts:43-57`）的要义恰恰是把「谁干的」持久写进 `task.json`；
> `approvals` / `degradations` / `disputes` 三个数组均为**追加式**，本仓对「历史不覆盖」有一贯做法。
> **撤回是本稿唯一允许改写既有声明的口子，它的审计面不该最弱。**

### 2.3 `topic claim` 子命令

`trivium topic claim --topic <主题> --stage <阶段> --driver <id> [--json]`

> **判定顺序：自上而下，首个命中的分支生效。**（r5 GLM-08）

| # | 条件 | 行为 |
| :--- | :--- | :--- |
| 1 | 该阶段**已有 run 留痕**且与 `--driver` 不同 | **退 64 并指向留痕**（「该阶段已由 <X> 执笔；换 Driver 请新开主题或在新阶段认领」） |
| 2 | 该阶段已声明且 driver **相同** | 幂等退 0 |
| 3 | 该阶段**零 run 留痕**、已声明且 driver 不同，**且该阶段目录下不存在旧声明 Driver 后缀的文件** | **允许改写**声明：写入新值，旧值追加进 `history[]`（含 `revoked_at`） |
| 3′ | 同上但**存在**旧声明 Driver 后缀的文件 | **退 64**，列出那些文件并写明出口：「它们在终端清理后可重试；会话内删不掉是刻意的（D3 全集字面保护）」 |
| 4 | 其余合法认领（新阶段首次声明、与既有留痕一致、与其他阶段不冲突） | 放行，写入声明 |

> **r6 修正（CODEX-02，分支 3′ 为新增）**：r6 的分支 3 只以「零 run 留痕」为前置，
> 而**写一份带后缀的原稿不产生 run 留痕**——零留痕窗口不会因为写了文件而关闭。
> 于是同一个真实会话可以：`claim glm` ⇒ 以「glm 是当轮 Driver」的身份对归档写 `-glm.md`
> ⇒ 撤回改 `claim claude` ⇒ 再写 `-claude.md`……**在首份 run 留痕诞生前依次拿到每一家的后缀豁免**。
> 而保护集 = 全集减当轮 Driver（`hooks.ts:527-531`），当轮 Driver 的第 2 级取值恰是本稿新加的自声明。
>
> **codex 给的两个药方我都没直接采纳**，理由：(a)「比对 `input.session_id` 与 `claimed_by`」
> 防的是**别的会话**搭车，防不住**同一会话**反复翻转——而威胁模型里执笔者就是同一个会话；
> (b)「撤回计数 ≤1」只是把能拿到的后缀数从 N 降到 2，量变不是质变。
> **改为把「留痕」的论域从 `run.json` 扩到「该阶段目录下的带后缀文件」**：
> 声明一旦被用过（产出了带该后缀的文件），它就不再是「尚无留痕的声明」，撤回权随之消失。
> 这与 §2.4 的权威排序完全同向——**留痕不可改、声明可撤回**，改的只是「什么算留痕」。
>
> **这一改同时关掉 GLM-06 的孤儿态**：孤儿原稿之所以能存在，正是因为撤回不看它。
>
> **镜像死锁仍然堵着**（分支 3 的原始职责）：`claim glm`（零留痕、零文件）⇒
> 发现该用 claude ⇒ 此时还没写任何 `-glm.md` ⇒ 分支 3 放行改写 ⇒ `--start --driver claude` 通过。
> 死锁序列要求的是「声明了但还没动手」，而那正是分支 3 仍然覆盖的区间。

> **r5 修正保留**：分支 1（原 r4 的分支 3）**提到首位**——r4 把它排在「已声明」判定之后，
> 导致「已声明 X 且留痕 Y≠X」这个非法态被两条分支给出**相反答案**（GLM-08）。
> 判据统一写作「该阶段**最新一份可读留痕**」，与 §2.4 交叉校验同源（r5 CODEX-03）。
> **`--stage` 必填**：不默认，避免「认领了哪一道」含糊。

### 2.4 三级判定、交叉校验与不变量

`resolveRoundDriver` 改三级：
1. **该阶段**最新 `run.json.driver`（现有行为不动，留痕损坏仍硬失败）；
2. **`drivers[<该阶段>].driver`**；
3. `DEFAULT_DRIVER`。拦截文案分别注明来源。

**交叉校验**（`topic resolve` 与 `review --start`），基准统一为「该阶段**最新一份可读留痕**」：
- 该阶段有留痕 ⇒ 与最新留痕比对，不符则报错且**指向留痕**；
- 该阶段零留痕但有声明 ⇒ 与声明比对；
- 该阶段零留痕且无声明 ⇒ 不校验。

`topic resolve` **保持纯只读**（USAGE 明写「不创建任何目录」）。

#### 自声明边界（**r6 修正 · CODEX-02，按「可反复声明」重写**）

claim 之后「当轮 Driver」第一次由**被保护方自己声明**，而它**直接决定 Write / Edit 侧的保护集**
（`hooks.ts:527-531`：保护集 = `criticRoleSuffixes(当轮 Driver)`）。

**先例 `ApprovalRecord.session_id` 不能照搬**（r6 CODEX-02 的核心论点，我认为成立）：
那个自声明只影响**对账**，不改变任何保护集；本稿这个自声明**改变保护集**。
两者的档位差是实的，不能用「都是自声明、都靠守规矩」把它们抹平。

因此本稿对这个自声明加**三重约束**，而不是只加可见性：

1. **必带 `claimed_by`**，在 `--json` 与预检可见（r6 已有）；
2. **一次性**：声明一旦被使用（该阶段目录出现该后缀的文件），撤回权即消失（§2.3 分支 3′）；
3. **全史留痕**：每次撤回把旧声明追加进 `history[]`，含 `revoked_at`（§2.2）。

**残余面如实登记**（写进 §7.3 R-l）：在「声明了、还没写任何文件」的窗口内，
撤回次数不设上限。这个窗口里执笔者拿到的是「可以选一个后缀」而不是「可以依次拿到所有后缀」——
因为一旦用掉就锁死。**不假装它是机械边界**：终端里直接写文件同样绕过整条链路（与 §7.3 R-c 同源）。

**不变量**：`runs[].driver` 是**留痕**，`drivers[<阶段>]` 是**声明**。
**同阶段二者不一致没有合法来源**（只可能来自手改或历史遗留）⇒ **预检报错**，指向留痕。
`run-files-parity` / `registry-parity` 增这两个键关系的盯防点。

`cmdApproval` 在 `decision === 'approved'` 时、`recordApproval` 之前，对每个待批阶段**无条件**执行

`rejected` / `abandoned` 不复核。**不加确认码**（v1.2.3 ② 撤销过）。

**抽取时必须带上「推断不出 runId 即拒绝」**：`cli.ts:946-957` 为此显式抛错，注释原文

照字面抽取就是在新代码里重建一条**已被双审打穿两次**的通道，
而 J2 要保的 L2 Driver 场景里 run_id 缺失最可能发生。**该分支列为抽取函数的验收项之一。**

### 4.4 复核范围含 sha256 抽核

演进设计 §9.4 原文含「**含 `run.json.artifacts` 的 sha256 抽核**」。
`checkAdjudication`（`gate.ts:164-197`）只做意见编号与裁决件比对，**不含工件哈希核对**；
审查工件被删/改时 `_meta` 结构化原文还在，裁决齐备性照常通过——正是 L2 Driver 要兜的形态。

并入 `checkRecordedArtifacts`（`archive.ts:440`，成本一行）。
**注意**：`--await-approval` 现状同样不含抽核（`cli.ts:957-977`），
声明「同源抽成一个函数」会把这个缩窄**原样继承**——**两处一起补齐**。
