## 0. 本轮的形状

**三侧独立收敛到同一处**：§3.1.1「把原稿登记进 `artifacts[]`」这一句里，
登记路径的**形态**从头到尾没有写。codex 判阻断、gemini 判重要、glm 判重要，
三条给出的是同一个故障的三个切面：

- **CODEX-01 / AGY-02**：`checkRecordedArtifacts` 以 `path.join(archiveRoot, a.path)` 取文件
  （`archive.ts:447`），登记项恒为**归档相对路径**（`writeMeta` 的 `relPath`、
  收尾的 `path.relative(ctx.archiveRoot, p)`）。按 §3.1.1 字面 push 绝对路径 ⇒ 解析到归档根下
  一个不存在的位置 ⇒ 判 `missing` ⇒ 全仓每次提交被拦。
  **这与本节硬约束 2 否决 `request.subject_path` 所用的是同一个故障**——我换了取值来源，
  就没再检查取值**形态**，于是在同一节里把自己刚拒绝的死路又走了一遍。
- **GLM-01**：即便改成 `path.relative`，`locateSubject` 的显式分支（`topic.ts:76-105`）
  对被审对象**不设域**——`--plan-file doc/…` 合法，登记结果是 `../../doc/…`，
  `path.join` 归一化后指向真文件，**把提交锚的不可变保护静默扩张到 `doc/` 下任意被点名的文档**，
  与本仓「设计文档审后回补修订」的常态工作流正面相撞。
- **CODEX-03**：登记发生在 `--start`（骨架期），而 `checkArchiveIntegrity` 过滤条件是
  `present.filter((r) => r.artifacts.length > 0)`，**没有 status 过滤**（`hooks.ts:1273`）。
  于是 failed / 作废轮的原稿登记照样绑锚——而「作废轮 + 继续改稿」在 r1～r6 这六轮里是最高频事件。

我逐条核过代码，四条**全部属实**。下一稿 §3.1.1 整节重写，采用一个能同时关掉四条的形态：

> **登记时点从 `--start` 移到收尾，且仅当 `meta.status === 'success'`；
> 路径取 `path.relative(archiveRoot, input.subjectPath)`；
> 仅当解析结果不以 `..` 越出归档根时才登记，越出则不登记并在 `run.json` 与预检
> 如实标注「本轮原稿不在保护集」。**

时点后移不削弱保护：送审窗口内原稿被改由 `subject_sha256` 的 `subject_drift` 判定承接，
锚② 要管的本就是**审完之后**的不可改。这一改让 CODEX-01（形态）、GLM-01（域）、
CODEX-03（作废轮）三条一并落地，而不是各打一个补丁。

**第二处三侧汇合**是 §3.2.2 的「出口三处」：CODEX-04 与 GLM-02 独立指出 `gate.ts:350`
的第四处（教用户 `git restore` 恢复结论文件，而该命令因路径含 `_meta` 在会话内必被守卫拒），
AGY-03 与 CODEX-05 独立指出协议片段 `CLAUDE.md.snippet:28-29` 这第五处。
**焦点六问「三处够不够」，答案是不够，而且不够的方式正是我自己在 §4.2.2 立的那条药方所针对的**——
我给误拦面写了判据式表述，却用人工枚举去数出口处数。下一稿把「同类文案清单」的得出方式
改成一条可执行的 grep 判据，结果进 §3.3 用例与第 5 步回溯核对项。

**焦点三（元数据目录还有没有第三个刻意可变项）三侧独立复核，一致结论：没有。**
codex 逐一枚举 `writeMeta` 全部调用点、glm 另独立重跑了 `git log --name-only` 数据面、
gemini 推演完备。两个排除项 + 求值顺序条款完备——这是 r4 栽过一次之后，本轮唯一一个
三侧都给出正面结论的问题。

**焦点一（拆分边界）三侧均判成立**，且不是纸面承诺：codex 与 glm 都去读了 M10b r1 稿，
核到移交项与 AC-21 份额确实被对侧接住。但 AGY-01 补出一处真空（§6.2 漏列 RUNBOOK 行、
FR-28 不可整体转达成）、CODEX-07 补出一处（主设计 §16.1「前置四条缺一不可」的归属重排
是对设计契约的**改**而非**解**，必须显式回溯）。两条都接受。

**一处三侧分歧**：CODEX-02 判 §2.3 分支 3 开出新绕过，而 glm 在「认为正确」里明确判它
**未**开出新绕过，GLM-06 则把同一现象登记为无害残留（孤儿原稿）。我判 **CODEX-02 成立**，
理由见该条裁决——分歧的根源是分支 1 的「留痕」只认 `run.json`，而写一份带后缀的原稿
**不产生 run 留痕**，零留痕窗口因此不会因为写了文件而关闭。glm 看的是「孤儿会不会被误选」
（不会，`locateSubject` 按当轮后缀过滤），codex 看的是「同一会话能不能依次拿到每一家的后缀豁免」
（能）。两者测的不是同一个命题，codex 那个是安全命题。
