## 2. 第 1 步：EV-72 按阶段 Driver 落盘

### 2.1 问题

plan / bug 原稿在 `review --start` 之前由 Driver 写出，那一刻该阶段零留痕，`resolveRoundDriver`
回落缺省 Driver，非缺省 Driver 的 `-<id>.md` 原稿被判伪造件退 2。

### 2.2 落盘形态：按阶段

`TaskMeta` **additive** 加可选字段：

```
drivers?: { [stage: 'plan'|'code'|'bug']: { driver: AgentId; claimed_at: string; claimed_by: string } }
```

**不是主题级单值**——它要与 `resolveRoundDriver` 第 1 级「该**阶段**最新 `run.json.driver`」同构；
主题级单值会精确覆盖跨阶段换 Driver 发生的那一刻（r2 双审两侧命中）。
schema 仍 `trivium.task.v1`：缺该字段 = 「未声明」。

### 2.3 `topic claim` 子命令

`trivium topic claim --topic <主题> --stage <阶段> --driver <id> [--json]`

> **判定顺序：自上而下，首个命中的分支生效。**（r5 GLM-08）

| # | 条件 | 行为 |
| :--- | :--- | :--- |
| 1 | 该阶段**已有 run 留痕**且与 `--driver` 不同 | **退 64 并指向留痕**（「该阶段已由 <X> 执笔；换 Driver 请新开主题或在新阶段认领」） |
| 2 | 该阶段已声明且 driver **相同** | 幂等退 0 |
| 3 | 该阶段**零留痕**、已声明且 driver 不同 | **允许改写**声明，更新 `claimed_at` / `claimed_by` 并留日志 |
| 4 | 其余合法认领（新阶段首次声明、与既有留痕一致、与其他阶段不冲突） | 放行，写入声明 |

> **r5 修正（分支 1 与分支 3 均为新增）**：
> - **分支 1**（原 r4 的分支 3）**提到首位**：r4 把它排在「已声明」判定之后，
>   导致「已声明 X 且留痕 Y≠X」这个非法态被分支 1（幂等）与分支 3（退 64）给出**相反答案**（GLM-08）。
>   提到首位后，留痕永远优先——与 §2.4 的权威排序一致。
>   判据统一写作「该阶段**最新一份可读留痕**」，与 §2.4 交叉校验同源（r5 CODEX-03）。
> - **分支 3 是 r5 CODEX-03 的核心修正**。r4 只堵了「先留痕、后错认领」，
>   **镜像序列仍通向死锁**：①`claim --driver glm`（零留痕，放行）→
>   ②`--start --driver claude` 被交叉校验拒 → ③改不回声明（r4 分支 2 拒绝同阶段不同 driver、
>   不提供覆盖旗标）→ ④建不了留痕 → ⑤`task.json` 对 Write/Edit 与 Bash **双侧独占**
>   （`hooks.ts:460-481`）⇒ 出路只剩新开主题或终端手改受保护文件——
>   **而后者正是本稿用来判定 r3 死锁不可接受的同一条理由**。
>   分支 3 与「不提供覆盖旗标」**不冲突**：撤回的是**尚无留痕**的声明，
>   理由直接引 §2.4 的权威排序——**留痕不可改、声明可撤回**。
> - **`--stage` 必填**：不默认，避免「认领了哪一道」含糊。

### 2.4 三级判定、交叉校验与不变量

`resolveRoundDriver` 改三级：
1. **该阶段**最新 `run.json.driver`（现有行为不动，留痕损坏仍硬失败）；
2. **`drivers[<该阶段>].driver`**；
3. `DEFAULT_DRIVER`。拦截文案分别注明来源。

**交叉校验**（`topic resolve` 与 `review --start`），基准统一为「该阶段**最新一份可读留痕**」：
- 该阶段有留痕 ⇒ 与最新留痕比对，不符则报错且**指向留痕**；
- 该阶段零留痕但有声明 ⇒ 与声明比对；
- 该阶段零留痕且无声明 ⇒ 不校验。

`topic resolve` **保持纯只读**（USAGE 明写「不创建任何目录」）。

**自声明边界**：claim 之后「当轮 Driver」第一次由**被保护方自己声明**，而它直接决定 Write/Edit 侧的保护集。
先例是 `ApprovalRecord.session_id`（`meta.ts:43-57`）。故必带 **`claimed_by`**，在 `--json` 与预检可见。

**不变量**：`runs[].driver` 是**留痕**，`drivers[<阶段>]` 是**声明**。
**同阶段二者不一致没有合法来源**（只可能来自手改或历史遗留）⇒ **预检报错**，指向留痕。
`run-files-parity` / `registry-parity` 增这两个键关系的盯防点。

## 3. 第 2 步：EV-55 跨时间面重写（安全关键面）

> **前置**：EV-74 / EV-79 小主题须在本步开工前完成，钩子见 §6.1。

### 3.1 提交锚：登记 + 位置，两条判据

#### 3.1.1 先补登记：原稿进 `artifacts[]`（**仅 plan / bug**）

`--start` 时把原稿的 `path` + `sha256` 登记进 `artifacts[]`。

- **成本极小**：`prepareRun` 已算出 `subjectSha256`；`metaArtifacts` 是 `{path, sha256}[]`
  且收尾为**追加**语义，多 push 一条即可。
- **两条硬约束**（r3 三侧命中）：
  1. **仅对 plan / bug 的原稿文档生效**——code 阶段的被审对象本就是 `_meta/changes-<runid>.diff`，
     已作为 `pendingDiff` 登记（`review.ts:837-844`），再登记即重复条目。
  2. **禁止用 `request.subject_path` 取值**——`freeze.ts:447` 的 code 分支是
     `<archiveRoot>/_pending/changes.diff`，注释自认「这里先给逻辑路径」。
     照字面登记会把**不存在的路径**写进 `artifacts[]` ⇒ `checkRecordedArtifacts` 判 missing
     ⇒ **提交锚永久拦且无法恢复**。取值改用 plan / bug 分支的 `input.subjectPath`
     （`freeze.ts:449-451`，来源是 `topic.ts:76-100` 的 `locateSubject`，返回 `fs.exists` 已验的真绝对路径）。

> **这一步做完，「已送审原稿不可改」当场成立——不需要再写第二条判定。**（见 3.1.2）

#### 3.1.2 判据只有一条新的：`_meta/` 位置

> **r5 修正（CODEX-01，本轮唯一做减法的一条）**：r4 写了两条判据，第 1 条是
> 「路径出现在任一 `artifacts[]` 内 ⇒ 拦」——**它是对既有「锚②」的重复实现**。
> `hookPreCommit` → `checkArchiveIntegrity` 今天就在遍历各主题 run.json 的 `artifacts[]`
> 并按 sha256 把登记工件的 missing/modified 判为 `GATE_BLOCK`（`hooks.ts:1274-1281`）。
> 所以 3.1.1 一登记，保护即由**锚②承接**。r4 把保护从无到有全记在「登记 + 第 1 条」头上，
> **归因错了对象：真正让它成立的只有 3.1.1 一条**。
> 重复实现不是零成本——同一状态两套规范（一套按路径命中、一套按内容比对，出口文案还不同），
> 正是本仓最忌的形状。**故本稿删去原第 1 条。**

`immutableChangeReason` 新增**一条**判据：

> **位于 `_meta/` 目录内 ⇒ 拦，但排除两项**：
> ① basename 为 **`changes.diff`**（便利副本，每轮覆盖写）；
> ② **`run-*.json` 且已提交版本的 `status === 'running'`**（收尾回写）。

- 判据从「后缀」改为「位置」，消除了「需要当轮 Driver 才能判别原稿与审查件」的缺口
  （r2 GLM-01）——原稿与审查件的不可变性改由**锚②**按登记承接，谁登记了谁不可变。
- **求值顺序**：`run-*.json` 的既有分支（`hooks.ts:506-521`）**先于**位置判据求值，
  或把它的条件内联进排除项 ②。两种写法等价，实施时择一并在注释写明。

> **r5 修正（AGY-01 / GLM-01 两侧命中）**：r4 只排除了 `changes.diff`，
> 而 `hooks.ts:506-521` 为 `run-*.json` 专设了分支——已提交版本是 `running` 时返回 `null`，
> 注释原文「说明有人在运行中途提交过，本次改动是正常收尾，**不能拦**」。
> r4 的判据按字面会拦它，**与 r4 自己写的「`run-*.json` 的既有分支不动」直接矛盾**，
> 且 r4 的 D2 写「`_meta/` 有且仅有一个刻意可变的例外」是错的。
>
> **例外集到此完备**，有两条独立证据：
> (i) 代码面——`writeMeta` 的全部调用点里只有 `alias = 'changes.diff'` 用固定名，其余一律带 run_id；
> (ii) 数据面——`git log --name-only -- '*_meta/*'` 里被 >1 次提交改动的文件只有各主题的
> `changes.diff`（4 个主题、最多 6 次），其余全部 1 次。
> 两条均来自 r5 codex 侧的实测。**`run-*.json` 是条件性例外**（只在「中途提交」这个边缘场景生效），
> 不表现为反复覆盖，故数据面看不到它——这正是它在 r4 被漏掉的原因。

#### 3.2.1 误拦面：判据式表述，不靠枚举

D3 后被拦的是「`writeLike` ∧ 命令文本提到受保护角色后缀」这个交集。**今天走得通、之后要改法的形态**：

| # | 形态 | 出口 |
| :--- | :--- | :--- |
| 1 | commit message 带工件名 | 写进文件，`git commit -F <文件>` |
| 2 | 原稿克隆（本主题 r1→r6 的工作流） | 改用 Write 工具落新文件 |

| 4 | 带重定向的命令 | 去掉重定向，读工具输出 |
| 5 | **命令 B 自身：焦点含写动词字面** | **改焦点措辞**（FR-20 逐字，**改之前要问用户**） |
| 6 | **撤销／暂存带后缀的已跟踪文件** | **终端直接执行** |

**该表不是穷举。** CLAUDE.md 与协议片段写**判据式表述**：

> 凡「命令**像**写命令（`WRITE_LIKE` 词边界字面匹配）」且「命令文本提到受保护的角色后缀」，
> 两条同时成立即拦——**不区分「写它」与「说它」**。上表是举例，新的写动词组合随时会命中同一判据。

> **r4 曾要求 CLAUDE.md「覆盖上表全部形态」——按表逐条抄就会漏**（r4 自己就漏了第 6 行）。
> 判据式表述与 `hooks.ts:792-921` 的实现同构（`writeLike` 前置门 + `roleSuffixAnywhere`），
> 判据与实现同源就不会像枚举表那样腐烂（r5 codex / glm 均确认）。

`rejected` / `abandoned` 不复核。**不加确认码**（v1.2.3 ② 撤销过）。

**抽取时必须带上「推断不出 runId 即拒绝」**：`cli.ts:946-957` 为此显式抛错，注释原文

而 J2 要保的 L2 Driver 场景里 run_id 缺失最可能发生。**该分支列为抽取函数的验收项之一。**

### 4.4 复核范围含 sha256 抽核

演进设计 §9.4 原文含「**含 `run.json.artifacts` 的 sha256 抽核**」。
`checkAdjudication`（`gate.ts:164-197`）只做意见编号与裁决件比对，**不含工件哈希核对**；
审查工件被删/改时 `_meta` 结构化原文还在，裁决齐备性照常通过——正是 L2 Driver 要兜的形态。

并入 `checkRecordedArtifacts`（`archive.ts:440`，成本一行）。
**注意**：`--await-approval` 现状同样不含抽核（`cli.ts:957-977`），
声明「同源抽成一个函数」会把这个缩窄**原样继承**——**两处一起补齐**。
