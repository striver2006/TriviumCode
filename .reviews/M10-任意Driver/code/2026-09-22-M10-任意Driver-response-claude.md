- **CODEX-02**：不变量与交叉校验的错误文案教用户敲 `topic claim --stage X --driver Y`，
  而 `--topic` 是必填——**照文案敲，第一次就退 64**。这正是 r7 §3.2.2 全节在处理的
  「报错教的命令当场被拒」，也是本轮焦点第四点我自己点名要审查员核的那一条。
  更难看的是：**我给它配的用例是子串匹配**，而那个子串在缺 `--topic` 的错误命令里同样存在，
  于是判据零鉴别力，反而把错文案钉成了期望值。我在焦点五里让审查员用「构造恰好绕开被测判据」
  这把尺子去量别人，自己这条正中靶心。
- **CODEX-01**：交叉校验分不清「没传 `--driver`」与「传了缺省值」——`resolveDriver(null)`
  直接返回 `DEFAULT_DRIVER`。后果是**任何非缺省 Driver 的主题上，省略该旗标的
  `review --start` / `topic resolve` 一律退 64**，而文案恰恰建议「去掉 --driver」。
  去掉之后仍解析成缺省值、仍不等于留痕值，**照文案做第二次仍然被拒**。
  同一条病，另一个位置。

## 3. 修改方案（审批后执行）

**A. 一处语义统一**（CODEX-03 / GLM-01）

`driver-claim.ts` 导出单一判据 `resolveStageDriver(layout, stage)` → `ok(run|claim|default)` / `corrupt`，
四个消费点共用（`hooks.ts`、`cli.ts` 两处、`topic-args.ts`）。入口在 `corrupt` 档拒绝启动。
文案口径统一为「最新一份**可读**留痕」。

**B. 一处语义补全**（CODEX-01）
