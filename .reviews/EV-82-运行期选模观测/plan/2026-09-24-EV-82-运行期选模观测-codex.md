**问题**：「只动顺序」有三个边界没写清。①键序并非随便挪得动：JS 对象按 OrdinaryOwnPropertyKeys 排序，整数样键名（"0"/"1"/"2"…）永远排在其它键之前并按升序，JSON.stringify 落盘也是这个顺序——若副本源里某个 provider 键或模型键是整数样，置首会静默变成无操作，而用例若只用 bigmodel-coding-plan 这类非整数键就测不出来。②成员定位规则要与导入器同源：包内成员收集用 `(成员.id ?? 键名).trim()`、跳过 deleted:true、并按 id 去重（同 id 的后者被丢），本仓同名函数也 trim 并压进 Set——Set 丢掉了「id → 键名」的映射，而计划只写「按规则找到对应的键再挪动」，没说 id 带空白、deleted 成员、两个键同 id 时挪哪一个。③请求模型已在首位时变体是恒等操作，这条用例没有，而它恰是「只有顺序变了」这条对拍能否覆盖置首实效的边界。

**依据**：被审计划 §4 与 §7「置首变体」用例清单；/Applications/ZCode.app/.../zcode.cjs 内 collectLegacyCliModelMembers（`(s.id??o).trim()`、`deleted===true` 跳过、`t.has(a)` 去重）与 importLegacyCliPersonalProviderConfig（Object.entries 保序遍历 provider/models、成员序写成 modelOrder）；src/trivium/adapters/zcode.ts:568-586 legacyProviderMembers、588-600 qualifyAgainstCliConfig（返回 providerKey/modelId）。

**建议**：用例补三格：整数样键名、成员 id 带前后空白、两个键同一个 id；再补「请求已在首位」的恒等格。实现里对「找不到对应键／挪不动」的情形不要静默当成功，至少在 note 里留一句，免得实验落进 (F3) 时读的人分不清是 CLI 行为还是变体没生效。
