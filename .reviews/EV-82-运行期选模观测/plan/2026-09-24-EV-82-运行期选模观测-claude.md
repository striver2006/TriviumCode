## 2. 本段做什么、不做什么

**做**：
1. **运行期观测**：两条探针臂拉起后，在清理之前读副本 HOME 下 CLI 日志里的 `bootstrap.app.startup.runtime_config.completed`，取 `context.model` 作「运行期选定」。
2. **「请求模型置首」变体**：同形臂增一个副本变体，只调整副本里的**顺序**，把请求的 provider 排到 `provider` 映射的首位、请求的模型排到该 provider 的 `models` 映射首位；键与值都不动。
3. **实验**：同形臂分两次拉起，一次原样、一次置首，读两次的运行期选定；白名单臂也读一次。

**不做**：
- 不改审查臂 `prepareZcodeHome` 的缺省行为；修法在第三段。
- 不写 v2 个人配置文件去补思考档位。个人文件在场时 CLI 不做 legacy 导入，要补就得把 provider 规则连同凭据一起写进 v2（v1.3.32 撤掉的那条路，凭据面多一份）。本段不碰；若实验显示只有它能修，第三段另议。
- 不做 T2（修复之后才做）。

## 3. 改动一：运行期观测

- **新函数** `readRuntimeSelectedModel(home)`（`probes/zcode.ts`）：读 `<home>/.zcode/cli/log/*.jsonl`，找事件 `bootstrap.app.startup.runtime_config.completed`，返回其 `context.model`（`<providerId>/<modelId>` 字符串）；找不到返回 null。**只读这一个字段**，不读、不返回日志里的其它内容（日志可能含会话内容）。
- **接线**：两条探针臂在 `finally` 清理**之前**调用它，结果放进返回值的新字段 `runtimeSelected`（可为 null）。
- **展示**：doctor 的两臂 note 各加一段「运行期选定 <值>」；再加一条对照：运行期选定的 modelId 段 ≠ 请求时，打印「配置读取层写出了请求值，但运行期没有选它」。
- **机读**：本段**不进** `ProbeSection`。目前没有运行期消费方，只进 notes 与报告（M10b r5 §4.6 的「有消费方才进机读」）。

**零配额的前提**：凭据换哨兵后，CLI 仍会走到启动阶段并记下这条事件，再在鉴权或建模处失败。这一点第一段没验过，是本段实验的第一个读数：
**哨兵拉起下读不到这条事件 ⇒ 运行期观测在零配额下不可得**，按第 5 节 (E) 格处置，不改用真实凭据去跑。

## 4. 改动二：「请求模型置首」变体

- 同形臂的 `opts` 增 `variant?: 'as-is' | 'requested-first'`，缺省 `as-is`。
- `requested-first`：在 `transformCopy` 里（凭据替换之前或之后均可，只动顺序），按 `qualifyAgainstCliConfig` 限定出的 `<providerKey>/<modelId>`：
  - 重建 `provider` 对象，使 `providerKey` 排在首位，其余按原序；
  - 重建该 provider 的 `models` 对象，使 `modelId` 对应的成员键排在首位，其余按原序。
  - `modelId` 取的是成员的 `id ?? 键名`（与导入器同规则）：按规则找到对应的**键**再挪动。
- 键、值、嵌套结构一律不变；用例对拍「只有顺序变了」。
- **它的意义**：若运行期确是「默认选择不可选 ⇒ 回落第一个」，置首后回落的恰好就是请求模型。所以它**既是对 S2 的实验**，也是第三段修法的候选之一（见第 6 节）。

## 5. 实验与判读（零配额）

改动合入后 build + install（各单独一条），在干净工作树上跑 `.trivium/bin/trivium doctor --only zcode --no-model-calls`（两臂 + 同形臂置首变体一次）。
请求模型 `GLM-5.3-Flash`（非首位）。读三个值：白名单臂、同形臂原样、同形臂置首三者的运行期选定。

**判定次序**：先看运行期选定是否读得到，再按下表。

| 格 | 读数 | 读出什么 | 下一步 |
| :-- | :--- | :--- | :--- |
| (E) | 三者都读不到启动事件 | 哨兵拉起走不到启动阶段，运行期观测在零配额下不可得 | 报告用户；是否用一次真实单侧派发（有配额）验证修法候选，由用户定 |
| (F1) | 原样 = `GLM-5.3`（首位），置首 = `GLM-5.3-Flash` | **S2 在 headless 路径上成立**：默认选择不可选、回落第一个；置首能让回落落在请求模型上 | 第三段：审查臂采用置首（见第 6 节），再做 T2 |
| (F2) | 原样 = `GLM-5.3-Flash` | 零配额下运行期已经选中请求模型，真实运行的回落发生在启动之后（例如鉴权后刷新注册表），或与真实凭据有关 | 报告用户；第三段需要在真实凭据下观测，涉及配额 |
| (F3) | 原样 = `GLM-5.3`，置首仍 = `GLM-5.3` | 回落不是「第一个模型」，S2 不成立或另有过滤 | 报告用户；回到静态检索找真正的回落规则 |
| (F4) | 白名单臂与同形臂原样的运行期选定不同 | 两种副本在运行期层面有差异（配置层之外的 H2 形态） | 报告用户；按 EV-94 ② 处置 |

**层级**：本实验看得见启动阶段的运行期选定，看不见启动之后（鉴权、注册表刷新、服务端映射）。(F1) 是「启动阶段已选中请求模型」，**不等于**真实运行全程用它；那由第三段的 T2 与 rollout 逐条模型来证。

**具名报告**：结果追加进 `doc/05_testing/REPORT_2026-09-24_ev82_review_arm.md` 新的一节（第二段实验），含三个运行期选定、落格与下一步。

## 7. 验证

- `npm run typecheck && npm run build && npm test` 全绿；build 与 install:local 各单独一条。
- **运行期观测**：
  - 用例：假入口在副本 HOME 下写一份含启动事件与其它事件的日志，断言只取到 `context.model`；没有该事件 ⇒ null；日志不存在 ⇒ null；
  - 用例：读取发生在临时根清理之前（假入口写日志，臂返回的 `runtimeSelected` 非 null，且临时根随后被清）；
  - 用例：返回值与 note 里不含日志的其它字段。
- **置首变体**：
  - 用例：只有顺序变了（键集、值逐项相等，首位是请求的 provider 与成员键）；成员 `id` 与键名不同时按 `id` 找对键；
  - 流程用例：假入口模拟「默认选择不可选 ⇒ 回落 provider 首个模型」并写启动事件，断言原样变体的运行期选定是首位、置首变体是请求模型。
- **变异**：观测不读启动事件（读错事件名）⇒ 红；读取挪到清理之后 ⇒ 红；置首不挪 models 顺序 ⇒ 红。
- `trivium doctor --selftest` 全绿。

## 10. 给审查员的重点

1. S5 的启动事件能否作为「运行期选定」的依据：它记的是启动时解析出的模型，会不会在第一次请求前又被改写。

4. 置首变体「只动顺序」是否真的只动顺序，`id` 与键名不同的成员能否正确定位。
5. 第 6 节修法候选是否漏项；M1 的守卫盲区改判据的思路是否成立。
