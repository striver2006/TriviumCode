## 3. 改动一：运行期观测（**r2 修正**：CODEX-02、CODEX-05、AGY-04、GLM-06）

- **新函数** `readRuntimeSelectedModel(home, launched)`（`probes/zcode.ts`），返回**带成因的读数**：

  | 成因 | 含义 |
  | :--- | :--- |
  | `not_launched` | 该臂没拉起（早退：副本源缺失、限定失败、残余扫描命中等） |
  | `no_log_dir` | 副本 HOME 下没有 `.zcode/cli/log` |
  | `no_log_file` | 目录在，没有 `.jsonl` |
  | `no_event` | 文件在，没有 `bootstrap.app.startup.runtime_config.completed` |
  | `no_model_field` | 事件在，`context.model` 缺失或不是字符串（S5：选定为空时整键消失） |
  | `ok` + `model` | 读到了 |

- **取法**（与 C6 对齐）：排序取最新 `.jsonl`（探针 HOME 每次新建、单会话，这条前提写进注释）；同一文件多条该事件取**最后一条**；单行 JSON 解析失败跳过；I/O 异常 fail-closed，返回对应成因，**不抛、不回传日志原文**。
- **只取一个字段**：不读、不返回日志里其它任何内容（日志可能含送审包全文）。
- **日志必须落进副本 HOME**：探针拉起环境的清除清单加 `ZCODE_LOG_DIR`（与三个目录键同理，C7）。
- **接线**：两条探针臂在 `finally` 清理之前调它，结果进返回值的新字段 `runtimeSelected`。
- **doctor 展示**：两臂 note 各加「运行期选定 <值或成因>」。运行期选定的 modelId 段 ≠ 请求时，加一条对照：「配置读取层写出了请求值，但运行期没有选它」。
- **机读**：**`ProbeSection` 里**没有消费方，本段不进（CODEX-05）；注释写明「探针读的是审查臂同一个字段」。

## 4. 改动二：「请求模型置首」变体（**r2 修正**：CODEX-04、AGY-03、GLM-08）

- 同形臂 `opts` 增 `variant?: 'as-is' | 'requested-first'`，缺省 `as-is`。
- **目标取法**：同形臂拉起前已调 `qualifyAgainstCliConfig`，得 `<providerKey>/<modelId>`，经**闭包**传进 `transformCopy`，不改回调签名。限定失败走既有早退（AGY-03）。
- **成员定位**与导入器同一规则：在 `providerKey` 的 `models` 里，按 `(id ?? 键名).trim()` 匹配 `modelId`，跳过 `deleted: true`；重复 id 取**第一个**匹配键（先到先得，GLM-08）。
- **重排**：重建 `provider` 对象使 `providerKey` 在首；重建该 provider 的 `models` 使目标键在首；其余按原序，键、值、嵌套一律不变。
- **挪不动不当成功**（CODEX-04）：以下情形在返回值与 note 里写「置首未生效：<原因>」，该次读数**不落 (F1) / (F3)**：
  - 整数样键名（JS 对象恒把它们排在前面，挪不动）；
  - 找不到对应键；
  - 请求本来就在首位（恒等）。

## 6. 第三段修法候选（本段只列，不实施）（**r2 修正**：CODEX-03、AGY-05、GLM-05、CODEX-07）

| 候选 | 做法 | 代价与风险 |

## 10. 给审查员的重点（若代码双审）

1. 带成因读数的六种成因是否覆盖全部读不到的形态；fail-closed 是否真的不抛、不回传原文。
