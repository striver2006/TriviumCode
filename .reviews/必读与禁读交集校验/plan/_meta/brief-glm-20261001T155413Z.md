## 2. 设计

### 2.1 纯函数：交集判定（`brief.ts`，新增导出）

```ts
export type DenyConflictDirection = 'under' | 'contains';
export interface DenyConflict {
  entry: string;          // 第 4 段条目，原样（报错与告警按用户写法点名）
  denyEntry: string;      // 撞上的禁读条目，原样
  category: DenyCategory; // 命中点的类别
  direction: DenyConflictDirection;
}
export function findDenyConflicts(entry: string, denyPaths: readonly string[], ctx: DenyContext): DenyConflict[]
```

判定（逐条禁读条目 `d`）：

1. 两侧归一：`entryAbs = normalizeAbs(expandHome(entry), projectRoot)`，`dAbs = normalizeAbs(d, projectRoot)`——与 `classifyDenyPath` / `checkPeerLeak` 同一口径（`path.resolve` 吃掉 `./`、`..`、绝对路径，抹 `/private`），**不 realpath**（理由见 §4 ①）；
2. `under`：`isUnder(entryAbs, dAbs)`（含相等）。命中点是**条目本身**：
   - `isOrchestratorReadable(entry)` 为真 ⇒ 跳过（具名放行，决策二）；
   - `category = classifyDenyPath(entry)`；`own-run-material` ⇒ 跳过（决策二）；
3. `contains`：`dAbs !== entryAbs && isUnder(dAbs, entryAbs)`。命中点是**那条禁读条目**：`category = classifyDenyPath(d)`；`own-run-material` ⇒ 跳过（防御性；当前禁读条目里只有运行根整棵，判 `peer-run-output`）。

「命中点」取法与 §10.1.1「分档的粒度是命中，不是禁读条目」一致：条目落在整棵运行根之下时，按条目自己的位置判它是己方还是对端。

`DenyContext`（`{ projectRoot, triviumDir, runRoot, critic, sensitiveGlobs }`）抽成 `brief.ts` 里的一个工厂 `denyContextFor(cfg, projectRoot, critic)`，第 8 段渲染（`brief.ts:309-315`）改用它——两处同一份上下文，不再各拼一份。

- 类别人读标签集中成一张 `Record<DenyCategory, string>` 表（`own-run-material` 也给一格，编译期穷尽；它不会出现在文案里）。

### 2.5 剔除告警（`warnings`）

- `PreparedRun` / `RunContext` 加 `mustReadPruned: PreflightWarning[]`（按条目聚合一条），由 `prepareRun` 产出；
- `startRun`：`warnings = [...collectWarnings([...]), ...rc.mustReadPruned]`（追加在后，既有两项顺序不变）；纯文档跳过分支仍为 `[]`（没有审查员会被拉起，与「不计算」口径一致）；
- 同步路径 `runReviewLocked`：把 `detail` 串并进 `ReviewOutcome.warnings`（`string[]`），人读模式随既有的 `warn` 循环打印；
- 工作进程从交接文件重建上下文时该字段给 `[]`——任务书已在 `--start` 时渲染进交接文件，工作进程不重算；
- 单条形状：`name: '必读清单剔除'`，`detail: ⚠️ 任务书第 4 段的「X」（来源：建议核实）落在 codex、glm 侧的禁读集里（对端审查件，读了该侧作废；禁读条目「Y」），已从这几侧任务书的第 4 段剔除，其余侧照常列出。来源是编排器自动生成的，无需处理；若确实需要审查员看到其中内容，请把它写进被审对象本身。`
  - 「若确实需要」那半句只在作废类出现？——不分：两类都给同一出口，简单；
- 第 4 段**不**加任何解释（决策四）。若剔除后某张清单为空，沿用既有的空清单兜底句（如「被审文档中未出现路径式引用」）——这句在剔除场景下措辞不精确，接受（§4 ③）。
