### 1.5 §3.7.1 说适配器「规则写法读 `rule_syntax`」，而落盘值不是生产形态

配一条单测锁住「解析器认得本机落盘的那个真实值」。

## 2. 形状：四个子步，**顺序不可交换**

EV-42 与 EV-43 都写「**编写适配器之前**先补实测」，而 EV-43 又要求
「用与适配层一致的 stdin 传参结构」。这是先有鸡还是先有蛋——**解法是把适配器切成两半**：

```text
3a  adapters/claude-trace.ts（纯解析，零调用）
  + adapters/claude.ts 的「下半身」：buildClaudeArgs / invokeClaude /
      readonlyArgsFromProbe / readonlyToolsFromProbe / denyRuleShapeOf / buildDenySettings

```

**这个切分点要在留痕里写明**：第 2 步产出的只是 argv/exec 封装，不是「适配器」意义上的
编写；否则下一轮双审会按 BACKLOG 字面判它违反了触发条件。

**脚本 import 生产函数是有先例的，不是我发明的**：`scripts/codex-sandbox-control.mjs:194-207`
调的就是生产的 `invokeCodex` + `readonlyArgsFromProbe` + `prepareCodexHome`，
探测逻辑（夹具、哨兵、判词）全在脚本里，`adapters/codex.ts` 内**一行探测逻辑都没有**。
EV-43 那句「不在生产 `adapters/claude.ts` 内实现探测逻辑」指的正是这条边界——
**它不禁止脚本调用适配器的 argv/exec 封装**。

> **这一条推翻了我的初稿。** 初稿写的是「脚本自建配方 + 补一条对账用例断言两份配方等价」。
> 那是给漂移加守卫；import 生产函数是**消除漂移**。本仓四轮账的对策 1 逐字就是
> 「**能让类型或结构保证的，不要留给『记得写对』**」——自建配方正是留给记得写对。

**EV-42 / EV-44 的装置与 EV-43 不同，别打包**：前两者的结论要落**必填探针字段**，
所以实测臂必须住在 `probes/claude.ts`（探针是探测逻辑的家，EV-43 那句管的是 `adapters/`）。
脚本只负责**取证与定形**，产物是报告里的证据表，不是落盘字段。

**手工回填 `config.local.yaml` 是结构性不可行的**（决定性证据）：`probes/claude.ts:1067` 是
`probe.path_deny = await probeClaudePathDeny(bin, fx);` ——**整体赋值**。

被无条件覆盖回 `null`。而 `peer_deny_applied` 读的正是这一格：回填的 `true` 会在某次
doctor 之后静默变回 false，**一次「我以为自己验过」的教科书形态**。

## 3. EV-42：逐文件 deny 形态

### 3.1 结案判据（BACKLOG 原文，两条腿都成立才算）

注入 `Read(<具体文件>)` 后 ① **哨兵未泄漏** ② **该次记入 `permission_denials`**。

> 第 ② 条与第 1 步 P-b 的观测**看起来冲突**，实则论域不同，**且已有代码级证据**：
> P-b 那次 `permission_denials` 是空数组、拒绝信息在 `tool_result` 里，测的是
> **白名单外工具**（`Write` 走「工具不存在」路径）；而 `probeClaudePathDeny` 的主 Read
> 判据逐字就是 `recorded = t.permissionDenials.length > 0`，且它**实测成立**
> （落盘 `supported: true`）——**白名单内工具被路径规则挡住确实进 denials**。
> 两者不冲突。这条要写进脚本注释，免得下一个读者以为哪边是错的。

### 3.2 实测面必须覆盖**三种** deny 条目形状

这一条初稿没有，是核 `freeze.ts:265-350` 查出来的：**`enumerateDenyPaths` 产出的是混合集**。

| 形状 | 出处 | 状态 |
| :--- | :--- | :--- |
| 项目相对**文件** | `freeze.ts:318,326`（`.reviews/<topic>/plan/…-glm.md`） | EV-42 的字面论域，**`file_shape_verified` 只由它决定** |
| 项目相对**目录** | `freeze.ts:344`（`.trivium`） | 未测 |
| **项目外绝对路径** | `freeze.ts:345`（`expandHome(cfg.runtime.run_root)`） | **从未测过** |

第三种尤其要测：`--restricted` 本身就把文件工具限制在工作目录内
（`probes/claude.ts:12-14`）——它可能**根本不需要** deny 规则，也可能让规则语法当场报错。
三种各跑一次，后两种的结论进报告与 §3.7 行内标注。

### 3.3 探针第三臂：两个方案，**推荐 A**

| | **A：新增独立第三臂** | B：把主臂规则从目录 glob 改成逐文件 |
| :--- | :--- | :--- |
| 每次 doctor 增加调用 | **+1**（现 6 → 7，约 +$0.008） | 0 |
| `rule_syntax` 落盘形态 | 仍是目录 glob | 变逐文件，与生产注入形态一致 |
| 丢失的事实 | 无 | 「目录 glob 形态可用」从活断言降级为历史记录 |
| 归因 | 两种形状各有独立观测，谁成立谁不成立分得开 | **一次观测同时承载两个结论，形状与可用性再次塌缩** |

**推荐 A**：`types.ts:206-211` 已经把 `coverage_complete`（对哪些**工具**生效）与
`file_shape_verified`（对哪种**路径形状**生效）明写为两件事；B 等于把刚拆开的两格并回去，
且失去「目录形态成立、逐文件形态不成立」这个**最可能的真实结果**的表达能力。
**反对 A 的理由如实登记**：doctor 成本 +17%，绝对额约 $0.008/次——这个反对理由弱，但它是真的。

第三臂与既有 Grep 负对照臂**完全同构**：

| | 主 Read 臂（现有） | Grep 负对照臂（现有） | **逐文件臂（新增）** |
| :--- | :--- | :--- | :--- |
| 注入规则 | `Read(./<dir>/**)` | 同上 | **`Read(<具体文件>)`** |
| 腿一 | 哨兵未泄漏 | 哨兵未泄漏 | 哨兵未泄漏 |
| 腿二 | 进 `permission_denials` | 真发起过（否则 `unverified`） | **进 `permission_denials`** |
| 落格 | `supported` | `coverage_complete` | **`file_shape_verified`** |

三态映射抽成纯函数 `judgeFileShape()`，与既有 `judgeDenyCoverage` /
`judgeStrictMcpConfig` / `judgeVerboseBinding` 同形——这是四轮账里
「唯一没有再出问题的做法」之一（报告 §12 对策 1）。`!completed` 或没发起过 ⇒ `null`。

**四个 return 分支全部要带齐 `PathDenyProbe` 的六个键**（`claude-events.test.ts:669`
那条契约测试逐个检查），且 `PATH_DENY_MIN_HITS['claude.ts']` 的逐文件下限要跟着调。

### 3.4 否定结案路径**要真的走**

BACKLOG 明写：若实测确认逐文件形态**不生效**，以否定结论结案——`file_shape_verified`

### 5.2 配套交付物（无论裁定如何都必须落）

```text
字段名：ClaudeProbe.project_memory_blocked   （boolean | null，必填三态）
语义：  --restricted 在场时，项目记忆文件是否仍被阻断进入上下文
        true  = 仍被阻断（现状）—— 本条结论成立
        false = 不再被阻断 —— **本条结论作废**，第 ⑤ 件要重开
```

**命名理由**：不叫 `project_memory_loaded`（正向命名会让 `null` 读起来像「没加载」）；
不叫 `restricted_blocks_memory`（把旗标名写进字段名，厂商改名即失真）。

**判据（纯函数 `judgeProjectMemoryBlocked`，两臂）**：

| 观测 | 结论 |
| :--- | :--- |
| 受限臂未跑完（超时 / 无 result / 非 success） | `null` |

## 8. 两个我核出来的**新缺口**（顺手补，不补也要登记）

### 8.1 分解形的 `Read,Grep,Glob` **逃出第 6 条的分词器**

`quotedTokens`（`registry-parity.test.ts:1144-1165`）按空白切分、按 `=` 切两半，
而黑名单里的是**逗号连写**的 `'Read,Grep,Glob'`。写成 `['Read','Grep','Glob']`
三个独立字面量 ⇒ 三个 token 分别是 `Read`/`Grep`/`Glob`，**一个都不在黑名单里 ⇒ 全绿**。
**而那正是 `readonlyToolsFromProbe` 被绕过后最自然的写法。**

**补法**：归属映射里给每个 token 再派生一份「分解形」（含 `,` 的 token 按 `,` 切开，
各段也登记为该家的 token），**只在归属家自己的适配器文件上启用**这条加强判据
（别家文件里出现裸 `Read` 误伤面太大）。纯收窄，无真阳性损失。

### 8.2 白名单派生与 `judgeToolSurface` 是两套口径，**没有对账**

探针侧 `judgeToolSurface`（`probes/claude.ts:246-266`）用 `READONLY_TOOLS.split(',')`
作期望集；适配器侧用 `readonlyToolsFromProbe(probe.readonly_flags)`。
两者今天同值，因为 `readonly_flags` 就是 `[...READONLY_INVARIANTS]`（`:906`）。
探针有**三个清空点**（工具面读回为空 `:889`、工具面脏 `:896`、breach `:980`），
清空后派生返回 `[]` ⇒ 适配器该侧不可用（§6.4 挡住），链路自洽。
**但「两者同源」这件事没有任何用例守着。**

**补法**：一条契约用例，断言 `readonlyToolsFromProbe([...READONLY_INVARIANTS])`
与 `READONLY_TOOLS.split(',')` 逐项相等（测试可以 import 探针）。
「一处事实一个来源」的机器对账，成本一行。
