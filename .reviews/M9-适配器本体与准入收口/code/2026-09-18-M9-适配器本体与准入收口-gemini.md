**问题**：EV-39 静态主扫的分解形 token 仅匹配单个工具单词或完整食谱常量字符串，漏检了「逗号分隔的部分子集或重排组合」（如 'Read,Grep' 或 'Read,Glob,Grep'），且分解形检查仅限定在归属家自身文件上运行。

**依据**：在 test/unit/registry-parity.test.ts 中，PROBE_RECIPE_TOKENS 包含完整字符串 'Read,Grep,Glob'，decomposedTokensOf(cli) 生成单项 Set {'Read', 'Grep', 'Glob'}。quotedTokens 提取的是带引号字面量。若适配器代码写入 'Read,Grep'，因不等于完整 recipe 且不匹配单项 decomposed，会同时漏过检查 ② 与 ④；此外检查 ④ 仅对归属本厂商的适配器生效，跨厂商适配器若写入其分解项则不会触发拦截。

**建议**：将分解形匹配升级为集合子集包含判定：对扫描到的任意逗号分隔字符串拆分后，若其所有元素均为已知工具名且属于该厂商，即认定为字面重建；同时将跨厂商错用判定延伸至跨厂商分解项。
