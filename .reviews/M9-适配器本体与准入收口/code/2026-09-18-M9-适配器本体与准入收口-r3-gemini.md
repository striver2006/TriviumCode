### AGY-01 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `scripts/mutation-check.mjs:192-202,285-289` |
| 类别 | correctness ｜ 层次 code |
| 置信度 | high |

**问题**：哨兵文件在检测到上次异常退出并抛错中止时，会在 finally 块中被误删，导致装置在下一次启动时失去保护，将污染的工作树误作干净基线。

**依据**：在 scripts/mutation-check.mjs 中，let dirtyExit = false 初始化于第 163 行。第 192 行调用 const stale = await staleRun()，若检测到哨兵文件存在，于第 194 行抛出 Error。该 Error 直接跳入第 258 行的 finally 块。在 finally 块中，遍历 targets 进行 copyFile 恢复并执行 build()。因为这些操作未抛错，dirtyExit 依然为 false。随后在第 288 行执行：if (!dirtyExit) await fs.rm(SENTINEL, { force: true })，直接将哨兵文件删除了。这意味着脚本在报出「上一次运行没有善终，确认后手动删除哨兵」的同时，自己在 finally 里把它删除了，下一次再跑时 staleRun() 返回 null，直接把带变异的脏工作树当成了干净基线。

**建议**：将 staleRun() 检查移出包裹 finally 恢复逻辑的 try 块（在备份与写盘之前先检查），或者在因 staleRun() 抛出异常时显式标记 dirtyExit = true，防止 finally 块自动移除哨兵。此外建议补充 SIGINT/SIGTERM 信号监听。

### AGY-02 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `scripts/claude-admission-control.mjs:257-273,382-386` |
| 类别 | contract ｜ 层次 code |
| 置信度 | high |

**问题**：准入脚本未同步 buildDenySettings 返回值由 string 改为对象的重构，传入 [object Object] 并导致 JSON.parse 抛出 SyntaxError。

**依据**：在 src/trivium/adapters/claude.ts:302-331 中，buildDenySettings 的签名被重构成返回 DenySettingsBuild 对象（{ json, ruleCount, bytes, skipped }）。在 scripts/claude-admission-control.mjs:257 中，const settingsJson = mod.adapter.buildDenySettings(s.paths, tools, shape) 取得的是该对象。在第 259 行将此对象传给 callOnce -> buildClaudeArgs，导致 --settings 参数被组装为 '[object Object]'。紧接着在第 273 行执行 JSON.parse(settingsJson) 时，对对象执行 JSON.parse 会抛出 SyntaxError: Unexpected token 'o', "[object Object]" is not valid JSON。第 382 行同理。准入脚本因此无法正常执行 deny-shape 与 stdin-parity 用例。

**建议**：在 scripts/claude-admission-control.mjs 的第 257 行与第 382 行取 denyBuild.json 作为 settingsJson 传给 callOnce，并在第 273 行直接使用 denyBuild.ruleCount。
