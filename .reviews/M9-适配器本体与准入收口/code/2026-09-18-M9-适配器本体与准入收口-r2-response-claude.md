## 1. 三个焦点的答案

**焦点一：约三十倍是否属实、剪枝会不会反过来漏掉本该禁读的东西？**
**量级属实但口径要改准**（§0.2）：同一时刻复算是 **25.5 倍**，我报的 30 倍是跨时刻相除，
且 v1.3.26 把它写成了「实测」。
**而「会不会反过来漏掉」——会，且本仓就是实例**（§0.3，CODEX-03）。
gemini 判「零漏禁」是基于「跨主题属于既往已完结任务」这个前提，
而 codex 指出该前提在「同一条工作换过名」时不成立——**后者对**。

**焦点二：两处新判据的边界划得对不对？**
**语法门划错了**（CODEX-02 ≡ GLM-04）：判据该是「是否仍能**字面**匹配」而非「是否破坏语法」，
`[ ] * ?` 是 fail-open 的口子且不进 `skipped`。
**分解形论域扩得对**（三侧一致），但**扩域有副作用**（CODEX-08：④-a 会误伤散文），
且**三处文档没跟上**（§0.4）。

**焦点三：五道闸是不是真能防住它声称防住的三类失败？装置自己有没有「声称强于事实」？**
**三类失败里防住了两类半**：闸 1（全路径备份）与闸 5（恢复后比对）成立；
闸 2「绝不吞」**在收尾那次不成立**（GLM-05）；闸 3 只防「测得出的」坏基线（CODEX-06）。
**装置自己有两条声称强于事实**（闸 4 的「产物」、闸 2 的「绝不」），
**且有一个不设防的入口**（`case.file ∉ targets`，三侧全中）——
**它在自己的入口上复现了自己要防的第二类失败**。

## 2. 本轮修改

### 2.1 补做三条 r1 未落地的承诺（GLM-01 / GLM-02）

- `claude.ts:479` 与探针侧同形处的注释改成字段**真实能承诺的范围**：
  「本机曾实测该逐文件形状可拦；**对本次注入的每条规则是否生效它一无所知**——
  逐条结果看 `trace.json` 的 `denySettings.skippedPaths`」；
- 报告 **§6 第三处**改成与 §2.1 同口径；
- **并在本轮留痕里如实记下「r1 有三条承诺未落地」这件事本身**（§0.1），
  不把它悄悄补上就算了。

### 2.2 让「跳过」在判定面可见（CODEX-01）

取 codex 建议的第 ① 条：把本次注入的规模与跳过条数**回传进 `CriticResult`**
（`deny_rule_count` / `deny_bytes` / `deny_skipped`），
`report.ts` 在 `skipped > 0` 时推一条**与 `peer_deny_applied === false` 同档**的降级旗标。

**理由**：现在唯一记录在 `trace.json` 而全仓无消费方，且两条失败出口
（超时、未产出最终回复）在写 `trace.json` **之前**就 return——连那份记录都没有。
`guard.ts` 自己写着这类东西「要出现在判定结果里，而不是只躺在 `trace.json`」。

### 2.3 语法门判据从「破坏语法」改成「仍能字面匹配」（CODEX-02 ≡ GLM-04）

`denyPathRepresentable` 的不可表示集合从 `( ) \n \r` 扩到
**`( ) [ ] { } * ? ! \n \r`**，走同一条「跳过 + 逐条记名」通道（接上 §2.2 的判定面告警）。

**非 ASCII 仍然放行**——那条理由不变（267/270 是中文主题名，挡掉等于关通道），
而 glob 元字符与那条理由**无关**，挡它们零代价。

门注释里那句「已登记为准入脚本的后续实测项」**改准**：它当前不是登记，是一句空话。
真实登记见 EV-49（准入脚本补含元字符的路径臂）。

### 2.4 同族主题剪枝的限制写进持久面（CODEX-03）

**本轮落**：把「跨主题（**含同一条工作换过名**）的对端意见不再入禁读集」
写进设计的限制清单与 `enumerateDenyPaths` 的契约注释——
它现在只活在函数注释的一句解释性文字里，**不是承诺边界**。

**换扫描键登记 EV-48**，不在本轮做：那会改变**所有主题**的禁读集，
是比 topic 剪枝更大的行为改动，不宜在同一轮里对同一处连做两次
（与 r1 暂缓 EV-47 同一条理由）。

### 2.5 复算结果补进报告 + 口径改准（GLM-03）

- 报告补一张复算表：剪枝前后的 `deny_paths` 条数、规则数、字节数、ARG_MAX 占比，
  **并写明装置**（用生产 `buildDenySettings` 对真实 `run.json` 的 `deny_paths` 复算）；
- 设计 v1.3.26 里「**实测**降到」改成「**复算**为」，并补上 codex 的同时刻复算值
  （25.5 倍）与两个口径的差别——**跨时刻相除与同时刻复算不是一回事**。

### 2.6 变异装置：补第六道闸 + 两条声称改准（AGY-01 ≡ CODEX-04、GLM-05、CODEX-06）

| 项 | 改法 |
| :--- | :--- |
| 闸 4 的「产物」 | **补真正的产物断言**：变异后比对被测**产物**哈希（而非源文件）。取 codex 的第 ① 条而不是改措辞——r1 我接受该条时落点写的就是产物哈希，改措辞等于第二次降格 |

## 4. 一条要带走的：**裁决件本身需要一道机器闸**

本轮 §0.1 那三条是第六、七、八次同形，但它们与前五次有一个**本质区别**：

前五次的载体是代码注释、测试断言、实测报告——那些东西**有机器判据可挂**
（用例、契约扫描、类型检查），而本仓这一年补的正是这些。

**这三条的载体是裁决件**：一份写着「我会怎么改」的承诺书，
它走完了 `gate --check`（只查每条意见有没有裁决）与人工审批，
**而「承诺的落点是否真的被改了」从来没有任何东西检查**。

> **可执行的对策**：裁决件的「落点」列若写了具体文件或具体措辞，
> **下一轮开跑前应当有一道检查**：把上一轮 `kind: response` 件里承诺的落点
> 逐条与工作树比对（措辞类 grep、文件类看 diff 是否触及），
> 不符的在本轮 BRIEF 里显式列出。
>
> 这与「行为断言必须指得出用例」「完成声明要由机器产出」同族，
> 只是把论域再扩一层：**从「我写的代码」扩到「我写的承诺」**。
> 本轮是审查员替这道闸干了活（glm 逐条回去核 r1 应答件），
> 而那不该依赖审查员恰好想到这么做。

**这条本身也是一句承诺**，所以它按自己的规矩登记为 **EV-50**，而不是只写在这里。
