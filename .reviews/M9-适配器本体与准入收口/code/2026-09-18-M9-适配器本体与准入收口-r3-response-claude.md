## 2. 逐条改法

### 2.1 哨兵只删自己创建的那个 + 闸 6 不发假告警（AGY-01 ≡ GLM-02 ≡ CODEX-01、GLM-07）

取 codex 的 `wx` 方案，它**一并解决三个问题**：

| 改动 | 解决 |
| :--- | :--- |
| `fs.writeFile(SENTINEL, …, { flag: 'wx' })` 独占创建，成功才置 `mine = true` | stale 分支下 `mine` 恒 false ⇒ `finally` 不删哨兵；**并发两跑**的 check-then-write 窗口一并堵上 |
| `finally` 改成 `if (mine && !dirtyExit) rm(SENTINEL)` | 任何 stale 分支一律保留文件 |
| 加 `backupDone` 标志，`finally` 的恢复循环与 `rm(bak)` 只在 `backupDone` 时执行 | 闸 6 的假「树已脏」告警（GLM-07） |

同批改准两处文案：

- 284-287 行的注释——它现在描述的是一个实现没做到的行为；
- 199 行的拒绝文案——不再让操作者去删一个装置自己已删掉的文件。

**装置自身要有自测。** 这是 §0.2 的直接教训：变异装置是测别人的工具，
它自己此前一条用例都没有。本轮补一条**不花配额、不动工作树**的用例：
以临时目录为根跑 stale 分支，断言 ①退出非零 ②哨兵**仍在** ③恢复循环未打印告警。
这条用例的存在理由是它**能红**——把 `mine &&` 去掉当场红。

### 2.2 准入脚本跟上返回型（AGY-02）

257 / 382 行取 `.json`，273 行直接用 `.ruleCount`（不再 `JSON.parse`）。

**但只改这两行不够。** 根因是「`tsc` 的覆盖面 ≠ 调用面」，而本仓的 `scripts/*.mjs`
全部 import 生产模块——每一个都是同一个形状的潜在缺口。
本轮补一条**机器判据**：`scripts/` 下每个 `.mjs` 至少被一条 `node --check` 级的

我不把这条写成「以后记得改」——那正是 §0.1 第四条的形态。

## 3.5 修复后补记：**§2.9 的裁决被我自己的实测推翻了**

本节是修复完成后追加的，不改上面的裁决表——**裁决仍是「接受 CODEX-05 / GLM-06」**，
被推翻的是我给出的**改法**。

§2.9 第 1 步写的是「立刻把逗号、空格、反斜杠并入不可表示集合」，
理由是「三者都可达、匹配语义都未测，跳过的代价可见、fail-open 的代价不可见」。
§2.12 又写了「测出来若与保守黑名单相左，以实测为准放宽」。

**两条都执行了，而后者否决了前者**（实测见报告 §4.2，CLI 2.1.276，各一次真实调用）：

| 臂 | 观测 | 处置 |
| :--- | :--- | :--- |
| `[` | 哨兵**泄漏**、denials 空 ⇒ 匹配不到自身，fail-open | **挡**（判断正确） |
| `,` | 未泄漏、**进 denials** ⇒ 规则照常生效 | **放行**（首版挡错了） |
| 空格 | 未泄漏、**进 denials** ⇒ 规则照常生效 | **放行**（首版挡错了） |
| `*` | 未泄漏、也没进 denials | **判不出**；维持挡，但理由换成 r2 立的**过匹配**（独立成立） |

这个方言把路径**当字面量**处理，所以挡逗号与空格是**净损失**——
本可以被正常屏蔽的路径，规则被白白丢掉；而空格那一类恰恰来自
`walkSensitive` 对敏感文件的文件系统派生，**是最不该丢规则的一类**。

**反斜杠没排臂**，如实记为未测、维持挡，**不拿另两个的结论替它背书**。
剩余两格（`*` 的三义性、反斜杠）登记 **EV-51**。

这一节留在这里，是因为「保守超集零代价」这个论证本身有问题：
**它把「我没测」当成了「挡了不亏」**，而实测证明挡了会亏。
门的方向正确不论证字符集正确——codex 点破的正是这个区分，我先接受了这条意见，
却在同一轮里又按被它否定的方式改了一次。
