## 2. 本轮修改

### 2.1 `freeze()` 补 `topic`，并把调用链变成用例（CODEX-01）

- `review.ts:650` 的实参补 `topic: ref.topic`；
- **补一条调用链用例**：断言真实调用点确实传了 `topic`（照 `deny-matrix` 那条教训——
  只测被调函数的用例守不住调用点，而那正是 `driver` 那次失败的原因）；
- 改完**复算一次** claude 的 settings 规模，与 §0.1 的数字对照，结果进报告。

### 2.2 deny 规则逐条形状校验（CODEX-02 ≡ AGY-02）

- `buildDenySettings` 生成前**逐条校验路径能否表示成一条规则**（按 `rule_syntax`
  派生的形状），不满足的**跳过并逐条记因**到 `trace.json` 的 `degradations`；
- **新增第三格语义**：现在只有「没注入」与「注入了但被拒」，补上「这条路径无法表示」；
- `deny_paths` **去重**；
- **`peer_deny_applied` 的注释口径改准**：它能承诺的是「本机曾实测该形状可拦」，
  **不是**「本次这批规则条条生效」——我原来那句说得比字段能知道的多。

### 2.3 规模记录与阈值（CODEX-03）

- `trace.json` 的 `denySettings` 除 `ruleCount` 外**补 JSON 字节数**；
- **设一个基于 `ARG_MAX` 的阈值**，超阈值时明确报错或降级，而不是等 spawn 失败（E2BIG）；
- 设计 §3.7.1 那句 ARG_MAX 论证**标明它的论域是 prompt**，并补 settings 这一路。

### 2.4 分解形判据的三处漏检（CODEX-05 ≡ AGY-01 ≡ GLM-04）

| 漏检形态 | 修法 |
