**问题**：哨兵闸的拒绝路径自解除。闸 3 前半发现 stale 哨兵时在 try 块内 throw（191-201 行），控制流照常进入 finally：恢复循环对刚备份的文件做 no-op 拷贝必然成功、收尾 build() 从未被碰过的树上重建也必然成功 ⇒ dirtyExit 保持 false ⇒ 288 行 if (!dirtyExit) await fs.rm(SENTINEL) 把那个 stale 哨兵删掉。于是拒绝是一次性且自毁信号的：错误信息还指示操作者「确认工作树无误后删掉 .mutation-check-running 再来」（199 行），而文件已被本轮删除；若操作者据此直接重跑（消息让他先确认、但他刚被告知要删的文件已不在），第三次运行将在可能带着上次变异的树上静默开跑——恰是这道闸要防的「残留变异被当成干净基线」。装置的核心保证（善终信号跨运行持久、只由人确认后消除）在最需要它的那条路径上失效。
