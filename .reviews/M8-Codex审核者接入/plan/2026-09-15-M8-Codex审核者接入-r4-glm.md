### GLM-01 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §3.3（对应 src/trivium/adapters/base.ts:274-293、src/trivium/guard.ts:136）` |
| 类别 | correctness ｜ 层次 plan |
| 置信度 | high |

**问题**：「status completed + exit_code 0 + 命令形态为写类 ⇒ 沙箱失守」的推理链至少有三种第三种解释，且第一种几乎必然触发：(a) §3.3 明写「写动词的识别复用措施 b 已有的资产（WRITE_VERB_TARGET 那张表的动词集）」，但那张表的键集混着四类条目——写入点（cp/mv/install/tee）、链接（ln）、目录目标（cd/mkdir/rmdir/touch/pushd）、非读取动词（rm/chmod/chown），后两类不是写动词：cd/pushd 是纯目录切换、无写系统调用，在只读沙箱下恒成功。审查员第一次 `cd src/trivium && grep …` 就会以「写动词 + exit 0」进 write_events。(b) 幂等空操作：`mkdir -p <已存在>` 不发写调用即退 0，`rm -f <不存在>` 按 POSIX 退 0——写动词在场、成功退出，但没有任何写入发生。(c) 失败掩码：`touch x || true`、`; true`、未执行的条件分支——整条命令的 exit 0 不代表写子命令成功，「未被拒则退非零码」只对单条简单命令成立。而 guard.ts:136 是 `write_events.length > 0` 即 readonlyBreach、无分级，误报直接坐实「只读失守」指控（代价按 §3.3 自己的表述是整侧作废）。「误报面极小」的结论不成立。

**依据**：src/trivium/adapters/base.ts:274-293（WRITE_VERB_TARGET 全键集，注释自证混着「目录目标」「非读取动词」两类非写入条目）；src/trivium/guard.ts:136-137（readonlyBreach = result.write_events.length > 0）与 guard.ts:375-381（「只读失守」告警文案、不自动回滚要人工核对）；被审计划 §3.3 原文「复用…那张表的动词集…不新起一张表」；src/trivium/probes/codex.ts:637-652（负对照唯一形态：cwd 创建 breach.txt——§3.3 推理链的实测基础只覆盖这一种）

**建议**：§3.3 改为显式定义「写动词集」为该表键集的真子集（至少剔除 cd/pushd/ln，并单列 mkdir -p / rm -f 的幂等形态）；区分「整条命令 exit 0」与「写段成功」——按段判定，或对含 `||`/`;` 掩码结构的命中降级为「待人工核实」档而非直接失守；判定语义改动同步落进 §6 用例。
