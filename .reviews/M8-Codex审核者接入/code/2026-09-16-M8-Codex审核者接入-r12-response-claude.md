CODEX-07 ③ 提的这一点我认为成立，但**改法属新决策，不在本件裁定**。

论点：`profile` 名是**本机事实**（`$CODEX_HOME/<name>.config.toml` 得真存在），
把它钉进进 Git 的共享层，等于要求每个协作者的机器上恰好有 `qwen` 这个 profile。
而 `config.local.yaml` 正是为这类本机事实准备的逃生门——**被我当作「冗余影子」删掉的那一层**。

我当时删它的理由（避免共享层与本机层同值并存、日后改共享层被静默顶掉）本身成立，
但它没有回答「这两个键是不是本该分在两层」。

**一个可能的分工**：共享层只钉**模型与 effort**（项目级选择，有实测依据），
`profile` 留给本机层或内置默认（环境事实）。代价是又回到「codex 的 profile 靠默认兜底」，
而那正是决策 C 想消除的不对称。

两者不能兼得，需要你拍板。**本件不动它**，按现状（共享层钉两者）交付，并把这条记进待议。
