## 1. 处置

### 1.1 引号与分段的交接（AGY-01 ≡ GLM-02）

**根因**：`dequoted` 阶段对**不含空格**的引号段原样保留内容（`` ` ${inner} ` ``），
随后 `split(/\|\||&&|[|;()]/)` 对整串分段——引号内的 `;`、`|`、`(`、`)`
到这一步已经和真分隔符无法区分。

**修法**：无空格分支若 `inner` 含段分隔符（`;&|()`）也**整段丢弃**，
与含空格分支同判「宁可漏报不虚构」。这样一并防住两种后果：
假分段（真实读取落段首被当动词吞掉）与写动词上下文丢失（写目标被计成读取）。

代价是 `grep '};' src/a.ts` 里的 `src/a.ts` 提不出来——**这是漏报，可接受**；
而现状是同一条命令要么整条漏、要么把 `sed -i` 的写目标计成读取，后者是虚报，更坏。

**文档块措辞一并改**（GLM-02 的第二点）：现在写着引号穿透「与措施 b 的 F-5/F-9 同向」，
而 F-5 的穿透**不产生这种错切**——措施 b 是在整串上搜字面量，不分段。
改为如实描述两者的差别，不再宣称同向。

补负断言：`grep '};' src/a.ts`、`sed -i 's/|/x/' src/a.ts` 各一条。

### 1.2 归因扣除的边界敏感匹配（AGY-03 ≡ GLM-01）

实跑确认 `"write_to_file(/proj/src/metadata.ts)".includes("data.ts") === true`——
不相干文件被误扣。

**修法**取 GLM 给的省事解：`ev.includes('/' + f)`。
漂移侧是项目相对路径（`freeze.ts` 的 `diffTrees` 输出），
证据侧嵌的是绝对路径（`agy-events.ts` / `zcode-trace.ts` 的 `${toolName}(${path})`），
相对路径在绝对形态里恒被 `/` 包住，这一条就能杀掉尾段子串误扣。

**注释改为如实描述**（GLM-01 的第 (a) 点）：r6 应答件写的是「扣除前要先解析出路径」，
而实现做的是包含判定。**承诺与实现的落差要消掉**——
改注释说清这是边界敏感的包含判定，以及它的已知限制：
agy 侧参数 JSON 被 `slice(0, 80)` 截断时可能漏扣，**漏扣方向保守**（留在原桶）可接受。

补负断言：「尾段子串不相干文件不得被扣除」。

### 1.3 report 的重复文案（AGY-02 ≡ GLM-03）

`:257` 的合并 suffix 与 `:287` 的独立 push 并存，`un > 0` 时必然同屏两条。
**删独立行**，保留合并行内的 suffix——数值本来就没重复计数
（`shown = drift.files.length + un`，归因激活时前者恒 0），重复的是文案。

`:250` 的注释「整批移进了 `unattributed_drift_files`」改为「扣除确诊失守后的余批」——
`attributedToBreach` 扣除之后就不是整批了，这是 §1.2 那次修改留下的措辞欠账。

### 1.4 集成测试补第四面与精确计数（AGY-04、AGY-05 ≡ GLM-05、GLM-03、AGY-06）

1. **补第四面**：调用复盘报告渲染，断言 `guardFlags` 含降级两行与合并后的漂移行。
   五面留痕的第四面此前零判据，而本轮 report.ts 三处新逻辑恰好都没被咬住——
   AGY-02 那个重复 push 能溜进来，正因为没有断言。
2. **精确计数**：断言 gemini 侧 `project_reads` 的确切值。

   `evidence_ok === true` 这个聚合断言——改坏一条命令不会红。
   **落断言前先实跑校正一次期望值**，不照搬审查员算的 6（他们没跑，我也不该照抄）。
3. **反向断言**：正文横幅用例补 glm 侧的 `doesNotMatch`（AGY-04 第二点）。

实际只改了 `base.ts` 的注释，设计文档 grep「虚报/虚高/断尾」零命中。

- **加排除规则**：`cd`、`git -C`、`mkdir` 的目录目标位不是读取，按 `cp` 的 `last`/
  `all-after-flags` 同款处理；URL 形态（`//` 开头或含 `://`）不进 gitObj 剥离。
  这四类都是审查员命令的高频形态，实跑已确认全部虚报。
