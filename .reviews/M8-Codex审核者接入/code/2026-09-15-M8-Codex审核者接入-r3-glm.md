### GLM-02 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/adapters/base.ts:403（F-6 入口的 before === '.' 分支）与 :302-315（prefixIsOnlyDotHops）` |
| 类别 | correctness ｜ 层次 code |
| 置信度 | high |

**问题**：焦点一的反面发现：归一判段引入一个新的误报面。「文件名 = 前置点 + deny 短名」的命令会被判命中：deny 为 .env 时 `cat ..env`、`cat n/...env`，deny 为 id_rsa 时 `cat .id_rsa`。机制：这类匹配的 before 字符是 '.'，被 F-6 入口放行；回扫出的 prefix（`.`、`n/..`）经 normalize + filter 后段列表为空，`.every()` 对空数组恒真 → 判命中。而 `..env`/`.id_rsa` 是单一文件名，shell 不在文件名内做点级解析——任何 cwd 下都不可能读到 deny 文件，纯属误报，代价是误作废一侧。这正是 r2 收窄想消灭的 sensitive_globs 短名误报族（config.ts:238 默认含 `.env*`、`**/id_rsa*`）的残余入口，且【误报】组现有四条用例没有任何一条钉这个方向。

**依据**：base.ts:389-403（before === '.' 进 F-6 分支）、:302-315（normalize(prefix).split('/').filter 后 .every，空段列表恒真）逐行手推：`cat ..env`（deny 含 .env 的 rel 拼写）——拼写于 index 5 命中、before='.'、token=`..env`、prefix=`.` → normalize('.') → 段列表空 → true；`cat n/...env`——prefix=`n/..` → normalize → '.' → 同样恒真。test/unit/peer-leak-command.test.ts:176-199【误报】组仅覆盖兄弟目录/他库绝对/路径尾巴/`~` 四族，无点串方向用例；config.ts:238 为 sensitive_globs 默认值。本条为逐字符手推、未实机运行。

**建议**：二选一：(1) F-6 锚定只认 before === '/'——'.' 粘连视为文件名一部分直接判否（现有全部 F-6 真阳性的 deny 拼写前都是 '/'，'.' 分支没有可失去的真阳性）；或 (2) prefixIsOnlyDotHops 要求 prefix 以 '/' 结尾——不结束于 '/' 的 prefix 是文件名内嵌点，判非 hop。无论选哪个，补 `cat ..env`、`cat n/...env` 两条负断言。
