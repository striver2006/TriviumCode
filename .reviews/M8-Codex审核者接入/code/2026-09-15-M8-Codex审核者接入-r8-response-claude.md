**修法回到 r6 应答件的原案**：从 `toolName(<path>)` 剥出路径、归一后**相等比对**。

## 1. 处置

### 1.1 归因扣除改为路径解析后相等比对（GLM-01 ≡ AGY-03）

```ts
// 从 `toolName(<path>)` 取最后一对括号内的内容，归一后相等比对
const breachedAbs = new Set(breachedFiles.flatMap(ev => { …剥括号… }));
const attributedToBreach = (f) => breachedAbs.has(nodePath.resolve(projectRoot, f));
```

取**最后**一对括号（`lastIndexOf(')')`）而不是第一对：路径自身含括号时
（`write_to_file(/proj/report(1).ts)`）按第一对切会把路径截断。

**已知限制如实登记**（漏扣方向，保守可接受）：剥不出路径的形态一律**留在原桶**——
agy 侧拿不到 `path` 时用 `JSON.stringify(parameters).slice(0, 80)` 填充、
被截断的长路径、不带括号的自定义事件串。宁可多报一个「无法归因」，
也不要把有证据的漂移悄悄归掉。

注释里把三轮的失败路子都记下来（§0.2 那张表），让下次改这条判据的人
不必重走一遍。

### 1.2 git 范围与引用排除（AGY-02）

两条判据分开，因为误伤面不同：

- **范围语法**（含 `..`）：无条件排除。真实路径里出现连续两点只能是 `../` 前缀，
  不会是中缀——所以 `cat ../Other/x.ts` 不受影响（已补断言）。
- **裸引用**（`origin/master`、`refs/…`）：**只在 `git` 命令段内**排除。
  `origin/master` 与一个真实的同名目录在字面上无从区分，脱离 git 上下文去排除会误伤。

边界登记补上这一族（注释 + 设计 §11.1 表）。

### 1.3 引号漏报的限定表述（GLM-02）

注释从「② 这一类没有付出漏报代价……引号内本来就不是路径」
改为「② **在引号内是模式/脚本时**不付漏报代价」，并显式写出反例：
`cat 'report(1).ts'`、`cat 'src/a;b.ts'` 的引号内**就是路径**，与 ① 同付漏报代价。

两处漏报登记（`base.ts` 文档块、设计 §11.1 表）都从「引号内含空白的路径」
改为「引号内含**空白或段分隔符**的路径」。

> 这条清单是第 3 步标定折减系数的依据（GLM-02 指出），少登记一族就会让
> 「读数系统性偏低」的口径少算一类。

### 1.4 漂移行的零值抑制（AGY-01）

`shown === 0` 时不推漂移行——那种情形下「只读失守」旗标已经把事说清了，
再打一条「漂移 0 个文件」纯属噪音。

### 1.5 非读取动词进表（GLM-03）

`rm` / `chmod` / `chown` / `ln` / `pushd` 补进 `WRITE_VERB_TARGET`。

**`ln` 用 `all-after-flags` 而不是 `last`**：我起初按 `cp` 类比设成了 `last`，
测试当场红——`ln -s a.ts b.ts` 里**两个参数都不读内容**，源只是被记下路径、
链接名是写入点，与 `cp` 不同族。这是 GLM-03 提的处置在实现时又细分出的一格。

登记措辞按 GLM-03 改口径：「表外的**目录型**动词」→「`WRITE_VERB_TARGET` **表外动词**的
目标/参数位——目录型（`rsync`）与非读取型（`echo src/a.ts`）都算」。
类别不止一类，登记就不该只点一类。
