## 1. 处置

### 1.1 提取器重写（AGY-01 ≡ GLM-02、GLM-03、AGY-05）

四处结构性改动：

1. **按命令边界分段**：先以 `|`、`;`、`&&`、`||` 切成命令段，**每段各自取段首为动词**，
   再套写动词规则。现在的实现在整条展平表上取 `rawTokens[0]`，管道后的 `tee`、
   第二条命令的读取全都判错。
2. **动词取 basename**：`/bin/cp` 与 `cp` 走同一条规则；动词 token 本身不计入路径。
3. **fd 前缀重定向**：判定改为「剥掉前导 `[0-9]*` 后再看 `>` / `>>`」，覆盖 `2>`、`2>>`、`1>`。
4. **`~` / `$HOME` 展开**：提取后、归一前展开，与措施 b 的 `spellingsOf` 同口径。

判型收窄两条（GLM-03）：

- 不含 `/` 且形如 `\d+(\.\d+)+` 的版本形态不计（`v1.3.8..v1.3.9`）；
- **引号内含空格的段整段丢弃**——宁可漏报也不虚构半截路径。
  这一条是对口径 1「引号穿透」的修正：穿透是为了拿到被包住的路径，
  而不是为了把一个路径切成两半。

每族补一条负断言：`2>` 形态、管道内 `tee`、双命令 `cp`、版本区间、带空格引号路径。

### 1.2 归因分流的两个边界（AGY-02，方向按 GLM 保留）

**方向不动**：「任一侧 `unavailable` ⇒ 整批不归因」保留。指纹是整树快照、
无法逐侧分配，GLM 的论证成立。

**两处边界修正**：

1. **改用 `input.capabilities` 计算**，不用 `sides`。
   `sides` 只含成功侧（`timeout`/`failed` 在循环里被 `continue` 跳过），
   而 capability 是**静态声明**，从 `input.capabilities` 直接可得，不依赖该侧是否跑成。
   现在的写法有个很坏的性质：**不可用侧崩得越彻底，归因越"自信"**——
   它超时 ⇒ 不进 `sides` ⇒ `anyReadonlyUnavailable=false` ⇒ 漂移被记成开发者手改。
2. **扣除已确诊失守的文件**：`readonlyBreach` 为真时，那批文件有正向证据，
   不该进「无正向证据」的桶。`breachEvidence` 是事件描述串（`write_to_file(/abs/x)`）
   而非纯路径，扣除前要先解析出路径；解析不出的保守留在原桶并在注释里写明这个限制。

**连带**（GLM-08）：`report.ts` 推漂移旗标时把两个桶合并展示，
改为「漂移 N 个文件（其中 M 个无法归因）」，避免「漂移 0 个」与「N 个无法归因」并排。

### 1.3 补集成测试，兑现「机器判据」（GLM-01 ≡ AGY-04、GLM-07）

**这一条是本轮最该接受的。** 我在 `stub.ts` 里写着「`command-trace` 形态仍然可以在
集成测试里被真实走到」——现在时，而没有任何测试这么做。
r2 裁决 AGY-04 之所以把挂载点从注册表改到适配器，理由就是「桩可以声明能力、
泛化才有机器判据」。判据没兑现，那条论证就只剩一半。

补一条走真实子进程的集成测试：`TRIVIUM_STUB_CRITIC` 注入 `command_trace` 模式跑
`review --start`，一次用例咬住整条链：

- 该侧 `evidence_ok === true`（回填生效，`toolTotal` 分档生效）；
- `run.v2` 的 `guard.verification_degraded` 落了该侧的 `readonly`/`path`/`evidence_threshold`；
- 审查文档 front-matter 出现 `readonly_verification` / `path_verification` 两键；
- 运行时告警含降级两行。

**桩的六条命令同时补齐**（GLM-07）：现在六条全是只读命令，
注释却声称覆盖「写目标位、逃逸相对」。补一条含 `2>/dev/null` 或 `tee`、
一条 `cat ../Other/x.ts`，使声明与清单一致——**并让新增的集成测试咬住它**，
否则下次写错清单仍然不会红。

### 1.4 零值与折减依据（AGY-03 ≡ GLM-05、GLM-06）

**零值特判**：`configured <= 0` 直接返回 `configured`。
`config.v2.json` 对 `min_project_reads` 允许 `minimum: 0`（显式关闭下限），
现在 `command-trace` 侧被静默重新启用为 1，是两族语义分叉。
GLM-05 的观察更省事：`Math.max(1, ·)` 的**唯一作用面就是 0**，去掉它即可。

**折减依据改写**（GLM-06）：删掉「实测样本里直引形态占多数」——
r3 裁决 §1.2 刚判定该样本「是探针单次哨兵 fixture、不能用于标定审查全过程阈值」，
而全仓实测样本只有 1 条命令，n=1 谈不上「占多数」。
改为如实表述：依据是**设计预期**（BRIEF 提供绝对路径、提取以直引绝对形态为主，
这是 r3 裁决已给的合法依据），系数值**待第 3 步真实 codex 轨迹回标**。

> 这条是我刚记过的教训当场复发：r3 裁决 §2 第 1 条写的就是「引用一个已有机制作为
> 新口径的依据前，先读它的实现」，而这次是**引用一份我自己刚判定不可用的样本当依据**。
> 形状同源：论据没核实就写下。

### 1.5 注释、文案与文档同步（GLM-04、AGY-06、GLM-03、AGY-07）

- **`types.ts` 的消费方注释**改为「消费方（**M8 第 3 步起**）：`doctor` 的能力对账
