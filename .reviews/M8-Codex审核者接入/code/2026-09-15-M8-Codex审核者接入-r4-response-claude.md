## 2. 逐条处置

### 2.1 AGY-01 + GLM-06 —— `tildeUserHit` 的正则重写

**根因是我手写了第二套边界定义**，没复用 `CMD_BOUNDARY`。五类问题：

| # | 形态 | 方向 | 来源 |
| :--- | :--- | :--- | :--- |
| ① | `echo ~;cat/.trivium/runs`（九种控制符） | 误报 | AGY-01 |
| ② | `diff {other,~user/…}`（右花括号） | 漏检 | AGY-01 |
| ③ | `pkg@1.0~alpha/…`（`~` 前无边界） | 误报 | AGY-01 |
| ④ | `x~y/…`（词中 `~`，shell 只在词首展开） | 误报 | GLM-06 |
| ⑤ | `~$HOME/…`（不是合法登录名） | 误报 | GLM-06 |

**落点**：正则改为从 `CMD_BOUNDARY` 派生字符类（**一处定义，三处共用**），并加词首边界：
用户名段排除全部边界字符与 `$`，后缀段同样排除全部边界字符。
③④ 由词首边界解决，⑤ 由排除 `$` 解决。

**GLM-06 判 nit 我不照搬**：它的理由是「方向保守、概率低」，成立；
但既然 ①②③ 已经要动这条正则，④⑤ 顺手一起收**零额外成本**，
留着就是「已知却不改」——那正是本主题反复批评的形态。

### 2.2 GLM-02 —— 替换外壳被回扫切掉

`pathTokenAround` 在 `(`、`{`、反引号处截断，于是 `$(pwd)/<rel>` 的 token 只剩 `/<rel>`——
**`UNRESOLVABLE` 永远看不到它本要保守处理的那个 `$`**。

`$VAR/` 能命中纯属巧合：`$` 不是边界字符，留在 token 里了。

**按 GLM 的建议 (a) 真收**，不登记为 B-7。理由：
`cat $(git rev-parse --show-toplevel)/.env` 是 **agent 在任意 cwd 读项目根文件的教科书写法**，
与 F-6 的 `../` 同属「非对抗穿透」——威胁模型承诺必检的那一类。
登记为盲区就是又一次把承诺面缩到实现的形状上。

**落点**：回扫后检查截断点左侧是否紧邻 `(`/`{`/反引号（替换标记的外壳），是则保守命中。

## 5. 一条要带走的

**§2.6 那条是本轮最该记的，因为它不是疏忽，是论证上的偷换。**

我给 B-6 写的拒绝理由是「剥引号要处理嵌套与转义」——那是**完整引号解析**的难度。
而实际需要的只是「删掉所有引号再扫一遍」，**不需要解析任何结构**。
我用一个更难的问题替换了实际问题，再以前者的难度为由拒绝了后者。

这比前几轮的「写下不存在的保证」更隐蔽：那些是**事实错误**，查一下就能发现；
这个是**论证结构错误**，读起来完全通顺，只有真去想「那个更简单的做法为什么不行」
才会发现它从未被评估过。

所以纪律再加一条：**写下「不做，因为太难」之前，先写清楚「最简单的可行版本是什么」。**
如果写不出那个版本，说明我还没想清楚；如果写出来了、发现它并不难，
那么「太难」就是个假理由。

> 本轮另有一处同族的小账：AGY-03 的死论证我已经删过**三次**（§18.1、`guard.ts`、
