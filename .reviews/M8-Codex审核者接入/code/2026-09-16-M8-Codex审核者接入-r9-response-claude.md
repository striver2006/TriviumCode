### 1.1 掩码判据重写（AGY-02 ≡ GLM-01，blocker）

**判据改为**：`&` 只在作为**命令分隔符**（后台运行）时算掩码——前后都不是 `&`，
前面不是 `>`（排除 `2>&1`、`>&2`），后面不是 `>`（排除 `&>file`）。

```
/\|\||;|(?<![&>])&(?![&>])/
```

**管道另行处置**（AGY-02 的补充，glm 未提）：`a | b` 在无 `pipefail` 时整条退出码
只反映最后一段，`touch src/x.ts | true` 同样是掩码形态。但 `|` 已经是**分段符**
（`segments` 按它切开），所以正确做法不是把它并进 masked，而是
**让掩码判定按段计算而不是按整条计算**——这也一并解决 glm 指出的 heredoc 问题
（正文含 `&&`/`;` 时整条被掩码）。

**锁例**（每条都必须是新用例，不是改断言）：

| 命令 | 期望 |
| :--- | :--- |
| `cd . && echo x > src/a.ts` | `writes` 非空 |
| `echo x > src/a.ts 2>&1` | `writes` 非空 |
| `echo x > src/a.ts &> /dev/null` | `writes` 非空 |
| `touch src/x.ts \| true` | 疑似（管道掩码） |
| `touch src/x.ts &` | 疑似（后台掩码） |
| `touch src/x.ts \|\| true` | 疑似（既有行为不变） |

**注释同步**：`base.ts` 两处「`&& `不算掩码」的断言旁边各加一行指向锁例的引用
（§0.2 的新纪律：写下行为断言就当场指出断言它的用例）。

### 1.2 `looksLikePath` 按动词分档（AGY-01 ≡ GLM-02）

**重定向目标不过滤**：`>` / `>>` 右侧紧邻的 token **就是**写入目标，
不需要「看起来像路径」这道启发式——它本来是给「参数位猜测」用的。
这一改直接消掉 `echo bad > Makefile` 的完全漏报。

**写动词的操作数按动词分档**：

| 动词族 | 过滤 | 理由 |
| :--- | :--- | :--- |
| `mkdir` / `rmdir` / `rm` / `touch` / `ln` / `install` / `truncate` | **不过滤** | 非旗标操作数恒为路径 |
| `chmod` / `chown` | **跳过第一个非旗标操作数**（mode / owner），其余不过滤 | 见 §1.4 |
| `cp` / `mv` / `tee` / `dd` | 不过滤 | 同上 |

**锁例**：`echo bad > Makefile`、`rm Makefile`、`mkdir build`、`touch LICENSE`
四条全部进 `writes`；`chmod 644 src/a.ts` 的 `644` 不得成为 sink。

### 1.3 幂等判定认长旗标（GLM-03）

`^-\w*p` / `^-\w*f` 改为同时认 `--parents` / `--force`（以及 `-p` / `-f` 的组合形态）。
**锁例**：`mkdir --parents src/existing` 与 `rm --force src/gone.ts` 均落疑似档。

> 这一条的方向是**防误杀**：判不出幂等就会把一次没有实际写入的成功命令
> 判成只读失守、整侧作废。本主题历轮对误杀方向的定级一贯更重（r8 在案）。

### 1.4 `chmod`/`chown` 首操作数与第五处回落（AGY-03、AGY-04）

**① `chmod`/`chown`**：写入位改为「跳过第一个非旗标操作数」。
锁例：`chown user.name /tmp/target.ts` 落疑似（目标在项目外）而非 `writes`；
`chmod 644 src/a.ts` 仍进 `writes` 且 sink 是 `src/a.ts`。

**② 第五处回落**：`review.ts` 把 `sides` 的解析**提到** `checkModelSlugs` 之前，
并显式传第四个参数。

锁例走集成测试（单测守不住调用链——M7b 第 5 步的教训）：
`review --start --critics <非默认侧> --model-<该侧> <非法 slug>` 必须退 64。

### 1.5 `ln` 单操作数与 `-t` 目标目录（AGY-05、GLM-04）

- **`ln` 单操作数**：过滤后只剩 1 个操作数时，目标是 cwd 下的 `basename`，
  而不是那个操作数本身。锁例：`ln -s /etc/passwd` → 目标归一为 `<projectRoot>/passwd` → `writes`。
- **`-t <dir>` / `--target-directory=<dir>`**：识别该形态并把目标位改判为那个目录。
  锁例两条（双向）：`ln -s -t /tmp src/a.ts` 落疑似；`cp -t src /tmp/a.ts /tmp/b.ts` 进 `writes`。

## 3. 一条给自己的记账

本轮暴露的三个缺陷有同一个形状：**我写下了一句关于行为的话，却没有断言守着它**。

- 注释说「`&&` 不算掩码」——没有用例断言（§0.2）；
- 契约注释说「进 doctor 输出」——没有消费方（GLM-05）；
- 收敛注释说「消灭同一个问题两个答案」——同一个文件里造了新的（GLM-07）。

v1.3.8 记过一条几乎相同的教训（「凡写下『保住了/会红/已覆盖』，当场指出对应断言在哪一行」），
r4 我又给自己加了一条（「凡写下『复用 X』，同句写出 X 的取值」）。
这一轮说明**那两条的适用面都定窄了**：它们只管「声称覆盖」与「声称复用」，
而这次栽的是**声称行为**。

统一成一条：**注释里任何形如「X 会 / 不会 Y」的断言，落笔时必须同时指出
断言它的那一行用例；指不出来就不许那样写。** 修复批次 A 的每条注释都按这条办。
