## 1. 逐条处置

### 1.1 GLM-05 —— 守卫接错了源（本轮唯一的实现缺陷）

**我把「守卫也要被守着」这条教训执行了一半。** r2 我把注释约定升级成运行期断言、
r2 变异验证又逼我给断言本身补了单测——**但没有人检查这个断言喂的是不是正确的输入**。

实测确认两条独立的事实源：

```
实际传参：readonlyArgsFromProbe → 无条件 push ZCODE_READONLY_DENYLIST（常量）
断言输入：bashStillDenied(probe.readonly_flags) ← 探针候选串的「接受性」记录
          probes/zcode.ts:75 那个固定串：'Write,Edit,MultiEdit,ApplyPatch,Bash'
```

两个失效方向，glm 都列了：

| # | 场景 | 后果 |
| :--- | :--- | :--- |
| ① | 有人从 `ZCODE_READONLY_DENYLIST` 删掉 `Bash` | 探针记录不变 → 断言通过 → `command_texts` 恒空 → **措施 b 在该侧静默失效**。**这正是守卫号称要拦的那个场景** |
| ② | 探针候选串被改（实际执行仍禁 `Bash`） | 断言误炸，整侧无谓判 failed |

**我认为 glm 把它记 minor 是低估了**——它使一个安全守卫在自己的目标场景下失效。
但严重度是审查员的判断，我不改它的标注，只在这里说明我的处置优先级：**排第一条**。

**落点**（按 glm 的建议，两条都做）：
1. 断言的输入换成 `readonlyArgsFromProbe(probe.readonly_flags)` 的**返回值**——
   那才是真正传出去的东西；
2. `zcode-bash-denied.test.ts` 补一条 `bashStillDenied([ZCODE_READONLY_DENYLIST]) === true`——
   现有用例全传字面量镜像串，守不住常量本身的漂移。

## 4. 一条要带走的

**我在写下一条规矩的同一份文档里违反了它。**

v1.3.8 的变更条里我写：

> 凡写下「保住了 / 会红 / 已覆盖」这类保证，当场指出它对应的断言在哪一行；
> 指不出来就不许那样写。

而同一条变更记录里还写着「这句死论证我删过四次才**删干净**」——
**「删干净」就是这类保证，而我没有去核实它。** 第五处就在同一个补丁新增的测试注释里。

同族的还有三处：r4 修复清单第 6 项、第 8 项、以及 `known-forms-parity` 的动机注释。
**四处都是「完成声明」，四处都没核实。**

所以规矩要再具体一格，从「写保证时指出断言」推到**写完成声明时**：

> **「已改完 / 已删干净 / 全仓 N 处」这类完成声明，落笔前必须跑一次 grep 并把结果贴出来。**
> 记不清改了几处，就不要写数字——写「见下方清单」，让清单自己说话。

这一条比前面几条都具体，因为它有个**可执行的动作**（跑 grep、贴结果），
而不是一个需要自觉的原则。本主题已经证明：**需要自觉的纪律，我守不住。**

> 附带一条本轮的好消息，值得如实记：**区间对账机制生效了**——
> 它这轮没红，不是因为没查，而是因为区间字面量确实都对齐了。
> 漏掉的全是它论域之外的散文（AGY-04 点破的根因）。
> 这说明方向对，把论域从「区间」扩到「计数词」是同一条路的下一步，
> 不是另起炉灶。
