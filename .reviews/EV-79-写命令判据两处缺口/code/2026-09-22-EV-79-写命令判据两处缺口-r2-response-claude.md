## 4. 关于只读失守误报：本轮结论仍予采信，理由

   拿一条已知误报去作废审查结论，等于让缺口本身决定哪些意见可以被听见。

## 5. 一处方法记账（第二次写同一条）

应答件 §4 我写过：

> 凡写下「实测 / 断言见 / 位于某行 / 共 N 条」，落笔时必须当场打开被指向的那个东西核一眼。

**然后我在同一批改动里写了一条自己没核过的断言**（CODEX-01 ≡ GLM-01），
并且在证据脚本里犯了第二次同族错误（`_case_dir` 不校验，CODEX-02）——
两者都是「写下防御/断言，但没验证它在该失效时真的失效」。

补一条更可操作的：

> **新增一条防御性代码或一条回归断言时，当场做一次反向验证**——
> 把防御删掉（或把断言的前提破坏掉），确认它真的变红。
> 改不动产物就构造一个等价的最小输入验证观测差异。
> **「看起来能守住」和「删掉会红」是两回事**，本主题已经在这两件事之间栽了三次。
