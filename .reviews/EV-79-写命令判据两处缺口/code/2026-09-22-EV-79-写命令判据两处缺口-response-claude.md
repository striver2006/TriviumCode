## 2. Driver 侧复核实测

19 条我逐条核实，其中四处做了实测。**有一处我的实测比两侧的推演更精确**，记在下面。

### 2.1 读面对强制覆盖族：漏点不是两侧说的那一族（判 CODEX-02 ≡ GLM-01）

两侧都推演「文法少吞 `[|!]?` ⇒ `>&\| src/leak.txt` 的目标重新漏进读面」。
我做了这个变异并实测：

| 变异后（文法去掉 `[\|!]?`） | `extractPathTokens` |
| :--- | :--- |
| `echo x >&\| src/leak.txt` | **`[]`** —— 没漏 |
| `echo x >\| src/leak.txt` | **`[]`** —— 没漏 |
| `echo x >&! src/leak.txt` | **`["src/leak.txt"]`** —— **漏了** |

**原因**：读面自己的分隔正则是 `/\|\|&&\|[\|;()]/`，**没有 lookbehind**，
把 `\|` 后缀当分隔符切走了，于是 `\|` 族碰巧被挡住；`!` 不在那个字符集里，才是真漏点。

**所以**：「该补读面用例」成立（两侧对），「`>&\|` 会漏」不成立（机制要更正）。
补用例时 **`>&!` / `>>!` 是必补的真漏点**，`>&\|` / `>\|` 作对照并注明它们靠另一条正则挡住——
那是**耦合不是设计**，将来有人改那条分隔正则，这一族会跟着破。

| `cp /tmp/a src/b.ts >& 2` | `writes=[c]`、`suspected=[]` | 目标变 `2` ⇒ `/proj/2` 仍在项目内 ⇒ **观测形状相同** |
| `cp src/a.ts /tmp/out.ts >& 2` | `writes=[]`、疑似「项目外」 | 目标变 `2` ⇒ 项目内 ⇒ `writes=[c]` ⇒ **可分辨** |

注释与变异清单都指了前者。**真判别器是后者。**

### 2.3 写入目标冒充读取（判 CODEX-03）

| 命令 | `extractPathTokens` |
| :--- | :--- |
| `sed -i s/x/y/ src/f.ts` | `[]` ✓ |
| `sed -i s/x/y/ src/f.ts 2>&1` | **`["src/f.ts"]`** ✗ |
| `sed -i s/x/y/ src/f.ts >& 2` | **`["src/f.ts"]`** ✗ |

尾部重定向 token 抢走了「从段尾反向找第一个非 `-` token」的排除位。
与「证据自证」同类，EV-96～99 覆盖不到 ⇒ 新登 EV-100。

### 2.4 EV-98 的成因写错了（判 CODEX-09）

## 4. 一处方法记账

本轮 19 条里有 **6 条**是「我宣称了某件事，而那件事没有支撑」：

- 注释指向的用例不是判别器（CODEX-04）
- 组头说「每格都对应实测」而紧贴 fd 族无实测行（CODEX-05）
- 注释与设计按「既成实测」引用 rm 退码，而证据件里没有（CODEX-06 ≡ GLM-02）
- 行号引用在插入 41 行后全部失真（CODEX-08 ≡ GLM-03）
- EV-98 的成因经实测不成立（CODEX-09）
- 计数三处对不上账（CODEX-11 ≡ GLM-04）

设计 v1.3.10 定过一条纪律：「注释里任何『X 会 / 不会 Y』的行为断言，落笔时必须同时指出
断言它的那一行用例」。本轮说明它**不够**——还要加一句：

> **凡在注释、证据件抬头或留痕里写下「实测 / 断言见 / 位于某行 / 共 N 条」，
> 落笔时必须当场打开被指向的那个东西核一眼。**
> 指针类表述的失效是静默的：代码照常跑、测试照常绿，只有读它的人被带偏。

这一条与 EV-95（无执行能力却写「实测」）同源，但适用面更宽——EV-95 管的是跨侧的
能力边界，这条管的是**自己写的指针指向自己**。建议随本主题一并记进设计的方法教训段。
