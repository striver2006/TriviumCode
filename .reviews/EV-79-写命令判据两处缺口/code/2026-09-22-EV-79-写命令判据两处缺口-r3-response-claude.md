## 2. 需要展开的两条

### 2.1 为什么 `gate.test.ts` 的新断言要用**否定式**（判 CODEX-r3-01）

该侧建议「断言文案含『是否被 ignore』**或**不含『则是写事件判据误报』式反推句」。两者我取后者，理由是上一轮焦点六的教训：

- **肯定式锁**（断言含某短语）把文案钉死在一种写法上，文案正常演进就误伤——这正是我上一轮问「锁法是否过紧」的那个担心，而当时的答案之所以是「不过紧」，只因为它锁的是字段名而非措辞。换成锁措辞，那个担心就真的成立了。
- **否定式锁**（断言**不含**反推句）只禁掉一种语义，对措辞怎么演进都不敏感，而它要防的恰恰就是「有人把这句话改回双向口径」。判别力方向和误伤面都对。

落点写法：断言 `message` 不匹配 `/没有改动则是.*误报/`，并配一条正向的弱断言保留 `snapshot.drift` 字段名在场（原断言不删——它守的是「处置要给出 drift 分档指引」这个独立事实）。

### 2.2 对账表改造的真正难点（判 CODEX-r3-03 ≡ AGY-03 ≡ GLM-04）

三侧都要求「实测侧要有程序化输入」，但这件事有个约束要先说清：对账表脚本是 `node`，实测侧数据在 shell 探针的 `.out.txt` 里，**两者不可能在同一次执行里联动**（探针要真建文件，node 脚本跑在项目里不能建）。所以「派生」只能是**抄录 + 具名**：

- `CASES` 每行补第四字段，值来自 `probe-redirect-operators.out.txt` 的「建出文件」列，**并在行内注明抄自该文件的哪一格**；
- 由「判据取不到目标 且 第四字段为真写入」派生 `X:miss`，期望值里**不再出现** `X:miss` 字样；
- 脚本启动时核一次 `probe-redirect-operators.out.txt` 的存在与其戳，戳不上就整表拒跑。

这样 X 档的相符性就从「反填」变成「两份独立留痕的交叉核对」。它仍不是真正的端到端，但**失真面从"永远相符"降到"抄录出错"**，而抄录出错会被第三步的戳核对捕获一部分。这条限度我写进脚本注释，不当成完备。
