### GLM-02 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `doc/05_testing/evidence/ev79-shell-redirect-20260922/probe-delete-exit-codes.sh:34-41（probe_rm）` |
| 类别 | correctness ｜ 层次 code |
| 置信度 | high |

**问题**：probe_rm 把取报错与取退出码分成两次执行（38-39 行），对删除类命令这两次不幂等：第一次（取 err）若目标存在即已删除，第二次（取 rc）测到的是「目标已不存在」的退出码——`rm -r <存在>` 会从真实的 rc=0 记成 rc=1，方向恰是「把可达形态记成不可达」，正中缺口一论证的关键格。当前六个 case 全是「不存在目标 + 长旗标」，恰好安全（既有数据无失真）；而「对照：目标存在」段（53-56 行）作者单独写、只跑一次——说明坑是知道的，但通用函数没防、注释没警示。后续把存在目标形态加进 probe_rm（缺口一论证最自然的扩展方向）会产出与该对照段自相矛盾的 rc。这是焦点二点名问的「两次执行同一命令取报错与取退出码是否会彼此干扰」的格子：答案是对当前数据不干扰、对结构埋雷。

**依据**：读 probe-delete-exit-codes.sh 全文：38-39 行 err/rc 双次执行、52-56 行对照段单次执行的写法差异、43-50 行现有六格全部为不存在目标或长旗标形态。对照 probe-redirect-operators.sh:44-66 的 probe_zsh/probe_bash 同为双次执行，但 echo 重定向族幂等（重复执行 rc 不变、判别法只看建出什么文件），不受此坑影响。

**建议**：err 与 rc 合并为一次执行（先记 rc 再截 err），或在 probe_rm 注释写明「本函数只可用于对目标状态不敏感的形态（不存在/不可达），存在目标须仿对照段单次执行」。
