### 1.1 缺口一：递归 + 强制的四种写法全部落进疑似档

| 命令 | `writes` | `suspected` | 真实可达？ |
| :--- | :--- | :--- | :--- |
| `rm -rf src/existing-dir` | `[]` | `rm 的幂等形态…` | **可达** |
| `rm -r --force src/existing-dir` | `[]` | `rm 的幂等形态…` | 否（长旗标，见 §1.4） |
| `rm -R -f src/existing-dir` | `[]` | `rm 的幂等形态…` | **可达** |
| `rm --recursive --force src/existing-dir` | `[]` | `rm 的幂等形态…` | 否（长旗标，见 §1.4） |
| **对照** `rm -r src/existing-dir`（无 `-f`） | **`[命令]`** | `[]` | **否**——退 1，进不了判定层（§1.4） |
| **对照** `rm -f src/gone.ts`（无 `-r`） | `[]` | `rm 的幂等形态…` | **可达** |

> **「真实可达」列是 r2 新增的**，因为 r1 通篇写「以下全部在编译产物上实测」，
> 读起来像一份**真实可达形态清单**，而其中三行不是：
> 两行长旗标在本机 BSD `rm` 上根本跑不起来（退 64），
> 对照行 `rm -r <不存在>` 退 1 而判定层只收退 0 的命令。
> 它们作为**分类器直调的合成输入**仍然有效（单测本就直调 `classifyWriteCommands`），
> 但**不能拿来当可达性依据**。

> BACKLOG 写的是「`rm -rf` 短旗标形态修前已如此，长旗标是 `3812f4c` 扩展时新纳入的」——
> 实测确认**四种写法今天都落疑似**，不只是长旗标那一格。

**成因**（`base.ts:967-970` 的 `idempotent` 判据）：

```ts
const idempotent =
  (verb === 'mkdir' && tokens.some((t) => /^-\w*p/.test(t) || t === '--parents')) ||
  (verb === 'rm' && tokens.some((t) => /^-\w*f/.test(t) || t === '--force'));
```

判据只问「有没有 `-f`」，不问「是不是递归」。

### 1.2 缺口二：双流重定向静默漏检，且**倒过来产出一条假读取**

| 命令 | `writes` | `suspected` | `extractPathTokens`（读路径） |
| :--- | :--- | :--- | :--- |
| `echo secret &> src/leak.txt` | `[]` | `[]` | **`["src/leak.txt"]`** |
| `echo secret &>> src/leak.txt` | `[]` | `[]` | （同上形态） |
| `echo secret &>src/leak.txt`（紧贴） | `[]` | `[]` | `[]` |
| **`echo secret >& src/leak.txt`** | `[]` | `[]` | **`["src/leak.txt"]`** |
| **`echo secret >&src/leak.txt`**（紧贴） | `[]` | `[]` | `[]` |
| **对照** `echo x > src/a.ts` | `[命令]` | `[]` | **`[]`** |
| **对照** `echo x > src/a.ts &> /dev/null` | `[命令]` | `[]` | — |

> 后两格 `>&` 是 **r2 新增**（glm 实测，r1 的论域里没有）。
> bash REDIRECTION 章把 `&>word` 与 `>&word` 并列为双流重定向的两种格式，
> 二者**语义等价**。

**成因（两条，同源）**：

1. `REDIRECT_RE = /^[0-9]*>>?/` 只认可选 fd 前缀，**认不出以 `&` 打头的 token**。
   于是 `&>` 拿不到写目标，`echo` 又不在 `WRITE_VERBS` 里（兜底也不命中）。
2. `>&` **能**命中 `REDIRECT_RE`（匹配掉 `>`），但残留 `&src/leak.txt` 以 `&` 打头，
   被 `base.ts:828` 的 fd 复制排除 `if (!glued.startsWith('&')) sinks.push(glued)` 整个吞掉。
   分离写法 `>& src/leak.txt` 的残留是**裸 `&`**，既不 push 也不走 `else if (tokens[i+1])` 分支，
   于是下一 token `src/leak.txt` 无人认领，落进读路径。

> **`SEGMENT_SPLIT_RE` 那一半是对的**：它的否定环视 `(?<![>&])[|;&](?![>&])` 护住了
> `&>` 里的 `&` 不作分隔符。r9 双审那个 blocker 修的正是这一半，**只修了一半**。

**BACKLOG 没写到的第三个后果**：双流重定向的目标会被 `extractPathTokens` 当成**读取路径**
报上去。正常的 `>` 因为 `REDIRECT_RE` 命中而被跳过，`&>` 命中不了、`>&` 命中但残留非空，
于是 `src/leak.txt` 以读取的身份进了路径面——
而路径面正是**措施 a（禁读核验）与 `consulted` 交叉核对**的输入。
所以这不只是「少记一次写」，还是「多记一次读」，两个方向同时错。

### 1.3 实测确认**不是**缺口的（本轮不动，避免顺手扩大范围）

### 1.4 平台事实（r2 新增，本机 shell 实测）

r1 对退出码全靠 POSIX 语义推理，而 §2.4 的**整个可承受性判断都压在这两个数上**。
在 `mktemp -d` 返回的临时目录内实测：

| 命令 | 退出码 | 对判定层的含义 |
| :--- | :--- | :--- |
| `rm -r nope_dir` | **1**（`No such file or directory`） | **进不了判定层**——契约只喂 `exit_code === 0` |
| `rm -rf nope_dir` | **0** | **可达**——本次收紧新引入的误杀路径 |
| `rm -f nope.txt` | **0** | 今天已走幂等档，本次不变 |
| `rm --recursive --force nope_dir` | **64**（`illegal option -- -`） | 本机 BSD `rm` 不接受长旗标 ⇒ 不可达 |
| `rm --recur --forc nope_dir` | **64** | GNU 风格缩写同样不可达 ⇒ 判据维持等值匹配，不改前缀匹配 |

**判定层的调用契约**（`base.ts:891-894`）：

```
入参 `succeededCommands` 必须**只含成功执行的命令**（`status: completed`
且 `exit_code === 0`），由适配器筛好再喂进来。本函数不看退出码——
```

**这两件事合起来推翻了 r1 §2.4 的第一条断言**，见 §2.4。

## 2. 缺口一的修法

### 2.1 判据

`idempotent` 的 `rm` 分支加一条排除：**同时出现递归旗标时不算幂等**。

> **递归旗标的形态要一次写全**：`-r` / `-R` / `--recursive`，
> 且要认得**簇合形态**（`-rf` / `-Rf` / `-fr` / `-vrf`）。
> 与现有 `-\w*f` 同款用 `/^-\w*[rR]/` 加长旗标等值，不另造一套匹配方式。
> **不改成前缀匹配**：长旗标缩写在本机不可达（§1.4），前缀匹配只会平白扩大误判面。

### 2.2 这是一次**反方向**收紧，要说清为什么

本仓在这条判据上的一贯定级是「误杀更重」——判不出幂等就会把没写的命令判成失守、整侧作废。
本条**反过来**：把一类原本进疑似的命令提到 `writes`，**主动增加误杀面**。

**主论证：这是白名单内的单调性违背。**
今天 `rm -r src/x` 判 `writes`（失守），而**加上** `-f` 之后 `rm -rf src/x` 反而降级到疑似。
在同一张动词白名单内，给命令**增加**一个破坏性旗标却让它的判定**变轻**——
这是判据自身的单调性缺陷，与「该不该扩大白名单」无关，修它不牵连任何表外形态。

`-f` 的幂等豁免本身是对的（`rm -f <不存在>` 退 0），但它的适用理由只对「目标不存在」成立，
而判定层不做 I/O、判不出目标存不存在。对**非递归**的 `rm -f <文件>` 这个不确定性可以接受；
`-r` 把论域从一个文件扩到整棵子树之后就不能了。

> **附注（不作为主论证）**：`-r` + `-f` 在直觉上也是破坏力最大的一格。
> 但**不能用破坏力排序来论证本条**——按那个标准，
> §1.3 登记的 `git clean -fdx` / `find -delete` / `sudo rm -rf` 破坏力同级甚至更难诊断，
> 而它们今天是**彻底静默**（连疑似都不进），蕴含的必做集合远大于本主题两条。
> r1 用的正是破坏力论证，它会让下一个人误以为「这一面已经收口了」。

### 2.3 备选与取舍

| 方案 | 做法 | 评价 |
| :--- | :--- | :--- |
| **A（推荐）** | 递归 + 强制 ⇒ 不算幂等，进 `writes` | 最直接；误杀面见 §2.4，可承受且可诊断 |
| B | 仍进疑似，但换一条更重的 `why` 文案并驱动告警 | 不改失守判定 ⇒ `guard` 以 `write_events` 非空为唯一判据 ⇒ 闸门仍然绿 ⇒ 等于没修 |
| C | 只在「目标在项目内**且**可静态解析」时提到 `writes` | **与 A 零差异**——`base.ts:974-986` 的判定顺序本就是「项目外 → 疑似」「提不出目标 → 疑似」，A 天然满足该前提，C 只是把现状判据重写一遍 |

**取 A。** 但 §2.4 的误杀面必须如实登记，不假装它不存在。

### 2.4 误杀面与新增作废面（如实登记）

> **本节是 r2 相对 r1 改动最大的一节。** r1 这里有四处问题，三侧双审全部命中：
> 登记口径错（CODEX-01）、只登记了缺口一（CODEX-03）、
> 成本估计取不到证据（CODEX-09）、承诺了契约落不下的字段（AGY-01）。

#### 2.4.1 缺口一的误杀面

修完之后，`rm -rf <项目内、但实际不存在的目录>` 会被判 `writes` ⇒ 只读失守 ⇒ 整侧作废。

- **这是本次新引入的一条可达误杀路径。**
  `-f` 恰恰让目标不存在时命令也**退 0**（§1.4），从而穿过「只喂成功命令」的契约进到判定层。
  不可达的是**不带 `-f`** 的同形态：`rm -r <不存在>` 退 1，今天就进不了判定层。

  > r1 写的是「它不是新引入的形态：`rm -r <不存在>` 今天就已经这样判」。
  > 那句话在**分类层面**成立（分类器直调确实判 writes），在**可达层面不成立**。
  > 按错误的基线会让后续排障者高估或低估误杀频率。

- **误杀一次的代价**：整侧作废并重跑一轮，等于各侧一次配额 + 一次墙钟。
  按 M10a 台账的口径（r7 稿 :662），r4 那轮 codex 脚本级超时 25m0s 直接导致**整轮作废重跑**——
  重跑不是零成本，量级就在这里。
- **误杀的实际频率取不到**（判断，非事实）：审查员在只读审查里跑递归删除，
  我**判断**属异常行为，但本仓取不到证据支持这个判断——
  轨迹文件不进 `.reviews/` 归档，`~/.trivium/runs/` 又在任务书禁读面内。
  **结案时由 Driver 去 `runs/` 目录核一次历史频率**，把数写进结案留痕。

#### 2.4.2 缺口二的新增作废面（r1 完全没登记）

取方案 A 之后，`&>` / `>&` 的写面与 `>` **完全同权**。于是这类命令第一次成为整侧作废触发器：

| 命令 | 今天 | 修后 |
| :--- | :--- | :--- |
| `make -j4 &> build.log` | `writes=[]`，只留一条假读取 `build.log` | **`writes=[命令]`** ⇒ 失守 |
| `npm run build &> /tmp/log` | 同上 | 「写入目标在项目外」⇒ 疑似（不失守） |

**裁定口径：项目内的双流日志重定向按「正确失守」处理**，与 `> build.log` 同权，不另设豁免。
依据是本仓既有裁决——只读承诺保护的是**被审项目与归档留痕**，
审查员把构建日志写进项目根本来就违反该承诺，今天不报是缺口不是特性。

> 这类命令在审查里比 `rm -rf` **常见得多**，所以必须在计划里定死口径。
> 不定的话，实施与下一轮双审会分叉：有人按「正确失守」写用例，有人按「构建日志不该算失守」判它变色。
> §4 为此专设一条用例（非写动词 + 组合重定向）。

#### 2.4.3 `why` 文案：契约实况，不是承诺

r1 写「写进 run.json 的 `why` 要说清『递归 + 强制不按幂等处理』」。**这落不下去**：

```ts

}
```

命令一旦进 `writes` 就只剩原始命令行（`base.ts:759`），`why` 是 `SuspectedWrite` 的字段（`:761`）。

**改为**：成因说明落在**代码注释**与 **guard 侧告警文案**，不承诺结构化字段。
若确需让 `writes` 携带成因，那是扩契约的事，**另立主题**（与 EV-75 的 run.v2 guard 段形状问题同面）。

## 3. 缺口二的修法

### 3.1 两处同源改动

r1 只改 `REDIRECT_RE` 一处。纳入 `>&word` 之后必须改两处——它们是同一个缺口的两半。

#### 改动 ①：`REDIRECT_RE` 认 `&` 前缀

```ts
// 今天（base.ts:497）
const REDIRECT_RE = /^[0-9]*>>?/;
// 改为
const REDIRECT_RE = /^(?:&|[0-9]*)>>?/;
```

**取互斥分支写法**，不取 r1 的 `/^&?[0-9]*>>?/`。
后者把互斥的 `&` 与 fd 数字写成连缀，多认了现实中不存在的 `&2>`；
三侧核过多认对判定层无副作用、两种写法对真实输入逐 token 等价，
但互斥写法更严密地表达了语法事实，**零代价**，故定为首选。

#### 改动 ②：fd 复制分界改判（`base.ts:828`）

今天的分界是「残留以 `&` 打头即排除」：

```ts
const glued = t.replace(REDIRECT_RE, '');
if (glued) {
  if (!glued.startsWith('&')) sinks.push(glued);   // ← 把 >&file 一并吞掉
} else if (tokens[i + 1]) { … }
```

这道排除**该分的类没分**：`&` 后是 `1`/`2` 才是 fd 复制，是路径就是文件目标。
改为**保留前缀信息**后分三路：

```ts
const m = REDIRECT_RE.exec(t);
if (!m) continue;
const prefix = m[0];                 // '>' / '>>' / '2>' / '&>' / …
const glued = t.slice(prefix.length);
const hasFdPrefix = /[0-9]/.test(prefix);
```

| 残留形态 | 判定 | 例 |
| :--- | :--- | :--- |
| 不以 `&` 打头、非空 | 文件目标，`sinks.push(glued)` | `>out.txt`、`&>src/leak.txt` |
| 以 `&` 打头，且 `prefix` 含 fd 数字 | fd 操作，**排除** | `2>&1`、`1>&2` |
| 以 `&` 打头，`&` 后是**纯数字**或 `-` | fd 复制 / 关闭 fd，**排除** | `>&2`、`>&-` |
| 以 `&` 打头，`&` 后是**其它非空内容** | 双流文件重定向，`sinks.push(glued.slice(1))` | `>&src/leak.txt` |
| 残留是**裸 `&`** | 分离写法，取**下一 token** 作目标 | `>& src/leak.txt` |
| 残留为空 | 分离写法，取下一 token（今天已如此） | `> out.txt`、`&> out.txt` |

> **`&` 后是 `-` 必须排除**：`[n]>&-` 是 bash 关闭 fd 的标准形态，不是文件。
> r1 的裁决件没写这一格，是本稿起草时补上的。
>
> **`2>&word`（fd 前缀 + 非数字）维持排除**：bash 对它报 `ambiguous redirect` 并退非零
> ⇒ 进不了判定层，不可达。§4 为这一格设用例钉住，防止后来者「顺手放开」。

### 3.2 为什么不取「只补写面」

| 位置 | 做法 | 影响面 |
| :--- | :--- | :--- |
| **A（推荐）** | 改 `REDIRECT_RE` + fd 分界，三个消费点同时受影响 | 一处改全部对齐 |
| B | 只在 `writeSinksOfSegment` 里单独认 `&>` / `>&` | 写面修好、**读面那条假读取仍在**；两份判据不同宽，正是本仓反复栽的形状 |

**取 A。** 理由是 §1.2 的第三个后果：这一个正则同时喂着写面与读面，
只修写面会让「双流重定向的目标算读取」这条假读取留下来，而它喂的是禁读核验。

### 3.3 影响面：`REDIRECT_RE` 的三个消费点

全仓 `grep` 确认消费点**恰为三处**：`base.ts:535`、`:584`、`:823-825`。

| # | 位置 | 今天的作用 | 改后预期 |
| :--- | :--- | :--- | :--- |
| ① | `extractFromSegment` 分离写法跳过下一 token（`:535`） | `… 2> out.txt` 的 `out.txt` 不算读路径 | `&> f` 的 `f` 也不再算读路径——**修掉 §1.2 的假读取** |
| ② | `extractFromSegment` 紧贴写法跳过本 token（`:584`） | `2>out.txt` 不算读路径 | `&>f` / `>&f` 同样跳过（`>&f` 今天已跳过，不变） |
| ③ | `writeSinksOfSegment` 取写目标（`:823-825`） | `>f` / `> f` 取到目标 | `&>f` / `&> f` / `>&f` / `>& f` 也取到目标——**修掉写面漏检** |

> **消费点① 必须连带改**（本稿起草时新发现，r1 与裁决件都没写）。
> 它今天的条件是「残留**为空**才 skip 下一 token」：
>
> ```ts
> if (REDIRECT_RE.test(t) && t.replace(REDIRECT_RE, '') === '') skip.add(i + 1);
> ```
>
> 而分离写法 `>& src/leak.txt` 的 token 是 `>&`，残留是**裸 `&`** 不是空
> ⇒ 不 skip ⇒ `src/leak.txt` 进读路径。**只改消费点③ 修不掉这条假读取。**
> 条件要扩成「残留为空**或**残留是裸 `&`」，与 §3.1 改动 ② 的最后两行保持同一口径。
>
> 这正是 r1 §8 第 2 条自陈的那个风险（「我只实测了修前行为，修后行为是推的」）
> 第二次兑现——**§4 的读面用例必须正反各一，不能只测负断言。**

> **`glued.startsWith('&')` 的排除职责保住、但分得更细**：`2>&1` 的残留 `&1` 仍被排除。
> 改了 `REDIRECT_RE` 之后 `2>&1` 仍命中 `2>`、残留仍是 `&1`，**行为一字不变**——
> 但这条要有用例守着，因为它和新加的 `&` 前缀在同一个正则上。

### 3.4 不受本改动影响的一族（登记，防止后来者踢翻）

**引号内的 `&>` 字面量**（`grep -n '&>' src/a.ts`、`awk '/&>/' src/a.ts`）修前修后都正常：
`reads` 仍含 `src/a.ts`、`writes` 仍为空。

免疫**不是**本节判据给的，而是 `base.ts:653-655`（读面）与 `:928-930`（写面）的引号剥离口径：

```ts
cmd.replace(/(['"`])([\s\S]*?)\1/g, (_m, _q, inner) =>
  /[\s;&|()]/.test(inner) ? ' ' : ` ${inner} `)
```

含 `&` 的引号段整体被换成空格，`&>` 根本不成为 token。
**改引号口径会踢翻它**，故 §4 加锁例固化。

## 4. 测试

新增用例落在 `test/unit/codex-write-verbs.test.ts`（既有 22 条，与本主题同面）。

**缺口一**

- `rm -rf src/existing-dir`、`rm -r --force …`、`rm -R -f …`、`rm --recursive --force …`
  ⇒ **四种写法都进 `writes`**（不是只测一种）；
  后两条是**分类器直调的合成输入**，本机不可达（§1.4），用例仍有效；
- **回归**：`rm -f src/gone.ts`（无 `-r`）仍判幂等进疑似——
  这条是上一轮 r9 GLM-03 挣来的行为，不得被本次收紧误伤；
- **回归**：`mkdir --parents src/existing` 仍判幂等（同一个 `idempotent` 表达式，改一处要守另一半）。

**缺口二 · 写面**

- 分离：`echo secret &> src/leak.txt`、`echo secret &>> src/leak.txt` ⇒ 进 `writes`；
- **紧贴**：`echo secret &>src/leak.txt`、`echo secret &>>src/leak.txt` ⇒ 进 `writes`
  （走 `glued` 分支，与分离写法是**不同支路**，r1 漏测）；
- **`>&` 两形态**：`echo secret >&src/leak.txt`（紧贴）、`echo secret >& src/leak.txt`（分离）⇒ 进 `writes`；
- **作废面**：`make -j4 &> build.log` ⇒ 进 `writes`（非写动词 + 组合重定向，§2.4.2 的裁定口径）。

**缺口二 · 读面（正反各一，R-b 的落点）**

- **负**：上述 `&>` / `>&` 四条命令的 `extractPathTokens` ⇒ **不含** `src/leak.txt`；
  其中 `echo secret >& src/leak.txt` 一条专测消费点① 的连带改动（§3.3）；
- **正**：`extractPathTokens('cat src/a.ts')` ⇒ **仍含** `src/a.ts`；
  `extractPathTokens('grep foo src/a.ts &> /dev/null')` ⇒ 仍含 `src/a.ts`、不含 `/dev/null`。

**缺口二 · fd 操作回归（一字不变）**

- `echo x >&2`、`echo x 2>&1`、`echo x 1>&2` ⇒ 不进任何一档；
- `echo x >&-` ⇒ 不进任何一档（关闭 fd，§3.1 新增的那一格）；
- `echo x 2>&file` ⇒ 不进任何一档（ambiguous redirect、不可达，钉住「别顺手放开」）；
- **回归**：`echo x > src/a.ts 2>&1`、`cp /tmp/a src/b.ts 2>&1`、`echo x > src/a.ts &> /dev/null`
  仍进 `writes`（既有「掩码：fd 重定向不是掩码」那条用例不得变色）。

**引号免疫锁例（§3.4）**

- `grep -n '&>' src/a.ts` ⇒ `writes` 空、`reads` 含 `src/a.ts`。

**用例标题与论域对齐**

- 既有用例（`codex-write-verbs.test.ts:160-161`）标题写着 `（2>&1 / >&2 / &>）`
  而 cases 数组里没有 `>&2` 条目——顺手补齐，标题与论域不符的口子本仓已开过一次。

**变异验证**（隔离 worktree 副本里跑，不改真实工作树）

| 变异 | 应红的用例 |
| :--- | :--- |
| 去掉递归排除 | 四种递归+强制写法 |
| 递归排除只认短旗标 | `rm --recursive --force …` |
| `REDIRECT_RE` 退回不认 `&` | `&>` 写面 + 假读取两条 |
| fd 分界退回 `!glued.startsWith('&')` | `>&src/leak.txt` / `>& src/leak.txt` 两条 |
| 消费点① 退回「残留为空才 skip」 | `>& src/leak.txt` 的读面负断言 |
| fd 分界放开「`&` 后纯数字」那一格 | `>&2` / `2>&1` 回归条 |
| 引号剥离改成保留含 `&` 的段 | 引号免疫锁例 |

   请核这次的四小节是否还有同类问题，尤其 §2.4.2 把
   `make … &> build.log` 定为「正确失守」这个裁定——它比 `rm -rf` 常见得多。
2. **§3.1 改动 ② 的六格分界表**是本稿最弱的一环：`>&-`、`2>&word` 两格是我按 bash 语义推的，
   **没有实测**（§1.4 只测了 `rm` 的退出码）。请核这两格，以及六格是否互斥且穷尽。
3. **§3.3 的消费点① 连带改动**是本稿起草时才发现的，r1 与裁决件都漏了。
   请核「残留为空**或**裸 `&`」这个条件是否还漏了第三种残留形态。
4. **§1.1 新增的「真实可达」列**：请核三个「否」判得对不对，
   以及这个区分会不会让后来者误以为那几条用例可以删。
5. **§1.3 的四条已知残余**：请核登记措辞是否如实——
   特别是「管道末段」那条，我只接受了 codex 的实质发现，**没有**改 `|&` 那一行的口径（它写段在首段）。
6. **范围**：本稿仍不动 `WRITE_VERBS`、`SEGMENT_SPLIT_RE` 与 `writeSinksOfSegment` 的
   `-t` / `dd of=` 特例。D4 动的是 fd 复制分界——如果你认为那也属于「既有特例」而不该动，
   请说清它与 `-t` / `dd of=` 的区别在哪（我的理由：它是本缺口的成因本身，不是独立特例）。
