## 1. 现状核实

**以下全部在 `bf3342b` 的编译产物上实测**（`classifyWriteCommands(cmds, '/proj')`），
不是读代码推的。

### 1.1 缺口一：递归 + 强制的四种写法全部落进疑似档

| 命令 | `writes` | `suspected` |
| :--- | :--- | :--- |
| `rm -rf src/existing-dir` | `[]` | `rm 的幂等形态…` |
| `rm -r --force src/existing-dir` | `[]` | `rm 的幂等形态…` |
| `rm -R -f src/existing-dir` | `[]` | `rm 的幂等形态…` |
| `rm --recursive --force src/existing-dir` | `[]` | `rm 的幂等形态…` |
| **对照** `rm -r src/existing-dir`（无 `-f`） | **`[命令]`** | `[]` |
| **对照** `rm -f src/gone.ts`（无 `-r`） | `[]` | `rm 的幂等形态…` |

> BACKLOG 写的是「`rm -rf` 短旗标形态修前已如此，长旗标是 `3812f4c` 扩展时新纳入的」——
> 实测确认**四种写法今天都落疑似**，不只是长旗标那一格。

**成因**（`adapters/base.ts` 的 `idempotent` 判据）：

```
(verb === 'rm' && tokens.some((t) => /^-\w*f/.test(t) || t === '--force'))
```

判据只问「有没有 `-f`」，不问「是不是递归」。它的理由写在注释里、且是对的：
`rm -f <不存在>` 按 POSIX 退 0，判不出幂等会把一次没有实际写入的成功命令判成只读失守、
**整侧作废**，那是误杀方向，「本主题对这个方向的定级一贯更重」。

### 1.2 缺口二：`&>` / `&>>` 静默漏检，且**倒过来产出一条假读取**

| 命令 | `writes` | `suspected` | `extractPathTokens`（读路径） |
| :--- | :--- | :--- | :--- |
| `echo secret &> src/leak.txt` | `[]` | `[]` | **`["src/leak.txt"]`** |
| `echo secret &>> src/leak.txt` | `[]` | `[]` | （同上形态） |
| **对照** `echo x > src/a.ts` | `[命令]` | `[]` | **`[]`** |
| **对照** `echo x > src/a.ts &> /dev/null` | `[命令]` | `[]` | — |

**成因**：`REDIRECT_RE = /^[0-9]*>>?/` 只认可选 fd 前缀，**认不出以 `&` 打头的 token**。
于是 `&>` 既不被当作重定向记号（拿不到写目标），`echo` 又不在 `WRITE_VERBS` 里（兜底也不命中）。

> **`SEGMENT_SPLIT_RE` 那一半是对的**：它的否定环视 `(?<![>&])[|;&](?![>&])` 护住了
> `&>` 里的 `&` 不作分隔符。r9 双审那个 blocker 修的正是这一半，**只修了一半**。

**BACKLOG 没写到的第三个后果（本稿实测新增）**：`&>` 的目标会被
`extractPathTokens` 当成**读取路径**报上去。正常的 `>` 因为 `REDIRECT_RE` 命中而被跳过，
`&>` 命中不了，于是 `src/leak.txt` 以读取的身份进了路径面——
而路径面正是**措施 a（禁读核验）与 `consulted` 交叉核对**的输入。
所以这不只是「少记一次写」，还是「多记一次读」，两个方向同时错。

### 1.3 实测确认**不是**缺口的（本轮不动，避免顺手扩大范围）

| 形态 | 实测结果 | 判断 |
| :--- | :--- | :--- |
| `echo x 2>&1` / `echo x >&2` | `writes=[]`、无疑似 | 对：fd 复制不是文件写入，`glued.startsWith('&')` 已排除 |
| `touch src/x.ts \|& cat` | 判**掩码**进疑似 | 对：整条退出码确实不代表写段成功 |
| `touch src/x.ts & echo done` | 判**掩码**进疑似 | 对：后台执行同理 |
| `echo x > src/a.ts &> /dev/null` | `writes=[命令]` | 今天靠**第一个 `>`** 取到目标而成立；修完仍须绿（见 §4） |

## 2. 缺口一的修法

### 2.1 判据

`idempotent` 的 `rm` 分支加一条排除：**同时出现递归旗标时不算幂等**。

> **递归旗标的形态要一次写全**：`-r` / `-R` / `--recursive`，
> 且要认得**簇合形态**（`-rf` / `-Rf` / `-fr`）。
> 与现有 `-\w*f` 同款用 `/^-\w*[rR]/` 加长旗标等值，不另造一套匹配方式。

### 2.2 这是一次**反方向**收紧，要说清为什么

本仓在这条判据上的一贯定级是「误杀更重」——判不出幂等就会把没写的命令判成失守、整侧作废。
本条**反过来**：把一类原本进疑似的命令提到 `writes`，**主动增加误杀面**。

理由：`rm -f` 的幂等理由只对「目标不存在」成立，而判定层不做 I/O、判不出目标存不存在。
对**非递归**的 `rm -f <文件>` 这个不确定性是可接受的（最坏是删掉一个文件）。
但 `-r` 的语义是「整棵子树」，`-f` 的语义是「不管在不在都别问」——
**两者合起来恰恰是破坏力最大、而当前判据给了最宽豁免的那一格**。
把最具破坏性的形态整体划进「可能没写」，与这条判据存在的理由背反。

### 2.3 备选与取舍

| 方案 | 做法 | 评价 |
| :--- | :--- | :--- |
| **A（推荐）** | 递归 + 强制 ⇒ 不算幂等，进 `writes` | 最直接；误杀面见 §2.4，可承受且可诊断 |
| B | 仍进疑似，但换一条更重的 `why` 文案并驱动告警 | 不改失守判定 ⇒ 闸门仍然绿 ⇒ 等于没修 |
| C | 只在「目标在项目内**且**可静态解析」时提到 `writes` | 与 A 的实际差别很小（项目外与解析不了本就先走疑似），徒增一个分支 |

**取 A。** 但 §2.4 的误杀面必须如实登记，不假装它不存在。

### 2.4 误杀面（如实登记）

修完之后，`rm -rf <项目内、但实际不存在的目录>` 会被判 `writes` ⇒ 只读失守 ⇒ 整侧作废。
这是真实存在的误杀，代价是**重跑一轮**。

- 它**不是**新引入的形态：`rm -r <不存在>`（无 `-f`）今天就已经这样判（见 §1.1 对照行）。
  本次只是让 `-f` 不再豁免它。
- 审查员在只读审查里跑递归删除本身就是异常行为；误杀一次的代价（重跑）
  小于漏报一次的代价（失守不被发现）。
- **写进 run.json 的 `why`／告警文案要说清**：「递归 + 强制不按幂等处理」，
  让排障者一眼看出是这条判据而不是别的。

## 3. 缺口二的修法

### 3.1 两个可选位置

| 位置 | 做法 | 影响面 |
| :--- | :--- | :--- |
| **A（推荐）** | 改 `REDIRECT_RE` 为 `/^&?[0-9]*>>?/` | **三个消费点同时受影响**（见 §3.2），一处改全部对齐 |
| B | 只在 `writeSinksOfSegment` 里单独认 `&>` | 写面修好、**读面那条假读取仍在**；两份判据不同宽，正是本仓反复栽的形状 |

**取 A。** 理由是 §1.2 实测出的第三个后果：这一个正则同时喂着写面与读面，
只修写面会让「`&>` 的目标算读取」这条假读取留下来，而它喂的是禁读核验。

> `&` 与 fd 前缀的**顺序**：POSIX/bash 里是 `&>`、`&>>`，没有 `2&>` 这种写法。
> 正则写成 `^&?[0-9]*>>?` 允许了 `&2>`（不存在的形态），属**多认**而非少认；
> 多认的后果是把一个不会出现的 token 当重定向，判定层没有副作用。
> 若审查员认为该收紧成 `^(?:&|[0-9]*)>>?`，我接受——两种写法对真实输入等价。

### 3.2 影响面：`REDIRECT_RE` 的三个消费点

| # | 位置 | 今天的作用 | 改后预期 |
| :--- | :--- | :--- | :--- |
| ① | `extractFromSegment`（分离写法跳过下一 token） | `… 2> out.txt` 的 `out.txt` 不算读路径 | `&> f` 的 `f` 也不再算读路径——**修掉 §1.2 的假读取** |
| ② | `extractFromSegment`（紧贴写法跳过本 token） | `2>out.txt` 不算读路径 | `&>f` 同样跳过 |
| ③ | `writeSinksOfSegment`（取写目标） | `>f` / `> f` 取到目标 | `&>f` / `&> f` 也取到目标——**修掉写面漏检** |

> **`glued.startsWith('&')` 那条排除必须保住**：`2>&1` 的残留是 `&1`，
> 它是 fd 复制不是文件。改了 `REDIRECT_RE` 之后 `2>&1` 仍命中 `2>`、残留仍是 `&1`，
> 行为不变——但这条要有用例守着，因为它和新加的 `&` 前缀在同一个正则上。

   如果你认为这两条缺口的根因牵连到它们，请说清牵连在哪——
