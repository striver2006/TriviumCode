## 3. Driver 侧复核实测（原稿没做、本轮补做）

三侧有两处结论互斥、一处依赖我这边才能取到的平台事实，我在临时目录里补测如下。
**闸门期未改任何业务文件**，实验全部在 `mktemp -d` 返回的目录内进行。

### 3.1 `rm` 各形态在目标不存在时的退出码（判 CODEX-01 与 CODEX-06）

| 命令 | 退出码 | 含义 |
| :--- | :--- | :--- |
| `rm -r nope_dir` | **1**（`No such file or directory`） | 进不了判定层（契约只喂 `exit_code === 0`） |
| `rm -rf nope_dir` | **0** | **可达**——本次收紧新引入的误杀路径 |
| `rm -f nope.txt` | 0 | 今天已走幂等档，不变 |
| `rm --recursive --force nope_dir` | **64**（`illegal option -- -`） | 本机 BSD `rm` 不接受长旗标 ⇒ 不可达 |
| `rm --recur --forc nope_dir` | **64** | GNU 风格缩写同样不可达 |

**对 CODEX-01**：坐实。§2.4「它不是新引入的形态」按可达层面是**错的**，必须改。

**对 CODEX-06**：限定。缩写不认在本机不可达，判据不必改成前缀匹配。

### 3.2 上一条的溢出后果（三侧都没完整指出，本轮 Driver 自查新增）

既然本机 `rm` 拒收一切长旗标，那么原稿 §1.1 表里
`rm --recursive --force src/existing-dir` 那一行、以及 §4 要求的同名用例，
**在本机永远不会作为真实轨迹出现**——它们是分类器直调的合成输入，不是可达形态。
这不影响单测的有效性（单测本就直调 `classifyWriteCommands`），
但原稿 §1.1 通篇写的是「以下全部在编译产物上实测」，读起来像一份真实可达形态清单。
r2 稿要把这两处**标注清楚**，否则下一个人会拿它当可达性依据。

### 3.3 `>&word` 的残留形态（判 GLM-01 / AGY-04）

`base.ts:823-828` 取写目标的顺序是：`REDIRECT_RE.test(t)` ⇒ `glued = t.replace(REDIRECT_RE, '')`
⇒ `if (!glued.startsWith('&')) sinks.push(glued)`。
对 `>&src/leak.txt`：旧正则 `^[0-9]*>>?` 命中 `>`，残留 `&src/leak.txt`，被排除；
换成 `^(?:&|[0-9]*)>>?` 后，`&?` 分支因首字符是 `>` 而不参与，`[0-9]*` 空，仍只命中 `>`，
**残留一字不变**，仍被排除。GLM-01「修后原样保留」核实无误。
