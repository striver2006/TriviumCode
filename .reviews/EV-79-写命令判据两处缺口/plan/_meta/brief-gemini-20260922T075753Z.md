### 1.1 缺口一：递归 + 强制的四种写法全部落进疑似档

| 命令 | `writes` | `suspected` | 真实可达？ |
| :--- | :--- | :--- | :--- |
| `rm -rf src/existing-dir` | `[]` | `rm 的幂等形态…` | **可达** |
| `rm -r --force src/existing-dir` | `[]` | `rm 的幂等形态…` | 否（长旗标，形态不可达） |
| `rm -R -f src/existing-dir` | `[]` | `rm 的幂等形态…` | **可达** |
| `rm --recursive --force src/existing-dir` | `[]` | `rm 的幂等形态…` | 否（长旗标，形态不可达） |
| **对照** `rm -r src/existing-dir`（无 `-f`） | **`[命令]`** | `[]` | **可达**（目标存在 ⇒ 退 0）——见下 |
| **对照** `rm -f src/gone.ts`（无 `-r`） | `[]` | `rm 的幂等形态…` | **可达** |

> **「真实可达」列的两类「否」含义不同，不要混读**：
> - **形态不可达**（两行长旗标）：本机 BSD `rm` 不接受任何长旗标，退 64（§1.4），
>   命令根本跑不起来。它们是**分类器直调的合成输入**，单测仍有效，
>   但**不能当可达性依据**，也**不能因为「不可达」就删掉用例**。
> - **条件不可达**（不存在的目标）：`rm -r <不存在>` 退 1 进不了判定层，
>   但 `rm -r <存在目录>` **退 0 且完全可达**，判 `writes` 正是这条判据今天的**正确检出**。
>
> r2 在对照行上把这两类混成了一个「否」：行名标的是 `existing-dir`（存在），
> 论据却来自 `nope_dir`（不存在）的实测——**以 existing-dir 之名行 nope 之实**。
> 三侧独立命中（CODEX-01 ≡ AGY-03 ≡ GLM-04）。它同时是 §2.2 单调性论证的基座，
> 而 r2 §4 恰好没有回归条钉住这半边——「标注不可达 + 无用例」合起来，
> 后来者会把它当可删的合成用例。**§4 为此专设一条钉死用例。**

**成因**（`base.ts:967-970` 的 `idempotent` 判据）：

```ts
const idempotent =
  (verb === 'mkdir' && tokens.some((t) => /^-\w*p/.test(t) || t === '--parents')) ||
  (verb === 'rm' && tokens.some((t) => /^-\w*f/.test(t) || t === '--force'));
```

判据只问「有没有 `-f`」，不问「是不是递归」。

### 1.2 缺口二：双流重定向静默漏检，且**倒过来产出读面污染**

| 命令 | `writes` | `suspected` | `extractPathTokens`（读路径） |
| :--- | :--- | :--- | :--- |
| `echo secret &> src/leak.txt`（分离） | `[]` | `[]` | **`["src/leak.txt"]`**（假读取） |
| `echo secret &>> src/leak.txt`（分离） | `[]` | `[]` | （同上形态） |
| `echo secret &>src/leak.txt`（紧贴） | `[]` | `[]` | **`["&>src/leak.txt"]`**（垃圾 token） |
| `echo secret >& src/leak.txt`（分离） | `[]` | `[]` | **`["src/leak.txt"]`**（假读取） |
| `echo secret >&src/leak.txt`（紧贴） | `[]` | `[]` | `[]` |
| **`echo secret 2>& src/leak.txt`** | `[]` | `[]` | **`["src/leak.txt"]`**（假读取） |
| **对照** `echo x > src/a.ts` | `[命令]` | `[]` | `[]` |
| **对照** `echo x > src/a.ts &> /dev/null` | `[命令]` | `[]` | **`["/dev/null"]`** |

> 第 6 行 `2>&` 是 **r4 新增**（见 §1.4 的可达性实测）。
> 第 3 行 r2 填的是 `[]`，**实测是 `["&>src/leak.txt"]`**（GLM-03）；
> 最后一行 r2 标「—」未测，实测是 `["/dev/null"]`。

**读面有两种不同症状，不要合并登记**：

- **假读取**（分离形态）：写目标以**读取身份**进路径面，喂进措施 a 的禁读核验。
- **垃圾 token**（紧贴 `&>` 形态）：整个 `&>src/leak.txt` 被当成一条路径收进读面
  （今天 `REDIRECT_RE` 认不出它，`:584` 跳不过，又因含 `/` 被 `:612` 的「像路径」判据收走），
  归一后落在项目内，还会计入 `projectReads` 证据面。

**写面成因（三条，同源）**：

1. `REDIRECT_RE = /^[0-9]*>>?/` 认不出以 `&` 打头的 token ⇒ `&>` 拿不到写目标，
   而 `echo` 不在 `WRITE_VERBS` 里（兜底也不命中）。
2. `>&` **能**命中（匹配掉 `>`），但残留 `&src/leak.txt` 以 `&` 打头，
   被 `base.ts:828` 的 `if (!glued.startsWith('&')) sinks.push(glued)` 整个吞掉。
3. `2>&` 同理：命中 `2>`，残留 `&src/leak.txt`，同一道排除吞掉。
   分离写法 `>& f` / `2>& f` 的残留是**裸 `&`**，既不 push 也不走 `else if (tokens[i+1])`
   分支，于是下一 token 无人认领、落进读路径。

> **`SEGMENT_SPLIT_RE` 那一半是对的**：否定环视 `(?<![>&])[|;&](?![>&])` 护住了
> `&>` 里的 `&` 不作分隔符。r9 双审那个 blocker 修的正是这一半，**只修了一半**。

| **zsh 5.9** | `echo HELLO >& 2`（分离） | **0** | **无**名为 `2` 的文件 ⇒ fd 复制 |
| **zsh 5.9** | `echo X >& -`（分离） | **0** | **无**文件 ⇒ 关闭 fd |
| **zsh 5.9** | `echo Y >&2foo` | **0** | **建了 `2foo`** ⇒ 双流**文件**重定向 |

**这张表推翻了 r2 的三处判断**：

1. **`2>&<非数字>` 可达**（第 1～2 行）。r2 写它「ambiguous redirect、退非零、不可达，维持排除」，
   还要 §4 用例把排除钉死——那会把一条可达的静默写通道当正确行为锁住。
   > 双审两侧在这一格给出**互相矛盾**的实测：一侧说两个 shell 都退非零（bash 对、zsh 错），
   > 另一侧说两个 shell 都 rc=0（zsh 对、bash 错）。上表是 Driver 侧复测的结果，两半各取其正。
   >
   > **顺带一个有利性质**：把 `2>&word` 收进写面在 bash 环境下**无害**——
   > bash 下它退 1，根本进不了 `succeededCommands`。新判据在两个 shell 下都正确。
2. **分离 fd 形态是 fd 操作不是写文件**（第 5～6 行）。r2 的 cell 5 会把 `2` / `-` 当写目标，
   而 `isResolvablePath('2')` 与 `isResolvablePath('-')` 均返回 true（`base.ts:801-803`），
   一路走到 `normalizeAbs` 判成项目内写入 ⇒ **假失守 ⇒ 整侧作废**。
   基线实测这三条今天写面双空，**所以这是修法自己新引入的误杀面**（§2.4.3）。
3. **fd 判据必须等值不能前缀**（第 7 行）。`>&2foo` 是文件写入，
   按前缀实现（`/^&\d/` 一类）会把它误排除，那是**静默漏检**方向。

## 2. 缺口一的修法

### 2.1 判据

`idempotent` 的 `rm` 分支加一条排除：**同时出现递归旗标时不算幂等**。

> **递归旗标的形态要一次写全**：`-r` / `-R` / `--recursive`，
> 且要认得**簇合形态**（`-rf` / `-Rf` / `-fr` / `-vrf`）。
> 与现有 `-\w*f` 同款用 `/^-\w*[rR]/` 加长旗标等值，不另造一套匹配方式。
> **不改成前缀匹配**：长旗标缩写在本机不可达（§1.4.1），前缀匹配只会平白扩大误判面。

### 2.2 这是一次**反方向**收紧，要说清为什么

本仓在这条判据上的一贯定级是「误杀更重」。本条**反过来**：把一类原本进疑似的命令提到
`writes`，**主动增加误杀面**。

**主论证：这是白名单内的单调性违背。**
今天 `rm -r src/x` 判 `writes`（失守），而**加上** `-f` 之后 `rm -rf src/x` 反而降级到疑似。
在同一张动词白名单内，给命令**增加**一个破坏性旗标却让它的判定**变轻**——
这是判据自身的单调性缺陷，与「该不该扩大白名单」无关，修它不牵连任何表外形态。

`-f` 的幂等豁免本身是对的（`rm -f <不存在>` 退 0），但它的适用理由只对「目标不存在」成立，
而判定层不做 I/O。对**非递归**的 `rm -f <文件>` 这个不确定性可以接受；
`-r` 把论域从一个文件扩到整棵子树之后就不能了。

> **附注（不作为主论证）**：`-r` + `-f` 在直觉上也是破坏力最大的一格。
> 但**不能用破坏力排序来论证本条**——按那个标准，§1.3 登记的表外动词破坏力同级甚至更难诊断，
> 而它们今天写面彻底静默，蕴含的必做集合远大于本主题。

### 2.3 备选与取舍

| 方案 | 做法 | 评价 |
| :--- | :--- | :--- |
| **A（推荐）** | 递归 + 强制 ⇒ 不算幂等，进 `writes` | 最直接；误杀面见 §2.4，可承受且可诊断 |
| B | 仍进疑似，但换一条更重的 `why` 文案并驱动告警 | 不改失守判定 ⇒ `guard` 以 `write_events` 非空为唯一判据 ⇒ 闸门仍然绿 ⇒ 等于没修 |
| C | 只在「目标在项目内**且**可静态解析」时提到 `writes` | **与 A 零差异**——`base.ts:974-986` 的判定顺序本就是「项目外 → 疑似」「提不出目标 → 疑似」 |

**取 A。**
