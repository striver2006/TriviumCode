## 2. Driver 侧复核实测（裁定三侧争议）

### 2.1 `2>&word`：两侧结论直接冲突（判 GLM-01）

| shell | 命令 | rc | 是否落盘 |
| :--- | :--- | :--- | :--- |
| **zsh 5.9** | `echo ERRLINE 2>& t1.txt` | **0** | **建了 t1.txt** |
| **zsh 5.9** | `{ echo A; echo B >&2; } 2>&t2.txt` | **0** | **t2.txt 内容为 `B`** |
| bash 3.2 | `{ echo A; echo B >&2; } 2>&b1.txt` | 1（`ambiguous redirect`） | 未建 |
| bash --posix | 同上 | 1（`ambiguous redirect`） | 未建 |

**裁定**：codex 的 bash 实测对、zsh 实测错（它报的 `bad substitution` 是 `${...}` 语法错误，
不是重定向行为）；glm 的 zsh 实测对、bash 描述错（bash 默认模式并非 rc=0）。
**决定性的是 zsh**——codex 侧命令经 `/bin/zsh -lc` 拉起，所以 `2>&word` 是可达的真实写入，
r2 的「不可达」论断不成立。

> 顺带一个对本主题有利的性质：把 `2>&word` 收进写面在 bash 环境下也**无害**——
> bash 下它退 1，根本进不了 `succeededCommands`。所以新判据在两个 shell 下都正确。

### 2.2 分离 fd 形态（判 GLM-02 ≡ AGY-01）

| 命令（zsh） | rc | 目录内是否出现同名文件 |
| :--- | :--- | :--- |
| `echo HELLO >& 2` | 0 | **无**名为 `2` 的文件 ⇒ fd 复制 |
| `echo X >& -` | 0 | **无**文件 ⇒ 关闭 fd |

**裁定**：前两行坐实 cell 5 会造假失守；第三行坐实 GLM-06——判据必须等值不能前缀。

## 3. §3.1 的新分界表（六格塌缩为四格）

GLM-01 + AGY-02 + GLM-02 + GLM-06 四条合起来给出的解法是同一个：
**`hasFdPrefix` 整个退出判定**。去掉它之后表严格互斥、穷尽，且逐格都有实测支撑。

按**行序短路**判定，残留 `glued = t.slice(prefix.length)`：

| # | 条件（等值，非前缀） | 处置 | 实测依据 |
| :--- | :--- | :--- | :--- |
| 1 | `glued === ''` | 分离写法，取下一 token；下一 token 恰为纯数字或 `-` 时排除 | `> out.txt`、`&> out.txt` |
| 2 | `glued === '&'`（裸 `&`） | 分离写法，取下一 token；下一 token 恰为纯数字或 `-` 时**排除** | §2.2 前两行 |
| 3 | `/^&(?:\d+\|-)$/.test(glued)` | fd 复制 / 关闭 fd，**排除** | `>&2`、`2>&1`、`>&-`、`2>&-` |
| 4 | 其余（含 `&` 后非空非数字、以及不以 `&` 打头） | **文件目标**：以 `&` 打头则取 `glued.slice(1)`，否则取 `glued` | `>&src/leak.txt`、`&>src/leak.txt`、**`2>&file`**、`>&2foo` |

> **第 4 格现在同时收 `2>&file`**——这是本轮相对 r2 的实质反转（GLM-01）。
> 第 1、2 格的下一 token 分流是本轮新增（GLM-02 ≡ AGY-01）。
> 三格的等值写法是本轮新增（GLM-06）。
> `hasFdPrefix` 不再出现（AGY-02 的诊断 + GLM-01 的实测）。

**待登记的 zsh 特有族**（GLM-01 建议，只登记不修）：`>&\| word` / `>&! word`（clobber 强制）
在第 4 格下会取到 `\|word` / `!word` 这样的错目标；`>>& word` 则被新正则的 `>>?` 正常覆盖、无需特判。
