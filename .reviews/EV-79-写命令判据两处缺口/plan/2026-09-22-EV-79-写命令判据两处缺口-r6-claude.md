### 1.1 缺口一：递归 + 强制的四种写法全部落进疑似档

| 命令 | `writes` | `suspected` | 真实可达？ |
| :--- | :--- | :--- | :--- |
| `rm -rf src/existing-dir` | `[]` | `rm 的幂等形态…` | **可达** |
| `rm -r --force src/existing-dir` | `[]` | `rm 的幂等形态…` | 否（**形态**不可达） |
| `rm -R -f src/existing-dir` | `[]` | `rm 的幂等形态…` | **可达** |
| `rm --recursive --force src/existing-dir` | `[]` | `rm 的幂等形态…` | 否（**形态**不可达） |
| **对照** `rm -r src/existing-dir`（无 `-f`） | **`[命令]`** | `[]` | **可达**（目标存在 ⇒ 退 0） |
| **对照** `rm -f src/gone.ts`（无 `-r`） | `[]` | `rm 的幂等形态…` | **可达** |

> **两类「否」含义不同**：
> - **形态不可达**（两行长旗标）：本机 BSD `rm` 不接受任何长旗标，退 64（§1.4.1）。
>   它们是**分类器直调的合成输入**，单测仍有效，**不能因为「不可达」就删掉用例**。
> - **条件不可达**（目标不存在时）：`rm -r <不存在>` 退 1 进不了判定层，
>   但 `rm -r <存在目录>` **退 0 且完全可达**，判 `writes` 正是这条判据今天的**正确检出**。
>   **§4 为它专设回归条**，它是 §2.2 单调性论证的另一半。

**成因**（`base.ts:967-970` 的 `idempotent` 判据）：

```ts
const idempotent =
  (verb === 'mkdir' && tokens.some((t) => /^-\w*p/.test(t) || t === '--parents')) ||
  (verb === 'rm' && tokens.some((t) => /^-\w*f/.test(t) || t === '--force'));
```

判据只问「有没有 `-f`」，不问「是不是递归」。

### 1.2 缺口二：重定向目标漏检，且**倒过来污染读路径面**

直调 `classifyWriteCommands(cmds, '/proj')` 与 `extractPathTokens(cmd)`：

| 命令 | `writes` | `suspected` | 读路径 |
| :--- | :--- | :--- | :--- |
| `echo secret &> src/leak.txt` | `[]` | `[]` | **`["src/leak.txt"]`** |
| `echo secret &>src/leak.txt` | `[]` | `[]` | **`["&>src/leak.txt"]`** |
| `echo secret >& src/leak.txt` | `[]` | `[]` | **`["src/leak.txt"]`** |
| `echo secret >&src/leak.txt` | `[]` | `[]` | `[]` |
| `echo secret 2>& src/leak.txt` | `[]` | `[]` | **`["src/leak.txt"]`** |
| `echo secret >>& src/leak.txt` | `[]` | `[]` | **`["src/leak.txt"]`** |
| `echo secret >>&src/leak.txt` | `[]` | `[]` | `[]` |
| `echo secret >&\| src/leak.txt` | `[]` | `[]` | `[]` |
| **对照** `echo x > src/a.ts` | **`[命令]`** | `[]` | `[]` |
| **对照** `echo x > src/a.ts &> /dev/null` | **`[命令]`** | `[]` | **`["/dev/null"]`** |

**读面有两种不同症状，分开登记**：

- **假读取**（分离形态）：写目标以**读取身份**进路径面。
- **垃圾 token**（紧贴 `&>` 形态）：整个 `&>src/leak.txt` 被当成一条路径收进读面
  （`REDIRECT_RE` 认不出它、`:584` 跳不过，又因含 `/` 被 `:612` 的「像路径」判据收走），
  归一后落在项目内，还会计入 `projectReads` 证据面。

**读面污染的危害落在哪里**：

回填（`effectiveReadPaths` → `extractPathTokens`）的**消费方只有三处**，
`base.ts:676-682` 的文档注释明写：

> **消费方只有三处**：`checkEvidence` 的 `no_trace` 与 `projectReads`、
> `judgeSide` 的 consulted 交叉核对。
> **措施 a（`checkPeerLeak`）不吃回填**

`guard.ts:277-283` 同款，落款还是「r2/r3 双审两侧均确认」；
`guard.ts:305-307` 的 `checkPeerLeak` 入参确实只有 `read_paths ∪ search_hit_paths`；
`guard.ts:413-421` 的 `matchConsulted` 确实吃 `effectiveReadPaths`。

> **「喂进措施 a 的禁读核验」这个归因是错的**，r1～r4 四稿一直这么写（r5 双审 CODEX-02 更正）。
> 命令原文的禁读核验是**措施 b**，它扫 `command_texts` 字面量，与 `REDIRECT_RE` 无关。
>
> **真正的危害是「证据自证」**：一条从未读过的路径，只要被某次重定向当过目标，
> 就能让 `consulted` 里的虚假声明通过 `judgeSide` 的交叉核对——
> 审查员可以借此坐实自己没读过的文件。

**写面成因（同源）**：`REDIRECT_RE = /^[0-9]*>>?/` 只认「可选 fd 前缀 + `>`」，
于是前置 `&` 的拼写整条认不出；后置 `&` 的拼写虽能命中 `>`，
但残留以 `&` 打头，被 `base.ts:828` 的 `if (!glued.startsWith('&')) sinks.push(glued)` 一刀切掉；
而强制覆盖后缀（`|` / `!`）则让残留变成 `|p1.txt` 这样的错目标。

> **`SEGMENT_SPLIT_RE` 那一半是对的**：否定环视 `(?<![>&])[|;&](?![>&])` 护住了
> `&>` 里的 `&` 不作分隔符。r9 双审那个 blocker 修的正是这一半，**只修了一半**。

| `{ echo A; echo B >&2; } 2>&b2.txt`（`--posix`） | **1** | 同上 |
| `echo X >>& f` | **2** | `syntax error`，不建文件 |
| **`echo X >& bashsep.txt`（分离，无 fd 前缀）** | **0** | **建出文件** ⇒ **该形态在 bash 下可达** |

> **最后一行是 r6 新增的更正**（r5 双审 CODEX-04）。
> r5 打算在 §4 用例注释里写「在 bash 下这些形态退非零、进不了判定层」——
> 那对**分离写法的 `>& 文件`不成立**，它在 bash 下 rc=0 且真建文件。
> 该说法只对**带数字前缀的 `2>&文件`**成立。**D6 的结论不受影响**（见下），
> 但注释若留着错事实，会把后来者按错前提改判据。

**从这张表读出三条结论**：

1. **fd 语义只属于无后缀的 `[n]>&` 一族**（第 7、8 行）。
   `>>&`（第 5、6、12、13、20、21 行）是双流**追加文件**重定向；
   `&>`（第 3、4 行）是双流文件重定向；
   **带 clobber 后缀的 `>&|` / `>&!`（第 14～19、22～25 行）也是文件**——后缀消去了 fd 语义。
   **`&` 在 `>` 的哪一侧、`>` 是一个还是两个、有没有 clobber 后缀，共同决定语义。**
2. **同一个 fd 族里，是不是 fd 操作取决于目标位**（第 7～11 行）：
   目标恰为纯数字或 `-` 才是 fd 操作，否则是文件。第 9 行 `>&2foo` 建出文件，
   **所以判据必须等值匹配**，前缀匹配会造成静默漏检。
3. **文本判据外壳无关，取各外壳拼写的并集**。
   `2>&word` 在 zsh 是文件写、在 bash 是 `ambiguous redirect`；
   `>>&` 在 zsh 是文件写、在 bash 是语法错。两者都属「一侧可达即须收」，
   而**可达性已经被 `succeededCommands` 的 `exit_code === 0` 收敛掉了**——
   在某外壳下退非零的形态根本进不了判定层。**所以收进写面在两个外壳下都不亏**，
   这才是 D6 的承重论证（不依赖「bash 下不可达」这个已被证伪的一般化说法）。

#### 1.4.3 只读环境下的复测法（**给审查员用**）

审查侧**建不了文件**（zcode 侧 denylist 含 `Bash`、gemini 侧工具面只有 `Read,Grep,Glob`），
所以 §1.4.2 的判别法在审查侧**不可执行**。这是 r3 两侧结论互相矛盾、
以及 r4 一侧声称实测而其实零命令的根因（BACKLOG **EV-95**）。

**可用的替代判别法（不落盘）**：把目标指向**不存在的目录**，或在不可写目录下跑，
从**报错文本**区分三种情形：

| 报错 | 含义 |
| :--- | :--- |
| `no such file or directory: <路径>` / `operation not permitted: <名>` | 该 token 被当**文件目标**打开 |
| `ambiguous redirect` | 该拼写在本外壳下**不合法**（不可达） |
| `syntax error near unexpected token` | 语法不支持（不可达） |
| 无报错、rc=0、无文件 | **fd 操作** |

例：`/bin/zsh -c 'echo X >>& /nonexistent-dir-zzq/t.txt'` 报
`no such file or directory: /nonexistent-dir-zzq/t.txt` ⇒ `>>&` 的宾语是文件。

> **r5 的第 5 轮双审里，codex 侧用这个方法独立复现了当时全部 21 行、无一推翻**，
> 并据此发现了第 22～25 行那一格。方法有效。

## 2. 缺口一的修法

### 2.1 判据

`idempotent` 的 `rm` 分支加一条排除：**同时出现递归旗标时不算幂等**。

> **递归旗标的形态要一次写全**：`-r` / `-R` / `--recursive`，且要认得**簇合形态**
> （`-rf` / `-Rf` / `-fr` / `-vrf`）。与现有 `-\w*f` 同款用 `/^-\w*[rR]/` 加长旗标等值。
> **不改成前缀匹配**：长旗标缩写在本机不可达（§1.4.1），前缀匹配只会平白扩大误判面。

### 2.2 这是一次**反方向**收紧，要说清为什么

**主论证：这是白名单内的单调性违背。**
今天 `rm -r src/x` 判 `writes`（失守），而**加上** `-f` 之后 `rm -rf src/x` 反而降级到疑似。
在同一张动词白名单内，给命令**增加**一个破坏性旗标却让它的判定**变轻**——
这是判据自身的单调性缺陷，与「该不该扩大白名单」无关，修它不牵连任何表外形态。

`-f` 的幂等豁免本身是对的（`rm -f <不存在>` 退 0），但它的适用理由只对「目标不存在」成立，
而判定层不做 I/O。对**非递归**的 `rm -f <文件>` 这个不确定性可以接受；
`-r` 把论域从一个文件扩到整棵子树之后就不能了。

> **附注（不作为主论证）**：`-r` + `-f` 在直觉上也是破坏力最大的一格。
> 但**不能用破坏力排序来论证本条**——按那个标准，§1.3 登记的表外动词破坏力同级甚至更难诊断，
> 而它们今天写面彻底静默，蕴含的必做集合远大于本主题。

### 2.3 备选与取舍

| 方案 | 做法 | 评价 |
| :--- | :--- | :--- |
| **A（推荐）** | 递归 + 强制 ⇒ 不算幂等，进 `writes` | 最直接；误杀面见 §2.4 |
| B | 仍进疑似，但换一条更重的 `why` 文案并驱动告警 | 不改失守判定 ⇒ `guard` 以 `write_events` 非空为唯一判据 ⇒ 闸门仍然绿 ⇒ 等于没修 |
| C | 只在「目标在项目内**且**可静态解析」时提到 `writes` | **与 A 零差异**——`base.ts:974-986` 的判定顺序本就是「项目外 → 疑似」「提不出目标 → 疑似」 |

**取 A。**

### 2.4 误杀面与新增作废面（如实登记）

#### 2.4.0 作用面：两层，不要混成一层

**第一层——代码论域，只在 codex 一侧。**

**第二层——安全原则，适用全项目。**

#### 2.4.1 缺口一的误杀面

修完之后，`rm -rf <项目内、但实际不存在的目录>` 会被判 `writes` ⇒ 只读失守 ⇒ 整侧作废。

  从而穿过「只喂成功命令」的契约进到判定层。不可达的是**不带 `-f`** 的同形态（退 1）。
- **代价**：**整轮作废重跑**。本主题自己就吃过一次——plan 第 2 轮因 codex 侧超时整轮作废。
- **误杀频率可核，但窗口有限**：`retention.run_dir_days` 默认 30 天、
  `codex.ts:614-630` 另把 trace 落盘，所以**核得到**，
  只是样本是「**本机、codex 侧、近 30 天，到期整删**」。
  **结案留痕必须连窗口与单机性一起写**，否则后来者会把它当误杀率；
  **0 命中只能证弱不能证无**。
- **零成本诊断指纹**：本误杀形态是「目标不存在 ⇒ 必然没有任何工作树改动」，
  故 `snapshot.drift` **恒 false**；而 §2.4.2 的 `make -j4 &> build.log` 是真落盘、真失守，
  drift 非 false。`gate.ts:305-325` 的 readonly_breach 处置文案本就先核 drift 再分两步，
  **据此可把两档分开**，不必只靠去 `runs/` 数频率。

#### 2.4.2 缺口二的新增作废面

取方案 A 之后，双流重定向的写面与 `>` **完全同权**。于是这类命令第一次成为整侧作废触发器：

| 命令 | 今天 | 修后 |
| :--- | :--- | :--- |
| `make -j4 &> build.log` | `writes=[]`，只留一条假读取 | **`writes=[命令]`** ⇒ 失守 |

依据见 §2.4.0 第二层。三侧对这一裁定均无异议。

#### 2.4.3 分离 fd 形态的误杀面（r4 引入、r5 消除，保留登记）

r4 的分界表写「残留是裸 `&` ⇒ 取下一 token 作目标」而没有分流，
于是 `echo x >& 2` / `echo x >& -` 会把 `2` / `-` 当写入目标——
`isResolvablePath` 对两者都返回 true（`base.ts:801-803`）⇒ 归一成 `/proj/2` ⇒ **假失守**。
而 §1.4.2 第 7、8 行实测这两条是 fd 操作、不产生任何文件。

**处置**：§3.1 规则 2 对下一 token 做等值分流（纯数字或 `-` ⇒ 排除）。§4 为这两条设用例。

#### 2.4.4 `why` 文案：契约实况，不是承诺

```ts
export interface WriteCommandClassification {

```

命令一旦进 `writes` 就只剩原始命令行（`base.ts:759`），`why` 是 `SuspectedWrite` 的字段（`:761`）。
成因说明落在**代码注释**与 **guard 侧告警文案**，**不承诺结构化字段**。

## 3. 缺口二的修法

### 3.1 判别轴是**运算符形态**，不是残留

> fd 与文件的语义取决于**运算符本身**——同一残留 `&2`，
> 在 `>&2` 是 fd 复制、在 `>>&2` 是写文件 `2`。

#### 改动 ①：`REDIRECT_RE` 认全运算符

```ts
// 今天（base.ts:497）
const REDIRECT_RE = /^[0-9]*>>?/;
// 改为：可选 fd 数字或 &，然后 > 或 >>，然后可选 &，然后可选 clobber 后缀
const REDIRECT_RE = /^(?:&|[0-9]*)>>?&?[|!]?/;
```

#### 改动 ②：按运算符分流（`base.ts:821-833`）

```ts
const op = REDIRECT_RE.exec(t)?.[0];
const glued = t.slice(op.length);
// 唯一有 fd 语义的一族：无后缀的 [n]>& —— 单个 >、& 在其后、& 不在其前、且不带 clobber 后缀
const isFdOp = /^[0-9]*>&$/.test(op);
```

> **`isFdOp` 必须无 clobber 后缀**（r6 相对 r5 的核心修正，三侧同时命中）。
> r5 写的是 `/^[0-9]*>&[|!]?$/`，把 `>&|` / `>&!` / `2>&|` / `2>&!` 划进了 fd 族，
> 于是规则 1、2 会把 `echo x >&| 2` 当 fd 操作排除——
> 而 §1.4.2 第 22～25 行实测它们**全部建出文件**。**clobber 后缀消去 fd 语义。**
>
> **防回退注释要写进代码**：这一格与「规则 1、3 必须等值匹配」是同一族陷阱——
> 判据一旦放宽（加后缀、改前缀），就会把真实写入静默吃掉。

**四条规则，按序短路**：

| # | 条件 | 处置 | 覆盖形态 |
| :--- | :--- | :--- | :--- |
| 1 | `isFdOp` 且 `glued` **恰为**纯数字或 `-` | fd 操作，**排除** | `>&2`、`2>&1`、`1>&2`、`>&-`、`2>&-` |
| 2 | `isFdOp` 且 `glued === ''`（分离） | 取下一 token；**恰为**纯数字或 `-` 则排除，否则作文件目标。**无论哪一支，`consumed.add(i + 1)` 一律执行** | `>& 2` 排除；`>& src/leak.txt` 取目标 |
| 3 | `isFdOp` 且 `glued` 非空非数字非 `-` | **文件目标** `glued` | `>&src/leak.txt`、`2>&src/leak.txt`、`>&2foo` |
| 4 | 非 `isFdOp` | **文件目标，无条件**：`glued === ''` 取下一 token，否则取 `glued` | `> 2`、`>> 2`、`&> 2`、`>>& 2`、`>>&2`、`&>src/leak.txt`、**`>&\|t.txt`、`>&\| 2`、`>\|p1.txt`**、`2>>&1` |

> **规则 4 的「无条件」是要害**：r4 在这里加了「下一 token 是纯数字或 `-` 就排除」，
> 而 §1.4.2 第 1～6 行证明这些运算符**没有 fd 语义**、目标位就是文件名，
> 那一格造成 `echo x > 2`（今天判 `writes`）降为双空——**静默漏检回归**。
> 分流**只属于 fd 族**（规则 2）。
>
> **规则 2 的 `consumed.add(i + 1)` 不可省**（r5 双审 AGY-02）：
> `base.ts:844-846` 的写动词操作数是
> `tokens.filter((t, i) => i > verbIdx && !consumed.has(i) && !t.startsWith('-'))`，
> 靠 `!consumed.has(i)` 过滤。若排除 fd 目标时不 consume，那个数字 token 会留在 args 里，
> `mode === 'last'` 的动词会把它当最后一个操作数——
> **`cp /tmp/a src/b.ts >& 2` 的写目标会被篡改成 `2`**。
> 既有用例 `codex-write-verbs.test.ts:212`「重定向记号不得混进写动词的操作数」正是守这个的。
>
> **规则 4 不需要 `slice(1)`**（r5 双审 AGY-03 ≡ GLM-04）：
> 新正则的 `&?` 会把紧跟运算符的 `&` 吞进 `op`，规则 4 下 `glued` 不会以 `&` 打头。
> 唯一可能的剩余路径（`>>&&x` 一类）要么是重定向缺目标的语法错、
> 要么被 `SEGMENT_SPLIT_RE` 的环视切走，均不可达。
> r5 保留了这个从句（来自 r4 的旧正则心智），**本稿删掉**——
> 不可达的规格会诱导写出不可测的分支，`§4` 的变异清单也无从为它设变异。

### 3.2 为什么不取「只补写面」

| 位置 | 做法 | 影响面 |
| :--- | :--- | :--- |
| **A（推荐）** | 改 `REDIRECT_RE` + 运算符分流，三个消费点同时受影响 | 一处改全部对齐 |
| B | 只在 `writeSinksOfSegment` 里单独认这些拼写 | 写面修好、**读面污染仍在**；两份判据不同宽，正是本仓反复栽的形状 |

**取 A。** 理由是 §1.2 的读面那一半：同一个正则同时喂写面与读面，
只修写面会让「重定向目标以读取身份进路径面」留下来，
而它喂的是 **`projectReads` 证据面与 `consulted` 交叉核对**——
即审查员能借一条从未读过的路径坐实虚假的 `consulted` 声明。

### 3.3 影响面：`REDIRECT_RE` 的三个消费点

全仓 `grep` 确认消费点**恰为三处**：`base.ts:535`、`:584`、`:821-833`。

| # | 位置 | 今天的作用 | 改后预期 |
| :--- | :--- | :--- | :--- |
| ① | `extractFromSegment` 分离写法跳过下一 token（`:535`） | `… 2> out.txt` 的 `out.txt` 不算读路径 | 各拼写的分离目标也不再算读路径——**修掉假读取** |
| ② | `extractFromSegment` 紧贴写法跳过本 token（`:584`） | `2>out.txt` 不算读路径 | `&>f` 整条不再进读面——**修掉垃圾 token** |
| ③ | `writeSinksOfSegment` 取写目标（`:821-833`） | `>f` / `> f` 取到目标 | 各拼写的紧贴与分离形态都取到目标——**修掉写面漏检** |

> **消费点① 的条件**：它今天是「残留**为空**才 skip 下一 token」。
> 新正则把运算符整体吞掉后，分离写法的残留**本来就是空**（`>&`、`>>&`、`&>`、`>|` 都被吞完），
> 所以这个条件**不需要改**——r4 曾为旧正则加过「或裸 `&`」的补丁，换轴后自然消失。
> **但仍要有用例守着**，因为它依赖新正则把后缀吞干净这一点。
>
> **①与③ 对下一 token 的处理刻意不对称**：③ 要分流（fd 族里的 `2` 不是写目标），
> 而 ① **一律 skip**。理由是职责不同：
> **① 的 skip 对文件目标是必要的**（重定向目标是写位、不是读证据），
> 对 fd 编号则是顺手且无害的统一。两条判据不同轴，不要为对称而合并。
>
> > r5 在这里给的论据是「若 ① 也分流，`echo x >& 2` 的 `2` 会归一成 `/proj/2` 进 projectReads」——
> > **那个机制描述是错的**（r5 双审 GLM-03）：`base.ts:611` 的「像路径」判据是
> > `!t.includes('/') && !/\.[A-Za-z0-9]+$/.test(t)`，纯数字 `2` 既不含 `/` 也无扩展名，
> > 根本到不了 `out.push`。结论仍对，论据换成上面这条。

> **`>&2` 一族的排除职责保住但分得更细**：`2>&1` 的残留 `&1` 仍被规则 1 排除，
> 改了 `REDIRECT_RE` 之后它仍命中 `2>&`、残留仍是 `1`，**行为一字不变**——
> 但这条要有用例守着。

### 3.4 不受本改动影响的一族（登记，防止后来者踢翻）

**引号内的 `&>` 字面量**（`grep -n '&>' src/a.ts`）修前修后都正常。
免疫**不是**本节判据给的，而是 `base.ts:653-655`（读面）与 `:928-930`（写面）的引号剥离：

```ts
cmd.replace(/(['"`])([\s\S]*?)\1/g, (_m, _q, inner) =>
  /[\s;&|()]/.test(inner) ? ' ' : ` ${inner} `)
```

含 `&` 的引号段整体被换成空格，`&>` 根本不成为 token。**改引号口径会踢翻它**，故 §4 加锁例。

## 4. 测试

**缺口一**

- `rm -rf src/existing-dir`、`rm -r --force …`、`rm -R -f …`、`rm --recursive --force …`
  ⇒ **四种写法都进 `writes`**；后两条是合成输入（§1.1），用例仍有效；

**缺口二 · 写面（按 §3.1 四条规则组织）**

- **规则 4 · 前置 `&` 双流**：`echo secret &> src/leak.txt`、`&>src/leak.txt`、
  `&>> src/leak.txt`、`&>>src/leak.txt` ⇒ 进 `writes`；
- **规则 4 · 双流追加**：`echo secret >>& src/leak.txt`、`>>&src/leak.txt` ⇒ 进 `writes`；
- **规则 4 · 回归锁（r4 的漏检面）**：`echo x > 2`、`echo x >> 2`、`echo x &> 2`、
  `echo x >>& 2`、`echo x > -` ⇒ **仍进 `writes`**。
  注释写明：这些运算符没有 fd 语义，目标位是文件名（§1.4.2 第 1～6 行）；
- **规则 4 · clobber×数字（r5 的漏检面，本稿新增）**：`echo x >&| 2`、`echo x >&|2`、
  `echo x >&!2`、`echo x >&| -`、`echo x 2>&! 1` ⇒ **进 `writes`**。
  注释写明：**clobber 后缀消去 fd 语义**（§1.4.2 第 22～25 行），`isFdOp` 不得带 `[|!]?`；
- **规则 4 · 普通强制覆盖（本稿新增）**：`echo P >| p1.txt`、`>|p1.txt`、
  `>! p2.txt`、`>>| p3.txt`、`>>! p4.txt` ⇒ 进 `writes`，且目标是 `pN.txt` 而**不是** `|pN.txt`；
- **规则 3 · 后置 `&` 双流**：`echo secret >& src/leak.txt`、`>&src/leak.txt`、
  `echo secret 2>& src/leak.txt`、`2>&src/leak.txt` ⇒ 进 `writes`。
  注释写明：**收进写面在两个外壳下都不亏**（D6）——
  某拼写在别的外壳下退非零时，`exit_code === 0` 的契约已把它挡在判定层外。
  **不要写「bash 下这些形态退非零」**：分离写法的 `>& 文件` 在 bash 下 rc=0 且真建文件（§1.4.2 bash 表末行）；
- **规则 3 · 等值防线**：`echo Y >&2foo` ⇒ 进 `writes`（目标 `2foo`），防前缀式实现；
- **边界**：`echo x 2>>&1` ⇒ 进 `writes`（目标 `1`）；`echo x >>&-` ⇒ 进 `writes`（目标 `-`）；
- **作废面**：`make -j4 &> build.log` ⇒ 进 `writes`（§2.4.2 的裁定口径）。

**缺口二 · fd 操作回归（一字不变）**
