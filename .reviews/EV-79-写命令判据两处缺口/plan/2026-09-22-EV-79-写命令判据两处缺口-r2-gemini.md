### AGY-01 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §3.1 & §3.3` |
| 类别 | correctness ｜ 层次 plan |

**问题**：§3.1 六格分界表第 5 格「残留是裸 &」无条件将下一 token 提取为写入文件目标，导致分离式 fd 复制（如「>& 2」）与关闭 fd（如「>& -」）被误判为向项目内文件「2」或「-」写入，直接触发只读失守并导致整侧作废；同时分离式 fd 操作未将下一 token 加入 consumed，会使该 token 逃逸为后续写动词的操作数造成二次误判。

**依据**：查阅 src/trivium/adapters/base.ts:801-832, 844-846 与 Bash 手册 Redirection 章节。在 Bash 中，操作符「>&」与目标间空格可选，「>& 2」等价于「>&2」（重定向至 fd 2），「>& -」等价于「>&-」（关闭 fd）。在 plan §3.1 第 5 格中，裸「&」的下一 token 被无条件视为文件目标，传给 sinks 后「isResolvablePath('2')」为真，在 classifyWriteCommands:974-988 归一化为项目根下路径并判为 writes（只读失守）。此外，对于「2>& 1」，虽命中第 2 格排除，但代码未对分离写法的下一 token 标记「consumed.add(i + 1)」，导致「1」逃逸至后续写动词（如「cp src/a /tmp/b 2>& 1」中「1」被当作 mode: last 的目标）。

**建议**：① 在第 5 格增加下一 token 校验：若下一 token 为纯数字（/^[0-9]+$/）或「-」，属于分离式 fd 复制或关闭 fd，必须排除，不得 push 进 sinks；仅当下一 token 既非纯数字也非「-」时才作为文件写入目标；② 无论文件目标还是分离式 fd 操作，只要消费了下一 token，必须执行「consumed.add(i + 1)」；③ 在 plan §4 补充分离式 fd 操作测试（如「echo x >& 2」不进任何档，以及「cp src/a /tmp/b 2>& 1」正确识别）。

### AGY-02 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §1.1 & §1.4` |
| 类别 | contract ｜ 层次 plan |

**问题**：§1.1 表格第 87 行对照命令「rm -r src/existing-dir」的真实可达性被标注为「否」，理由写为「退 1，进不了判定层（§1.4）」，混淆了「删除已存在目录」与「删除不存在目录」的语境，容易误导维护者将该对照用例视为死用例。

**依据**：查阅 plan §1.1:87、plan §1.4:173 与 src/trivium/adapters/base.ts:893。在真实环境中，删除已存在目录「rm -r src/existing-dir」成功执行退 0，符合只喂成功命令的契约，完全真实可达且当前 HEAD 确实判 writes；§1.4 实测退 1 的对象是「rm -r nope_dir」（目标不存在）。§1.1 表格命令列写着「existing-dir」，可达性却套用不存在目录的退出码 1 判定为「否」，形成概念冲突。

**建议**：将 §1.1 第 87 行对照命令明确改写为目标不存在形态（如「rm -r src/nope_dir」或「rm -r <不存在>」），使其与 §1.4 的退出码 1 依据保持一致；若保留「existing-dir」，则应将真实可达性修正为「可达」。
