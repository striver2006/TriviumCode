### AGY-01 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `.reviews/EV-79-写命令判据两处缺口/plan/2026-09-22-EV-79-写命令判据两处缺口-r5-claude.md §3.1 改动 ②（:411）` |
| 类别 | correctness ｜ 层次 plan |
| 置信度 | high |

**问题**：isFdOp = /^[0-9]*>&[|!]?$/ 正则包含了可选强制覆盖后缀 [|!]?，导致 >&|、>&!、2>&|、2>&! 被误判归入 isFdOp。当这些强制覆盖运算符的操作数为纯数字或 - 时（例如 echo payload >&| 2、echo payload >&|2 或 2>&|1），会触发规则 1 或规则 2 被当作 fd 操作排除，导致文件写入静默漏检。shell 语义中 >&| 是 &>| 的别名，纯属双流强制覆盖写文件，其数字目标是文件名而非描述符。该形态直接构成符合 §3.1 运算符文法却仍被漏检的反例。

**依据**：1. 计划 §3.1 :410 注释明确声明「唯一有 fd 语义的一族：[n]>& —— 单个 >、& 在其后、& 不在其前」，字面上并未包含 [|!]?；
2. zsh 手册与规范确认 >&| word 与 &>| word 完全等价，是对 word 文件的强制截断写入；文件描述符复制操作不存在 noclobber 语义；
3. 计划 §1.4.2 证明 &> 2、&>> 2、>>& 2 与 2>>&1 遇到数字目标均建出同名文件；强制覆盖族同理，echo payload >&| 2 必然落盘名为 2 的文件；
4. 但按 §3.1 判据，isFdOp 判定为真，glued 或下一 token 为 2 时命中规则 1/2 排除，导致 writes 漏判；§3.1 表格 :446 行亦将 2>&|t.txt 标为 isFdOp=Y，仅因 t.txt 非数字才侥幸逃逸进规则 3；
5. 对照 doc/08_project/BACKLOG.md EV-79 论域说明与 .reviews/EV-79-写命令判据两处缺口/plan/2026-09-22-EV-79-写命令判据两处缺口-r5-claude.md §1.4.2 实测。

**建议**：将 isFdOp 正则严格收敛为 /^[0-9]*>&$/，剥离 [|!]?。使所有含 | 或 ! 的强制覆盖运算符（>&|、>&!、2>&| 等）在 isFdOp 处判定为 false，统一进入规则 4 无条件提取文件目标；在 §4 测试用例中补齐 echo x >&| 2 与 echo x >&|2 判定为 writes 的断言。

**问题**：§3.1 规则 2 中 isFdOp 且 glued === '' 分离写法下，若下一 token 为纯数字或 -，处置仅声明「fd 操作，排除」，未明确在 writeSinksOfSegment 中将下一 token 索引加入 consumed 集合。若未将其标记为 consumed，该数字 token 会残留在写动词参数序列中，导致如 cp /tmp/a src/b.ts >& 2 等命令的写入目标被末尾的 2 篡改覆盖。

**依据**：1. 查阅 src/trivium/adapters/base.ts:824-831，当前只要匹配重定向标记且为分离写法，即执行 consumed.add(i + 1)；

**建议**：在 §3.1 规则 2 及 §3.3 消费点 ③ 明确写明：在 writeSinksOfSegment 实现中，凡属于分离形态（glued === ''），无论该 token 最终是提取为 sink 还是被 fd 规则排除，consumed.add(i + 1) 均须无条件执行。
