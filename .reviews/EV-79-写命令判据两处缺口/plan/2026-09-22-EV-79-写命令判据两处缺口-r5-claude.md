### 1.1 缺口一：递归 + 强制的四种写法全部落进疑似档

| 命令 | `writes` | `suspected` | 真实可达？ |
| :--- | :--- | :--- | :--- |
| `rm -rf src/existing-dir` | `[]` | `rm 的幂等形态…` | **可达** |
| `rm -r --force src/existing-dir` | `[]` | `rm 的幂等形态…` | 否（**形态**不可达） |
| `rm -R -f src/existing-dir` | `[]` | `rm 的幂等形态…` | **可达** |
| `rm --recursive --force src/existing-dir` | `[]` | `rm 的幂等形态…` | 否（**形态**不可达） |
| **对照** `rm -r src/existing-dir`（无 `-f`） | **`[命令]`** | `[]` | **可达**（目标存在 ⇒ 退 0） |
| **对照** `rm -f src/gone.ts`（无 `-r`） | `[]` | `rm 的幂等形态…` | **可达** |

> **两类「否」含义不同**：
> - **形态不可达**（两行长旗标）：本机 BSD `rm` 不接受任何长旗标，退 64（§1.4.1）。
>   它们是**分类器直调的合成输入**，单测仍有效，**不能因为「不可达」就删掉用例**。
> - **条件不可达**（目标不存在时）：`rm -r <不存在>` 退 1 进不了判定层，
>   但 `rm -r <存在目录>` **退 0 且完全可达**，判 `writes` 正是这条判据今天的**正确检出**。
>   r4 之前把这两类混成一个「否」（以 `existing-dir` 之名行 `nope` 之实），三侧同时命中。
>   **§4 为「`rm -r <存在目录>` ⇒ writes」专设回归条**，它是 §2.2 单调性论证的另一半。

**成因**（`base.ts:967-970` 的 `idempotent` 判据）：

```ts
const idempotent =
  (verb === 'mkdir' && tokens.some((t) => /^-\w*p/.test(t) || t === '--parents')) ||
  (verb === 'rm' && tokens.some((t) => /^-\w*f/.test(t) || t === '--force'));
```

判据只问「有没有 `-f`」，不问「是不是递归」。

### 1.2 缺口二：双流重定向静默漏检，且**倒过来污染读路径面**

直调 `classifyWriteCommands(cmds, '/proj')` 与 `extractPathTokens(cmd)`：

| 命令 | `writes` | `suspected` | 读路径 |
| :--- | :--- | :--- | :--- |
| `echo secret &> src/leak.txt` | `[]` | `[]` | **`["src/leak.txt"]`** |
| `echo secret &>src/leak.txt` | `[]` | `[]` | **`["&>src/leak.txt"]`** |
| `echo secret >& src/leak.txt` | `[]` | `[]` | **`["src/leak.txt"]`** |
| `echo secret >&src/leak.txt` | `[]` | `[]` | `[]` |
| `echo secret 2>& src/leak.txt` | `[]` | `[]` | **`["src/leak.txt"]`** |
| `echo secret >>& src/leak.txt` | `[]` | `[]` | **`["src/leak.txt"]`** |
| `echo secret >>&src/leak.txt` | `[]` | `[]` | `[]` |
| `echo secret >&\| src/leak.txt` | `[]` | `[]` | `[]` |
| **对照** `echo x > src/a.ts` | **`[命令]`** | `[]` | `[]` |
| **对照** `echo x > src/a.ts &> /dev/null` | **`[命令]`** | `[]` | **`["/dev/null"]`** |

**读面有两种不同症状，分开登记**：

- **假读取**（分离形态）：写目标以**读取身份**进路径面。
- **垃圾 token**（紧贴 `&>` 形态）：整个 `&>src/leak.txt` 被当成一条路径收进读面
  （`REDIRECT_RE` 认不出它、`:584` 跳不过，又因含 `/` 被 `:612` 的「像路径」判据收走），
  归一后落在项目内，还会计入 `projectReads` 证据面。

**读面污染的危害落在哪里**（r4 CODEX-02 更正了此前四稿一直写错的归因）：

回填（`effectiveReadPaths` → `extractPathTokens`）的**消费方只有三处**，
`base.ts:676-682` 的文档注释明写：

> **消费方只有三处**：`checkEvidence` 的 `no_trace` 与 `projectReads`、
> `judgeSide` 的 consulted 交叉核对。
> **措施 a（`checkPeerLeak`）不吃回填**

`guard.ts:277-283` 同款，落款还是「r2/r3 双审两侧均确认」；
`guard.ts:305-307` 的 `checkPeerLeak` 入参确实只有 `read_paths ∪ search_hit_paths`。

> **所以「喂进措施 a 的禁读核验」这个归因是错的**，r1～r4 四稿一直这么写。
> 命令原文的禁读核验是**措施 b**，它扫 `command_texts` 字面量，与 `REDIRECT_RE` 无关，
> 改这个正则对它零影响。
>
> **真正的危害是「证据自证」**：一条从未读过的路径，只要被某次重定向当过目标，
> 就能让 `consulted` 里的虚假声明通过 `judgeSide` 的交叉核对——
> 审查员可以借此坐实自己没读过的文件。这比原来写的那条更重，也更贴近本主题要守的东西。

**写面成因（同源）**：`REDIRECT_RE = /^[0-9]*>>?/` 只认「可选 fd 前缀 + `>`」，
于是前置 `&` 的拼写整条认不出；后置 `&` 的拼写虽能命中 `>`，
但残留以 `&` 打头，被 `base.ts:828` 的 `if (!glued.startsWith('&')) sinks.push(glued)` 一刀切掉。

> **`SEGMENT_SPLIT_RE` 那一半是对的**：否定环视 `(?<![>&])[|;&](?![>&])` 护住了
> `&>` 里的 `&` 不作分隔符。r9 双审那个 blocker 修的正是这一半，**只修了一半**。

#### 1.4.1 `rm` 各形态的退出码

| 命令 | 退出码 | 对判定层的含义 |
| :--- | :--- | :--- |
| `rm -r nope_dir` | **1**（`No such file or directory`） | 进不了判定层——契约只喂 `exit_code === 0` |
| `rm -rf nope_dir` | **0** | **可达**——本次收紧新引入的误杀路径 |
| `rm -f nope.txt` | **0** | 今天已走幂等档，本次不变 |
| `rm --recursive --force nope_dir` | **64**（`illegal option -- -`） | BSD `rm` 不接受长旗标 ⇒ 形态不可达 |
| `rm --recur --forc nope_dir` | **64** | GNU 风格缩写同样不可达 ⇒ 判据维持等值匹配 |

#### 1.4.2 重定向运算符的语义（**本稿的地基**）

判别法：**跑完看目录里建出了什么文件**。建出同名文件 ⇒ 该 token 是**文件目标**；
不建文件且输出改道 ⇒ **fd 操作**。

| # | 命令（zsh） | rc | 建出文件 | 语义 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | `echo X > 2` | 0 | **`2`** | 文件 |
| 2 | `echo X >> 2` | 0 | **`2`** | 文件 |
| 3 | `echo X &> 2` | 0 | **`2`** | 文件 |
| 4 | `echo X &>> 2` | 0 | **`2`** | 文件 |
| 5 | `echo X >>& 2` | 0 | **`2`** | 文件 |
| 6 | `echo GLUED >>&2` | 0 | **`2`** | 文件（**紧贴也是文件**） |
| 7 | `echo HELLO >& 2` | 0 | **无** | **fd 复制** |
| 8 | `echo X >& -` | 0 | **无** | **关闭 fd** |
| 9 | `echo Y >&2foo` | 0 | **`2foo`** | 文件（**故判据须等值、不可前缀**） |
| 10 | `echo ERRLINE 2>& t1.txt` | 0 | **`t1.txt`** | 文件 |
| 11 | `{ echo A; echo B >&2; } 2>&t2.txt` | 0 | **`t2.txt`**（内容 `B`） | 文件（stderr 落盘） |
| 12 | `echo SEP >>& sep.txt` | 0 | **`sep.txt`** | 文件 |
| 13 | `echo GLU >>&glu.txt` | 0 | **`glu.txt`** | 文件 |
| 14 | `echo P1 >&\| t1.txt` | 0 | **`t1.txt`** | 文件 |
| 15 | `echo P2 >&! t2.txt` | 0 | **`t2.txt`** | 文件 |
| 16 | `echo P3 &>\| t3.txt` | 0 | **`t3.txt`** | 文件 |
| 17 | `echo P4 &>! t4.txt` | 0 | **`t4.txt`** | 文件 |
| 18 | `echo P5 2>&\| t5.txt` | 0 | **`t5.txt`** | 文件 |
| 19 | `echo P6 2>&! t6.txt` | 0 | **`t6.txt`** | 文件 |
| 20 | `{ echo OUT; echo ERR >&2; } 2>>&1` | 0 | **`1`** | 文件（**不是** fd 追加复制） |
| 21 | `echo X >>&-` | 0 | **`-`** | 文件（**不是**关闭 fd） |

**bash 3.2 对照**（同形态、默认模式）：

| 命令 | rc | 结果 |
| :--- | :--- | :--- |
| `{ echo A; echo B >&2; } 2>&b1.txt` | **1** | `ambiguous redirect`，不建文件 |
| `{ echo A; echo B >&2; } 2>&b2.txt`（`--posix`） | **1** | 同上 |
| `echo X >>& f`（codex 侧复核） | **2** | `syntax error`，不建文件 |

**从这张表读出三条结论**：

1. **fd 语义只属于 `[n]>&` 一族**（第 7、8 行）。`>>&`（第 5、6、12、13、20、21 行）
   虽然也含 `>&`，但它是**双流追加文件重定向**；`&>`（第 3、4 行）是双流文件重定向。
   **`&` 在 `>` 的哪一侧、以及 `>` 是一个还是两个，共同决定语义**——这是换轴的依据。
2. **同一个 fd 族里，是不是 fd 操作取决于目标位**（第 7～11 行）：
   目标恰为纯数字或 `-` 才是 fd 操作，否则是文件。第 9 行 `>&2foo` 建出文件，
   **所以判据必须等值匹配**，前缀匹配（`/^&\d/` 一类）会造成静默漏检。
3. **文本判据外壳无关，取各外壳拼写的并集**（r4 CODEX-06）。
   `2>&word` 在 zsh 是文件写、在 bash 是 `ambiguous redirect`；
   `>>&` 在 zsh 是文件写、在 bash 是语法错。两者都属「一侧可达即须收」，
   而**可达性已经被 `succeededCommands` 的 `exit_code === 0` 收敛掉了**——
   bash 下它们退非零，根本进不了判定层。**所以收进写面在两个外壳下都正确**，
   这才是 D6 的承重论证（r4 把它挂在「zsh 才是决定性的」下面，是把引证说重了：
   `base.ts:413-418` 是 `SUBSHELL_RE` 上方的**文档注释**而非拉起代码，
   注释自述依据是 n=1 的录制样本，且 `SUBSHELL_RE` 明写接受 `zsh|bash|sh|dash` 四种外壳）。

#### 1.4.3 只读环境下的复测法（**给审查员用**）

审查侧**建不了文件**（zcode 侧 denylist 含 `Bash`、gemini 侧工具面只有 `Read,Grep,Glob`），
所以 §1.4.2 的判别法在审查侧**不可执行**。这正是 r3 两侧结论互相矛盾、
以及 r4 一侧声称实测而其实零命令的根因（r4 CODEX-04；另见 BACKLOG **EV-95**）。

**可用的替代判别法（不落盘）**：把目标指向**不存在的目录**，或在不可写目录下跑，
从**报错文本**区分三种情形：

| 报错 | 含义 |
| :--- | :--- |
| `no such file or directory: <路径>` / `operation not permitted: <名>` | 该 token 被当**文件目标**打开 |
| `ambiguous redirect` | 该拼写在本外壳下**不合法**（不可达） |
| `syntax error near unexpected token` | 语法不支持（不可达） |
| 无报错、rc=0、无文件 | **fd 操作** |

例：`/bin/zsh -c 'echo X >>& /nonexistent-dir-zzq/t.txt'` 报
`no such file or directory: /nonexistent-dir-zzq/t.txt` ⇒ `>>&` 的宾语是文件。

## 2. 缺口一的修法

### 2.1 判据

`idempotent` 的 `rm` 分支加一条排除：**同时出现递归旗标时不算幂等**。

> **递归旗标的形态要一次写全**：`-r` / `-R` / `--recursive`，且要认得**簇合形态**
> （`-rf` / `-Rf` / `-fr` / `-vrf`）。与现有 `-\w*f` 同款用 `/^-\w*[rR]/` 加长旗标等值。
> **不改成前缀匹配**：长旗标缩写在本机不可达（§1.4.1），前缀匹配只会平白扩大误判面。

### 2.2 这是一次**反方向**收紧，要说清为什么

**主论证：这是白名单内的单调性违背。**
今天 `rm -r src/x` 判 `writes`（失守），而**加上** `-f` 之后 `rm -rf src/x` 反而降级到疑似。
在同一张动词白名单内，给命令**增加**一个破坏性旗标却让它的判定**变轻**——
这是判据自身的单调性缺陷，与「该不该扩大白名单」无关，修它不牵连任何表外形态。

`-f` 的幂等豁免本身是对的（`rm -f <不存在>` 退 0），但它的适用理由只对「目标不存在」成立，
而判定层不做 I/O。对**非递归**的 `rm -f <文件>` 这个不确定性可以接受；
`-r` 把论域从一个文件扩到整棵子树之后就不能了。

> **附注（不作为主论证）**：`-r` + `-f` 在直觉上也是破坏力最大的一格。
> 但**不能用破坏力排序来论证本条**——按那个标准，§1.3 登记的表外动词破坏力同级甚至更难诊断，
> 而它们今天写面彻底静默，蕴含的必做集合远大于本主题。

### 2.3 备选与取舍

| 方案 | 做法 | 评价 |
| :--- | :--- | :--- |
| **A（推荐）** | 递归 + 强制 ⇒ 不算幂等，进 `writes` | 最直接；误杀面见 §2.4 |
| B | 仍进疑似，但换一条更重的 `why` 文案并驱动告警 | 不改失守判定 ⇒ `guard` 以 `write_events` 非空为唯一判据 ⇒ 闸门仍然绿 ⇒ 等于没修 |
| C | 只在「目标在项目内**且**可静态解析」时提到 `writes` | **与 A 零差异**——`base.ts:974-986` 的判定顺序本就是「项目外 → 疑似」「提不出目标 → 疑似」 |

**取 A。**

### 2.4 误杀面与新增作废面（如实登记）

#### 2.4.0 作用面：两层，不要混成一层

**第一层——代码论域，只在 codex 一侧。**
`classifyWriteCommands` 全仓只在 `adapters/codex.ts:185` 与 `:614` 被调用；
`extractPathTokens` 只有 `effectiveReadPaths` 一个调用点，且它对非 `command-trace` 早退；
全仓只有 `codex.ts:271` 声明 `COMMAND_TRACE_CAPABILITY`（agy / claude / zcode 均 `TOOL_TRACE`）。
**所以下面三条误杀面的实际发生面、以及结案时去 `runs/` 核频率的论域，都只是 codex 侧。**

**第二层——安全原则，适用全项目。**
D5（项目内的双流日志重定向按正确失守处理，不设豁免）的裁定依据是
「只读承诺保护的是被审项目与归档留痕」，这是**全仓通用的安全不变量**，
在 M10 引入任意 Driver 与多审核者之后对全仓都有约束力，**不是 codex 单侧特权或单侧豁免**。

> r4 把这两层混成一层、说「论域**全部**限定在 codex 侧」，是反过来说过头了（r4 AGY-02）。
> 另三侧若将来也走命令轨迹，同一条原则照样适用，只是今天没有那条代码路径。

#### 2.4.1 缺口一的误杀面

修完之后，`rm -rf <项目内、但实际不存在的目录>` 会被判 `writes` ⇒ 只读失守 ⇒ 整侧作废。

- **这是本次新引入的一条可达误杀路径。** `-f` 恰恰让目标不存在时命令也**退 0**（§1.4.1），
  从而穿过「只喂成功命令」的契约进到判定层。不可达的是**不带 `-f`** 的同形态（退 1）。
- **代价**：**整轮作废重跑**（与 M10a r7 稿 :662 的引文口径对齐）。
  本主题自己就吃过一次——plan 第 2 轮因 codex 侧超时整轮作废，三侧全部重跑。
- **误杀频率可核，但窗口有限**（r4 CODEX-05 更正了 r4 的「取不到」）：
  `retention.run_dir_days` 默认 30 天、`codex.ts:614-630` 另把 trace 落盘，所以**核得到**，
  只是样本是「**本机、codex 侧、近 30 天，到期整删**」。
  **结案留痕必须连窗口与单机性一起写**，否则后来者会把它当误杀率；
  **0 命中只能证弱不能证无**。
- **零成本诊断指纹**：本误杀形态是「目标不存在 ⇒ 必然没有任何工作树改动」，
  故 `snapshot.drift` **恒 false**；而 §2.4.2 的 `make -j4 &> build.log` 是真落盘、真失守，
  drift 非 false。`gate.ts:305-325` 的 readonly_breach 处置文案本就先核 drift 再分两步，
  **据此可把两档分开**，不必只靠去 `runs/` 数频率。

#### 2.4.2 缺口二的新增作废面

取方案 A 之后，双流重定向的写面与 `>` **完全同权**。于是这类命令第一次成为整侧作废触发器：

| 命令 | 今天 | 修后 |
| :--- | :--- | :--- |
| `make -j4 &> build.log` | `writes=[]`，只留一条假读取 | **`writes=[命令]`** ⇒ 失守 |
| `npm run build &> /tmp/log` | 同上 | 「写入目标在项目外」⇒ 疑似（不失守） |

**裁定口径：项目内的双流日志重定向按「正确失守」处理**，与 `> build.log` 同权，不另设豁免。
依据见 §2.4.0 第二层。三侧对这一裁定均无异议。

#### 2.4.3 分离 fd 形态的误杀面

**这一条是 r4 的修法自己引入的，本稿的换轴方案已消除，但保留登记**：

r4 的分界表写「残留是裸 `&` ⇒ 取下一 token 作目标」而没有分流，
于是 `echo x >& 2` / `echo x >& -` 会把 `2` / `-` 当写入目标——
`isResolvablePath` 对两者都返回 true（`base.ts:801-803`）⇒ 归一成 `/proj/2` ⇒ **假失守**。
而 §1.4.2 第 7、8 行实测这两条是 fd 操作、不产生任何文件。

**本稿的处置**：§3.1 的 fd 族分离写法对下一 token 做等值分流（纯数字或 `-` ⇒ 排除）。
§4 为这两条设用例。

#### 2.4.4 `why` 文案：契约实况，不是承诺

```ts
export interface WriteCommandClassification {
  writes: string[];              // ← 只有命令行原文，没有 why
  suspected: SuspectedWrite[];   // ← why 只存在于这一档
}
```

命令一旦进 `writes` 就只剩原始命令行（`base.ts:759`），`why` 是 `SuspectedWrite` 的字段（`:761`）。
成因说明落在**代码注释**与 **guard 侧告警文案**，**不承诺结构化字段**。

## 3. 缺口二的修法

### 3.1 换轴：判别轴是**运算符形态**，不是残留

> **这是本稿相对 r4 的核心变化。** r4 按「残留长什么样」分格，
> 而 §1.4.2 证明 fd 与文件的语义取决于**运算符本身**——
> 同一残留 `&2`，在 `>&2` 是 fd 复制、在 `>>&2` 是写文件 `2`。

#### 改动 ①：`REDIRECT_RE` 认全运算符

```ts
// 今天（base.ts:497）
const REDIRECT_RE = /^[0-9]*>>?/;
// 改为：可选 fd 数字或 &，然后 > 或 >>，然后可选 &，然后可选 clobber 后缀
const REDIRECT_RE = /^(?:&|[0-9]*)>>?&?[|!]?/;
```

#### 改动 ②：按运算符分流（`base.ts:821-833`）

```ts
const op = REDIRECT_RE.exec(t)?.[0];
const glued = t.slice(op.length);
// 唯一有 fd 语义的一族：[n]>& —— 单个 >、& 在其后、& 不在其前
const isFdOp = /^[0-9]*>&[|!]?$/.test(op);
```

**四条规则，按序短路**：

| # | 条件 | 处置 | 覆盖形态 |
| :--- | :--- | :--- | :--- |
| 1 | `isFdOp` 且 `glued` **恰为**纯数字或 `-` | fd 操作，**排除** | `>&2`、`2>&1`、`1>&2`、`>&-`、`2>&-` |
| 2 | `isFdOp` 且 `glued === ''`（分离） | 取下一 token；**恰为**纯数字或 `-` 则排除，否则作文件目标 | `>& 2` 排除；`>& src/leak.txt` 取目标 |
| 3 | `isFdOp` 且 `glued` 非空非数字非 `-` | **文件目标** `glued` | `>&src/leak.txt`、`2>&src/leak.txt`、`>&\|t.txt`、`>&2foo` |
| 4 | 非 `isFdOp` | **文件目标**，无条件：`glued === ''` 取下一 token；否则取 `glued`（以 `&` 打头则 `slice(1)`） | `> 2`、`>> 2`、`&> 2`、`>>& 2`、`>>&2`、`&>src/leak.txt`、`&>\|t.txt`、`2>>&1` |

> **第 4 格「无条件」是要害**：r4 在这里加了「下一 token 是纯数字或 `-` 就排除」，
> 而 §1.4.2 第 1～6 行证明这些运算符**没有 fd 语义**、目标位就是文件名，
> 那一格造成 `echo x > 2`（今天判 `writes`）降为双空——**静默漏检回归**。
> 分流**只属于 fd 族**（第 2 格）。
>
> **第 1、3 格必须等值**（`/^(?:\d+|-)$/`）：§1.4.2 第 9 行 `>&2foo` 建出文件，
> 前缀匹配会把它误排除。

#### 验证：38 个形态逐格对照

用上述正则与判据对 38 个 token 做切分与分类，**与 §1.4.2 的实测语义逐行对账，0 处不符**。
关键行摘录（完整表在 code 阶段随 evidence 件落盘）：

| token | `op` | `glued` | `isFdOp` | 判定 | §1.4.2 实测 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `>` ␣`2` | `>` | `''` | n | 文件 `2` | 建出 `2` ✓ |
| `>>&` ␣`2` | `>>&` | `''` | n | 文件 `2` | 建出 `2` ✓ |
| `>>&2` | `>>&` | `2` | n | 文件 `2` | 建出 `2` ✓ |
| `>&` ␣`2` | `>&` | `''` | Y | **排除** | 不建文件 ✓ |
| `>&2` | `>&` | `2` | Y | **排除** | 不建文件 ✓ |
| `>&2foo` | `>&` | `2foo` | Y | 文件 `2foo` | 建出 `2foo` ✓ |
| `2>&src/leak.txt` | `2>&` | `src/leak.txt` | Y | 文件 | 建出 ✓ |
| `&>\|t.txt` | `&>\|` | `t.txt` | n | 文件 | 建出 ✓ |
| `2>&\|t.txt` | `2>&\|` | `t.txt` | Y | 文件 | 建出 ✓ |
| `2>>&1` | `2>>&` | `1` | n | 文件 `1` | 建出 `1` ✓ |
| `>>&-` | `>>&` | `-` | n | 文件 `-` | 建出 `-` ✓ |

### 3.2 为什么不取「只补写面」

| 位置 | 做法 | 影响面 |
| :--- | :--- | :--- |
| **A（推荐）** | 改 `REDIRECT_RE` + 运算符分流，三个消费点同时受影响 | 一处改全部对齐 |
| B | 只在 `writeSinksOfSegment` 里单独认这些拼写 | 写面修好、**读面污染仍在**；两份判据不同宽，正是本仓反复栽的形状 |

**取 A。** 理由是 §1.2 的读面那一半：同一个正则同时喂写面与读面，
只修写面会让「重定向目标以读取身份进路径面」留下来，
而它喂的是 **`projectReads` 证据面与 `consulted` 交叉核对**——
即审查员能借一条从未读过的路径坐实虚假的 `consulted` 声明。

> **注意**：这条理由在 r1～r4 写的是「喂禁读核验（措施 a）」，**那是错的**（§1.2）。
> 取 A 的结论不变，但理由换了，而且换成的这条更重。

### 3.3 影响面：`REDIRECT_RE` 的三个消费点

全仓 `grep` 确认消费点**恰为三处**：`base.ts:535`、`:584`、`:821-833`。

| # | 位置 | 今天的作用 | 改后预期 |
| :--- | :--- | :--- | :--- |
| ① | `extractFromSegment` 分离写法跳过下一 token（`:535`） | `… 2> out.txt` 的 `out.txt` 不算读路径 | 各双流拼写的分离目标也不再算读路径——**修掉假读取** |
| ② | `extractFromSegment` 紧贴写法跳过本 token（`:584`） | `2>out.txt` 不算读路径 | `&>f` 整条不再进读面——**修掉垃圾 token** |
| ③ | `writeSinksOfSegment` 取写目标（`:821-833`） | `>f` / `> f` 取到目标 | 各拼写的紧贴与分离形态都取到目标——**修掉写面漏检** |

> **消费点① 的条件要扩**。它今天是「残留**为空**才 skip 下一 token」：
>
> ```ts
> if (REDIRECT_RE.test(t) && t.replace(REDIRECT_RE, '') === '') skip.add(i + 1);
> ```
>
> 新正则把运算符整体吞掉后，分离写法的残留**本来就是空**（`>&`、`>>&`、`&>` 都被吞完），
> 所以这个条件**不需要再加「或裸 `&`」**——r4 那条补丁是旧正则的产物，换轴后自然消失。
> **但仍要有用例守着**，因为它依赖新正则把 `&` 吞干净这一点。
>
> **①与③对下一 token 的处理刻意不对称**（三侧两轮均确认该不对称）：
> ③ 要分流（fd 族里的 `2` 不是写目标），而 ① **一律 skip**——
> 无论下一 token 是文件还是 fd 编号，它都是重定向记号的一部分，本来就不该算读路径。
> codex 侧给了对称化的代价：若 ① 也分流，`echo x >& 2` 里被排除的 `2` 就不再 skip，
> 会以读路径身份归一成 `/proj/2` 进 `projectReads`——**比今天更坏**。

### 3.4 不受本改动影响的一族（登记，防止后来者踢翻）

**引号内的 `&>` 字面量**（`grep -n '&>' src/a.ts`）修前修后都正常。
免疫**不是**本节判据给的，而是 `base.ts:653-655`（读面）与 `:928-930`（写面）的引号剥离：

```ts
cmd.replace(/(['"`])([\s\S]*?)\1/g, (_m, _q, inner) =>
  /[\s;&|()]/.test(inner) ? ' ' : ` ${inner} `)
```

含 `&` 的引号段整体被换成空格，`&>` 根本不成为 token。**改引号口径会踢翻它**，故 §4 加锁例。

## 4. 测试

新增用例落在 `test/unit/codex-write-verbs.test.ts`（既有 22 条，与本主题同面）。

**缺口一**

- `rm -rf src/existing-dir`、`rm -r --force …`、`rm -R -f …`、`rm --recursive --force …`

- **单调性基线**：`rm -r src/existing-dir`（无 `-f`）⇒ 进 `writes`。
  D1 论证的另一半，且 §1.1 标它「可达」——**不得因「合成输入」被误删**；
- **回归**：`rm -f src/gone.ts` 仍判幂等进疑似（r9 GLM-03 挣来的行为）；
- **回归**：`mkdir --parents src/existing` 仍判幂等（同一个 `idempotent` 表达式）。

**缺口二 · 写面（按 §3.1 四格组织）**

- **第 4 格 · 前置 `&` 双流**：`echo secret &> src/leak.txt`、`&>src/leak.txt`、

- **第 4 格 · 回归锁（r4 的漏检面）**：`echo x > 2`、`echo x >> 2`、`echo x &> 2`、
  `echo x >>& 2`、`echo x > -` ⇒ **仍进 `writes`**。
  用例注释写明：这些运算符没有 fd 语义，目标位是文件名（§1.4.2 第 1～6 行）；
- **第 3 格 · 后置 `&` 双流**：`echo secret >& src/leak.txt`、`>&src/leak.txt`、

  （§1.4.2 结论 3），**防止后来者按 bash 的 ambiguous redirect 把它改回排除**；
- **第 3 格 · 等值防线**：`echo Y >&2foo` ⇒ 进 `writes`（目标 `2foo`），防前缀式实现；
- **第 4 格 · 强制覆盖族**：`>&| `、`>&!`、`&>|`、`&>!`、`2>&|`、`2>&!` 六种 ⇒ 进 `writes`；

- **作废面**：`make -j4 &> build.log` ⇒ 进 `writes`（§2.4.2 的裁定口径）。

**缺口二 · fd 操作回归（一字不变）**

- **第 1 格**：`echo x >&2`、`2>&1`、`1>&2`、`>&-`、`2>&-` ⇒ 不进任何一档；
- **第 2 格（§2.4.3 的处置）**：`echo x >& 2`、`echo x >& -` ⇒ **不进任何一档**；
- **回归**：`echo x > src/a.ts 2>&1`、`cp /tmp/a src/b.ts 2>&1`、`echo x > src/a.ts &> /dev/null`
  仍进 `writes`（既有「掩码：fd 重定向不是掩码」那条用例不得变色）。

**缺口二 · 读面（正反各一 + 消费面一条）**

- **负**：上述各双流形态的 `extractPathTokens` ⇒ **不含** `src/leak.txt`；
  分离形态专测消费点①，紧贴 `&>` 形态专测垃圾 token 被消除；
- **正**：`extractPathTokens('cat src/a.ts')` ⇒ 仍含 `src/a.ts`；
  `extractPathTokens('grep foo src/a.ts &> /dev/null')` ⇒ 仍含 `src/a.ts`、不含 `/dev/null`；
- **消费面（r4 CODEX-02 的落点）**：补一条作用在**危害出口**上的断言——
  重定向目标不再计入 `projectReads`，或不再让 `consulted` 交叉核对被坐实。
  只钉 `extractPathTokens` 的正负输出，守的是中间函数，与 §3.2 选 A 的理由脱钩。

**引号免疫锁例（§3.4）**

- `grep -n '&>' src/a.ts` ⇒ `writes` 空、`reads` 含 `src/a.ts`。

**用例标题与论域对齐**

- 既有用例（`:160-161`）标题写着 `（2>&1 / >&2 / &>）` 而 cases 数组里没有 `>&2` 条目——补齐。
