### 0.1 本轮的形状：**我换了工具，但没换掉「凭记性」这件事**

r1 我被打中的是「落点清单手写、漏了 AGENTS.md」。我的修法是改用 `grep` 生成。
codex 与 glm 各自独立指出同一件事：**锚点集本身仍然是我手写的措辞清单**。
实测第三族说法「由/从探针结论构造」两个锚点都抓不到，活体有六处
（`types.ts:153`/`:230`/`:363`、`adapters/base.ts:8`、`codex.ts:8`/`:76`、`zcode.ts:90`）。

**glm 给出的那一击最干净**：我这一轮**自己改写出来的** `README.md:325`
（「由适配层从探针结论取」）**逃出了我自己记录在案的两条命令**。
修法的产物，用修法自己的工具找不回来。

「用了 grep」不等于「不再靠记性」——记性只是从「落点」挪到了「措辞」。

### 0.2 一处我 r1 判错、本轮被翻正的

r1 我核了 `adapters/base.ts:8` 与 `codex.ts:8` 的铁律注释，判「**核实后不改**」，
理由是它有「设计文档里的示例」限定。**codex 指出我读错了句法**：

> 铁律（原则 P7）：命令行**一律由 probe 结论构造**，不得硬编码设计文档里的示例。

那个限定**只修饰后半句**。前半句「命令行一律由 probe 结论构造」没有任何限定，
而它正是判据一当场否定的绝对表述——同目录下 `agy` / `zcode` / `codex` 三个
`buildXxxArgs` 都硬编码着机制类旗标，本版表格自己就这么记。
**我把一个两截的句子当成一截读了**，于是「约束力最强的那句」从文档里搬进了代码里。

### 0.3 第三类误收了一格

codex 核出：判据一新增的第三类举 `--settings` 的 deny 覆盖面为例，说它「无机读字段」——
**但 `PathDenyProbe.supported` / `rule_syntax` 就是为它设的**（`types.ts:138`/`:140`，
我已复核存在），探针真的在测（`probeClaudePathDeny`）。
我把一个**已有落点**的事实升格成了「可名正言顺留在散文里」的一类。

更要紧的是它对准入判据的批评：第三类现在的理由是「漏了不会失守、只会白跑一次」——
那是**后果分级**，不是**分层**。后果分级可以被下一件不想给字段的事实引用来自我豁免。

### 0.4 三处枚举/断言不实，已逐条复核

| 我写的 | 实情 | 谁指出 |

| BACKLOG EV-12 写「M6 报告**第五节**第 9 条」 | 该条在 **§四**（证明边界），§五是里程碑结论 | CODEX-07 |

### 0.5 一条证据不复现，但建议照采

**CODEX-06 的实测数字在本机不复现。** 它称两条 `grep` 在 `sh -c` 下因花括号不展开
而命中 370 行、zsh 下 50 行。我实跑：`sh -c` 与重复 `--exclude-dir` 两种写法**都是 82 行**
——macOS 的 `sh` 是 POSIX 模式的 bash，会做花括号展开。

**但主张仍然成立**：`dash`/`ash` 确实不展开，而「可复跑」承诺的就是任意 shell 下同一论域。
重复写 `--exclude-dir` 严格更安全且零成本，故照采。**记此以免后续按「370/50」核对。**

## 2. 修复方案

### 2.1 锚点集：补第三族 + 明写它也是手写清单

- **加一句话，这句比补锚点更重要**：「锚点集本身也是手写清单，复跑时须轮换措辞、
  并用一次广撒网（如 `探针结论`）比对差集」。不写这句，下一轮仍会以「我用了 grep」收口。
  glm 用的正是这个手法才找出差集——把它写进判据。
- 据此处置新命中：`adapters/base.ts:8` 与 `codex.ts:8` 的**前半句**改分层表述

  `LLD_orchestrator.md` §5.1 正文仍以 `base.ts:8` 为唯一引用点，同步。
- **`README.md:325` 复核**：本轮改写后的新文本要能被新锚点集找回来，否则这条修法没闭环。

### 2.2 第三类：收窄准入 + 移出误收的一格 + 统一序数

- 判据一补准入约束：**「凡该事实已有或可以有机读字段，就必须落字段；第三类只收
  『落了字段也无信息量』的厂商事实」**——把「漏了不会失守」从判据降级为说明。
