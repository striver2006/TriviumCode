## 总判断

计划整体设计完备，扎实地解决了建仓失败被吞及夹具临时目录泄漏问题，但存在两处需修正的设计细节：最核心的是 §2.5 将记忆夹具失败落为 blocker 导致 doctor 阻断与 availability 可用性判据分裂，过度阻断且与 EV-196 既有规范冲突，应降级为 warning；其次 §2.4 关于 --no-model-calls 下探针均跳过夹具建仓的假设与 ZCode 实际代码事实不符，其零配额探针仍会建夹具；此外建议在 §2.1 明确超时判定优先于信号终止，并在 §3 明确采用小超时注入方案避免单测耗时 30 秒。

**结论**：`request-changes`

**问题**：记忆夹具失败落为 blocker 导致 doctor 阻断与 availability 可用性判据分裂，且与 EV-196 既有契约冲突

**依据**：查阅 src/trivium/probes/claude.ts:1516-1530 与 src/trivium/doctor.ts:262-405（claudeSeverity），project_memory_blocked 无论为 true 还是 null 均不构成阻断级问题；查阅 src/trivium/adapters/claude.ts:661-695，availability() 仅检查 probed_at/entrypoint/readonly_flags/strict_mcp_config_applied，完全不依赖项目记忆格。若按计划将 memoryFixtureFailure 落为 blocker，doctor 退出码将非零，而随后审查流水线的 preflight（调用 availability）却直接放行，两者口径严重脱节。此外，doctor.ts:408-410 明确记载 EV-196 决策：单格辅助探针偶发未刷新应出 warning 而非 blocker，以防过度阻断。

**建议**：将 memoryFixtureBlocker 调整为 memoryFixtureWarning 并放入 warnings 数组（不阻断 doctor），保留保持 project_memory_blocked 旧值及建议重跑的排障说明，消除与 availability 的口径分叉并维持与 EV-196 的连贯性。

### AGY-02 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §2.4` |

**问题**：计划关于「--no-model-calls 下各探针在建夹具之前就返回」的前提假设与 ZCode 探针代码事实不符

**依据**：查阅 src/trivium/probes/zcode.ts:1407-1569，ZCode 的只读旗标探针（probeReadonlyFlags）与模型覆盖探针（probeModelOverride）是零配额探针，在第 1407 行调用 createFixture()，直到第 1562 行才判定 opts.skipModelCalls 并早退。因此在 --no-model-calls 下若 git 损坏，ZCode 依然会触发建夹具失败并抛出 ProbeFixtureError，与计划 §2.4 所称的「--no-model-calls 下各探针在建夹具之前就返回，本来就不受影响」直接矛盾。

**建议**：修正计划 §2.4 的推演陈述，如实记录 ZCode 零配额探针在 --no-model-calls 下依然依赖夹具仓库的事实，并同步将此分支行为（如跳过模型调用时 git 损坏产生 ZCode 侧 blocker）纳入测试断言或实施预期。

### AGY-03 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |

**问题**：步骤失败成因排版未明确「超时」优于「信号终止」的判定优先级

**依据**：查阅 src/trivium/util/exec.ts:281-330，当 timeoutMs 触发超时后，子进程被 SIGTERM 杀掉，退出时 run 返回的结构中 timedOut 为 true，且 signal 亦为 'SIGTERM'。计划 §2.1 列出的四种失败形态若未规范判定顺序而先判 signal，超时格（如 U11）将被错误判定为「被信号 SIGTERM 终止」，导致超时文案分支不可达。

**建议**：在计划 §2.1 实现规范中明确分支判定顺序：必须先检测 r.timedOut 为 true（归为超时），再检测 r.signal 非 null（归为被外部信号终止）。
