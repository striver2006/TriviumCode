## 认为正确的部分

- initFixtureRepo 结构化为 FIXTURE_REPO_STEPS 六步逐步检查并统一 30s 超时，基线提交加 --allow-empty 保证空目录建仓恒有 HEAD，彻底消除了此前静默忽略 git 失败的问题
- fixtureRepoStepError 的判定顺序严格按「超时 → 启动失败 → 信号 → 退出码」推演，避免了 run 在超时发信号时被误报为被信号终止的问题
- 探针夹具工厂抽取 buildFixtureRoot 共享骨架，建到一半失败自动调用 removeFixtureRoot 删除临时目录并抛出 ProbeFixtureError，收敛了 EV-199 残余 ①
- doctor.ts 的 guardFixture 精准拦截 ProbeFixtureError，该侧不赋值不 checkpoint 保持落盘结论不动，并在末尾排除 fixtureFailed 侧避免误报尚无探针实现；非 ProbeFixtureError 的普通异常原样重抛维持内部错误语义
- claude 记忆夹具在 probeClaude 内部就地捕获 ProbeFixtureError 并由 doctor 转换为 warning，保护了主夹具已耗配额的探测成果，契合可用性口径
- 计划外新增测试注入口 DoctorOptions.probeBins 动机明确（防止本机 homebrew codex 优先于 PATH 导致非预期拉起真实 CLI 耗配额），生产缺省为 null 保持原有逻辑，偏离显式且已在报告和设计文档中记录
