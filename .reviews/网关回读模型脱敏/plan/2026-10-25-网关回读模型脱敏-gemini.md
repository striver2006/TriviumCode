### AGY-01 · 次要（minor）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §1.1` |
| 类别 | correctness ｜ 层次 plan |
| 置信度 | high |

**问题**：isModelNameKey(key) 未对键名执行大写归一化（case normalization）。若用户在 settings.json 的 env 段配置了含小写字母的模型名键（如 ANTHROPIC_model 或 ANTHROPIC_default_haiku_model），正则将因大小写失配而判定为假，导致合法模型名被误划入替换集脱敏，使回读降级为 unverified；反之，若键名中包含小写凭据词（如 ANTHROPIC_auth_model），分段查表时 CREDENTIAL_WORDS.has 也可能因大小写不符而漏拦。此外，凭据词表未覆盖 PASS、PASSWD、PWD 等变体（secrets.ts:217 已覆盖 passwd）。

**依据**：查阅 src/trivium/adapters/claude-route.ts:45，extractSettingsEnv 的过滤正则为 /^(ANTHROPIC_|CLAUDE_)/.test(k)，未限制 k 必须全大写；而 plan §1.1 的 isModelNameKey 正则 /^(ANTHROPIC|CLAUDE)_(?:[A-Z0-9]+_)*MODEL(?:_NAME)?$/ 与凭据词表均为大写。

**建议**：在 isModelNameKey(key) 入口先统一将 key 转换为大写（如 const upper = key.toUpperCase()），再进行正则匹配与下划线分段检查；同时凭据词表可补充 PASS、PASSWD、PWD，与 secrets.ts 既有词表对齐。

### AGY-02 · 吹毛求疵（nit）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §1.2` |
| 类别 | correctness ｜ 层次 plan |

**问题**：claudeModelReadback(init) 未对全空白字符串做防御。若网关回报全空格的畸变模型名，会被误判定为有效模型并赋予 envelope 来源；同时 hasRedactionMark(s) 应具备类型防卫和大小写容差。

**依据**：查阅 plan §1.2，claudeModelReadback 对空白或缺失模型的处理为「init 为空、init.model 为空或缺失：{ model: init?.model ?? null, source: 'unverified' }」，若 init.model 遇到纯空格字符串（如 "   "），在 JS 中为 truthy 且不含脱敏标记，会流向 envelope 分支。

**建议**：在 claudeModelReadback 中增加 trim 防护，对 !init?.model || init.model.trim() === '' 统一返回 { model: null, source: 'unverified' }；在 hasRedactionMark(s) 中先做 typeof s === 'string' 防护，并对 <redacted 做大小写不敏感匹配（如 /<redacted/i.test(s)）。
