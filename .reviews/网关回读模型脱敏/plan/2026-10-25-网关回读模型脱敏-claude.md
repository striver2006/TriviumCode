## 〇、要解决的问题

### 0.1 现状机制（已读代码核实）

开了 `agents.claude.settings_env_source: user_settings` 时，`route.settingsEnv` 是 `extractSettingsEnv`（`src/trivium/adapters/claude-route.ts:34-48`）从 `~/.claude/settings.json` env 段提取的 `ANTHROPIC_` / `CLAUDE_` 前缀非空字符串值。它有两个用途：经 `claudeInvocationEnv`（`claude-route.ts:93-95`）进子进程环境；以及作为逐值脱敏的替换表。

`scrubGatewayEnv(text, env)`（`src/trivium/adapters/claude.ts:528-536`）对 env 的**全部值**（长度 ≥ 8）一视同仁地原串替换成 `<redacted-env>`，再过 `redactSecrets` 模式脱敏。调用它的两条出口：

| 出口 | 脱敏对象 | 之后从脱敏文本里解析的字段 |
| --- | --- | --- |
| `invokeClaude`（`claude.ts:544-564`） | stdout / stderr / commandLine | `run()` 落盘 `stdout.jsonl` 后 `parseClaudeEvents(out.stdout)`（`:1112-1113`）→ `trace.json` 的 `init`（`:1120`）→ `buildClaudeResult` 取 `model_effective: trace.init?.model ?? null`、`model_effective_source: trace.init?.model ? 'envelope' : 'unverified'`（`:696`、`:704`）；探活 `authProbe` 只用 `completed`（`:889-890`）；目录臂 `probes/claude-directory.ts:55` 只用 `init.cwd` |
| 探针 `execArgv`（`src/trivium/probes/claude.ts:781-822`） | stdout / stderr | `parseClaudeEvents(stdout)`（`:802`）→ `probe.model_flag = read.init.model === selectedModel`（`:1319-1320`）；另有 `init.tools`、`init.cwd`、`sessionId`、`toolUses`、`finalText`、`completed` |

另有两份工具脚本经 `invokeClaude` 拿脱敏后的 stdout 再取 `trace.init?.model`：`scripts/agent-access-admission.mjs:140`（`readback.model`）、`scripts/agent-access-closeout.mjs:250`（`readback.model` 与 `model_source: 'envelope'`）。

### 0.2 失效路径

CC Switch 网关回报的 `init.model` 恰好等于 env 段里某个模型名键的值（Windows 实测：`kimi-for-coding` 一族，命中 `ANTHROPIC_DEFAULT_*_MODEL` / `*_MODEL_NAME`；需求侧另有实测事实：网关下 `--model` 只能传别名，真实模型名只在 env 的模型名键里）。于是：

1. 审查调用：`init.model` 被换成 `<redacted-env>`，`model_effective` 记占位符、`model_effective_source` 仍记 `envelope`（因为占位符是非空字符串）——AC-20「拿不到记 unverified」被绕过；`family_comparisons.right_model` 拿占位符当模型名（Windows 审查文档副本里两处都是占位符）。
2. 探针：`windows-doctor.json` 第 514 行的探针原文里 `"model":"<redacted-env>"`，`model_flag: false`（第 47、108 行）。**受影响，同批修**：占位符既不可能等于 `selectedModel`，又不是「回读与请求不符」，记 `false` 是错的结论；修好之后真实模型名可回读时按真实值比，只剩占位符时记 `null`（没核对成）。
3. 两份脚本：同形缺陷（占位符记成 `readback.model`、`model_source: envelope`），同批修。

### 0.3 探针侧其余取自事件流的字段——核实结论：不受影响

被吞的前提是「字段的合法取值恰等于某个注入值（≥ 8 字符）」。逐个核：

- `init.tools`：CLI 内置工具名（`Read`、`Grep`、`Glob`、`StructuredOutput` 与 MCP 工具名），不是 env 值；
- `init.cwd`：夹具临时目录 / 项目根的绝对路径；
- `sessionId`：CLI 生成的 UUID；
- `toolUses[].input`：模型对夹具文件的读取参数（夹具路径、glob 模式）；
- `finalText`：与哨兵 `SENTINEL_OPEN_…`、`NO-PROJECT-MEMORY`、`OK` 比对——编排器自造的串；
- `completed`：由 `result` 事件的 `type` / `subtype` / `is_error` 决定，不含 env 值。

这些字段只有在 CLI 回显了某个凭据值时才会被替换——那正是脱敏要做的事，修复前后在凭据值上完全相同（凭据键的替换不放松，见 1.1）。真正「合法取值等于 env 值」的只有模型名，而模型名只出现在 `init.model`（以及模型自述的正文里，正文不参与判定）。所以本主题只改模型名这一类，其余字段不动，依据如上。

### 0.4 一条读数我核不了，不拿它当论据

`windows-readout.md` 第 2 步说三个模型名键的值出现在 `.trivium\config.local.yaml` 与 doctor 输出里、「探针本来就把它记进 models 并落盘」。但 `probeClaude` 的 `models` 初值是 `[]`（`probes/claude.ts:1205`），全仓没有写它的代码；config 里出现模型名更可能是用户为各阶段配的模型 slug。我**不**用「模型名早已合法落盘」作为放开模型名的理由，理由见 1.1。该句的订正放进本主题报告的「附带订正」一节（只改证据判读的措辞，不改结论）。

## 一、改法：① 模型名键不进逐值替换 + ③ 回读命中占位符一律记 null / unverified

选 ① + ③，不选 ②（先从原始事件流解析再脱敏）。理由：

- 任务目标要求网关机器上 `model_effective` 记真实模型名——它一定会以明文进 `run.json`、审查文档、`family_comparisons`。模型名在本系统里本来就是明文记录的字段（另三家的 `model_effective` 都是明文）。既然模型名必须落盘，再在 `stdout.jsonl` / `trace.json` 里把它抹掉，只会让同一次运行的两份留痕互相矛盾（`trace.json.init.model` 是占位符、`model_effective` 是真名）。
- ② 要把未脱敏的原始 stdout 带出 `invokeClaude` 的边界，让含凭据原文的字符串多活过一层函数，多一个「误把原文落盘」的面；而且从原文解析出的 `init.model` 本身仍要再判「是不是含了凭据值」，绕一圈又回到 ①③ 的判据。
- ③ 是独立于 ① 的兜底：任何路径（模式脱敏的首尾预览、凭据值恰好被网关当模型名回显、将来别的脱敏规则）只要让模型字段带上脱敏痕迹，都记 null / unverified，不靠 ① 的键名划分完备。

### 1.1 `scrubGatewayEnv` 只对凭据类键逐值替换（`claude.ts:528-536`）

新增 `isModelNameKey(key)`（放 `claude-route.ts`，与 `extractSettingsEnv` 同处——「哪些键算什么」的口径集中一处）：

```
/^(ANTHROPIC|CLAUDE)_(?:[A-Z0-9]+_)*MODEL(?:_NAME)?$/ 且键名的任一段都不在凭据词表里
凭据词表：TOKEN、KEY、SECRET、AUTH、PASSWORD、CREDENTIAL、CREDENTIALS、BEARER、COOKIE、HEADER、HEADERS、URL
```

覆盖：`ANTHROPIC_MODEL`、`ANTHROPIC_SMALL_FAST_MODEL`、`ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL`、`ANTHROPIC_DEFAULT_*_MODEL_NAME`、`CLAUDE_CODE_SUBAGENT_MODEL`。不覆盖（照旧替换）：`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_API_KEY`、`ANTHROPIC_CUSTOM_HEADERS`、`*_MODEL_DESCRIPTION` 一类非严格后缀、以及任何名字里带凭据词的「伪模型键」（如 `ANTHROPIC_AUTH_MODEL`）。口径与 Windows 检查脚本 `check-gateway-exposure.ps1:31` 的 `_MODEL(_NAME)?$` 同向且更严（多了前缀锚定与凭据词表）。

替换表的构造（**fail-closed，凭据优先**）：

1. 替换集 = 全部**非模型名键**的值（≥ 8 字符）；
2. 模型名键的值只有同时满足下面三条才豁免，否则照旧进替换集：
   - 键名过 `isModelNameKey`；
   - 值本身过一遍 `redactSecrets` 无命中（模型名键里误填了令牌形态的值，照旧替换）；
   - 值不等于替换集里任何一个值（同一个值既出现在凭据键又出现在模型名键，按凭据处理）；
3. 替换集按长度**降序**逐个替换（加固：短凭据值是长凭据值子串时，先替换短的会把长值切成「占位符 + 残段」，残段原样落盘。这是现状就有的问题，降序是严格收紧，不放松任何一处）；
4. 最后照旧过 `redactSecrets` 模式脱敏（不变）。

凭据值只要出现在文本里就照旧整串替换——模型名值里若含凭据值子串，凭据部分照样被换掉，模型字段因此带上占位符，由 1.2 兜成 unverified。

签名 `scrubGatewayEnv(text, env)` 不变，`invokeClaude` 与 `execArgv` 两个调用点不改，两条出口同批生效。`env` 为 `undefined` / `{}`（未开启、env 段为空、读不到）时替换集为空、只过 `redactSecrets`——与修复前逐字相同。

### 1.2 回读判据：带脱敏痕迹的模型名不算回读成功

在 `secrets.ts` 导出 `hasRedactionMark(s)`：含 `<redacted`（覆盖 `<redacted-env>`、缺省 `<redacted>`、PEM 占位符）或含 `…`（`redact()` 首尾预览的唯一分隔符，`secrets.ts:225-228`）即真。口径与生产占位符的代码放同一个文件，新增脱敏形态时在那里一并改；单测逐一喂各形态的实际产出（不手写字面量）锁住「生产方产出的每种形态都被认出」。

在 `adapters/claude-trace.ts` 导出 `claudeModelReadback(init)`，返回 `{ model, source }`：

- `init` 为空、`init.model` 为空或缺失：`{ model: init?.model ?? null, source: 'unverified' }`——与修复前逐字相同（修复前空串记 `""` + `unverified`，保持）；
- `init.model` 带脱敏痕迹：`{ model: null, source: 'unverified' }`；
- 其余：`{ model: init.model, source: 'envelope' }`。

消费方全部改走它：

- `buildClaudeResult`（`claude.ts:696`、`:704`）：两格取同一次判定的产出，不再各写一遍条件；
- 探针 `model_flag`（`probes/claude.ts:1320`）：`read.init` 为空或 `selectedModel` 为 null → `null`（不变）；回读带脱敏痕迹 → `null`（新）；其余 → `read.init.model === selectedModel`（不变；这里仍用原值比较，保持空串 / 缺失时记 `false` 的既有行为）；
- `scripts/agent-access-admission.mjs:140`、`scripts/agent-access-closeout.mjs:250`：`readback.model` / `model_source` 改取 `claudeModelReadback`（脚本 `model_source` 原先缺省记 `null`、不记 `unverified`——保留它自己的取值集，只把「占位符」并进 null 那一支）。

`trace.json` 的 `init` 照旧原样记解析结果（脱敏后的文本解析所得）：开启后它是真实模型名；只剩占位符时它记占位符，而 `model_effective` 记 null——`trace.json` 是排障原文，不是判定面，保持原样便于看出「回读被吞」。
