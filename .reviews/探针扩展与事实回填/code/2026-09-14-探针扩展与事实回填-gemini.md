## 总判断

最危险问题是 migrateProbeSection 无条件将全局时间戳赋给未探过的旧段 probed_at，导致升级后 preflight 误把未探过的 CLI 判为「已探但入口丢失」而硬阻断（AGY-02）；同时适配层以 !probe 判定未探测恒不成立，导致未探测被误报为入口文件不存在（AGY-01）。
探针段以 cliName 索引收归 probe.cli 的格式变更是必要且值得的，不仅干净解除了元数据与各家事实的冲突，也使类型推导与 schema 约束严密对齐。VersionProbe 与预检第三态的处理克制且符合设计纪律。修复上述迁移回填与状态判定缺陷、并补齐迁移单测后方可合入。

**结论**：`request-changes`

### AGY-01 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/adapters/agy.ts:177` |
| 类别 | correctness ｜ 层次 code |
| 置信度 | high |

**问题**：availability() 与 run() 以 !probe / !p 作为「尚未探测」的判据恒为 false，导致未探测被误判为「探过但可执行文件不存在」

**依据**：在 src/trivium/config.ts:388-410 中，defaultProbe() 会通过 emptyCommonProbe() 为全部 ALL_CLI_NAMES 预填充空壳对象（probed_at: null, entrypoint: null）；patchProbe() 读写时也通过解构合并（line 595）保证其存在。因此在 src/trivium/adapters/agy.ts:176-177 与 src/trivium/adapters/zcode.ts:163-164 中，p 恒为非空对象，if (!p) 分支恒不可达；随后的 if (!p.entrypoint) 恒为真，将「未探测（probed_at 为 null）」误报为「探针未找到可执行文件/入口」。同理在两文件的 run() 中（agy.ts:200-203, zcode.ts:201-204），probe 恒为真值对象，三元表达式恒输出「入口未探测到」，导致「未探过」与「探过但没找到入口」分开答复的契约失效。

**建议**：将判断条件改为以 probe.probed_at 是否非空为准（如 if (!p?.probed_at)），与 doctor.ts:817 及 preflight.ts:970 的判据口径对齐。

### AGY-02 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/config.ts:463` |
| 类别 | correctness ｜ 层次 code |
| 置信度 | high |

**问题**：migrateProbeSection 对未实探过的旧段回填 probed_at 导致预检误判，且判据未排除 null 并存在覆写新形状风险

**依据**：在 src/trivium/config.ts:463 中，legacyKeys 使用 typeof p[n] === 'object' 过滤，由于 JS 中 typeof null === 'object'，YAML 中的空字段会被纳入迁移列表导致 old 变为 {}。更关键的是第 481 行：if (old['probed_at'] === undefined) old['probed_at'] = p['generated_at'] ?? null;。若旧磁盘文件仅运行过 doctor --only zcode，则 p['generated_at'] 有新鲜时间戳，但 p['agy'] 的 bin/entry 均为 null。经迁移后，old['probed_at'] 被无条件填入 generated_at；随后 src/trivium/preflight.ts:970 的 if (!probe?.probed_at) continue 无法跳过 agy，并在第 974 行因 entrypoint 为 null 判为「不可调用」硬阻断预检。此外第 483 行若 p['cli'][name] 已存在时，cli[name] = old 会导致已有新形状被旧数据覆写。

**建议**：判据显式排除 null；仅在 old 确实具有探测结果（如 old.bin 或 old.entry 非空）时才回填 probed_at，未探过的旧段保持 probed_at: null；并在已有 cli[name] 时保留新属性。
