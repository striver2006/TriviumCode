**问题**：VersionProbe.runner 的语义在三层不一致，是「第三家一来就不够用」的具体形态。schema 层放行任意字符串；TS 类型只有 'node' | null；读侧 readCliVersion 写死 `vp.runner === 'node' ? <按 runtime.node 解析> : <直接执行 entrypoint>`——任何非 node 非 null 的值（盘上手工或未来第三家写入 'python' 等）都被静默按「直接执行」处理，而不是按「无法理解这个运行时」处理。同时 'node' 这个运行时名的解析规则（cfg.runtime.node）仍硬编码在读侧，与「命令行由探针结论构造，不由读侧按家分支猜」的 P7 宣言构成一处残余例外。TS 类型层会拦住新代码写字面量 'python'，但拦不住盘上值，且 schema description 未声明「非 node 值的行为」。

## 认为正确的部分

- probe.cli 按 cliName 索引、键集以 ALL_CLI_NAMES 为唯一来源，是 EV-05① 的正解：探针结论确是 CLI 的事实而非 Agent 的事实，同厂商多 Agent 共用一条 CLI 时天然共享一份结论；registry-parity 的两条对账（cliName 全表唯一、具名键 ⊆ cliName 集）把复用方案自己的前提机器化了。
- migrateProbeSection 与 migrateConfigV1 同规格（只读侧迁移、不回写、幂等），loadCtx 与 patchProbe 双路径都补了迁移，migrated 的 kind 区分使探针段迁移不再打出误导性的「critics 改名」出路——「第一个错误不得把用户引向第二个错误」执行得到位。
- 迁移不造 version_probe、靠「版本漂移检查覆盖面」第三态点名并给出「重跑 doctor 可补齐」出路，保守选择正确：编造取版本方式可能把错误命令落成事实；schema 的 commonProbe.required 刻意不含 version_probe，与迁移产物自洽（该缺口本身只是 F1 所述的测试弱化，不是行为缺陷）。
- TTL 按键判定（probed_at）修复了「--only X 刷新全局时间戳使其它侧过期结论蒙混过关」的失真，且测试是真会失败的：判定直测（全局新鲜但某键过期）、落盘断言（--only agy 不动 zcode 的 probed_at）、--only env 不写任何厂商段三条各守一个变异面，起草时漏判据直测、被变异验证打脸后补上的做法值得沿用。
- checkpoint(null) 修掉了末次落盘借用厂商标签的丢更新路径（原 --only env 会把起点 clone 的 zcode 段整段写回），与「没探过的段一个字节都不碰」的注释重新一致。
- 「已登记但尚无探针实现」给第三种答复（点名、不进 blockers、不退 64）且不维护「已实现清单」（以盘上 probed_at 有无为判据），避免了又一处要人工同步的枚举；cli.ts 的 --only 取值集合从注册表派生，消除了写死三值白名单的退 64。
- checkCliVersions 的三态口径与 checkModelSlugs 一致，「无从查」不判失败但点名，避免「检查过」与「没得检查」在输出里长得一模一样。
