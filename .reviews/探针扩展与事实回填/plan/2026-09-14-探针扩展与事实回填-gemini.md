### AGY-01 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §4.3` |
| 类别 | maintainability ｜ 层次 plan |
| 置信度 | high |

**问题**：probeKey 属于过度登记（将命名约定升格为结构字段），且会打断既有的接入套件验收测试 stub-agent-kit.test.ts。

**依据**：在 src/trivium/agents/registry.ts 中，已登记的四家 Agent 其 cliName 分别为 agy, zcode, claude, codex，恰好逐字对应探针段的键名。探针的本质是探测 CLI 工具的能力，按 cliName 索引在概念上完全自洽，盘上数据无需任何迁移。更关键的是，test/fixtures/stub-agent-kit/overlay.ts:208 的桩 Agent 登记项已包含 cliName: '${STUB_ID}'；若在 AgentDescriptor 中新增必填字段 probeKey，overlay 补丁将无法通过 TS 类型检查，直接导致 test/integration/stub-agent-kit.test.ts 失败。

**建议**：放弃新增 probeKey 字段，明确探针段以 cliName 为索引键。这样既无二元推算风险，又保持了最小改动面，且能无缝兼容既有桩 Agent 夹具。

### AGY-03 · 重要（major）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `plan §5 第 1 步` |
| 类别 | correctness ｜ 层次 plan |

**问题**：第 1 步改动面遗漏了 src/trivium/cli.ts 与 src/trivium/guard.ts，导致验收判据 ① 无法通过且存在编译期与运行期破坏。

**依据**：1. src/trivium/cli.ts:466-470 硬编码校验了 ['agy', 'zcode', 'env'].includes(onlyRaw)，非法值直接抛 EXIT.USAGE（64 码）。若第 1 步不修改 cli.ts，doctor --only codex 绝不可能如验收判据 ① 所言「不再退 64 而是给出已登记未实现」，它会在进入 doctor.ts 之前就被 cli.ts 拦截。连带 cli.ts:91 的 USAGE 提示也未更新。\n2. src/trivium/guard.ts:126 硬编码读取 [...cfg.probe.agy.scratch_paths, ...cfg.probe.zcode.scratch_paths]。当 ProbeSection 按计划泛化为 Partial<Record<...>> 时，tsconfig.json 的 noUncheckedIndexedAccess: true 会使该处产生类型报错；若强转或缺失 agy 段，则会在运行时抛出 TypeError: Cannot read properties of undefined。

**建议**：将 src/trivium/cli.ts（--only 白名单与 USAGE）和 src/trivium/guard.ts（从所有探过/登记的 Agent 动态汇集 scratch_paths）显式纳入第 1 步改动面，并补齐相应单测断言。

**问题**：判定 codex --profile「没有安全退路」存在夸大，漏掉了 -c key=value（--config）命令行覆盖这一强退路，且导致第 2 步实测手法过早绑定 CODEX_HOME。

**依据**：演进设计 doc/02_design/2026-09-13-通用Agent编排与动态多审设计.md §3.1（第 101 与 123 行）及变更记录（第 817 行）明确记载，Codex 的模型与 effort 覆盖主路径本就包含 -m 与 -c key=value；Codex CLI 支持通过 -c 动态覆盖配置项（如 -c model_provider="deepseek"、-c model_reasoning_effort="low"），无需修改用户全局配置，也无需构造 CODEX_HOME 副本。且本机五份 toml 暂无 [profiles.*] 段仅说明用户未配置 profile，并不等于 CLI 不支持 --profile。计划第 2 步声称「若 --profile 不被接受，实测手法要整体改走 CODEX_HOME 副本」是不必要的收窄。

**建议**：将冲突 A 的严重性从「没有安全退路、设计级降级」下调为常规探针项；在第 2 步中将 -c key=value 纳入模型与 provider 覆盖的实测路径，优先验证 -c 能否动态切换 provider 与 effort，而非直接走笨重的 CODEX_HOME 副本。
