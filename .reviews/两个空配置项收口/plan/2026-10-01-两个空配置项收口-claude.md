## 2. codex 命令白名单核查（用户决策 四；零配额，计划阶段已做）

只看本机 codex 自带帮助与本地规则检查子命令，**未发起任何模型调用**。原始输出将收进 evidence（§7）。

### 2.1 读到的

- 版本 `codex-cli 0.159.2`；
- `codex exec --help`：`-s, --sandbox read-only|workspace-write|danger-full-access`（「执行模型生成的 shell 命令时的沙箱策略」）；另有 `--ignore-rules`（「Do not load user or project execpolicy `.rules` files」）；
- `codex execpolicy check --rules 〈文件〉 〈命令词元…〉`：按规则文件评估一条命令，输出 JSON 决定；
- 适配器现状：`buildCodexArgs`（`src/trivium/adapters/codex.ts:70-84`）不传任何规则相关参数；运行时 `CODEX_HOME` 是隔离副本（`codex-home.ts`，只留 `model*` 顶层键与 `[model_providers*]` 段），宿主的用户级规则不会被带进去。

### 2.2 零配额实测（scratchpad 下临时规则文件，`codex execpolicy check`）

| 规则 | 命令 | 输出 decision |
| :-- | :-- | :-- |
| `prefix_rule(pattern=["git","show"], decision="forbidden")` | `git show HEAD` | `forbidden` |
| `prefix_rule(pattern=["cat"], decision="allow")` | `cat x` | `allow` |
| 同上两条 | `ls`、`rm -rf x` | **无匹配**（`matchedRules: []`，无 decision） |
| 同上 | `bash -lc 'git show HEAD'` | 无匹配 |
| 同上 | `/usr/bin/git show HEAD` | 无匹配（另有 `--resolve-host-executables` 旗标，未测） |
| `prefix_rule(pattern=[], decision="forbidden")` | `ls` | **解析失败**（空模式不合法） |
| `prefix_rule(pattern=[["git","ls"],"show"], …)` | `git show` / `ls show` | 均 `forbidden`（首位可列备选） |

### 2.3 结论

**有机制，但不是白名单**：codex 0.159.2 的 execpolicy 是**按命令前缀**的 `allow` / `prompt` / `forbidden` 规则，未匹配的命令不产生决定、落回沙箱与审批策略（我们的配方是 `-s read-only`）。空模式不合法——**写不出「默认拒绝、只放行清单内」**；能做的只是**逐个前缀禁止**（黑名单形态）。包一层 `bash -lc` 或写绝对路径时，`check` 子命令不匹配；运行期会不会先拆 shell 包装再匹配，帮助里没写、零配额核不了。

所以 `readonly_commands`「白名单」语义在 codex 侧**不可直接执行**；可执行的只有「禁止某些前缀」（例如收窄 git 通道时禁 `git show` / `git log -p`）。该能力本主题不接线（用户决策 四），在 BACKLOG 新登 EV-184 写清机制与代价（§5.3）。
