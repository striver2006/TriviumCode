### 3.1 论域

- **索引 README**：`doc/` 下每个一级子目录的 `README.md`，其中恰有一行 `## 当前已归档文件`（整行、去首尾空白后相等）的即入论域。**按规则求，不手抄。**
- **下限清单**：`KNOWN_INDEXED_DIRS` = 上述六个目录。测试断言论域 ⊇ 下限清单——有人改了某份 README 的节标题、它就从论域里悄悄掉出去，这里先红（与 facade T2「根级门面文件都在论域内」同形）。新增目录带了这一节会自动入论域，不必改清单。
- 节标题出现两次以上 ⇒ `section_ambiguous`，红（哪一节算索引说不清）。

### 3.2 节与条目的解析

- **节范围**：从节标题下一行到下一个一级或二级标题（`# ` / `## `）之前；`###` 小节属于本节（02_design 靠它分组）。围栏代码块（```）内的行跳过。
- **条目**：节内**顶格**以 `- [` 起头、紧跟 `](目标)` 的列表项；目标即该项的**第一条**链接。其余链接（条目描述里的、非列表行里的）是**行内链接**。
- 不起头于链接的列表项（05_testing 的 `` `evidence/` ``）不是条目，不参与对账。
- 命名规范表、测试分层要求等其它节的文字不在判据内（S9 的示例文件名因此不报）。
- 目标解析：去掉 `#…` 片段、`decodeURIComponent`（失败则用原文），相对 README 所在目录求路径；`http(s):`、`mailto:` 等带协议的与纯 `#锚点` 不解析。

### 3.3 判据（每条失败都点名 README 与文件）

| 种类 | 判据 | 失败文案点名 |
| :--- | :--- | :--- |
| `missing` | 目录的每个**顶层常规文件**（README.md 自身、子目录、以 `.` 起头的隐藏文件除外）必须恰被一条条目指向；零条 ⇒ 缺登 | README 路径 + 文件名 |
| `duplicate` | 同一文件被两条以上条目指向 | README 路径 + 文件名 + 各条行号 |
| `dangling` | 条目目标必须是存在的**常规文件**（不存在或是目录都报） | README 路径:行号 + 目标 |
| `inline_dangling` | 行内相对链接的目标必须存在（文件或目录均可——05_testing 的行内链接指 evidence 子目录） | README 路径:行号 + 目标 |
| `order` | 见 §3.4 | README 路径:两条的行号 + 文件名 |
| `section_ambiguous` / `not_in_domain` | §3.1 | README 路径 |

**跨目录条目**（S6：02_design 指向 05_testing 的 M0 报告）：目标必须存在（`dangling` 照判），但不计入本目录的覆盖——它在本目录没有对应文件，也不替 05_testing 的覆盖计数（覆盖只数本 README 自己的条目）。

**是否含非 `.md` 文件**（用户决策要求论证）：**含**。理由：`doc/README.md` 编写规范第 1、2 条要求一级目录下直接放 `.md` 文档；有人把 `.csv` / `.png` / `.pdf` 放在顶层而不是 `evidence/` 下，要么是需要进索引的归档件，要么是放错了位置的原始留痕——两种都该当场暴露。只按 `.md` 数会让这类文件永远看不见。隐藏文件（`.DS_Store` 等，已被 `.gitignore` 忽略）排除，避免 macOS 噪声。代价：编辑器在顶层留下的非隐藏备份（如 `foo.md~`）也会红——`.gitignore` 已忽略 `*~`，但测试读的是工作树不是 Git 索引，这类文件存在时会误报；判断为可接受（fail-closed、极少见、删掉即可），登记于 §6 ③。

**为什么读工作树、不读 Git 索引**：本测试要在「新报告写了、还没 `git add`」时就红——那正是漏登发生的时刻。

### 3.4 顺序判据的口径

- **分组**：按 `###` 小节分组（无 `###` 的节整节一组）；只看**本目录条目**（跨目录条目不参与排序）。
- **组内规则**：① 文件名不含日期的条目（`CASE_` / `PLAN_` / `BENCHMARK_` / `ADR_` / `LLD_` 等）必须全部排在含日期的条目之前（落实「非报告文件放在最前」）；② 含日期的条目按 (日期, 完整文件名码点序) **严格**升序。日期取文件名里第一个 `YYYY-MM-DD`。
- **为什么按小节分组、不做整节全序**：02_design 按类别组织（S8），现在整节的日期子序列碰巧升序，但以后在「唯一实现依据」小节加一份新日期的设计文档，会与下方「受控增量规范」小节 09-13 那份形成整节逆序——那不是错。分组后五份非 05_testing 的 README 现状全部满足（已核：每个小节要么只有无日期条目，要么只有一条含日期条目）。
- **无日期条目之间不排序**（02_design 的 `ADR_002` 在 `ADR_001` 前是新者在上的有意安排，不在判据内）。
