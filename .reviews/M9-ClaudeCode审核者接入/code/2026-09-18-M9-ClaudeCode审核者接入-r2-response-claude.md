## 1. 本轮的形状：**守卫做到了判据，没做到修法**

r1 我被打中的是「把『没测到』算成『确认没有』」。这一轮修完，三侧换了个角度打同一件事：

| 我做了 | 我没做 |
| :--- | :--- |
| 三个**判据**抽纯函数 + 用例 + 变异验证 | 装配 argv 的那个函数里两个**新分支**零用例（GLM-r2-01） |
| 判定侧前置补了**纵深用例** | 产出侧「赋值必须在清空点之后」这个**位置即判据**零守卫（GLM-r2-03） |

| 为第 3 步复验**留了分支** | 那条分支**接不通**，而我把它写进设计当保证（CODEX-01） |

共同结构：**我守住了「结论怎么算出来的」，没守住「算它的那套装置本身」。**
r1 的教训是「三态字段的 `null` 要在产出侧产出」；这一轮的教训要加一条——
**凡是「位置 / 分支 / 默认值」这类不体现在返回值里的修法，都得另找一条能红的判据把它钉住**。

## 2. 修法

> 闸门期不改业务文件。以下是经审批后要落的改动。

### 2.1 删掉 `promptVia` 死分支，并改准设计措辞（CODEX-01）

取 CODEX-01 的**第二个**选项：**删分支**，不留「有分支=有通路」的中间态。

理由：把 stdin 能力真做进 `execProbe`（第一个选项）意味着探针要新增一臂 stdin 形态的
负对照——那是**第 3 步**的实测任务，现在做等于替第 3 步先花一笔配额，
且第 3 步真正要验的是**适配层自己的配方**，不是探针的。

设计 §3.7.1 那半句改为：
> 复验需在 `adapters/claude.ts` 内**自建 stdin 配方**（`adapters/` 不得 import `probes/`），
> 按 EV-41 §1.4 登记的边界逐格重测。

### 2.2 EV-40 的 true 臂补第四道门 + `omitVerbose` 补守卫（CODEX-02 + GLM-r2-01）

- **判据加 `stderrHasOutput: boolean`**：true 臂要求「非零退出 **且** stdout 零事件
  **且** stderr 非空」。这是**有无**判据，不匹配任何文案——
  刻意不看 `requires --verbose` 字串那条纪律原样保留（codex 自己也明说不建议恢复文案匹配）。
  四格三态表补成五格，加一条「非零 + 两头皆空 ⇒ `null`」的用例。
- **`omitVerbose` 补守卫**：`probeArgs` 重新导出并加两条纯断言
  （`omitVerbose:true` 时 argv 不含 `--verbose`；不传时含）。
  r4 把它改回私有的顾虑（「M9 不得 import」）**如今已由 `registry-parity`
  的 grep 契约机器守着**（GLM-r2-01 的论证，我核过：第 5 条正是那条），导出不再构成风险。

### 2.3 夹具推导重写（CODEX-03 ≡ GLM-r2-04 ≡ AGY-01）

一处改动同时收三条：

```

return { ...base, strict_mcp_config_applied:
  judgeStrictMcpConfig(base.tool_surface_checked, base.readonly_flags) };
```

JSDoc 那句「再也分不开」到这时才成立——**现在它是先写下来、后兑现的，顺序反了，记一笔。**

### 2.4 删掉那句「同真同假」（AGY-02 ≡ GLM-r2-05 ≡ CODEX-05）

三侧给的反例是两条不同的路径，合起来说明这句等价断言**按现实现就是假的**。

> `false` 当且仅当**已核对**且组合内确无该旗标（含 breach 与工具面脏两种清空）；
> `null` 当且仅当**本轮没核对成**（含 `tools` 读回为空、拿不到 `init`，
