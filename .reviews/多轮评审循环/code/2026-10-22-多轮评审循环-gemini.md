### AGY-01 · 次要（minor）

**问题**：previousRoundFacts 遍历历史 runId 时遇到读取失败（!m）直接 return null，导致续链回退为新起一链并重置轮次计数，与计划稿声称的「依赖 resolveStageDriver 先拒跑」口径不一致

**依据**：src/trivium/review.ts:302 中 `for (const id of ids) { const m = await readRunMeta(layout, stage, id); if (!m) return null; ... }`。然而 resolveStageDriver 使用 latestRunMeta 只读取最新的 run.json，若最新的运行是正常失败的（无 round_verdict），resolveStageDriver 会成功采纳 driver 并放行。若链中更早的某轮 run.json 损坏或被外部破坏，previousRoundFacts 在检查旧轮时遇到 !m 会返回 null，导致 deriveReviewLoop 认为不存在上一轮，从而静默从 round 1 重新起链，max_rounds 预算被静默重置，而非 fail-closed 报错拦截。

**建议**：在 previousRoundFacts 遍历旧 run 元数据时，对于已确认存在于文件系统但反序列化/解析失败的 run.json，应显式向上抛出错误或标记元数据损坏，避免与「从未存在过前序轮次」产生混淆导致静默新起链重置轮次。
