### GLM-02 · 吹毛求疵（nit）

| 项 | 内容 |
| :--- | :--- |
| 位置 | `src/trivium/util/exec.ts:573` |
| 类别 | maintainability ｜ 层次 code |
| 置信度 | medium |

**问题**：shutdownTrackedTrees 文档块写「首个 SIGTERM 按组发，组员与组长同时收到；**只有忽略 SIGTERM 的组员会漏**」，设计 §7.5 同格写「组长 CLI 已退出而同组有**忽略 SIGTERM 的**后代」。这只对「处理器运行时组长还活着」的子格成立。另一子格是：组长在处理器运行**之前**已退出（含正常退出）——'exit' 已到、liveTrees 已删（或被 exitCode 过滤），该组从 pending 里消失、**一个信号都不发**，此时同组遗留的任何后代无论是否响应 SIGTERM 都收不到信号（响应的也没人给它发）。exec.ts:228-233 的 exitTimer 注释明说「孙进程拖住管道不闭合」是真实形状，所以「响应但遗留」的组员并非纯理论。这一格与取消无关地预存（正常收尾同样遗留），但措辞把它说窄了会让后来的人低估遗留面。

**依据**：src/trivium/util/exec.ts:576-581（按句柄过滤 + liveTrees，已读全文）；src/trivium/util/exec.ts:150-152（'exit' 删除先于句柄可观察，二者同步）；src/trivium/util/exec.ts:228-233（孙进程遗留的真实形状自认）；被审 diff 行 65（设计 §7.5 覆盖不到的格的措辞）。

**建议**：把 exec.ts 该行与设计 §7.5 的 h 格措辞改为「组长已退出（含处理器运行前已正常退出）后同组遗留的后代——整组不会再收到任何信号，是否响应 SIGTERM 无关」；GLM-01 的 MANUAL 修订可引用同一句。
