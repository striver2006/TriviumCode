## 〇、要解决的问题

### 0.1 现状机制（已读代码核实）

`gatewayScrubPlan(env)`（`src/trivium/adapters/claude.ts:535-547`）决定网关 env 的哪些值进逐值替换集。模型名键的值要四道守卫同时满足才豁免：①`isModelNameKey(k)`（`claude-route.ts:64-67`）；②`redactSecrets(v).count === 0`；③值不等于任何非豁免键的值；④`looksLikeModelName(v)`（`claude-route.ts:75-79`）。

守卫 ④ 的第一行是字符集 `^[\w./:+-]{1,128}$`，不含方括号。

### 0.2 失效路径（Windows 实测）

CC Switch 写进生效模型名键的值带 Claude Code 的上下文窗口后缀：`ANTHROPIC_MODEL` / `ANTHROPIC_DEFAULT_SONNET_MODEL` 为 `qwen3.8-flash[1m]`，`ANTHROPIC_DEFAULT_OPUS_MODEL` / `ANTHROPIC_DEFAULT_FABLE_MODEL` / `CLAUDE_CODE_SUBAGENT_MODEL` 为 `qwen3.8-max[1m]`；`*_MODEL_NAME` 四键与 `ANTHROPIC_DEFAULT_HAIKU_MODEL` 不带后缀。

1. 带后缀的 5 个键过不了守卫 ④，成为非豁免键，它们的值进 `credentialValues`（`claude.ts:539-540`）。
2. 同值的几个带后缀键互为「与凭据同值」——守卫 ③ 显示 ✗ 是 ④ 的连带结果，不是独立原因（判读「诊断」表）。
3. 这两个值进替换集。审查调用里 `init.model` 是 `qwen3.8-max[1m]`，被替换成 `<redacted-env>`；`claudeModelReadback`（`claude-trace.ts:449-453`）认出痕迹，`model_effective` 记 null、来源 `unverified`。兜底按设计生效，但 AC-20 的回读还是拿不到。
4. 探针同理：`model_flag` 记 null（EV-256 验收时是 false）。

### 0.3 附带核实的事实：`init.model` 不是「网关回报」

判读里的探针原文同一次调用有三处模型信息：

| 字段 | 值 | 含义 |
| :--- | :--- | :--- |
| `system/init` 的 `model` | `qwen3.8-max[1m]`（被吞） | CLI 把别名 `opus` 按 `ANTHROPIC_DEFAULT_OPUS_MODEL` 解析出的**配置值**，含 CLI 侧的上下文窗口后缀 |
| assistant 消息的 `message.model` | `qwen3.8-max` | 服务端（网关）在 API 响应里回报的模型名，CLI 发请求前已剥掉后缀 |
| `result.modelUsage` 的 `canonicalModel` | `qwen3.8-max[1m]` | 按模型分桶的用量表；键与值都可能有多个（本机原生运行样本里 sonnet 一档同时出现 `claude-haiku-4-5` 与 `claude-sonnet-5`，是 CLI 的旁路调用） |

所以 EV-257 的代码注释与主设计 v1.3.179 那段说「CC Switch 网关在 `system/init` 回报的模型名恰等于这些键的值」不准确：`init.model` 等于键值，是因为它就是 CLI 读这些键解析出来的，不是网关回报的。这处描述本批一并改准（§3.4）。

本机运行目录抽样（`~/.trivium/runs` 下 33 份 claude `stdout.jsonl`，只 grep 模型字段）：`init.model` 与 assistant `message.model` 全部逐字相同（`claude-opus-5-5` 3 份、`claude-sonnet-5` 5 份、`qwen3.8-flash` 22 份），都不带后缀。两者不同目前只在「配置值带后缀」这一种情形下观察到。

## 二、改法

### 2.1 守卫 ④：只放行末尾一个上下文窗口后缀

`src/trivium/adapters/claude-route.ts`：

```ts
/**
 * Claude Code 的上下文窗口后缀（`sonnet[1m]` 一类）的无锚片段：1～4 位不以 0 开头的数字加小写 k 或 m。
 * 只定义片段、不带锚：守卫 ④ 要锚在串尾，profile 元数据要放在闭引号之前，锚定由各使用点自定（计划三审 AGY-01 ≡ GLM-01）。
 */
const CONTEXT_WINDOW_SUFFIX_PATTERN = String.raw`\[[1-9][0-9]{0,3}[km]\]`;
const CONTEXT_WINDOW_SUFFIX = new RegExp(`${CONTEXT_WINDOW_SUFFIX_PATTERN}$`);

/** 剥掉末尾一个上下文窗口后缀；没有就原样返回。只剥一个 */
export function stripContextWindowSuffix(value: string): string {
  const m = CONTEXT_WINDOW_SUFFIX.exec(value);
  return m ? value.slice(0, m.index) : value;
}

export function looksLikeModelName(value: string): boolean {
  const base = stripContextWindowSuffix(value);
  if (!/^[\w./:+-]{1,128}$/.test(base)) return false;
  if (/^[0-9a-f]{8}-…$/i.test(base)) return false;   // UUID 判据原样
  return base.split(/[^A-Za-z0-9]+/).every((seg) => seg.length <= 16);
}
```

边界逐条：

| 输入 | 剥后 | 结果 | 理由 |
| :--- | :--- | :--- | :--- |
| `qwen3.8-max[1m]`、`claude-sonnet-4[200k]` | 去掉后缀 | 放行 | 目标形态 |
| `qwen[1m]-max`（方括号在中间） | 不剥 | 拒 | 字符集仍不含方括号 |
| `qwen3.8-max[1m][1m]`（两个后缀） | `qwen3.8-max[1m]` | 拒 | 只剥一个，剩下的方括号过不了字符集 |
| `qwen[abc]`、`qwen[1g]`、`qwen[0m]`、`qwen[12345m]`、`qwen[1M]`、`qwen[]`、`qwen[ 1m]` | 不剥 | 拒 | 后缀内容不符 |
| `[1m]`（只有后缀） | 空串 | 拒 | 剥后长度 1～128 不满足 |
| 随机令牌 + `[1m]`、UUID + `[1m]` | 令牌 / UUID | 拒 | 剥后其余判据照旧生效（最长段 > 16 / UUID 形态） |
| `[` + 随机令牌 + `]`（方括号包住的凭据） | 不剥 | 拒 | 后缀内容不符，字符集拒 |

取舍说明：

- **只认小写 k / m**：Claude Code 文档与 CC Switch 实测写的都是 `[1m]`；大写不认是 fail-closed，代价只是那个值照旧替换、回读记 `unverified`。
- **数字 1～4 位、不以 0 开头**：覆盖 `[1m]`、`[200k]`、`[1000k]`；上限防长数字串借后缀形态混进来。
- **守卫 ②③ 看的仍是完整值**（含后缀）：守卫 ② 对整串跑模式脱敏，守卫 ③ 按整串比同值，都不受剥后缀影响。只有守卫 ④ 看剥后的部分。
- **剩余边界不变**：由短段拼成、形似模型名的凭据填进模型名键，修复前后都会放行（主设计 v1.3.179 已登记）；本批只是把同一条边界延伸到「这种凭据再加一个合法后缀」，不新开口子。

**同值模型名键的连带豁免**：不改 `gatewayScrubPlan`。守卫 ④ 放行后，带后缀的 5 个键都成为候选，`credentialValues` 只收非候选键的值，候选之间同值不算冲突，5 个键一并豁免。反过来，只要有一个**非模型名键**（或过不了守卫 ①②④ 的键）挂着同一个值，这个值照旧进替换集，所有挂它的模型名键都不豁免（凭据优先，S3 已锚、本批再加带后缀形态）。

### 2.2 `claudeProfileMetadata`：同一缺口，三种形态都放行同一个后缀

`claude-route.ts:92-100` 的模型名值字符集同为 `[\w.\/:+-]`，profile 文件里 `export ANTHROPIC_MODEL="qwen3.8-max[1m]"` 整行不匹配，`modelsDeclared` 漏掉这个模型。

**消费面**：全仓只有 `doctor.ts:1199` 一处——打一行注记「配置声明模型：…；不代表完整服务端目录」。不进判定面、不进指纹（指纹用的是 profile 文件的 sha256），也不参与脱敏。

**处置**：改，理由是注记现在会对带后缀的 profile 说「未声明」，与实际不符。改法：

- 双引号、单引号、不加引号三种形态的值都改为 `[\w.\/:+-]+(?:${CONTEXT_WINDOW_SUFFIX_PATTERN})?`——由 §2.1 的同一个无锚片段派生，行级正则自己管锚定（值后面是闭引号或空白 / 注释 / 行尾）。可选后缀用非捕获组包住，三个捕获组仍是整个值（含后缀），`m[2] ?? m[3] ?? m[4]` 的分组序号不变。
- **不加引号的形态也放行**：包装器 `~/.local/bin/cld` 是 bash、用 `source` 读 profile（第 77 行）；shell 对赋值右侧不做路径名展开，`export M=qwen[1m]` 在放有能匹配的文件 `qwen1` 的目录里，sh / bash / zsh / dash 都输出原串（计划三审 CODEX-01 核出 r1 的理由错误，我已复跑）。不加引号的带后缀写法因此就是静态字符串。
- 键名范围与「插值 / 命令替换不收」不动。

### 2.3 AC-20 回读口径

**定**：`model_effective` 仍取 `system/init` 的 `model`（`claudeModelReadback(trace.init)`，来源 `envelope`），口径不变。assistant 消息的 `message.model` 不进判定面，只在 `trace.json` 里留痕并附一致性判定。

**理由**：

1. **与另三家同一语义**：AC-20 要的是「CLI 自己回报它按什么配置跑的」，不用请求值冒充。codex 读 rollout 的 `turn_context`、zcode 读会话文件、agy 读信封，都是客户端侧记录，没有一家用服务端回显。claude 取 `init.model` 与之同构；请求值是别名 `opus`，`init.model` 是 CLI 解析后的全名，不是冒充。
2. **未开网关的机器零变化**：本机 33 份样本 `init.model` 与 `message.model` 逐字相同；口径不动，`model_effective` 在这些机器上逐字不变。
3. **`message.model` 当主字段有三个问题**：①没有 assistant 消息的运行（首条消息之前就失败）会从 `envelope` 变成 `unverified`；②它是逐条消息的，CLI 回落到备用模型时会有多个值，要另定聚合规则；③在网关下它同样由网关控制，并不比 `init.model` 更权威。
4. **`result.modelUsage` 不能当单值用**：它按模型分桶，含 CLI 的旁路调用（本机样本有一档同时出现 haiku 与 sonnet）。
5. **后缀保留**：`[1m]` 是生效配置的一部分（上下文窗口），记下来更全。模型族比较不受影响——`MODEL_FAMILY_RULES`（`agents/registry.ts:70-78`）的 qwen 规则 `^qwen(?:\d|[-.])`、claude 规则 `^claude[-.]` 都只看前缀；本批加断言锁住。

**两者不一致时记什么**：`model_effective` 照记 `init.model`、来源 `envelope`，不降级、不告警（网关合法地改写模型名时也会不一致，告警会成稳态噪声）。不一致记在 `trace.json`：

- `parseClaudeEvents` 新增 `reportedModels: string[]`：`type === 'assistant'` 事件里 `message.model` 的值，只收 `typeof m === 'string' && m.length > 0`（空串不收，计划三审 AGY-02），去重、保持首次出现顺序。文本是脱敏后解析的，与 `init` 同口径。
- `claude-trace.ts` 新增纯函数 `claudeModelConsistency(init, reported): boolean | null`：
  - `claudeModelReadback(init).model` 为 null（缺失、空串、带脱敏痕迹）或 `reported` 为空 ⇒ `null`（没法比）；
  - 记 `m = init.model`、`b = stripContextWindowSuffix(m)`。`reported` 里每一项都等于 `m`，或者（`b !== m` 且 `b` 不含 `[` 且该项等于 `b`）⇒ `true`。剥后缀分支只在 init 恰好是「不含方括号的基名 + 一个合法后缀」时适用（计划三审 CODEX-03：r1 的写法会把 `qwen[1m][1m]` 对 `qwen[1m]` 判成一致）；
  - 否则 ⇒ `false`。
- `run()` 写 `trace.json` 时（`claude.ts:1144` 起的那个对象）加一键 `modelReadback: { init: trace.init?.model ?? null, reported: trace.reportedModels, consistent }`。spawn 失败那条早退分支（`:1129`）没有事件流，不加。

**谁读它**：判定面不读；Windows 验收清单第 2 步读它核「`init.model` 带后缀、`message.model` 不带、`consistent: true`」，事后复盘不一致时人工读。

**影响面**：

- 未开网关的机器：`model_effective` / `model_effective_source` 逐字不变；`trace.json` 多一个 `modelReadback` 键（全部机器都多，不受网关开关影响），其余键不变。
- 另三家：适配器与模型族比较一行不动，口径不变。
- 探针：不读 `reportedModels`，`model_flag` 口径不变。准入 / 收口两份脚本只用 `claudeModelReadback`，不变。
