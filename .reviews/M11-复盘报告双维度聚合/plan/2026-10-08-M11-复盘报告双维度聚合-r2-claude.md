## 2. 聚合规格（拟并入主设计 13.2，纪律 6b）

> 凡标「【D-n】」处随拍板改写。

### 2.1 总则

- **论域**：聚合只读报告已读出的东西——时间线轮次（`rounds`）与未进时间线的运行（`unlistedRuns`），数据源仍只有 `.reviews/`（P4）。
- **两个维度正交**（R23）：Driver 维度按 run.json 的 `driver`（发起方）分组；审核者维度按意见的提出方（产出方）分组。同一 Agent id 可同时出现在两张表里，各计各的。
- **读不到就说读不到**：分子或分母取不到时写「—」，不补 0。
- **顺序**：Driver、审核者都按注册表顺序；阶段按 plan / code / bug；「读不到 Driver」组与「来源不明」行排最后（CODEX-05）。

### 2.2 按 Driver 聚合

- **分组键**：时间线轮次按该轮 run.json 的 `driver`；未进时间线的运行按它自己 run.json 的 `driver`。
- **读不到 Driver 的轮次单独成组**（「读不到 Driver」），**不归给缺省 Driver、也不归给该阶段的认领声明**（声明说明「谁声明要写」，不是「那一轮是谁发起的」）。逐轮列原因：「找不到对应的 run.json」或「run.json 读不出（〈成因〉）」。读不到 Driver 就不知道该找谁的裁决件，按任何后缀去试都是猜。
- **run.v1 迁移轮次【D-3】**：推荐归 claude 并在该 Driver 的行注明「其中 N 轮为 run.v1 迁移，Driver 按 v1 惯例记为 claude」。
- **行集**（CODEX-03）：时间线轮次出现过的（Driver, 阶段）∪ 未进时间线运行出现过的（Driver, 阶段），各一行；再给每个 Driver 一行「合计」【D-2】。只有未进时间线运行的行，轮次写 0。
- **列与口径**（AGY-03：最后一列是「读不到 Driver」组的写法）：

  | 列 | 已知 Driver 的口径 | 读不到 Driver 组 |
  | :--- | :--- | :--- |
  | 轮次 | 该行时间线轮次数（含状态非 success 但产出了审查文档的轮次） | 轮次数 |
  | 已裁决 / 未裁决 | 有无本轮裁决件（按该轮 Driver 后缀定位）；未裁决轮次的意见计入意见数，**不进**采纳率分子分母 | 「—」 |
  | 意见数 | 各轮各侧合格意见之和（不跨侧去重）；逐条降级另记「另 N 条逐条降级」；结论读不到的侧不贡献、不记 0 | 「—」（读不出 run.json 就关联不到逐侧结论） |
  | 接受 / 驳回 / 暂缓 | 已裁决轮次裁决表行数之和 | 「—」 |
  | 采纳率 | 接受 ÷（接受 + 驳回 + 暂缓）；分母为 0 写「—」；整份回退编号【D-1】 | 「—」 |
  | 未进时间线的运行 | 该行 Driver 发起、没产出审查文档的运行数 | 「—」，表下注明：未进时间线的运行都有可读 run.json（读不出的只进主题告警），不存在读不到 Driver 的这一类 |

- 「读不到 Driver」组表下逐轮列：阶段 / 轮 / 原因。
- **不变式**：各已知 Driver 组接受 / 驳回 / 暂缓之和 = 第二节全主题采纳率的分子与分母（读不到 Driver 的轮次两边都不含）。

### 2.3 按审核者聚合

- **归属**：一条意见按**提出它的审核者**计——合格意见与严重度按 review json 所属的侧；裁决行按该行来源（「来源」列，缺省按编号前缀）；回退编号 `〈前缀〉-F〈n〉` 按前缀归到那一侧。来源判不出的裁决行单列「来源不明」，不猜。
- **重复意见不去重**：两侧对同一处各提一条，各计一条、各自的裁决各计一次；重合程度看第六节的配对指标。
- **论域**：只取有可读 run.json 的时间线轮次与未进时间线运行；「读不到 Driver」的轮次不计入任何审核者（没有 run.json 就不知道入选了谁）。
- **口径定义**：
  - **入选轮次**（CODEX-04）：只数**时间线轮次**——该侧在本轮 `critics_selected` 里，或本轮 run.json 有它的条目。未进时间线运行的入选与失败只在表 B 专列。
  - **产出结论轮次**（AGY-02、GLM-03）：该侧本轮有可读的合格结论（`sides[].findings` 非 null，即 review json 读得到）。零意见的结论（空审查）算；整份回退、失败、超时不算。
  - **失败**：该侧状态 `timeout` / `failed`；**整份回退**：状态 `parse_fallback`；**逐条降级轮次**：`findings_degraded` 非空。
  - **未进时间线运行中失败**（AGY-05）：该运行 run.json 里该侧 `critics[c].status` 为 `failed` / `timeout` 的次数；不看运行顶层状态。
- **表 A · 意见与裁决**（全阶段合并【D-2】）：审核者、入选轮次、产出结论轮次、合格意见数、blocker、major、minor、nit、逐条降级条数、接受、驳回、暂缓、其中整份回退编号（个数及其接受 / 驳回 / 暂缓）【D-1】。
- **表 B · 运行与模型**：审核者、失败、整份回退、逐条降级轮次、未进时间线运行中失败、生效模型（逐值计次，读不到写「**未回读到** ×N」）、思考等级请求（逐值计次，写法同 §2.4 请求列）、思考等级生效（逐值计次，写法同 §2.4 生效列）。缺席计「— ×N」，与 null 的各写法分开计次。
- 表下注一句：审核者的意见数（来自结论）与裁决行数（来自裁决表）来源不同，可以不等。

## 3. 实现

### 3.1 `meta.ts`（附加字段，不改判定）

`RunMetaReadResult` 成功分支加 `sourceSchema: 'trivium.run.v1' | 'trivium.run.v2'`，在 `readRunMetaDetailed` 两个成功出口各填一值。其余调用方只解构 `meta` / `cause`，不受影响。

### 3.2 `report.ts` 轮次枚举与裁决件按当轮 Driver【D-6】

`enumerateRounds` 先读该阶段全部可读 run.json，按 `rerun_index` 取该号最后一份（与现行「后写覆盖」同序）。轮次由**审查文档**（无 kind 的文件）定义：

- 第 n 轮**有**可读 run.json：后缀 ≠ 那份 run.json 的 `driver` 的文件是审查文档（与闸门同口径）。
- 第 n 轮**没有**可读 run.json（AGY-01）：先看内容——`isReviewArtifact` 为真即审查文档；为假再按后缀兜底：后缀不属于「本阶段任一可读 run.json 记过的 driver ∪ 缺省 Driver」才算。前者让 claude 作唯一产出方的轮次不再消失，后者保住既有「无 front-matter 的孤立审查文档照样出现」（`report.test.ts:370`），并让 codex 的新一轮计划 `…-r3-codex.md`（无 front-matter、codex 在排除集）不造幽灵轮次。这一规则只用于**枚举**，该轮 Driver 记为读不到。

`buildRound` 调 `loadDisposition` 时传 `meta.driver`。不改：`collectUnlistedRuns` 的选取口径、时间线列、未进时间线表的说明文字。

### 3.3 `report.ts` 数据补充

## 7. 不做与残余风险

- **不做**：审核者 × Driver 的二维矩阵；第四节加档位（`tier` / `tier_source`）列；读不到 Driver 的轮次按后缀试探裁决件；跨侧重复意见的语义去重。
- **R1**（GLM-05 重写）：无可读 run.json 的轮次号按 §3.2 枚举，残余两格——①审查文档 front-matter 缺失 / 损坏、且后缀落在排除集（缺省 Driver **无条件**在集内，所以 claude 的损坏审查件必中）⇒ 被当原稿排除；若它是该轮唯一产出方，该轮从时间线消失。run.json 读不出时 `collectUnlistedRuns` 会把那份 run.json 记进主题告警，**从未存在**时则完全无声。②那一轮的 Driver 是本阶段从未出现过的一家、其原稿无 front-matter ⇒ 被当审查文档，「读不到 Driver」组多计一轮。两格都只影响「读不到 Driver」组，不污染已知 Driver 的读数。不为①加 notes：那一格里绝大多数文件是合法原稿，逐个记进告警是噪音。
- **R2**：审核者的意见数与裁决行数来源不同、可以不等；表下注明。
- **R3**：`meta.ts` 的附加字段被所有 `readRunMetaDetailed` 调用方看到；只增不改，全量兜底。
