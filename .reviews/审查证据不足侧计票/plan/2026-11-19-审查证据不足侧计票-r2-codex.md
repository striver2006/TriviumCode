- 若重试成功，应取**新尝试**的证据和票。历史件没有这一张新票，无法实测当时重试会成功还是失败，也无法预言新票内容。

## 三、修复后的决策表

以下针对带轮次链的计划审或代码审。每行的重试数是**每个受影响侧额外调用审核者的次数**，按默认瞬时预算 1、尚未被占用、无独立漂移失败或泄漏计算。表中“中止”统一表示 `failed/partial`，运行或终态 `--wait` 退出 75，无计票、无 `next_action`，run 的 gate 记 `failed`，本机槽回 `idle`，流程停在失败出口。不得靠补裁决把这次中止变为可审批轮。

| 场景 | 额外重试 | strict：计谁、运行与轮次 | 允许降级：计谁、运行与轮次 | gate / 人工后果 |
| --- | ---: | --- | --- | --- |
| 全部证据达标、均有有效结构化票 | 0 | 全部；0，`success/full`，按票型定论 | 同 strict | 先待逐条裁决，校验通过后按下述动作分流 |
| 一侧首次不足，重试达标并产出有效票 | 1，仅该侧 | 本侧只取重试票，其余各一票；0，`success/full`，按最终票型 | 同 strict | 正常分流，首次票不进 gate 或独立来源 |
| 一侧重试仍不足，其余有效票达到半数，例如 2/3 或 1/2 | 1，仅该侧 | 中止；其余侧可留痕，整轮不计票 | 仅合格侧；0，`success/partial`，原因点名该侧；按有效票三档定论，排除原因 `insufficient_evidence` | strict 无裁决推进；降级按动作分流。2/3 可查共同阻断，1/2 的共同阻断记未执行 |
| 多侧仍不足，尚有完成侧但有效票不到入选半数，例如只剩 1/3 | 各不足侧 1；健康侧 0 | 有证据失败即中止，整轮不计票 | 只计幸存的一票；0，`success/partial`，`undetermined / human_review` | 降级轮先待裁决；校验通过后连 A 也进入 `awaiting_approval`，共同阻断记 `skipped-insufficient-sides(1)` |
| 全部侧最终证据不足，没有可继续处置的侧 | 各 1 | 中止，零张计票 | 同样中止，零张计票 | 两种策略均无轮次结论或人工审批停点 |
| 执行证据达标，整份解析回退（例：两侧都回退） | 0 次解析原因的模型重试 | 回退侧可裁决但不投票；例中 0，`success/full`，两侧排 `parse_fallback`，`undetermined / human_review` | 同 strict | 校验回退件的裁决后进入人工停点，独立来源不足；保留既有 L11 行为 |

`N` 为全部入选侧数，`n` 为有效结构化票数。运行允许完成后才执行 `n=0 或 2n<N → undetermined`。其余情况按达到半数的“不通过、修改后通过、通过”依序判；都未达半数取修改后通过。通过和修改后通过均为 `proceed`（校验通过后 A 回 idle，B/C 立人工停点）；不通过且未到上限为 `rerun`（校验后回 idle 续轮），到上限为 `human_review`。任一应裁决项未齐，gate 退 2，不推进。独立根因审 D 仍按本阶段的现行契约走停点，资格和共同阻断同样适用，不增设轮次链。[计票与动作](../../../src/trivium/round-verdict.ts#L76)

## 四、实现与兼容

### 1. 证据只使用既有共享重试预算

尝试级判定继续用 `guard.ts` 的 `judgeSide` 和现有请求、轨迹能力、路径归一化与阈值。回调返回泄漏命中及结构化证据，包含可辨识原因、实际工具次数与下限、项目读取数与生效下限。处理顺序固定为适配器执行结果 → 独立性作废 → 执行证据。适配器失败或超时沿用原原因及瞬时判据。成功尝试有作废命中时走现有的一次作废重跑，第二次命中以 `peer_leak` 收口。同次也缺证据只扣作废额度，作废前后继续共享瞬时额度。

- 每侧维护 `transientUsed` 和 `evidenceRetryUsed`。只有 `transientUsed < transient_max` 且 `evidenceRetryUsed = 0` 时，证据不足才发起一次重试，两者在安排重试时各增加一次。同次多条证据不足原因沿一条重试记录处理。普通瞬时重试只增 `transientUsed`。证据重试后再次证据不足即终止，此规则在 `transient_max > 1` 时仍生效。单侧总调用上界是 `1 + transient_max + 实际作废重跑次数`，最后一项至多为 1。等待预算沿用现有公式。
- 扩展 `onRetryBrief` 和 `buildRetryHint` 的入参，让证据重试携带结构化证据上下文，`.retry.md` 保留本次提示及实际扣额。只有作废重跑才按现行契约生成 `critics.*.attempts`。若其中某次是适配器成功但证据不合格，保留尝试的原始状态，在该次 `fail_reason` 记录证据原因，作废标记按实际命中填写。
- 预算耗尽且证据仍不足时，runner 进度发 `failed` 和证据原因，另行返回原始成功结果、证据判定与调用数。尝试判定异常记录告警，在终判补核，异常本身不扣额度。终判确证达标方可收作成功，仍无法判定则以运行错误收口。前后判定不一致时记录两次观测，按终判从严处置，无额外模型调用。

### 2. 桩能重现组合故障

桩按同次运行、同一审核侧的适配器实际调用序号选择显式测试项。序号项命中优先于现有 `spec.rerun`，否则沿用作废点名标题触发和基础项。没有序号配置时继续使用既有桩规则。为所选模式加可选的证据轨迹覆盖，支持泄漏或 `dirty_output` 与证据不足在同次出现。泄漏用例保留禁读命中并清空工具调用数，或保留禁读读取路径并清除其余合格项目读取，测试先证明确有两个条件同时命中。保持 `TRIVIUM_STUB_CRITIC` 与 `stub/0.0.0` 指纹。

### 3. worker 与归档复用逐侧资格

由 `guard.ts` 持有一个无 I/O 的逐侧资格判定，输入来自本轮实际入选集合。worker 适配器提供原始执行、终判证据和验证过的解析事实，归档侧提供 run 正本的执行、证据和泄漏记录及正式结构化件，两端调用同一判定。派生结果包含可继续处置、有效票、独立结构化来源及对应原因。采用现有注册表，按入选 ID 逐项构造并对账。以 `leakRecordVoids` 为作废依据。

- `executeRun` 将未经改写的原始结果传给 `judgeRun`。解析可暂存，以保留 `consulted`、逐条降级等诊断输入。确定资格后再发布正式结果，原始退出码、实际工具次数、项目读取数、生效下限及漂移归因均从原始轨迹保留。因证据重试替换尝试结果时，已经观测到的正向写入事件仍交终判作归因。最终证据失败侧发布侧级 `failed`，`fail_reason` 记实际证据原因，票级排除归一为 `insufficient_evidence`。用既有 `.failed.json` 分支保存实际调用数和原因，其登记路径与哈希纳入工件留痕。证据不足侧的暂存解析材料从正式审查件、`findings_degraded`、`parse_repairs`、`empty_review`、`parse_fallback_cause` 与 `measureAllPairs` 输入中剔除。
- 真正的适配器失败、超时和二次作废仍以原来类别处置。失败侧的占位 `evidence_ok=false` 不参与原因分类。为新 v3 的 `critics.*` 加可选 `evidence_failure_reason`，仅在原始执行成功、终判因证据不足而判 `failed` 时写入。取值为 `no_trace | insufficient_evidence | no_project_context`，多项不足时取 `checkEvidence` 现有顺序的首项，完整观测说明保留于 `fail_reason`。归档侧用此枚举、侧状态、证据位和既有泄漏记录恢复资格。适配器错误文本只作诊断。缺失或不一致的必要事实按 §四.4 拒绝推进。
- `decideMode` 取可继续处置的侧。计票由 `ballotOf` 认当前版本结构化结论，分母仍为全部入选侧。共同阻断取合格独立结构化来源。证据合格的整份回退仍算执行完成，原文与 F 编号按既有规约裁决，票与独立来源均排除。gate 的本地重解析即使找回可裁决意见，新运行也继续按原始回退事实判资格，历史运行沿用其原规则。证据合格的逐条降级仍须按原编号裁决，该条意见不参与共同阻断。

### 4. 新审查轮的 gate 资格

新计划审、代码审和根因审在 `prepareRun` 生成骨架前按既有配置和 `--allow-single` 计算实际策略，在 v3 正本及现有 worker 交接中冻结为 `effective_failure_policy: strict | degrade`。worker 校验并使用冻结值，正常收尾和异常、失联、取消的共用收尾保留该值。纯文档跳过和 verify 走各自现行契约。生产写出口及契约测试保证新审查骨架带标记，不能靠字段漏写落回历史语义。

- `gate --check`、`gate --await-approval` 和审批复核在同一入口读取本轮正本，再校验运行与资格。带新标记且 `status !== 'success'`，统一给出 `run_not_successful`，退出 2。覆盖运行中、取消、异常、漂移与严格策略中止，含纯超时及混合成因。适用阶段包括没有轮次链的新根因审。显式 `--run-id` 和完整裁决都不改变判定。该规则有意覆盖新审查运行的非证据中止。
- 对带标记的成功轮，用同一侧资格重建投票和独立来源，逐项核对入选侧覆盖、有效票、排票原因、三档计数、`outcome`、`next_action` 和运行期共同阻断人数及状态。有轮次链必须有正本计票，无轮次链按相应阶段的合法形态核对。失败策略、完成度或必要工件与资格矛盾时同样拒绝。发现冲突给出 `round_qualification_mismatch`，点名侧、字段和原因，退出 2。读取、重建与推进使用同一次载入的事实，资格拒绝在写 `joint_checks`、`disputes`、审批记录和状态之前结束。
- 新轮的 `--check-artifacts` 按资格检查应产出项。可裁决侧检查正式文档，失败侧检查已登记且哈希一致的失败件。全部入选侧仍参与未登记审查件检查。历史工件维持现行校验分支。
- 已通过运行资格的轮次继续沿用逐项裁决、共阻断策略、哈希复核与状态迁移。既有 hard 共同阻断仍可写审计结论。§三的三种业务后果分别是 strict 中止、降级成功后翻票续轮、降级成功但有效票不足转人工。

### 5. 共同阻断写明排除原因

运行期人数、`jointCheckState`、`findJointRejectedBlockers` 和审批前复核共用 §四.3 的独立来源集合。少于两侧时 `run.guard.joint_check` 与 gate 按现有分工记录未执行及人数，gate 对证据不足新增 `reason: 'insufficient-evidence'`，同步类型、提示与 `task.json.joint_checks`。此值表示至少一侧因证据不足而排除，即使同轮还有其他成因。另以可选 `excluded_sides` 保存新轮未执行时各排除侧的具体原因，覆盖证据不足、解析回退、作废及其他失败的混合情形。无证据失败时保留既有原因分类，归因范围取完整入选集合。方案保留所有历史 reason 值；旧记录照原样读取。

### 6. 按代际读取，兼容回滚

v1 原校验后在内存迁移，v2 走原只读校验，缺新标记的旧 v3 沿用既有展示及复核规则。历史票、`round_verdict`、`joint_checks` 与审批保持原记录。普通重读与报告无归档写入，历史 gate 操作只在隔离副本验收。兼容性基线使用 §一两份历史正本及其原件哈希。

旧 v3 schema 顶层为 `additionalProperties: true`，旧读取器会容忍 `effective_failure_policy`，并沿用自己的旧资格语义。`round_verdict.excluded` 值域封闭，出现 `insufficient_evidence` 的新记录会被旧读取器拒读。worker 与 gate 同版部署。若回滚业务行为，保留能读新增字段、原因枚举及新轮归档的兼容读侧，禁止用旧二进制对已经写入的新轮执行闸门推进。
