1. M11 的范围来源有六处（§1），核出 **4 件原文没写明、但会改变拆步的事实**：

## 3. 设计约束（已定事项的落地口径）

### 3.1 纪律 6b 的落法

M11 的特性契约（11.5 档位路由、7.1 旗标、13.1.1 配置形态、6.7.1 字段语义、11.1 思考等级透传、report 聚合规格）**在对应代码步开工前并入主设计并升次版本**。本计划把档位链路的契约**一次性**并入（第 2 步），因为 tiers、旗标、配置、run 字段、适配器回读五者互相咬合，分散并入会在中途出现「旗标已入规范、run 字段语义未定」的半截态；report 聚合与 AC-25 的契约与档位无关，**在各自那一步开头并入**（第 3、7 步）。取舍见 D-6。

### 3.2 事实先于契约

档位契约里有三处取决于实测（claude 有无思考等级机制、codex 的 effort 回读能证到哪层、agy 低中档 slug 的回读形态）。按纪律 1「先探路后编码」，第 1 步先拿事实，第 2 步再写契约；第 1 步的结论按纪律 6a 回填主设计 3.6 / 3.7，与第 2 步同版落盘。

### 3.3 run 契约（用户已定，本稿只写落地口径）

- 不升 v3；`effort_requested` / `effort_effective` / `tier_source` 在 v2 原地接线；字段**缺席** = M11 之前的旧留痕，**null** = 该侧没有这项事实。
- `effort_effective` 只取回读值，不采信请求值；请求值与生效值分记。
- 旧字段 `effort` 保留并继续写、与 `effort_requested` 同值；schema 描述标为旧名，新读者一律读 `effort_requested`；删不删不在 M11。
- 新增事实（档位名、生效值来源等）照 `unknown_reason` / `after_tree_hash` / `plan_final_check` 先例在 v2 原地扩可选字段；**`$defs.critic` 本身 `additionalProperties: true`，挂在它下面不触碰封闭节点**。若某个事实只能挂在顶层或 `guard` 这类封闭节点（顶层 `additionalProperties: true`，`guard` 为 false），按「要不要升版本」交用户定——目前核出的需求全部能挂在 `$defs.critic` 下，**未遇到须升版本的情形**。
- schema 描述去掉「待实施 · M11」字样与写侧接线同一步（第 6 步）。

### 3.4 config 契约

演进设计 §11 :629-635 早已把 `{tier}` / `{model, effort}` 定为 `config.v2` 的 M11 目标形态，schema 描述 :470 也写了「M11 随档位全链路放开」。所以 config 侧同样**原地扩 v2**：新增键全部可选，旧配置不改也能跑、行为不变。唯一的兼容代价是**旧构建读新配置会被 `additionalProperties: false` 拒在预检**（安全的失败，零工件），这与升 v3 时旧构建的表现相同。是否认可列为 D-3。

### D-1 · 主设计 18.1 #17：三档挂 Agent 还是挂模型（含三个子项）

- **候选**：(a) **挂 Agent**：`agents.〈id〉.tiers.{low,medium,high} = {model, effort?, profile?}`，组合可跨模型、跨家族（18.1 默认、演进设计 §5.4）；(b) **挂模型**：每个模型声明自己的三档 effort，档位只选 effort。
- **代价**：(b) 表达不了 glm「同族快慢两档靠换模型」与 gemini「档位编码在 slug」两个既有先例，等于只服务 codex 一家；(a) 要处理「组合里的 effort 必须是该模型的原生枚举」这条校验。
- **建议**：**(a)**。
- **子项 1 · 原生 effort 枚举从哪来**：(i) 配置里手写 `agents.〈id〉.models.〈m〉.efforts`（演进设计 §5.4 示例）；(ii) **探针现取**——codex 的 `debug models` 已在解析 `supported_reasoning_levels`（`probes/codex.ts:321-331`），只是没落盘；agy 由 slug 后缀派生；zcode / claude 无此概念。**建议 (ii)**：手写一份目录是第二个事实来源（设计原则 P7），且 codex 客户端不校验 effort（`effort_validated: false`），手写错了不会有任何报错；探针拿不到目录时按既有 slug 规则「跳过校验而非硬拒」，生效值回读兜底。代价是 `ProbeSection` 多一个字段。
- **子项 2 · `agents.codex.effort`（阶段级、枚举 low/medium/high、死键）**：(i) 档位上线后标 deprecated、由 tiers 取代；(ii) 接线（按现值 high 下传）。**建议 (i)**：它的枚举本身违反 11.5 禁令 ①（qwen 无 high、deepseek 无 medium），接线会把一个错误枚举变成真行为。`agents.gemini.effort` 有真实消费方，保留为「profile 格是裸 slug 时」的回落。
- **子项 3 · `init` 模板写不写 tiers**：建议**不写**——旧形态零改动可跑，tiers 是可选增强；写进模板等于把一组未经真审验证的组合冻进每个新项目（EV-130 的教训）。
