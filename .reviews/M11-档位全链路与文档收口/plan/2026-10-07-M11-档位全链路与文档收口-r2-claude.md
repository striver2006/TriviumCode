### 3.1 纪律 6b 的落法（D-6）

### 3.2 事实先于契约

### 3.5 档位数据模型（D-1，主设计 18.1 #17 拍板为「挂 Agent」）

- `agents.〈id〉.tiers` 为 `low` / `medium` / `high` 三键的映射（可缺键），每档是组合 `{model, effort?, profile?}`，可跨模型、跨家族；`effort` 取该模型的**原生枚举**值，缺省表示该 Agent 用模型选择承载档位差异（glm、gemini）；`profile` 只对 openai vendor 有意义（§3.6）。
- `agents.〈id〉.default_tier` 可选，取三档之一。
- **原生 effort 枚举不在配置里手写**（不加 `agents.〈id〉.models`）：codex 由探针从 `debug models` 的 `supported_reasoning_levels` 取并落盘（`probes/codex.ts:321-331` 已在解析，只差落盘）；gemini 由 slug 后缀派生；glm、claude 无此概念（第 1 步若证实 claude 有，再定）。探针拿不到目录时**跳过 effort 校验而非硬拒**（同既有 slug 规则），生效值回读兜底。
- `agents.codex.effort`（阶段级、枚举 low/medium/high、死键）**标 deprecated，不接线**；`agents.gemini.effort` 有真实消费方，保留为「档位表格子是裸 slug 时」的回落。
- `init` 模板**不写** tiers 示例。

### 3.6 厂商 profile 与档位（D-2，EV-22 + EV-27 结构部分）

- 档位条目可带厂商 `profile`：`tiers.high = {profile: deepseek, model: deepseek-v4-pro, effort: max}`，「换家族 = 换档位」。
- 新增 `--profile-codex 〈名〉` 作单次精确覆盖。
- 厂商 profile 的取值次序：`--profile-codex` > 档位条目的 `profile` > `agents.codex.profile` > 不传。
- preflight 核「档位里的模型在该 profile 的模型目录中」（`models_by_profile` 已有，`probes/codex.ts:933`）。
- 层级不拆：仍在共享层；协作者机器上没有那个 profile 时，在本机层 `config.local.yaml` 整段覆盖 `agents.codex.tiers`（v1.3.120 那句文档的延伸）。EV-27 结构部分按此结案。

### 3.7 路由优先级（D-8）

三级，自上而下：

1. **命令行**：`--tier-〈id〉` 选档；`--model-〈id〉` / `--effort-〈id〉` / `--profile-codex` 精确覆盖。精确值与档位同时给出时，**按字段合并**——精确值覆盖档位组合里的对应字段，并告警。`--effort-〈id〉` 可单独给，作用于其余各级解析出的模型；值对该模型原生枚举校验。
2. **档位表**：`profiles[active_profile].〈id〉.〈阶段〉`，三形态「裸 slug ｜ `{tier}` ｜ `{model, effort}`」；裸 slug 行为与今天逐字相同。
3. **Agent 默认档**：`agents.〈id〉.tiers[default_tier]`。

都没有时退 69（预检零工件），与今天「profile 未定义该阶段模型」的出口同一处。**原四级里的「主题级 `task.json` 覆盖」删除**：规范有、实现从未接线（`review.ts:1131`）；第 4 步同时删掉 `routeModel` 的 `topic` 参数，BACKLOG 登记一条「主题级覆盖从未接线，M11 删除」。

### 3.8 run.v2 新字段与 effort 回读口径（D-4、D-5）

`$defs.critic` 下：

| 字段 | 含义 | 取值 |
| :--- | :--- | :--- |
| `effort_requested` | 思考等级请求值 | 原生枚举值；该侧无此概念为 null |
| `effort_effective` | 思考等级生效值，只取回读 | 见下方逐家口径；回读不到为 null |
| `effort_effective_source` | 生效值从哪来（与 `model_effective_source` 同构） | 回读面名称或 `unverified`；该侧无此概念为 null |
| `tier` | 档位名 | `low` / `medium` / `high`；精确覆盖或裸 slug 时 null |
| `tier_source` | 档位或模型的来源 | `cli`（`--tier-〈id〉`）、`override`（精确值，档位不适用）、`profile`（档位表格子）、`agent_default`（`default_tier`）、`legacy`（档位表格子是裸 slug） |

顶层加 `profile`：本次实际使用的档位表名（`--profile` 覆盖后的 `active_profile`）。

逐家 `effort_effective` 口径：

- **codex**：先由第 1 步对照「请求值、会话文件 `turn_context.payload.effort`、厂商能否给出服务端回执」三者。能拿到服务端回执就以回执为准；拿不到则**退路**：接受 `turn_context.payload.effort` 为生效值，`effort_effective_source` 写明来源，主设计 6.7.1 与 PRD AC-23 达成边界写清「codex 侧只证到客户端解析，服务端归并不可见」。

- **glm**：null（D-9）。
- **claude**：null，除非第 1 步证实存在可回读的思考等级机制。
