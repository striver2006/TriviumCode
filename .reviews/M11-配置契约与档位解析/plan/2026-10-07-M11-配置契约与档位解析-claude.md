## 2. 待拍板（我给建议，不自行定）

### P-1 第 4 步到第 6 步之间的空窗（用户点名 1）

**问题**：档位条目里的 `effort` 与 `profile` 要到第 6 步才透传。本步若照常让档位改变模型，会出现两类「预检看到的」与「实际发出的」不一致：

- **厂商 profile**：档位写 `{profile: deepseek, model: deepseek-v4-pro}`，预检按 deepseek 目录校验模型；运行却以 `-p kimi`（`agents.codex.profile`）发起 deepseek 的模型 ⇒ 端点拒绝、该侧整格失败。
- **思考等级**：档位写 `effort: low`，预检按原生枚举校验通过；运行时 codex 不传 `-c`（取 profile 基底，本仓即 `max`），gemini 取 `agents.gemini.effort`——用户以为选了低档，实际跑的是另一档，留痕里也没有（run.json 的 effort 字段第 6 步才写）。

| 候选 | 做法 | 代价 |
| :--- | :--- | :--- |
| **A（建议）临时硬拒** | 校验链最后加一道**过渡闸**：解析结果里 `effort` 来自档位条目或 `{model, effort}` 格子（非空）、或厂商 profile 来自档位条目且**不等于** `agents.codex.profile` ⇒ 预检与 `review` 准备阶段退 64、零工件，文案写明「档位里的思考等级 / 厂商 profile 随 M11 第 6 步接线，当前版本不下传」。档位 profile 与 `agents.codex.profile` 相同时放行（运行与预检一致）。永久校验（枚举、名单、目录）排在过渡闸之前，非法值照常报可用值。第 6 步删过渡闸。 | 本步交付面只剩「档位换模型」；EV-27 结构部分要到第 6 步才实际可用（本步不能结案，见 §3.7） |

### P-5 本机层覆盖档位时的合并语义（起草时核出，倾向按规范直接落实）

`deepMerge` 对象逐键递归（§1.3）。两处后果：

- **`agents.〈id〉.tiers`**：本机层写 `tiers.high = {profile: x, model: y}`，共享层 `tiers.high = {profile: kimi, model: k, effort: max}`，合并出 `{profile: x, model: y, effort: max}`——effort 来自另一家族的模型。主设计 13.1.1 :3203 与 11.5 :2948 写的是「本机层**整段覆盖** `agents.codex.tiers`」。
- **`profiles` 格子**：共享层 `{model, effort}`、本机层 `{tier}`，合并成 `{tier, model, effort}`，两份文件各自合法、合并结果被 schema 拒——用户看到的报错指不出是哪个文件的问题。

**做法**：合并时 `agents.〈id〉.tiers` 整段替换（与规范字面一致），`profiles.〈表〉.〈id〉.〈阶段〉` 格子整格替换；其余键维持逐键合并。13.1.1 补一句合并语义。这一条改的是合并语义，所以列出来；用户若认为 `tiers` 应「逐档整条替换」而不是「整段替换」，请指出——那会让本机层只写一档时保留共享层的另两档。

## 3. 方案（按 P-1～P-5 取建议项写；拍板不同则按 §5 的分支改）

### 3.1 config 契约（任务一）

**schema `config.v2.json`**（原地扩，`$schema` 标识不变）：

- `$defs` 新增：
  - `tierName`：`enum: [low, medium, high]`；
  - `effortValue`：`type: string, minLength: 1`——**不写枚举**（11.5 禁令 ①：原生枚举随模型而异，由预检对探针结论校验）；
  - `tierEntry`：`{model: string(minLength 1), effort?: effortValue}`，`additionalProperties: false`，`required: [model]`；
  - `tierEntryOpenai`：在 `tierEntry` 基础上加 `profile?: string(minLength 1)`；
  - `tierEntryModelOnly`：`{model}`（zcode 支用，见下）；
  - `stageModel`：`oneOf` 三形态——`string(minLength 1)`（裸 slug）｜ `{tier: tierName}`（`required: [tier]`，`additionalProperties: false`）｜ `{model, effort}`（两键都必填，`additionalProperties: false`）。
- 四个 agent 分支各加可选 `tiers`（`properties: {low, medium, high}`，`additionalProperties: false`，`minProperties: 1`）与可选 `default_tier: tierName`：
  - antigravity / anthropic 支：值为 `tierEntry`；
  - openai 支：值为 `tierEntryOpenai`（`profile` 只对 openai vendor 有意义，11.5 :2942）；
  - **zcode 支：值为 `tierEntryModelOnly`，不收 `effort`**——glm 无此概念（11.5 :2954「glm 无」），按「原生枚举为空即跳过」会放行任意值并静默丢弃，schema 层拒更早、更准。这是对 11.5 的收紧，§6 请审查员核。
- `profiles.〈表〉.〈id〉` 的 `plan/code/bug` 改为 `$ref: stageModel`；Agent 级 `effort` 枚举键**不动**（无读取点，不在本步，见 §7）。描述 :470 去掉「M11 随档位全链路放开」与「退 69」，改写为三形态现状。
- openai 支：`effort` 移出 `required`，属性保留并加 `deprecated: true` 与描述（照 `readonly_commands` 先例），**类型约束不放宽**（仍是三阶段 `low/medium/high` 对象）。antigravity 支的 `effort` 不动（仍必填）。
- anthropic 支描述里「effort 同理不加：claude 侧没有对应的 CLI 旗标」改准（第 1 步已推翻，3.7 :459）。

**`types.ts`**：

- 新增 `TierName`、`TierEntry`（`{ model: string; effort?: string; profile?: string }`，`profile` 注释写明只对 openai 支生效、schema 只在该支放行）、`StageModel = string | { tier: TierName } | { model: string; effort: string }`。
- `ProfileEntry` 的阶段值改为 `StageModel`；四个 `*CriticConfig` 加 `tiers?: Partial<Record<TierName, TierEntry>>` 与 `default_tier?: TierName`。
- `CodexCriticConfig.effort` 删除（类型层）；`GeminiCriticConfig.effort` 保留。

**`config.ts`**：默认值删 `agents.codex.effort`；`init` 模板不写 tiers（模板取自默认值，删了默认值即不写）；合并语义按 P-5（§3.6）。

**旧配置零改动可载**：既有 `.trivium/config.yaml`、默认值、v1 迁移产物、带 `agents.codex.effort` 的旧配置都要过；裸 slug 格子走 `legacy` 来源，解析出的模型与今天 `routeModel` 逐字相同（§3.3 有等价性用例）。

### 3.2 废弃键（任务二）

- `DEPRECATED_CONFIG_KEYS` 加 `{ path: ['agents', 'codex', 'effort'] }`，**精确路径、不用通配**。注释写明不用通配的理由（`agents.gemini.effort` 有消费方）。
- 判定沿用 `deprecatedConfigKeysIn`（看合并结果：默认值不再带它 ⇒ 出现即某个磁盘源写了它）；提示沿用 `deprecatedConfigNotice`，doctor 与 preflight 各一条，其余命令不打。

### 3.3 档位解析（任务三）

新增纯函数 `resolveTier`（放 `adapters/base.ts`，与被取代的 `routeModel` 同处；不读盘、不读环境）：

```ts
resolveTier(cfg, critic, stage, cli?: { tier?, model?, effort?, vendorProfile? }) => {
  model: string | null;
  effort: string | null;
  vendorProfile: string | null;   // 非 openai vendor 恒 null
  tier: TierName | null;
  tierSource: 'cli' | 'profile' | 'agent_default' | 'legacy' | 'override' | null;  // 无模型时 null
  fieldOrigin: { model, effort, vendorProfile }: 'tier' | 'cell' | 'cli' | 'agent' | null;  // 供告警与过渡闸
  warnings: string[];
}
```

**第一段 · 基础组合**（取第一个命中者）：

1. `cli.tier` → `agents.〈id〉.tiers[cli.tier]`，来源 `cli`；
2. `profiles[active_profile].〈id〉.〈阶段〉`：`{tier}` → 该档、`profile`；`{model, effort}` → 该组合、`profile`；裸 slug → 该模型、`legacy`；
3. `agents.〈id〉.tiers[default_tier]` → `agent_default`。

档位名指向未定义的档时，解析函数**不抛**、返回「档位缺失」标记，由校验层（§3.4）统一报 64 并列可用档——解析保持纯函数、零副作用，报错文案集中一处。

**补全**：

- 厂商 profile（openai vendor）：档位条目的 `profile` > `agents.codex.profile` > null；
- 思考等级：基础组合给了就用；裸 slug 格子且该 Agent 配置段有阶段级 `effort`（只有 antigravity 支）时回落它（11.5 :2946「作裸 slug 时的回落」），与今天 `effortFor` 同值。
