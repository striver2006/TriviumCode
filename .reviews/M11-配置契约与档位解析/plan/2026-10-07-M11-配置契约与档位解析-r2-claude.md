### 3.3 档位解析（任务三）

新增纯函数 `resolveTier`（放 `adapters/base.ts`，与被取代的 `routeModel` 同处；不读盘、不读环境）：

```ts
resolveTier(cfg, critic, stage, cli?: { tier?, model?, effort?, vendorProfile? }) => {
  model: string | null;
  effort: string | null;
  vendorProfile: string | null;   // 非 openai vendor 恒 null
  tier: TierName | null;
  tierSource: 'cli' | 'profile' | 'agent_default' | 'legacy' | 'override' | null;  // 无模型时 null
  fieldOrigin: { model, effort, vendorProfile }: 'tier' | 'cell' | 'cli' | 'agent' | null;  // 供告警与过渡闸
  missingTier: { name: TierName; via: 'cli' | 'profile' | 'agent_default'; defined: TierName[] } | null;
  warnings: string[];
}
```

**第一段 · 基础组合**（取第一个命中者）：

1. `cli.tier` → `agents.〈id〉.tiers[cli.tier]`，来源 `cli`；
2. `profiles[active_profile].〈id〉.〈阶段〉`：`{tier}` → 该档、`profile`；`{model, effort}` → 该组合、`profile`；裸 slug → 该模型、`legacy`；
3. `agents.〈id〉.tiers[default_tier]` → `agent_default`。

档位名指向未定义的档时，解析函数**不抛**、填 `missingTier`，由校验层统一报 64 并列可用档（§3.4）。空串裸 slug 按「无模型」处理（与今天 `routeModel` 的 falsy 判定同）。

**补全**：

- 厂商 profile（openai vendor）：档位条目的 `profile` > `agents.〈id〉.profile` > null（字段取自配置段，不按 Agent id 判）；
- 思考等级：基础组合给了就用；裸 slug 格子且该 Agent 配置段有阶段级 `effort`（只有 antigravity 支）时回落它（11.5 :2946），与今天 `effortFor` 同值，`fieldOrigin.effort = 'agent'`。

**第二段 · 按字段叠加精确值**：`cli.model` / `cli.effort` / `cli.vendorProfile` 各自覆盖对应字段；被覆盖字段原本来自档位（`fieldOrigin === 'tier'`）时追加告警。`cli.effort` 可单独给。gemini 特例：模型 slug 带档位后缀且最终 `effort` 来自 `cli` 时告警「slug 已编码档位，`--effort-gemini` 不生效」——后缀判定经适配器钩子（§3.4），解析函数只收钩子结果，不写死后缀表。

**`tier` / `tier_source` 取值**（按 P-6 A；主设计 11.5 :2952 与 6.7.1 :1262 同步改写）：

| 情形 | `tier` | `tier_source` |
