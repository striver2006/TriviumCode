### AGY-01 · 吹毛求疵（nit）

| 类别 | maintainability ｜ 层次 code |

**问题**：集成测试 E1 使用文件系统的 mtimeNs 严格小于断言（< statusMt）来保证写入先后顺序，对底层文件系统的时间戳分辨率和时钟单调性存在脆弱依赖。在低时间分辨率文件系统或极端负载/虚拟机环境下，相隔极短的两次异步写可能落入同一时钟 tick 导致相等，引发偶发假红。

**依据**：test/integration/run-protocol.test.ts:313-316 定义了 mt = async (p: string) => (await fs.stat(p, { bigint: true })).mtimeNs 并断言 (await mt(a.runJson)) < statusMt 与 (await mt(a.taskJson)) < statusMt。结合 doc/05_testing/REPORT_2026-09-26_trace_field_fixes.md §3.3，此设计为了避免侵入 cancelRun 加中断测试钩子而依赖文件系统纳秒修改时间戳钉先后。

**建议**：可考虑在断言中允许相同纳秒时间戳的边界，或在两次写之间显式引入可控微小延迟/因果标记，或在注释中明确说明跨平台或特定容器化 CI 环境下时间戳分辨率的边界前提。
