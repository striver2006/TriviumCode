## 一、目标与范围

### 目标

把 `trivium.disposition.v1` 的 `role` 从 `{"const": "claude"}` 放宽为「任意已登记 Agent id」，
使**非缺省 Driver 能写出合法裁决件**，闸门闭环走得通。

这是 M9 第 6 步验收的**硬前置**：验收（J4/J5/J6）要让 claude 作为审核者真跑一次，
那就必须由别家当 Driver；而验收剧本要走完整闸门，闸门要裁决件。
非缺省 Driver 写不出合法裁决件 ⇒ **验收一次都跑不完**。这不是概率问题。

## 二、现状与约束

### 三条路各自撞墙

非缺省 Driver 今天写裁决件，三种写法**全部失败，且失败点各不相同**：

| 写法 | 失败在哪 | 谁拦的 |
| :-- | :-- | :-- |
| 照资产写（名与 `role` 都是 `claude`） | 闸门按 `driver` 定位，找不到 → `missing_disposition` | `gate.ts:164` |
| 改文件名、保留 `role: claude`（谎报件） | role↔driver 比对判红 | `gate.ts:233`（第 3 轮新加） |
| 诚实写 `role: codex` | **过不了 schema** → `bad_front_matter` | `disposition.v1.json` |

前两条是第 2/3 轮**刻意堵上**的。堵完之后，schema 这一条成了唯一还开着的口，**而它是死的**。

### 与 `run.v2` 的口径冲突（这是本条的根因）

同一个概念（Agent id），隔壁文件的处理是：

```json
"driver": { "type": "string", "minLength": 1,
  "description": "…取值是否为已登记 Agent 由代码层按注册表校验——此处不枚举…" }
```

而 `role` 在 schema 里**抄了一份 id**，与纪律 7「Agent id 的唯一来源是注册表」直接相抵。
本步就是把 `role` 拉回同一口径——**不是发明新做法，是消除一处偏离**。

### 存量影响：实测为零

- 归档 **72 份**裁决件，`role` **全为 `claude`**，文件名后缀与之逐份一致（第 2/3 轮两侧独立核过，我也核过）。
- `claude` 是已登记 Agent ⇒ 放宽 + 注册表校验后**照样通过**。
- 方向是**放松**约束，不是收紧 —— 与「契约演进不得锁死老主题」那条纪律同向，不逆向。

## 三、方案（每步可单独验证）

> 每步后：`npm run typecheck` → `npm run pretest` → 跑该步对应用例。

### 3.1 契约放宽 — [skills/dual-critic/schema/disposition.v1.json](skills/dual-critic/schema/disposition.v1.json)

```json
"role": {
  "type": "string",
  "minLength": 1,
  "description": "裁决件的执笔方（当轮 Driver）的 Agent id。取值是否为已登记 Agent 由代码层按注册表校验——此处不枚举，与 run.v2 的 driver 同源。M9 第 5 步之前恒为 claude。"
}
```

`required` 不动（`role` 仍必填）；`additionalProperties: true` 不动。

### 3.2 补注册表身份校验 — [src/trivium/schemas.ts:312](src/trivium/schemas.ts#L312)

`validateDispositionFrontMatter` 现在是纯 ajv 一段式：

```ts
export function validateDispositionFrontMatter(data: unknown): string[] {
  const v = compile('disposition', dispositionSchema as object);
  return v(data) ? [] : formatErrors(v.errors);
}
```

改成**两段式**，与 `validateRunMeta` 的既有形态逐字同构（`ajv` + `checkAgentIdentities`）：
schema 过了之后，再判 `role` 是不是已登记 Agent（用 `isAgentId`，`checkAgentIdentities:264` 校 `driver` 用的就是它）。

**这一步不能省**：只放宽不补校验＝净放松契约，`role: 随便写点什么` 会当场合法，
而「谁写的」是留痕的作者身份，正是审计系统最不该松的那一格。

> 已核：`isAgentId` 在 `schemas.ts` 已导入（`checkAgentIdentities` 在用），不新增依赖。

### 3.3 资产面 6 处 — 实测清单

| 文件 | 行 | 现状 |
| :-- | :-- | :-- |
| `skills/dual-critic/templates/disposition.md.template` | 5 | `role: claude` |
| `skills/dual-critic/templates/response.md.template` | 5, 16 | `role: claude`、`-response-claude.md` |
| `skills/dual-critic/templates/README.md` | 9, 10 | `-revised-claude.md`、`-response-claude.md` |
| `skills/dual-review-plan/SKILL.md` | 158 | 写出 `…-revised-claude.md` |
| `skills/dual-review-bug/SKILL.md` | 158 | 同上 |
| `skills/dual-review-code/SKILL.md` | 160 | 写出 `…-response-claude.md` |
| `skills/dual-run/SKILL.md` | 74, 89 | 同上两处 |

这些是**祈使句**——它们在指挥 Driver 用什么文件名与 `role`。
不改的话，非缺省 Driver 照着做，产出的正是上表第一种失败（`missing_disposition`）。

改法：把字面 `claude` 换成「当轮 Driver 的角色名」的表述（模板里用占位符，
SKILL.md 里用 `…-revised-<当轮 Driver>.md` 这类写法）。

**改完必须重跑 `install:local`** —— SKILL.md 与模板是装到 `~/.claude/skills/` 的，
仓内改了而不装，下一次 `/dual-review-*` 读的还是旧文本。

### 3.4 用例：两处**必须同改**，否则静默失效

**(a) `config-schema.test.ts:105` 的负例会当场失去意义。** 现状：

```ts
const bad = validateDispositionFrontMatter({ …, role: 'gemini', …, addresses: [] });
assert.ok(bad.some((m) => m.includes('role')), …);
assert.ok(bad.some((m) => m.includes('addresses')), …);
```

放宽之后 `gemini` 是**合法**取值，role 那条错误消失 ⇒ 第一条断言直接红。
**正确修法不是删它**，而是把负例换成一个**真未登记**的 id（如 `'nobody'`），
让它继续守「未登记 id 必须被拒」——那正是 3.2 新加的校验。
同时补一条**正例**：`role: <某个非缺省的已登记 id>` 必须返回 `[]`。

> 这一格是本步最容易做错的地方：红了之后顺手删断言，就把 3.2 的校验变成了没人看的代码。

**(b) T-11 第 3 格** [gate-loop.test.ts:1339](test/integration/gate-loop.test.ts#L1339)：

```ts
assert.notEqual(after.code, EXIT.OK, 'EV-66 若已修复，请把本断言改成期望通过');
assert.match(after.stdout + after.stderr, /bad_front_matter|role/, …);
```

翻成「期望通过」（`assert.equal(after.code, EXIT.OK)`），并**删掉**那条 `/bad_front_matter|role/`
断言——它描述的是被修掉的失败形态。

**T-11 前两格不动**：第 1 格（定位正确）与第 2 格（谎报件判红）与本步无关，
第 2 格反而会在本步之后成为**唯一**的作者身份锁（见 §四 R-1）。

### 3.5 新增用例

| # | 放哪 | 断言 |
| :-- | :-- | :-- |
| **N-1** | `config-schema.test.ts` | 未登记 id（`'nobody'`）→ 报错含 `role`；已登记非缺省 id → `[]`（3.4a） |

## 四、不可逆决策

| # | 决策 | 为什么不可逆 | 处置 |
| :-- | :-- | :-- | :-- |
| **R-1** | **放宽后，作者身份从「两道锁」变成「一道锁」** | 今天 `role` 被 schema 钉死是第一道，`gate.ts:233` 的 role↔driver 比对是第二道。放宽之后只剩后者，而它是**第 3 轮才写的、只被三格断言验过**。codex 在第 3 轮盲区里专门留话：「EV-66 把 role 放宽之后，该判据会变成唯一的作者身份锁……**我没有对那个未来形状做验证**」 | 本步补 **N-2** 独立单测；**请双审把这一处当重点看**（见 §七 D1） |
