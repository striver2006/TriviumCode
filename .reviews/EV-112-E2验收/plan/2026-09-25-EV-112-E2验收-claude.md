## 1. 为什么要这一轮

E1 只能零配额地走到模型调用之前：401 让 CLI 非零退出，`run()` 在失败早退处返回，回读与落点自检走不到；
artifacts、sessions、memories 要走到工具调用才会写。这一轮用真实配额让 glm 一侧完整跑一次，把这几格从静态读数升为实测。

## 2. 怎么进入无副本一支

`review.ts` 在派发前拒绝空模型，「未指定模型」这一成因在流水线里走不到；唯一可达的成因是副本源 `~/.zcode/cli/config.json` 缺失。
本轮在审查运行期间把它暂时挪开，跑完立即挪回。

## 3. 判据（跑完只读核）

1. run.json `critics.glm.model_route` 为 `global`，`model_effective` 非空且来源为 `trace`（首次读数，无基线可比）；
2. `carriers_landed` 为 `{ log: true, rollout: true, leaked_to_home: { log: false, rollout: false } }`，收尾播报里没有落点缺失或泄漏的句子；
3. 运行目录 `glm/home/.zcode/cli/` 下有 log、rollout、db，走到工具调用时还有 artifacts；
4. 真实 HOME 按内容查不到本次会话：`~/.zcode/cli/log` 里本次拉起后改过的文件、rollout、artifacts、sessions、会话库。

## 4. 请审查员看的

本稿第 2、3 节的判据是否足以说明「无副本一支的 CLI 产物确实落进了运行目录、没有写进真实 HOME」；有没有漏掉的判据。
